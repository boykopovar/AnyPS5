# libSceNpSnsYouTubeDialog technical debt

### Silent stubs

- [sceNpSnsYouTubeDialogOpen](../../../core/libs/prx/libSceNpSnsYouTubeDialog/Export.cpp) (libSceNpSnsYouTubeDialog) - with `ANYPS5_PSN_DIALOGS=show`, a successful open shows AnyPS5's notice that the feature needs PlayStation Network; the console's own display without PlayStation Network is not measured, and the notice wording is AnyPS5's.
- [libSceNpSnsYouTubeDialog](../../../core/libs/prx/libSceNpSnsYouTubeDialog/Export.cpp) - the YouTube dialog runs the common-dialog state machine but shows nothing and reports the user as having cancelled, as there is no YouTube account link. The names and NIDs are from the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceNpSnsYouTubeDialog.c); no type database has these prototypes ([Orbital's](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json) has none for this library). The signatures are the common-dialog family shape Orbital documents for sibling dialogs (`Open(const struct *param)`, `GetResult(struct *result)`, `void` otherwise), not measured ones, and console behaviour is not measured: nothing is read through `param` and only the leading `int32_t` of `result` is written. Returning `0x80B8000D` for an unwritable result pointer is a host-safety fallback.
