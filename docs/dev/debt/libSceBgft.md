# libSceBgft technical debt

### Silent stubs

- [sceBgftServiceIntDownloadRegisterTaskByStorageEx](../../../core/libs/prx/libSceBgft/Export.cpp) - the module's own checks, read from firmware 13.42 disassembly (review of #15131): `0x80990002` before initialization, `0x80990004` for a null params or taskId, then the params pointers — +0x8 must be non-null with `strnlen(s, 0x31) <= 0x30`, and a non-null +0x10, +0x20 or +0x28 string must satisfy `strnlen(s, 0x800) <= 0x7ff`, `strnlen(s, 0x259) <= 0x258` and `strnlen(s, 0x800) <= 0x7ff` respectively, a null there skipping the check; no task id is ever written. Valid initialized input returns `0x80990006`, the service's answer the module forwards to at `10db`, per the [etaHEN writeup](https://github.com/etaHEN/etaHEN/blob/5061a853/PS5%20technical%20writeups/pkg-writeup.md), whose decompiled handler ignores both arguments; the writeup predates the 13.60 module inspected here
- [sceBgftServiceIntDownloadRegisterTaskByStorage](../../../core/libs/prx/libSceBgft/Export.cpp) - takes `(params, taskId)`, settled by its 13.42 disassembly (review of #15131): `0x80990004` for null params, otherwise it copies 0x68 bytes of params, zeroes the u32 at +0x68 and takes the Ex path with the same taskId, so every later check and result matches Ex; the copy and the zero touch nothing the checks read, so they are not performed here
- [sceBgftServiceIntInit, sceBgftServiceIntTerm](../../../core/libs/prx/libSceBgft/Export.cpp) - Init follows its firmware 13.42 disassembly (review of #15131): `0x80990001` when already initialized, checked before `0x80990004` for a null parameter, otherwise it marks the client initialized and returns 0; the heap stays unused because no background transfer service exists on the host. The parameter is a heap pointer and size in the [airpsx](https://github.com/barisyild/airpsx/blob/aed9f7b5/src/cpp/lib/LibSceBgft.hx) and [etaHEN writeup](https://github.com/etaHEN/etaHEN/blob/5061a853/PS5%20technical%20writeups/pkg-writeup.md) usage, both supplying a live buffer; a zero `heapSize` is covered by no source, so it throws through `NotImplemented_nid_no_patch` rather than returning anything. Term (`0xb80`) is untraced and keeps returning 0 under Silent stubs; whether it clears the initialized state is unknown

The 13.60 label refers to the latter SDK-formatted word, not independently authenticated retail firmware or an introduction date. The [reproducible static audit](https://github.com/boykopovar/AnyPS5/pull/12367#issuecomment-6470603298) records the extraction/filtering procedure and the observed NID-set digest. Each row below was read as a defined `STT_FUNC` entry; RVA and size are symbol-table values, not runtime addresses or function bytes.
