# libSceFios2 technical debt

### Silent stubs

- [`sceFiosCacheFlushSync`, `sceFiosCacheFlushFileSync` and `sceFiosCacheFlushFileRangeSync`](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) are void no-ops on PS4 10.71. The host has no FIOS cache to invalidate, so these calls have no effect.
- [sceFiosCachePrefetchFH, sceFiosCachePrefetchFHRange, sceFiosCachePrefetchFHRangeSync, sceFiosCachePrefetchFHSync, sceFiosCachePrefetchFile, sceFiosCachePrefetchFileRange, sceFiosCachePrefetchFileRangeSync and sceFiosCachePrefetchFileSync](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) are no-ops on PS4 10.71 for valid files and handles. Async forms return a null operation, synchronous handle/range forms return success, and the synchronous full-file form returns SCE_FIOS_ERROR_UNIMPLEMENTED. No host cache backend exists.

- [`sceFiosArchiveGetMountBufferSize`, `sceFiosArchiveGetMountBufferSizeSync`, `sceFiosArchiveMount`, `sceFiosArchiveMountSync`, `sceFiosArchiveMountWithOrder`, `sceFiosArchiveMountWithOrderSync`, `sceFiosArchiveUnmount` and `sceFiosArchiveUnmountSync`](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) match PS4 10.71 results without an archive backend: async forms return a null operation, and synchronous forms return `SCE_FIOS_ERROR_UNIMPLEMENTED`.
- [`sceFiosOpRescheduleWithPriority`](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) returns without effect for every operation, active ones included. The host scheduler has no priority queues, so the new priority is ignored and an active operation is left as it is.

### Functional

- [libSceFios2 prototypes](../../../core/libs/prx/libSceFios2/include/Api.hpp) (libSceFios2) - the implemented exports take the prototypes of RPCS3's Vita FIOS2 module (`Emu/ARMv7/Modules/sceFios.h` and `sceFios.cpp`, jacquesjk/RPCS-DX12 at `9b8b7c9eea446095f24af19182032013837e6ca5`, 64-bit types substituted), checked against the PS4 headers and call sites of kalaposfos13/fios2 (`src/fios2.h`, `ae6ca1d78e7a822c2528f7660959167b9b3d8b63`), sonny-tel/libSceFios2 (`sceFios2.h`, `5d44f9e7a80ae00557af80fad335e4c74ef35d22`), Inori/GPCS4 (`SceFios2/sce_fios2.cpp`) and SonicMastr/SceLibcPosix (`src/internal/fios2.h`, Vita, `c2cd5e880a8770bdbfb58de761de11f396c1a2e7`).
- [Layouts](../../../core/libs/prx/libSceFios2/include/Api.hpp) (libSceFios2) - The `SceFiosOpAttr`, `SceFiosOpenParams`, `SceFiosStat` and `SceFiosDirEntry` layouts and the `SCE_FIOS_ERROR_*` values (`0x80820000` plus the enumeration order) come from the same sources; vascon-es, a PC port of a PS4 title (CUSA01176 and CUSA00935 version 01.24), at `57c3c202975ea48e574df2d1e4a620b4e18b7701`, confirms the `SceFiosStat` and `SceFiosDirEntry` offsets and the `fileSize`, `statFlags` bit 0 (directory) and `offsetToName` reads from the call sites of a PS4 title. None of it was measured on a PS5. The `SceFiosOpenParams` buffer sits at offset 8 in kalaposfos13 and sonny-tel and at offset 0x10 in vascon-es; only `openFlags` is read
- [Operations](../../../core/libs/prx/libSceFios2/src/Runtime.cpp) (libSceFios2) - only one I/O worker is modeled and there are no decompressor threads. The `deadline`, `priority`, `opflags`, `userTag`, `userPtr` and scheduler fields are stored and returned but have no effect, and `SCE_FIOS_OPEVENT_START` is never sent.
- [Completion values and parameters](../../../core/libs/prx/libSceFios2/src/Runtime.cpp) (libSceFios2) - `sceFiosOpSyncWait` returns the error or the low 32 bits of the result (1 or 0 for the existence queries, as in kalaposfos13/fios2), `sceFiosOpGetActualCount` returns the result (the size for `sceFiosFileGetSize`) also for a failed operation, and `sceFiosOpGetError` returns 1 while an operation is queued; none of these is measured. Handles of operations, files and directories share one number space that starts at 1. Nothing requires `sceFiosInitialize` first, and `SceFiosParams` is stored as `paramsSize` bytes (the 15 bits at bit 1 of the first word) without interpretation, so the storage buffers, `pathMax` (1024 is used), thread and scheduler settings are ignored
- [sceFiosExists, sceFiosFileExists, sceFiosDirectoryExists, sceFiosFileGetSize, sceFiosStat and their Sync forms](../../../core/libs/prx/libSceFios2/src/PathQueries.cpp) (libSceFios2) - paths go to `sceKernelStat`, so archive and alias mapping is the kernel's. A missing path is not an error for the existence queries. `SceFiosStat` carries only the sizes, the nanosecond dates as seconds since 1970 times 10^9 plus nanoseconds (the epoch and unit are not measured), `statFlags` bit 0 for a directory, and the kernel `st_uid`, `st_gid`, `st_dev`, `st_ino` and `st_mode`; other `statFlags` bits are 0. `sceFiosFileExists` and `sceFiosDirectoryExists` take the `pOutExists` argument of RPCS3's prototype, which kalaposfos13/fios2 omits, and `sceFiosFileGetSize` has no output pointer as in kalaposfos13/fios2 and sonny-tel (RPCS3 declares one)
- [sceFiosDelete, sceFiosFileDelete, sceFiosDirectoryCreate, sceFiosDirectoryDelete, sceFiosRename, sceFiosFileRead, sceFiosFileWrite, sceFiosFileTruncate and their Sync forms](../../../core/libs/prx/libSceFios2/src/PathOperations.cpp) (libSceFios2) - behaviour is inferred from the export names; none of it is measured. They run on `sceKernelStat`, `sceKernelOpen`, `sceKernelPread`, `sceKernelPwrite`, `sceKernelFtruncate`, `sceKernelMkdir`, `sceKernelRmdir`, `sceKernelUnlink` and `sceKernelRename`, so guest path mapping and the read-only application directory are the kernel's. `sceFiosFileWrite` opens the file write-only with creation and no truncation, `sceFiosFileTruncate` does not create it, directories are created with mode 0777 and files with 0666, `sceFiosDelete` removes a file or an empty directory, and a negative length returns `SCE_FIOS_ERROR_BAD_SIZE`, a negative offset `SCE_FIOS_ERROR_BAD_OFFSET`.
- [Error mapping](../../../core/libs/prx/libSceFios2/src/PathOperations.cpp) (libSceFios2) - A read stops at the end of the file and returns the bytes read. The mapping of kernel errors to `SCE_FIOS_ERROR_*` is chosen here: `ENOENT` and `ENOTDIR` to `BAD_PATH`, `EPERM`, `EACCES` and `ENOTEMPTY` to `ACCESS`, `EROFS` to `READ_ONLY`, `EEXIST` to `ALREADY_EXISTS`, `EISDIR` to `NOT_A_FILE`, `EINVAL` to `BAD_OFFSET`, `ENFILE` and `EMFILE` to `CANT_ALLOCATE_FH`, `ENAMETOOLONG` to `PATH_TOO_LONG`, `EFAULT` to `BAD_PTR`, and anything else to `UNKNOWN`. The prototypes follow RPCS3 (`sceFios.cpp` `sceFiosFileWrite`, `sceFiosFileTruncate`, `sceFiosRename`, `sceFiosDelete`) and kalaposfos13/fios2 (`sceFiosFileRead`)
- [sceFiosFHOpen, sceFiosFHOpenWithMode, sceFiosFHClose, sceFiosFHStat, sceFiosFHTruncate, sceFiosFHSync, sceFiosFHRead, sceFiosFHWrite, sceFiosFHPread, sceFiosFHPwrite, the vectored forms with their Sync forms, sceFiosFHSeek, sceFiosFHTell, sceFiosFHGetSize, sceFiosFHGetPath and sceFiosFHGetOpenParams](../../../core/libs/prx/libSceFios2/src/FileHandles.cpp) (libSceFios2) - a file handle owns one kernel descriptor, and `sceFiosFHRead`, `sceFiosFHWrite`, `sceFiosFHSeek` and `sceFiosFHTell` use its kernel position.
- [File handle errors and lifetime](../../../core/libs/prx/libSceFios2/src/FileHandles.cpp) (libSceFios2) - `openFlags` map as `SCE_FIOS_O_READ` 1, `SCE_FIOS_O_WRITE` 2, `SCE_FIOS_O_APPEND` 4, `SCE_FIOS_O_CREAT` 8 and `SCE_FIOS_O_TRUNC` 16 (sonny-tel/libSceFios2, SonicMastr/SceLibcPosix); `SCE_FIOS_O_DIRECT` (1 << 12) is ignored, no flags or null parameters open read-only, and the handle returns `SCE_FIOS_ERROR_WRITE_ONLY` or `SCE_FIOS_ERROR_READ_ONLY` for a transfer its flags exclude (the console result is not measured). The creation mode is 0777 unless `sceFiosFHOpenWithMode` is given one (`-1` means the default, as in kalaposfos13/fios2).
- [Open flags and offsets](../../../core/libs/prx/libSceFios2/src/FileHandles.cpp) (libSceFios2) - Opening a directory returns `SCE_FIOS_ERROR_NOT_A_FILE`. An invalid `whence` or a negative resulting position returns `SCE_FIOS_ERROR_BAD_OFFSET`, a vector count outside 1 to 1024 `SCE_FIOS_ERROR_BAD_IOVCNT`. The Readv and Writev exports transfer the vectors in order and stop at the first short one. `sceFiosFHGetPath` and `sceFiosFHGetOpenParams` return pointers that stay valid until the handle is closed; the stored `SceFiosOpenParams` has no buffer. The handle prototypes follow RPCS3's `sceFios.cpp` and kalaposfos13/fios2; `sceFiosFHToFileno`, `sceFiosFilenoToFH` and `sceFiosDeallocatePassthruFH` use a dump-derived 256-entry passthrough table; valid descriptor round-trips and stale descriptor reuse are unverified
- [sceFiosDHOpen, sceFiosDHRead, sceFiosDHClose, their Sync forms and sceFiosDHGetPath](../../../core/libs/prx/libSceFios2/src/DirectoryHandles.cpp) (libSceFios2) - the prototypes follow RPCS3 and kalaposfos13/fios2, with the `SceFiosBuffer` passed by value in two registers as in vascon-es. Opening reads the whole listing through `sceKernelGetdirentries` into host memory; the caller's buffer is never written. A title that opens with a null or too small buffer gets `SCE_FIOS_ERROR_BAD_SIZE` and the required size from `sceFiosOpGetActualCount`, the probe that vascon-es observes at the call sites of a PS4 title.
- [Required directory buffer size](../../../core/libs/prx/libSceFios2/src/DirectoryHandles.cpp) (libSceFios2) - The required size, `16` plus the name lengths plus one each, is chosen here and is not what the console reports, so a title that sizes its buffer from another source can get a false `BAD_SIZE`. `.` and `..` are not listed (unverified), entries come in kernel order, the end of the listing returns `SCE_FIOS_ERROR_EOF` and `sceFiosDHRead` fills `fileSize`, `statFlags` bit 0, `nameLength`, `fullPathLength`, `offsetToName` and `fullPath` as vascon-es reads them, with `fullPath` the opened path, a slash and the name
- [sceFiosDateGetCurrent, sceFiosDateFromComponents, sceFiosDateToComponents, sceFiosTimeIntervalFromNanoseconds and sceFiosTimeIntervalToNanoseconds](../../../core/libs/prx/libSceFios2/src/Time.cpp) (libSceFios2) - a `SceFiosDate` is taken as nanoseconds since 1970-01-01 UTC and a `SceFiosTimeInterval` as nanoseconds (identity conversions), as in kalaposfos13/fios2 (`src/fios2.cpp`, `time(nullptr) * 1000000000`) and RPCS3 (`sceFios.cpp`, 64-bit unsigned date); neither is measured, and both may descend from one Vita SDK. kalaposfos13/fios2 converts components through local time, here they are UTC (`sceFiosDateFromComponents` normalizes out-of-range fields like `timegm` and returns 0 before 1970). Only the nine leading `int` fields of `struct tm` are read and written, so `tm_gmtoff` and `tm_zone` are left untouched. `sceFiosTimeGetCurrent` uses the host monotonic clock in nanoseconds; cross-platform epoch equivalence is not measured
- [Operation threading](../../../core/libs/prx/libSceFios2/src/Runtime.cpp) (libSceFios2) - callback and teardown ordering still need comparison with a title or console. Termination from a callback, initialization, parameter updates or operation submission during termination, and waiting on or deleting another incomplete operation from a callback are unmeasured and throw through `NotImplemented_nid_no_patch`. Multi-worker pool configuration in `SceFiosParams` is ignored. A synchronous wait lets the worker complete the requested asynchronous operation while unrelated operations remain suspended; its console scheduling policy remains unverified. Queued cancellation and explicit deletion still deliver callbacks on their calling thread; their console callback affinity is unverified.
- [Date range](../../../core/libs/prx/libSceFios2/src/Time.cpp) (libSceFios2) - a date that is not representable as nanoseconds in 64 bits (components past about year 2554) makes `sceFiosDateFromComponents` return 0. That is an implementation choice for the unrepresentable case, not a console measurement; the console may wrap, clamp or fail differently
- [Guest inputs](../../../core/libs/prx/libSceFios2/src/Runtime.cpp) (libSceFios2) - `SceFiosOpAttr`, `SceFiosOpenParams`, `SceFiosParams`, the vector arrays and `struct tm` are copied with `GuestCopyIn_nid_no_patch`; a failed copy returns `SCE_FIOS_ERROR_BAD_PTR` (the operation handle value itself for an unreadable `SceFiosOpAttr`), or is ignored by the `void` exports. That the console returns `SCE_FIOS_ERROR_BAD_PTR` for an unreadable pointer is not measured

- [sceFiosInitialize, sceFiosUpdateParameters and sceFiosIsInitialized](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) - init accepts null/arbitrary sizes and stores raw parameters; updates replace the whole block. PS4 libSceFios2.sprx (init banner SDK 0x10710001), disassembly only: Initialize takes const SceFiosParams* and returns int32_t. Null returns BAD_PTR; size other than 0xb0, nonzero reserved fields or extraFlags beyond quiet return BAD_SIZE; schedulerAlgorithm >= 4 returns BAD_FLAGS. Repeated init returns 0 after UpdateParameters, which ignores calls before init or with another size, otherwise copying only maxChunk, pVprintf, pMemcpy, priorities and affinities. IsInitialized returns the init state and copies 0xb0 bytes to a non-null output only after successful init. PS5 and console behaviour remain unverified

- [SceFiosParams](../../../core/libs/prx/libSceFios2/include/Types.hpp) (libSceFios2) - forward-declared without a layout; the implementation applies only the `maxDecompressorThreadCount` default below, as the decompressor thread limit that `sceFiosArchiveSetDecompressorThreadCount` clamps to. The same module uses every offset of sonny-tel's 0xb0-byte layout and applies these defaults: `pathMax` 0 or above 1024 becomes 1024; `ioThreadCount` 0 becomes 1 and above 2 becomes 2; `threadsPerScheduler` 0 becomes 1 and above 3 becomes 3; `maxChunk` 0 becomes 0x80000; `maxDecompressorThreadCount` 0 becomes 2 and above 3 becomes 3; a null `pVprintf` or `pMemcpy` selects the library's own; a priority of -1 becomes 260, 700 and 260; stack sizes below 0x14000, 0x4000 and 0x4000 are raised to them. The op, FH and DH pools take elements of `pathMax` plus 0x100, 0x70 and 0x68 bytes, rounded up to 8

- [Kernel errors](../../../core/libs/prx/libSceFios2/src/Runtime.cpp) (libSceFios2) - FromKernelError differs from PS4: EFAULT becomes BAD_PTR, EINVAL BAD_OFFSET, ENOTDIR BAD_PATH, ENFILE/EMFILE (23/24) CANT_ALLOCATE_FH, ENAMETOOLONG (63) PATH_TOO_LONG, and unlisted errors UNKNOWN. Its shared mapper returns ACCESS for EPERM/EACCES/ENOTEMPTY; BAD_PATH for ENOENT/EINVAL/EOPNOTSUPP/ENAMETOOLONG/89; BAD_FH for EBADF; BUSY for EBUSY; ALREADY_EXISTS for EEXIST; MEDIA_GONE for ENODEV/ENOSYS; NOT_A_DIRECTORY for ENOTDIR; NOT_A_FILE for EISDIR; READ_ONLY for EROFS; EOF for ERANGE; TIMEOUT for ETIMEDOUT. ### Unknown function info

These exports are incomplete or have unknown behavior. Some have verified ABI signatures and guarded behavior for the probed state. Remaining no-argument declarations only preserve import resolution and are not verified ABI prototypes.

- Archive: [probed exports](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) - `sceFiosArchiveGetMountBufferSize`, `sceFiosArchiveGetMountBufferSizeSync`, `sceFiosArchiveMount`, `sceFiosArchiveMountSync`, `sceFiosArchiveMountWithOrder`, `sceFiosArchiveMountWithOrderSync`, `sceFiosArchiveUnmount` and `sceFiosArchiveUnmountSync` return the measured PS4 10.71 results; the host has no archive backend.
- Cache and prefetch: [probed exports](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) - `sceFiosCachePrefetchFH`, `sceFiosCachePrefetchFHRange`, `sceFiosCachePrefetchFHRangeSync`, `sceFiosCachePrefetchFHSync`, `sceFiosCachePrefetchFile`, `sceFiosCachePrefetchFileRange`, `sceFiosCachePrefetchFileRangeSync` and `sceFiosCachePrefetchFileSync` match measured behavior for valid files and handles on PS4 10.71; the host has no cache backend.
- IO filters: [probed exports](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) - `sceFiosIOFilterCache` validates measured descriptor sizes and accepts the probed index-0 setup when an overlay exists; runtime cache I/O remains incomplete. `sceFiosIOFilterPsarcDearchiver` follows the PS4 10.71 dump and probes for descriptor validation, start/stop reference counting, the mode 2 description and the mode -1 pass-through of non-archive ops; reading PSARC archives is unsupported because the host has no archive mounts.
- Overlays and resolution: [probed exports](../../../core/libs/prx/libSceFios2/src/Control.cpp) (libSceFios2) - `sceFiosOverlayResolveSync(flag, in, out, max)` follows PS4 10.71 measurements. It copies `in` to `out`, rejects flags other than 0 and 1 with 0x80820020 and walks overlays of order 0 to 0x7f, lowest order first. It matches whole path components after dropping empty and `.` components and a trailing slash. Opaque overlays always redirect; translucent and writable ones only when the source exists, writable with flag 1 always; newer ones when the source exists and is newer than the original or the original is missing. Not measured: `..` components (kept as they are), overlays with equal orders (kept in insertion order) and equal timestamps for a newer overlay (throws). The console raises SIGILL when the call comes before `sceFiosInitialize`; the host resolves anyway.

`PathNormalize` matches the measured common cases using host lexical normalization; unusual roots, platform path styles, truncation and invalid pointers need PS4 comparison. `Pathcmp`/`Pathncmp` match the measured bytewise cases. Overlay add, list, info, modify and remove maintain an in-process 0x258-byte overlay table; PS4 10.71 confirmed that a valid overlay add returns a positive ID, and the host tests cover list, info, modification and removal. `OverlayResolveSync` resolves against that table as described above. `sceFiosResolve` returns the measured null operation while FIOS is uninitialized and submits an operation when initialized; `sceFiosResolveSync` copies 0x410 bytes from request to result, matching the measured initialized and uninitialized PS4 10.71 cases. `sceFiosCacheContainsFileRangeSync` returns the measured `BAD_INDEX` for the no-filter state; valid filter behavior is unsupported. `sceFiosCacheContainsFileSync` checks path validity and reports no cached range because this implementation has no cache filter; a present-file probe is missing. `sceFiosIOFilterAdd`, `sceFiosIOFilterGetInfo` and `sceFiosIOFilterRemove` maintain the measured 256-slot callback table, return `BAD_INDEX` for occupied or empty slots, and clear it on FIOS termination. `sceFiosIOFilterCache` validates its 72-byte config and returns 0 for the measured index-0 configuration after an overlay exists; cache read/write behavior and remaining valid configurations are unverified. `sceFiosIOFilterPsarcDearchiver` returns the measured `BAD_PTR` for null descriptor in modes 0 and 1. From the dump, mode 0 checks the 0x38-byte descriptor field by field (`BAD_PTR`, `BAD_SIZE`, `BAD_ALIGNMENT`, `BAD_FLAGS`) and counts starts; other modes use a looser check, and a rejected descriptor makes every later non-zero mode return `BAD_PTR`. Mode 2 copies the dump's description string, and a null data pointer or unknown mode returns 0x8082001D. On PS4 10.71 FIOS calls each registered filter with mode -1 and a pointer to the op slot it allocated; registered behind a logging wrapper, the dearchiver returned 0 and left the slot unchanged for a plain open, read and close, which is what the host returns for every mode -1 call since no op can target a mounted archive. The host does not call registered filters per operation, and slot values are not validated. The PS4 work-buffer setup on first start and its 0x80820014 failure are not modelled. Calling mode -1 with a slot FIOS did not hand out crashed the PS4. `sceFiosIOFilterAdd` calls the filter with mode 0 before registering it and accepts 0 or 0x8082001D, and `sceFiosIOFilterRemove` calls it with mode 1 after clearing the slot, as measured on PS4 10.71. The decompressor thread count getter/setter follow the PS4 dump's byte clamp behavior; codec callback registration hooks are absent. `sceFiosCacheFlushSync`, `sceFiosCacheFlushFileSync` and `sceFiosCacheFlushFileRangeSync` are no-ops as measured on PS4 10.71; the host has no FIOS cache to invalidate. The cache prefetch exports match no-op behavior measured for valid files and handles on PS4 10.71; no host cache backend exists. Archive mount/unmount and `sceFiosArchiveGetMountBufferSize*` return the measured PS4 10.71 null-operation or `SCE_FIOS_ERROR_UNIMPLEMENTED` results; the host has no archive backend. `sceFiosOpSetBuffer` updates an operation buffer unless it is queued; mapping the dump's internal busy flag and relative pointer is not measured. `sceFiosOpWaitUntil` uses a host monotonic deadline; the dump confirms delegation to the operation wait, while timeout and racing-completion behavior need a live probe. `sceFiosOpReschedule` and its priority variant ignore missing or completed operations, while rescheduling an active queued operation has no effect because the host scheduler has no priority queues. Timestamp exports use host monotonic time and a process-local ring; debug dump text and timestamp formatting need valid-input compatibility probes. `sceFiosDLLTerminate` returns 0 and leaves FIOS initialized in the measured active state; behavior with live handles is unverified. `DirectoryCreateWithMode` and its Sync form use the shared mkdir operation with the requested mode; the initialized async probe confirmed create/wait/cleanup, but mode bits and callback ordering were not checked.
