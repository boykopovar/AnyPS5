- [sceFiosInitialize, sceFiosUpdateParameters and sceFiosIsInitialized](../../../core/libs/prx/libSceFios2/Export.cpp) (libSceFios2) - still throw and declare no parameters. In the PS4 libSceFios2.sprx whose init banner reports SDK 0x10710001, read from its disassembly, not from a PS5 module and not measured on a console: `sceFiosInitialize` takes a `const SceFiosParams*` and returns an `int32_t`, where sonny-tel declares the struct by value and `void`. It returns `BAD_PTR` for null; `BAD_SIZE` when `paramsSize` is not 0xb0, a reserved field is not zero, or `extraFlags` has a bit other than `quiet`; and `BAD_FLAGS` when `schedulerAlgorithm` is 4 or more. Called again, it returns 0 and only runs `sceFiosUpdateParameters`, which does nothing before init or for a struct of another size and otherwise copies `maxChunk`, `pVprintf`, `pMemcpy`, the priorities and the affinities. `sceFiosIsInitialized` returns whether init succeeded and, if it did, copies the 0xb0 bytes to a non-null pointer

- [SceFiosParams](../../../core/libs/prx/libSceFios2/Export.cpp) (libSceFios2) - not declared. The same module uses every offset of sonny-tel's 0xb0-byte layout and applies these defaults: `pathMax` 0 or above 1024 becomes 1024; `ioThreadCount` 0 becomes 1 and above 2 becomes 2; `threadsPerScheduler` 0 becomes 1 and above 3 becomes 3; `maxChunk` 0 becomes 0x80000; `maxDecompressorThreadCount` 0 becomes 2 and above 3 becomes 3; a null `pVprintf` or `pMemcpy` selects the library's own; a priority of -1 becomes 260, 700 and 260; stack sizes below 0x14000, 0x4000 and 0x4000 are raised to them. The op, FH and DH pools take elements of `pathMax` plus 0x100, 0x70 and 0x68 bytes, rounded up to 8

- [Kernel errors](../../../core/libs/prx/libSceFios2/Export.cpp) (libSceFios2) - nothing maps them yet. In the same module there is no not-initialized error: before `sceFiosInitialize`, file calls go straight to `sceKernelOpen`, `sceKernelRead`, `sceKernelTruncate` and the like. One routine with 47 callers, the pre-init calls among them, turns kernel errors into Fios errors: EPERM, EACCES and ENOTEMPTY into `ACCESS`; ENOENT, EINVAL, EOPNOTSUPP, ENAMETOOLONG and errno 89 into `BAD_PATH`; EBADF into `BAD_FH`; EBUSY into `BUSY`; EEXIST into `ALREADY_EXISTS`; ENODEV and ENOSYS into `MEDIA_GONE`; ENOTDIR into `NOT_A_DIRECTORY`; EISDIR into `NOT_A_FILE`; EROFS into `READ_ONLY`; ERANGE into `EOF`; ETIMEDOUT into `TIMEOUT`. Every other kernel code, such as EFAULT (`0x8002000e`), comes back unchanged
