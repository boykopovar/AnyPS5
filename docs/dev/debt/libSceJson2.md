# libSceJson2 technical debt

### Unknown function info

- [JSON real-number conversion](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) uses locale-independent `to_chars` with 17 significant digits and `from_chars`, following JSON's decimal-point grammar in RFC 8259 section 6. Out-of-range input falls back to a classic-locale stream so underflow retains the prior signed-zero behavior and overflow throws. Console rounding and formatting are unverified.
- [sce::Json::Array::pop_front](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - removes and destroys the first element; on an empty array it throws `std::out_of_range`, as `front` and `back` do here. The console's result for an empty array is unverified.
- [sce::Json::Parser::parse](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - a null text pointer with nonzero size throws instead of being dereferenced. A number that overflows a double (e.g. `1e309`) throws: whether the console rejects the document or stores an infinite real is unknown. Syntax validation for number tokens and destination state after a failed parse still differ from the system parser
- [sce::Json::InitParameter2, InitParameterRtti and InitParameterRtti2](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - initialization still ignores allocator storage and file-buffer size; allocation admission, allocator notifications and rollback are not implemented. The active-byte and enum validation rules follow the inspected initializer at `0x920` and `0x12b0`–`0x13f7`, but allocator failures can still differ. The module firmware version is unverified; these are library observations, not console measurements.
- [sce::Json::Value storage and recovery callback ABI](../../../core/libs/prx/libSceJson2/Export.cpp) - values use an 8-byte host-node wrapper rather than the inspected 32-byte inline layout. Special-float recovery at `0x2b90` receives a 32-byte return object through a hidden result pointer; correcting callback dispatch requires compatible payload, parent and auxiliary ownership. Current host allocation counts and request sizes do not follow the inspected library.
- [InitParameter2 special-float configuration](../../../core/libs/prx/libSceJson2/Export.cpp) follows assignment helpers at `0x40a0` and `0x41a0` and formatting at `0x26a0`: mode 0 converts non-finite numbers to strings, mode 1 to null, and mode 2 retains real values and emits lowercase non-JSON tokens. Parser acceptance of those tokens, floating-point exception flags, signaling-NaN behavior and concurrent reconfiguration remain unverified. Legacy initialization does not enable the conversion; its internal formatter differs from the host formatter and remains unsupported for non-finite serialization. `Value::set(double)` and `toString(String&)` expose no consistent return value and are declared `void`.
- [sce::Json::Object::Pair, sce::Json::Array::iterator and sce::Json::Object::iterator members](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - the signatures follow the mangled names, with `Array::iterator::operator++(int)` and `Object::iterator::operator++(int)` returning their copy through a result pointer before `this` as `begin` does, since the iterators have non-trivial destructors. `Pair(const String&, const Value&)` and default `Pair()` deep-copy or initialize into the layout `Object` iteration already hands out (key at 0, value at 0x10) and zeroes the 8 bytes between them; what the console keeps there is unknown.
- [sce::Json::Value handler registration](../../../core/libs/prx/libSceJson2/Export.cpp) - setter return types are inferred from a title that registers handlers on its root value and accepts 0 or `0x80848104`; the setters return 0. Signatures follow mangled names. The Vita null-access callback is also a member ([vitasdk](https://github.com/vitasdk/vita-headers/blob/15605617cbbb23d266f88af28899fdb573e2355e/include/psp2/json.h#L638)). Applying a handler to current descendants and parser-created values follows that caller; copies, `push_back` and object insertion do not carry handlers. Console ancestor lookup and propagation remain unverified.
- [sce::Json::Value type-mismatch dispatch](../../../core/libs/prx/libSceJson2/Export.cpp) - a typed getter on a non-null value of another type calls the registered handler with the requested type, value, null and context. It uses the returned value if its type matches, otherwise the default. The order of the two value pointers and the null second pointer remain unverified against the console.
- [sce::Json::Value element-access failure dispatch](../../../core/libs/prx/libSceJson2/Export.cpp) - the registered handler is not called: failed indexing or `getValue` throws because its error code is unknown. Without a handler, access reaches the null-access callback.
- [sce::Json::Value special-float recovery](../../../core/libs/prx/libSceJson2/Export.cpp) - a non-finite real carrying a handler throws during serialization. Assignment under InitParameter2 with a registered handler throws through `NotImplemented_nid_no_patch`, before changing the value. Callback result ownership, ancestor lookup, error propagation and reentrancy remain unimplemented or unverified; the title returns different replacements for its two function types.
- [sce::Json::MemAllocator::notifyError](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - the base class's virtual does nothing. A title's allocator that does not override it calls it through its own vtable; the library never calls the title's allocator, so it never reports an allocation failure. Whether the console's base implementation logs anything is unknown
- [sce::Json::String size, capacity, resize, append(const char*, size_t), operator+=](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - storage uses `std::string`; capacity and allocation growth do not match the system 32-bit capacity and allocator settings. Appending null text with a nonzero length throws instead of dereferencing it.
- [sce::Json::Array::iterator::advance and Object::iterator members](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - the return type of `advance` remains unverified. Object iterator advancement past the end throws instead of asserting. Dereferencing an empty array iterator throws instead of returning the system null-value pointer or an invalid address.
- [sce::Json::Value::operator bool](../../../core/libs/prx/libSceJson2/Export.cpp) (libSceJson2) - callback dispatch before conversion is not implemented. The system library invokes the applicable type mismatch handler before converting a non-boolean value, with SDK-dependent global callback handling.
