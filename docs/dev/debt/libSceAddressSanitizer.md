### Functional

- [Shadow memory](../../../core/libs/prx/libSceAddressSanitizer/src/ShadowAddressSpace.hpp) (libSceAddressSanitizer) - the console mapping is unverified; the first export that touches the shadow reserves the PlayStation mapping of [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/llvm/lib/Transforms/Instrumentation/AddressSanitizer.cpp) (scale 3, offset `1 << 40`) instead of `__asan_init`, which throws. Ranges reaching above `1 << 47` or into the shadow throw. Windows reserves only the free parts of the shadow range; runtime exports that need shadow the host already holds throw, but instrumented code that touches it inline reads or writes that host memory. A concurrent protection change can race with Windows page commitment, and the Linux mapping has not been run.
- [Runtime state](../../../core/libs/prx/libSceAddressSanitizer/Export.cpp) (libSceAddressSanitizer) - the allocator, global registration, fake stacks, thread registry and option parsing are missing, so a clean shadow does not prove an address is valid. Exports that read options use the [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/compiler-rt/lib/asan/asan_flags.inc) defaults (`allow_user_poisoning`, `poison_array_cookie`, `poison_partial` and `halt_on_error` true); guest overrides of `__asan_default_options` and of the default hooks are ignored.
- [Error reports](../../../core/libs/prx/libSceAddressSanitizer/Export.cpp) (libSceAddressSanitizer) - unlike [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/compiler-rt/lib/asan/asan_errors.cpp), reports omit the pid prefix, stack trace, address description and summary line and name every thread `T-1`; `_noabort` callbacks also exit with code 1; a misaligned 16-byte check also reports a poisoned third granule, which the LLVM fast path skips. The console report text and exit path are unverified.
- [Signatures and defaults](../../../core/libs/prx/libSceAddressSanitizer/include/Api.hpp) (libSceAddressSanitizer) - implemented exports take the signatures of the LLVM 18.1.8 public sanitizer headers and compiler-emitted callbacks, and the empty default options, empty hooks, zero `__sanitizer_get_unmapped_bytes` and empty version mismatch checks of LLVM 18.1.8; the console ABI and values are unverified.
