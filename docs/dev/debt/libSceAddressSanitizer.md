### Functional

- [Shadow memory](../../../core/libs/prx/libSceAddressSanitizer/src/ShadowAddressSpace.hpp) (libSceAddressSanitizer) - the console mapping is unverified; the first export that touches the shadow reserves the PlayStation mapping of [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/llvm/lib/Transforms/Instrumentation/AddressSanitizer.cpp) (scale 3, offset `1 << 40`) or `__asan_init`. Ranges reaching above `1 << 47` or into the shadow throw. Windows reserves only the free parts of the shadow range; runtime exports that need shadow the host already holds throw, but instrumented code that touches it inline reads or writes that host memory. A concurrent protection change can race with Windows page commitment, and the Linux mapping has not been run.
- [Runtime state](../../../core/libs/prx/libSceAddressSanitizer/Export.cpp) (libSceAddressSanitizer) - threads are numbered by first use instead of being registered, option parsing is missing, and the stack bounds come from the host thread, so a clean shadow does not prove an address is valid. Exports that read options use the [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/compiler-rt/lib/asan/asan_flags.inc) defaults (`allow_user_poisoning`, `poison_array_cookie`, `poison_partial` and `halt_on_error` true; `check_initialization_order` and `detect_stack_use_after_return` false), so `__asan_before_dynamic_init` and `__asan_after_dynamic_init` do nothing; the exported `__asan_option_detect_stack_use_after_return` starts at 0 and gates fake-stack creation, with Linux retaining its cached fake stack; guest overrides of `__asan_default_options` and of the default hooks are ignored.
- [Allocator](../../../core/libs/prx/libSceAddressSanitizer/src/Allocator.hpp) (libSceAddressSanitizer) - blocks come from host virtual-memory reservations on Windows and `operator new` on Linux, not the console allocator, and the quarantine is one global 256 MiB list without thread caches. Windows reserves each backing block separately with `VirtualAlloc2` and does not pool pages. Recycled blocks return to the host and their shadow is cleared rather than kept poisoned. Allocation and free keep only the caller address as their stack, so `__asan_get_alloc_stack` and `__asan_get_free_stack` return one frame. `allocator_may_return_null`, `max_allocation_size_mb`, the malloc hooks and `new`/`delete` mismatch checks are missing, so failures abort, and `__asan_print_accumulated_stats` omits the StackDepot and allocator lines.
- [Globals and fake stacks](../../../core/libs/prx/libSceAddressSanitizer/src/Globals.hpp) (libSceAddressSanitizer) - registration keeps a copy of each global, drops it on unregistration and records no registration stack, so ODR reports have none. A fake stack is created per thread with the log of the host stack size clamped to 16..20, and `__asan_handle_no_return` unpoisons from the caller to the host stack top; both throw if the host cannot report the stack. Stack addresses are recognised only by their shadow magic and are attributed to the calling thread. Fiber switches track the stack bounds but not the console fiber layout.
- [Reports and symbolizer](../../../core/libs/prx/libSceAddressSanitizer/src/ReportFile.hpp) (libSceAddressSanitizer) - there is no symbolizer, so frames show the module and offset only and `__sanitizer_symbolize_global` returns an empty string. The unwinder follows only frames with host unwind data (Windows) or glibc `backtrace` (Linux, unrun). `__sanitizer_set_report_fd` does not close the previous descriptor and the parent directories of a report path are not created. `coverage` is off as in [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/compiler-rt/lib/sanitizer_common/sanitizer_coverage_libcdep_new.cpp), so only `__sanitizer_dump_coverage` writes `.sancov` files, to the working directory.
- [Error reports](../../../core/libs/prx/libSceAddressSanitizer/Export.cpp) (libSceAddressSanitizer) - unlike [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/compiler-rt/lib/asan/asan_errors.cpp), access reports omit the pid prefix, stack trace, address description and summary line and name every thread `T-1`; allocator, global and UBSan reports keep the text but have no stack trace and no pid prefix; `_noabort` callbacks also exit with code 1; a misaligned 16-byte check also reports a poisoned third granule, which the LLVM fast path skips. The console report text and exit path are unverified.
- [Signatures and defaults](../../../core/libs/prx/libSceAddressSanitizer/include/Api.hpp) (libSceAddressSanitizer) - implemented exports take the signatures of the LLVM 18.1.8 public sanitizer headers and compiler-emitted callbacks, with the legacy type-mismatch and nonnull-return layouts from [LLVM 3.8](https://github.com/llvm/llvm-project/blob/llvmorg-3.8.0/compiler-rt/lib/ubsan/ubsan_handlers.h), and the empty default options, empty hooks, zero `__sanitizer_get_unmapped_bytes` and empty version mismatch checks of LLVM 18.1.8; the console ABI and values are unverified.

- [RTTI cache](../../../core/libs/prx/libSceAddressSanitizer/include/Api.hpp) (libSceAddressSanitizer) - `__ubsan_vptr_type_cache` is an exported zero-initialized array of 128 pointer-sized hashes, as in [LLVM 18.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.8/compiler-rt/lib/ubsan/ubsan_type_hash.h). The dynamic-type miss handlers still throw, so the runtime cannot validate or populate cache entries. Console RTTI validation is unverified.
