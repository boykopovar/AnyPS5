# libSceNpEntitlementAccess technical debt

### Silent stubs

- [sceNpEntitlementAccessRequestConsumeEntitlement, sceNpEntitlementAccessRequestConsumableEntitlementInfo, sceNpEntitlementAccessPollConsumableEntitlementInfo](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - implement only the signed-out path, as there is no PSN sign-in: like the other entitlement requests and polls here, they return `SCE_NP_ERROR_SIGNED_OUT` (`0x80550006`) for any arguments and write no request id, result or info. Whether a signed-out console fails at the request or creates a request whose poll fails is unverified; [idlesauce's PS4 notes](https://github.com/idlesauce/ps4-eboot-dlc-patcher/blob/d1d1e0f0dbd5e06da45b7d8f8ca1827d34546692/prx_src/libSceNpEntitlementAccess.c#L256-L289) say that `sceNpEntitlementAccessRequestConsumeUnifiedEntitlement` "returns ok even offline" and that `sceNpEntitlementAccessPollConsumeEntitlement` reports `0x817D0019`

- [sceNpEntitlementAccessInitialize](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) (libSceNpEntitlementAccess) - returns 0 without reading the init parameter or writing the boot parameter, so the boot parameter keeps what the caller put there. Both are 32 reserved bytes here, and PPSA01494 (at both of its calls), PPSA02225, PPSA03984, PPSA30839, PPSA31162 and PPSA34502 zero exactly 32 bytes of each right before the call. PPSA03984 and PPSA31162 test the result for a negative value. What the console writes into the boot parameter is unknown

- [sceNpEntitlementAccessAbortRequest, sceNpEntitlementAccessDeleteRequest](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - no request exists while signed out, so there is nothing to abort or delete; both ignore the request ID and return 0, following [sharpemu](https://github.com/sharpemu/sharpemu-mac/blob/main/src/SharpEmu.Libs/Np/NpEntitlementAccessExports.cs) (Gen4|Gen5, asserted by its lifecycle test) and the RAGE title that treats a negative cleanup result as log-only. Aborting or deleting an ID a signed-in console's table would still hold is unmeasured

### Unknown function info

- [sceNpEntitlementAccessGetAddcontEntitlementInfoIndividual](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - the prototype is not from the SDK and no title call site was read: the user ID, service label, entitlement label and info follow the runtime declaration of [dlc_emu](https://github.com/drakmor/dlc_emu/blob/fcf69b16d46a/src/dlc_modules/scenpentitlementaccess_exports.cpp#L102-L115), a replacement module. The user ID is not checked against the signed-in users: only `-1` returns the parameter error `0x80558003`, before the null checks, as in dlc_emu; any other ID gets the result of `sceNpEntitlementAccessGetAddcontEntitlementInfo`, which ignores the service label and the initialization state and returns `0x80558007` for an unlisted label where dlc_emu returns its no-entitlement error. dlc_emu also returns the parameter error for an empty or unterminated label or nonzero padding; here the first two give `0x80558007` and padding is ignored. None of this is measured
- [sceNpEntitlementAccessRequestConsumeEntitlement, sceNpEntitlementAccessRequestConsumableEntitlementInfo, sceNpEntitlementAccessPollConsumableEntitlementInfo](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - the parameter lists are unconfirmed: they follow [dlc_emu](https://github.com/drakmor/dlc_emu/blob/fcf69b16d46a9850578bce19dc2c1b4dc867cbb5/src/dlc_modules/scenpentitlementaccess_exports.cpp#L146-L220), a replacement module using the SDK header's types, while [idlesauce](https://github.com/idlesauce/ps4-eboot-dlc-patcher/blob/d1d1e0f0dbd5e06da45b7d8f8ca1827d34546692/prx_src/libSceNpEntitlementAccess.c#L185-L254) marks its lists as assumed and has a service entitlement label in the consume request and an `int32_t*` use limit as the poll's third argument, so those two are untyped pointers. A null request id is not checked, though both return their parameter error for it (`0x817D0002` in idlesauce): its order against the signed-out failure is unknown
- [sceNpEntitlementAccessGetEntitlementKey](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - the three-argument signature, 16-byte key and errors `0x817D0002`/`0x817D0007` follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libNet.cpp); PPSA01521 passes a service label, entitlement label and output pointer. Only the no-key path is implemented: local entitlement labels carry no keys, and the output is untouched on failure. Console error precedence and key provisioning are unverified. PPSA03984 01.020.000 (at 0x5949837) and PPSA30839 01.003.000 (0x4505EC5), disassembled for this entry, pass service label 0, a pointer into an array of their own with 28-byte elements and a stack output, one call per element in a loop; after a failure (a negative result in PPSA03984, any nonzero one in PPSA30839) they go on with the next element, and on success PPSA03984 reads 16 bytes of the output
- [Entitlement requests and polls](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp): native argument lists are restored for single-item, list and consume operations, plus abort/delete. Request IDs are 64-bit, labels occupy 20 bytes and transaction IDs occupy 72 bytes. List options occupy 32 bytes and results have a 64-byte stride; their field semantics and three list-result scalars remain unresolved. The existing signed-out responses do not reproduce native initialization, validation or asynchronous request handling; no request can be created while signed out, so the library keeps no request table.

### Functional

- [sceNpEntitlementAccessGetGameTrialsFlag, sceNpEntitlementAccessGetPftFlag](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) (libSceNpEntitlementAccess) - reports a full game, not a game trial or Play First Trial: writes 0 to the `uint32_t` output and returns 0, and a null pointer returns `0x817D0002`. The single-pointer signature, the value, the one-word write and the error of `sceNpEntitlementAccessGetGameTrialsFlag` follow [sharpemu](https://github.com/sharpemu/sharpemu/blob/a2983692930564815a77f81e74c151268f5b935f/src/SharpEmu.Libs/Np/NpEntitlementAccessExports.cs#L98-L116), which has no `sceNpEntitlementAccessGetPftFlag`; those of `sceNpEntitlementAccessGetPftFlag` follow [dlc_emu](https://github.com/drakmor/dlc_emu/blob/main/src/dlc_modules/dlc_content.cpp), which takes the same `SceNpEntitlementAccessGameTrialsFlag*` as the trials flag, writes the OFF value 0 and returns the parameter error for null; `0x817D0002` is the parameter error of KytyPS5, prosper and `sceNpEntitlementAccessGetEntitlementKey`, while `sceNpEntitlementAccessGetSkuFlag` here returns `0x80558003`. None of this is a console measurement, and PRAGMATA (PPSA02530) shows four live registers at the call, so further arguments are not ruled out
