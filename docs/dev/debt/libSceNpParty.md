# libSceNpParty technical debt

### Unknown function info

- [sceNpPartyGetState and sceNpPartyGetStateAsUserA](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - the 16-bit state, its `NOT_IN_PARTY` value 2 and the `INVALID_ARGUMENT` (`0x80552504`) error follow shadPS4's [np_party.h](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/np/np_party.h) and [np_error.h](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/np/np_error.h) (PS4); shadPS4 does not check for a null state. Both return `NOT_INITIALIZED` (`0x80552503`) before `sceNpPartyInitialize` and after `sceNpPartyTerminate`, and `sceNpPartyGetStateAsUserA` returns `INVALID_ARGUMENT` for user -1, as a [firmware 13.42 run](https://github.com/boykopovar/AnyPS5/pull/12948#issuecomment-6538287699) of the module under an emulator shows; there the state itself comes from the party service. Not measured on a PS5
- [sceNpPartyGetId, sceNpPartyGetMembersA, sceNpPartyGetMemberInfoA, sceNpPartyGetMemberSessionInfo, sceNpPartyGetMemberVoiceInfo and sceNpPartySendBinaryMessage](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - the user is never in a party, so these return `NOT_IN_PARTY` (`0x80552506`, shadPS4's np_error.h) and write nothing, or `INVALID_ARGUMENT` for a null pointer; the signatures are from [Orbital's type database](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json). Like `sceNpPartyGetState` they return `NOT_INITIALIZED` (`0x80552503`) first when the library is not initialized, as the [13.42 run](https://github.com/boykopovar/AnyPS5/pull/12948#issuecomment-6538287699) shows for these and `sceNpPartyGetMembers`/`GetMemberInfo`. That run reaches the party service past the module's own checks and finds no local `NOT_IN_PARTY`, so the answer after initialization stays this model. Not measured on a PS5
- [sceNpPartyInitialize, sceNpPartyTerminate and sceNpPartyCheckCallback](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - an initialized flag with `ALREADY_INITIALIZED` (`0x80552502`) and `NOT_INITIALIZED` (`0x80552503`) from shadPS4's np_error.h. Whether the console refuses a null initialize parameter, and which check comes first, is not known
- [sceNpPartyCreate, sceNpPartyCreateA, sceNpPartyGetStateAsUser, sceNpPartyJoin, sceNpPartyLeave, sceNpPartyShowInvitationList and sceNpPartyShowInvitationListA](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - Orbital has no prototypes for these and no credible ones were found. The declarations have no parameters solely to resolve known imports; this is not an ABI claim and callers must not call them until signatures are verified
- [sceNpPartyGetMembers, sceNpPartyGetMemberInfo and sceNpPartyRegisterHandler](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - the signatures are from [fpPS4](https://github.com/red-prig/fpPS4/blob/04cefd43e6fddd1ab033e7980cd356d14c964905/src/np/ps4_libscenpparty.pas) (PS4) and match their `A` variants, so the member queries behave like them: no party, `NOT_IN_PARTY` from [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/np/np_party.cpp), and handlers accepted but never called. How the console's non-`A` member structures differ from the `A` ones is not known, and nothing is written to them. Not measured on a PS5

### Functional

- [sceNpPartyGetVoiceChatPriority and sceNpPartySetVoiceChatPriority](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - the 11.00 wrapper confirms the out-pointer check in Get and, in Set, a 32-bit priority accepted only when `priority - 1` is 0 or 1, with `INVALID_ARGUMENT` for every other value. The priority belongs to the local party member, so both return `NOT_IN_PARTY` (`0x80552506`) and write nothing because no party ever exists; this matches the PS4 reimplementation in [PS4Recomp](https://github.com/wie-project/PS4Recomp/blob/main/pkg/runtime/modules/libSceNp/ps4_np_party.c). The console's result for a valid priority after initialization is not measured
- [sceNpPartyRegisterPrivateHandler and sceNpPartyUnregisterPrivateHandler](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - the 11.00 wrappers show that private registration requires the public handler callback recorded from offset 8 of the block passed to `sceNpPartyRegisterHandler`/`RegisterHandlerA`, returning `0x80552511` while it is absent; both accept any private-handler pointer, including null, store or clear it and return 0, and the handler is never invoked. Unregister returns `0x80552511` when no non-null private handler is registered. The name and exact meaning of `0x80552511` are inferred
- [sceNpPartyRegisterHandler and sceNpPartyRegisterHandlerA](../../../core/libs/prx/libSceNpParty/Export.cpp) (libSceNpParty) - both record the callback at offset 8 of the handler block so that private registration can check it; RegisterHandlerA returns `0x80552511` on a second registration while RegisterHandler accepts and replaces it, as the 11.00 wrappers do. The block's version field at offset 4 is not inspected, unlike the wrapper, and no callback is ever invoked. The rest of the block stays opaque and is not copied
