Not measured on a console. Closes when: a host camera is exposed to guests.
- [sceCameraOpen, sceCameraClose, sceCameraCloseByHandle, sceCameraStart, sceCameraStartByHandle, sceCameraStop, sceCameraStopByHandle, sceCameraGetFrameData and sceCameraIsValidFrameData](../../../core/libs/prx/libSceCamera/src/Handles.cpp) (libSceCamera) - follow [shadPS4's camera.cpp](https://github.com/shadps4-emu/shadPS4/blob/396c2a09a38d22eaa02aab32c1967263dceab95f/src/core/libraries/camera/camera.cpp) with no host camera configured: its check order and 584-byte frame data limit. Handle calls require a live ID; IDs are not reused, unlike shadPS4's counter. The console's ID reuse and exhaustion policy is unknown; exhaustion throws. `sceCameraStartByHandle` succeeds where `sceCameraStart` reports `NOT_CONNECTED`, as in shadPS4; which of the two the console does is not known. The open parameter is not read and no camera memory is mapped. Not measured on a console. Closes when: a host camera is exposed to guests.

- [sceCameraAudioClose, sceCameraAudioGetData, sceCameraAudioGetData2, sceCameraAudioReset](../../../core/libs/prx/libSceCamera/Export.cpp) (libSceCamera) - follow [shadPS4's camera_audio.cpp](https://github.com/shadps4-emu/shadPS4/blob/0614ce324be092791b758d79f93d9f1ca5b10a81/src/core/libraries/camera/camera_audio.cpp#L9-L43) with no camera attached, as the rest of the library does: they answer 0, and the data calls refuse a null buffer with `SCE_CAMERA_ERROR_PARAM` and write nothing, where shadPS4 notes the console answers 0 while failing internally. Not measured on a console
- [sceCameraDeviceOpen, sceCameraSetAttributeInternal](../../../core/libs/prx/libSceCamera/Export.cpp) (libSceCamera) - answer 0 and do nothing, before or after `sceCameraOpen`: shadPS4 marks both as stubbed on the console itself ([device open](https://github.com/shadps4-emu/shadPS4/blob/0614ce324be092791b758d79f93d9f1ca5b10a81/src/core/libraries/camera/camera_device.cpp#L9-L12), [internal attribute](https://github.com/shadps4-emu/shadPS4/blob/0614ce324be092791b758d79f93d9f1ca5b10a81/src/core/libraries/camera/camera_config.cpp#L324-L327)), where its unfinished calls log `(STUBBED)` instead. That is a PS4 source: the PS5 module was not read, and the parameter lists stay unverified because the bodies read no arguments. Not measured on a console
- [sceCamera2Initialize, Finalize, Open, Close, IsAttached and 28 handle calls](../../../core/libs/prx/libSceCamera/src/Camera2.cpp) (libSceCamera) - follow @BunnyFl's 13.42 [disassembly](https://github.com/boykopovar/AnyPS5/pull/12943#issuecomment-6521376114) and [emulator run](https://github.com/boykopovar/AnyPS5/pull/12943#issuecomment-6543803331), not a console. Each reads the app category at 0x50 of the `sceKernelGetAppInfo` record: below 0x1000000 and not 0x20f00, with Camera2 not initialized, it returns 0x8a760002. Here the record holds 0xffffffff, which skips it. `Initialize` sets the flag. `Finalize` returns 0x8a760015 while a `sceCameraOpen` handle is open, else clears it. No Camera2 handle opens, so `Close` and the handle calls return 0x8a760000. `Open` refuses a user other than 0xff or a nonzero type or index, and `IsAttached` a device other than 1, with 0x8a760000; past those, and in `Initialize` for a checked category, the driver would answer, so they throw.
