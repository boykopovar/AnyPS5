# libSceKeyboard technical debt

### Functional

- [sceKeyboardDebugGetDeviceId](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp) - validation and the -1 sentinel follow the [retail 11.00 dump decode](https://github.com/boykopovar/AnyPS5/issues/12063#issuecomment-6483898452): not-initialized, null output, -1 written up front, no device match returns INVALID_HANDLE, a match writes the device record's id. The decode binds the handle to a live device record, so an unopened or detached handle is the no-match case; whether firmware also has the mouse-style empty-slot success path is not decoded. The reported device id is a model constant for the single emulated device.
- [sceDbgKeyboardReadState](../../../core/libs/prx/libSceKeyboard/Export.cpp) - the [retail 11.00 dump decode](https://github.com/boykopovar/AnyPS5/issues/12063#issuecomment-6483898452) recovers its two-argument signature and shows it calls sceKeyboardReadState's shared path with a third argument of 1 instead of 0; the flag's semantic effect inside that path is not decoded, so the export stays unimplemented until the flag is understood.
- [sceKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/src/keyboard_impl.cpp): initialization, output length and reserved bytes remain unverified on a console; unconverted keys retain the host's length of 0. One title (PPSA15246) disassembled for this entry calls it after clearing the first 20 bytes of its output buffer (16-byte store 0x69942d, 32-bit store 0x699435; no size argument), uses a character only when the result is 0 and the first output byte is nonzero, and then reads the 16-bit value at offset 8. Which other output fields it reads and what its other arguments mean are not shown.

### Unknown function info

- [Keyboard export `l76jptHfizM`](../../../core/libs/prx/libSceKeyboard/Export.cpp) is recorded as a function with qualifier `E#A` in older and later version-labelled modules. In both, dynamic metadata maps library ID 4 and module ID 0 to `libSceKeyboard`. The older module-parameter words are `0x08540001` and `0x03200004`; the later words are `0x13590001` and `0x13600007`. The 17 older function NIDs under that qualifier have sorted-LF SHA-256 `42ee4240ba6e95c22083ea1ce753b81bdc8852b5f241675f4eecbd9bcca83ad9` using the [static ELF membership procedure](https://github.com/boykopovar/AnyPS5/pull/12367#issuecomment-6470603298). Version labels are not authenticated retail provenance; this digest identifies the NID set, not the binary or ABI. The export name, signature and behavior are unverified; this declaration throws.
- [sceDbgKeyboardGetHandle](../../../core/libs/prx/libSceKeyboard/Export.cpp) (logical `libSceDbgKeyboard`, NID `vob3PZretTg`) - signature and behavior are unknown. This parameterless `int` declaration is an import placeholder, not a verified ABI prototype; every call throws through `NotImplemented_nid_no_patch`. The binding is in the [13.60 inventory](https://github.com/xdCloudy/PS5-13.60-Function-Stub-Library/blob/bfec40deb4c47a17d7603ee2bc79aa6862c0c56b/data/firmware-13.60/libscedbgkeyboard-a009193dfc.jsonl).

- [sceDbgKeyboardClose, sceDbgKeyboardGetKey2Char, sceDbgKeyboardInit, sceDbgKeyboardOpen, sceDbgKeyboardRead](../../../core/libs/prx/libSceKeyboard/Export.cpp) (libSceKeyboard) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceKeyboard.c), but no credible prototypes were found. They are declared without parameters solely to resolve known imports; this is not an ABI claim.
- [sceKeyboardGetDeviceInfo and sceKeyboardSetProcessFocus](../../../core/libs/prx/libSceKeyboard/Export.cpp): pointer arguments are passed to device ioctls. Device-info storage is 168 bytes in the connection-query caller, but its fields and the process-focus layout remain unresolved.
- [sceKeyboardConnectPort, sceKeyboardDisconnectPort and sceKeyboardDeviceOpen](../../../core/libs/prx/libSceKeyboard/Export.cpp): argument widths are confirmed. The meaning/order of the two 32-bit port arguments and the final 32-bit device-open argument still require the device-service backend.
- [sceKeyboardPadEmulateClose and sceKeyboardPadEmulateOpen](../../../core/libs/prx/libSceKeyboard/Export.cpp): the supplied keyboard library has neither export; their signatures remain unresolved.
