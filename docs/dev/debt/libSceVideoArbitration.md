# libSceVideoArbitration technical debt

### Unknown function info

- [sceVideoArbitrationAcceptEvent and sceVideoArbitrationEnable](../../../core/libs/prx/libSceVideoArbitration/Export.cpp) (libSceVideoArbitration) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceVideoArbitration.c), but no credible prototypes were found. The declarations have no parameters solely to resolve known imports; this is not an ABI claim and callers must not call them until signatures are verified
- [sceVideoArbitrationInitialize](../../../core/libs/prx/libSceVideoArbitration/Export.cpp) (libSceVideoArbitration) - throws for a parameter block whose 64-bit size field is 0x18, and for one it cannot read (the console module reads it unchecked). The fields after the size are not interpreted, and the success path (the kernel objects the module creates) is not implemented, so arbitration is never initialized here. Only the 32-bit result and the first argument are claimed.
- [The answers without arbitration](../../../core/libs/prx/libSceVideoArbitration/Export.cpp) (libSceVideoArbitration) - in firmware 13.42's `libSceVideoArbitration.sprx` (SHA-256 `173eb883897d2b5519be69b10776049987505ad776817bb824b8cbd4c42de242`), read from disassembly and not run on a console, the module's constructor (`0x590`, run at load from the list at `0x8110`) sets the handle at `0xc028` to -1, and only a successful `sceVideoArbitrationInitialize` changes it. `sceVideoArbitrationEnable` (`0x490`) and `sceVideoArbitrationAcceptEvent` (`0x500`) return `0x819E0001` while it is -1, before reading their arguments. `sceVideoArbitrationInitialize` (`0x250`) returns `0x819E0002` for a null parameter block or a size other than 0x18.
