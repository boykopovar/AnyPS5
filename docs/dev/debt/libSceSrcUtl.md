# libSceSrcUtl technical debt

### Functional

- [sceSrcUtilityGetHandleSize, sceSrcUtilitySetPriority and sceSrcUtilityGetPriority](../../../core/libs/prx/libSceSrcUtl/Export.cpp) (libSceSrcUtl) - follow firmware 13.42's libSceSrcUtl.sprx, read from disassembly and not measured on a console, on its PS5 process path; their argument names are inferred from its checks. `sceSrcUtilityGetHandleSize` validates channels (1 to 8), mode (0 to 2), and supported input and output sample rates, returning 0x9678 bytes. `sceSrcUtilitySetPriority` and `sceSrcUtilityGetPriority` validate the handle pointer and its `0xDEADBEEFBAADF00D` initialization magic at offset 0x9470, reading and writing the 32-bit priority at offset 0x2C. Unit tests cover handle sizing, rates, error precedence, null and uninitialized handles, priority read and write, and magic corruption. For a PS4 process the module allows only 1 or 2 channels and refuses 22050 Hz to 192000 Hz, which is not modelled.
- [sceSrcUtilityCreateEx, sceSrcUtilityInitialize, sceSrcUtilityInitializeEx, sceSrcUtilityFinalize, sceSrcUtilityDeleteEx, sceSrcUtilityFlush and sceSrcUtilityResample](../../../core/libs/prx/libSceSrcUtl/Export.cpp) (libSceSrcUtl) - only the checks before the first AJM call are implemented, from firmware 13.42's disassembly, not measured on a console. `CreateEx` returns `0x815D0001` for a null context pointer, then `0x815D0000` for a null handle, then the `GetHandleSize` errors; `Initialize` the last two; `InitializeEx` `0x815D0001` for a null context pointer. `Finalize`, `DeleteEx`, `Flush` and `Resample` return `0x815D0000` without the handle magic; `Flush` then `0x815D0001` for a negative count or either null pointer and `0x815D000A` when the state at 0x30 is 2; `Resample` `0x815D0001` for a negative count. Argument names past the handle are not from a header.
- [sceSrcUtilityGetAjmContext](../../../core/libs/prx/libSceSrcUtl/Export.cpp) (libSceSrcUtl) - returns `0x815D0000` for a null handle and 0 for a null output; otherwise it copies the 32-bit AJM context at offset 0x9478 to the output and returns 0, without checking the magic, as firmware 13.42 does (read from disassembly). An unreadable handle returns `0x815D0000` and an unwritable output `0x815D0001` as a host-safety fallback, as `sceSrcUtilityGetPriority` does; the console faults there.

### Unknown function info

- [sceSrcUtilityFinalize, sceSrcUtilityFlush, sceSrcUtilityGetDelaySamples, sceSrcUtilityInitialize, sceSrcUtilityInitializeEx and sceSrcUtilityResample](../../../core/libs/prx/libSceSrcUtl/Export.cpp) (libSceSrcUtl) - throw past the checks under Functional (`sceSrcUtilityGetDelaySamples` for every input, still declared without parameters): in firmware 13.42 they drive AJM codec 19 (0x13), which this project's AJM lacks, and the conversion runs inside AJM, not in this module. `sceSrcUtilityInitializeEx` initializes an AJM context and registers codec 19; `sceSrcUtilityInitialize` checks its arguments like `sceSrcUtilityGetHandleSize`, clears the 0x9678-byte handle, creates a codec 19 instance, sends it a control job and marks the handle (0xDEADBEEFBAADF00D at 0x9470, priority 0x28 at 0x2C).
- [sceSrcUtilityCreateEx, sceSrcUtilityDeleteEx and sceSrcUtilityTerminateEx](../../../core/libs/prx/libSceSrcUtl/Export.cpp) throw through `NotImplemented_nid_no_patch` past the checks under Functional (`sceSrcUtilityTerminateEx` for every input: its null path returns without setting a result). Names and NIDs are bound by the [13.60 firmware inventory](https://github.com/xdCloudy/PS5-13.60-Function-Stub-Library/blob/bfec40deb4c47a17d7603ee2bc79aa6862c0c56b/data/firmware-13.60/libscesrcutl-970010b531.jsonl); behaviour past those checks remains unknown. The parameterless `int` declaration of `sceSrcUtilityTerminateEx` is an import-resolution placeholder, not a confirmed ABI signature. Their service behaviour is unimplemented.
