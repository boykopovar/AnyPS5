# libSceAppContent technical debt

### Silent stubs

- [sceAppContentGetGameTrialsFlag](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - returning `SCE_APP_CONTENT_ERROR_PARAMETER` for an unwritable game trials flag pointer is a host-safety fallback with console behavior unmeasured.

### Unknown function info

- [sceAppContentTemporaryDataMount2](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - an inaccessible non-null mount-point output returns `SCE_APP_CONTENT_ERROR_PARAMETER` instead of crashing the host. This is a host-safety fallback; the console's invalid-memory result is unmeasured. The checked output is written before creating or formatting storage, so a failed write leaves the files and mount state untouched. If a later host filesystem operation throws, the guest output may already contain `/temp0`; that case is unmeasured.

- [sceAppContentDownloadDataGetAvailableSpaceKb](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - a title whose `param.json` declares `downloadDataSize` 0 gets 0 KB and OK; the console's behaviour for a title without a download data area is unverified (it may return an error instead). shadPS4 stubs 1048576 KB. One disassembled title (PPSA15246) calls it with the `/download0` mount point and a zeroed 64-bit output, ignores the return value and multiplies the output by 1024, so for that title an error that leaves the output untouched and an OK with 0 KB look the same. `/download1` and `/download2` queries reflect their configured quota.
- [sceAppContentDownloadDataFormat](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - empties the `/download0`, `/download1`, or `/download2` directory, creating it if needed. Imported by PPSA01317. A null mount point returns `PARAMETER` and another mount point returns `NOT_MOUNTED` as in `sceAppContentTemporaryDataFormat` and `sceAppContentDownloadDataGetAvailableSpaceKb`; the console's error codes for both and its behaviour with files still open are unverified

- [sceAppContentDownload0Expand, sceAppContentDownload0Shrink, sceAppContentDownload1Shrink and sceAppContentDownload2Shrink](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - partition expansion and shrink behaviour on hardware is unverified. `sceAppContentDownload1Expand` and `sceAppContentDownload2Expand` expand `/download1` and `/download2` and update their reported quotas; the other partition expansion and shrink functions throw through `NotImplemented_nid_no_patch`.
- [sceAppContentUnknown_SWVxsi_ZBlw](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent, NID SWVxsi-ZBlw) - master data identifier query (UnknownMdid in [dlc_emu](https://github.com/drakmor/dlc_emu/blob/fcf69b16d46a9850578bce19dc2c1b4dc867cbb5/src/dlc_modules/dlc_content.cpp#L2258-L2262)). Reconstructed prototype (`const void* mdid, bool* matches`) from PPSA24263 (discussion #11591) call site at `app.exe+0x182dda2`; parameter validation and general matching against console entitlements remain unverified, and all calls throw through `NotImplemented_nid_no_patch`.
- [libSceAppContent pending exports](../../../core/libs/prx/libSceAppContent/Export.cpp) - 3 named callable exports (`sceAppContentDownload0Expand`, `sceAppContentDownload0Shrink` and `sceAppContentDownload1Shrink`) are listed in the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceAppContent.c) and were cross-checked against the same module in PS5 firmware 13.60. Their signatures and behaviour are unverified; the declarations use the no-parameter unknown-signature convention and throw through `NotImplemented_nid_no_patch`.
- [sceAppContentAppParamGetString, sceAppContentDownloadDataGetBlockSize, sceAppContentGetRegion and sceAppContentRequestPatchInstall](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - after their argument checks each passes its request to a service outside the module, whose answers are unknown, so they throw there. The checks follow firmware 13.42 `libSceAppContent.sprx` (read from disassembly, not measured on a console): `NOT_INITIALIZED` first, then `PARAMETER` for a null `value`, a null mount point or `blockSize`, a null `region`, and a null `text` or one longer than 255 bytes (`strlen`). Argument counts come from how each export forwards its registers. `DownloadDataGetBlockSize` forwards like `DownloadDataGetAvailableSpaceKb`, so its output is taken as `size_t*`; the type behind `region` and what `text` names are unknown.

- [Download partition expansion](../../../core/libs/prx/libSceAppContent/Export.cpp) - `/download1` and `/download2` expansion tracks size monotonically and reports available space in `sceAppContentDownloadDataGetAvailableSpaceKb`. The quota units and hardware shrink behavior remain unverified.

The host model throws `std::overflow_error` before writing the output or creating storage; no console error code is assigned.

- [Initialization](../../../core/libs/prx/libSceAppContent/Export.cpp) - service readiness and boot attributes are not modeled; successful initialization returns a zero boot record. Initialization-state guards, SDK 0x01500000 repeated-initialization errors and reserved-field checks are recovered. SDK-dependent service-error translation remains incomplete.

- [sceAppContentAppParamGetInt](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - returning `SCE_APP_CONTENT_ERROR_PARAMETER` for a non-null output that cannot be written is a host-safety fallback with console behavior unmeasured, as for `sceAppContentGetGameTrialsFlag`. - [Additional content](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - console add-on mounting behavior and error codes remain unverified on hardware; configured add-ons in `anyps5-entitlements.ini` are assumed installed (status 4). `sceAppContentAddcontMount` assigns mount points (`/addcont0` or configured targets) and aliases them to host content directories, returning `BUSY` on repeated mounts or `NOT_FOUND` when the host directory is missing. `sceAppContentAddcontUnmount` removes the alias and releases the mount point, returning `NOT_FOUND` when not mounted. Unconfigured add-ons answer `NOT_FOUND`. `sceAppContentGetAddcontInfo` and `sceAppContentGetAddcontInfoList` report configured add-ons.

- [Temporary app-content storage](../../../core/libs/prx/libSceAppContent/Export.cpp) console behaviour and hardware return values are unverified, including behaviour with open files across unmount; host filesystem failures throw. - [sceAppContentGetDownloadedStoreCountry](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - the firmware 4.03 `libSceAppContent.sprx` body (SHA-256 `36039805f77483b32861b7936ddcd859708b764682984a4625cb7f8d1efdabc4`) is a thin RPC client: initialization guard, null-parameter checks, an entitlement-label padding gate at SDK 0x01500000, then a vtable call marshalling a system-service request (selector `0x20005`, `{serviceLabel}` + a 0x14-byte label input + a 0x18-byte reply buffer) and translating the reply status into the `0x80d9xxxx` family; the translator passes `0x80d91000` GET_STORE_COUNTRY through unchanged.
  - The export signature is thunk-verified (`uint32_t serviceLabel, const NpUnifiedEntitlementLabel* entitlementLabel, void* storeCountry`); the body was not compared with 13.60 — its export inventory establishes symbol presence only. With no host system service the export answers `GET_STORE_COUNTRY` after the verified checks as the chosen fallback for an absent service, not a measured native result; the real service replies and the 0x18-byte reply layout are unverified.
