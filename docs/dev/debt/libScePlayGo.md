# libScePlayGo technical debt

### Functional

- [scePlayGoGetOptionalChunk, scePlayGoGetSupportedOptionalChunk, scePlayGoRequestOptionalChunk and scePlayGoSetToDoList](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - returning `0x80B2000A` (`SCE_PLAYGO_ERROR_BAD_POINTER`) for unmapped or unreadable chunk parameter pointers is a defensive host-safety fallback; whether console hardware faults or returns an argument error on unmapped memory is unmeasured.

### Unknown function info

- [scePlayGoSnapshot](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - signature `(int handle, const char* filename)` follows [pgo_stub](https://github.com/drakmor/pgo_stub/blob/c95dec777563/library.h#L130) and [rps5e](https://github.com/keklick1337/rps5e/blob/7028192c3246/crates/ps5hle/src/playgo.rs#L711-L715); what the console writes is unknown, so this export throws `NotImplemented_nid_no_patch`.

- [scePlayGoRequestOptionalChunk, scePlayGoGetRequiredDisc](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - the package's scenario count is not read: scenario (type 1) bits 0 to 4 are accepted for every package and bits from 5 up return `SCE_PLAYGO_ERROR_BAD_SCENARIO_CONFIGURATION`, and `scePlayGoGetSupportedOptionalChunk` and `scePlayGoGetOptionalChunk` report bits 0 to 4 for type 1 too. `scePlayGoGetRequiredDisc` always reports disc 0. Only `scePlayGoSetInstallSpeed2` checks initialization, and unlike both sources `scePlayGoInitialize` accepts a null or small buffer and a second call, and `scePlayGoTerminate` succeeds without it. These checks follow [pgo_stub](https://github.com/drakmor/pgo_stub/blob/c95dec777563/library.cpp#L559-L596) and [rps5e](https://github.com/keklick1337/rps5e/blob/7028192c3246/crates/ps5hle/src/playgo.rs#L313-L344), which may not be independent; none is measured
- [scePlayGoSetLanguageMask](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - stores the mask that `scePlayGoGetLanguageMask` then reports, and returns `SCE_PLAYGO_ERROR_BAD_HANDLE` for another handle, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/8d50471b7dc141dd700b51276b8edd1f293bce26/src/core/libraries/playgo/playgo.cpp#L346-L359) does on the PS4. shadPS4 also returns `SCE_PLAYGO_ERROR_NOT_INITIALIZED` before `scePlayGoInitialize` and starts from the system language's mask; here the mask starts with every language and initialization is not tracked. Not measured on a PS5
- [libScePlayGo](../../../core/libs/prx/libScePlayGo/Export.cpp) - the chunk set comes from `playgo-chunkdefs.xml` (every listed chunk plus chunks 0 through the default chunk), otherwise from `sce_sys/playgo-chunk.dat`, whose `plgx` header is read as holding the chunk count as a 16-bit value at offset 0x0A and ids 0 to count - 1 are taken as valid. The field was identified on four dumps, where exactly that many 0x20-byte entries follow from offset 0x100 (RIDE 4 PPSA01599: 35, Persona 5 Royal PPSA05110: 25, LEGO Horizon Adventures PPSA14632 and Kena PPSA01802: 1); the rest of the format is not decoded and ids are assumed to be contiguous. Every listed chunk is reported as installed (`LOCAL_FAST`). Without either file, a package with `sce_sys/playgo-scenario.json` (PPSA01748, whose dump lists no chunks) accepts ids 0 to 999 as installed, and `scePlayGoGetChunkId` lists the same ids. A title that builds its set of installed chunks from that list skips any chunk it does not see. The console's chunk limit is not known here, so an id from 1000 up is answered like an unlisted id of a package with no `playgo-*` file: it throws unless `APS5_PLAYGO_UNLISTED_CHUNKS` answers it (`=absent` ends PPSA02630's id walk, which otherwise asks for every id until one is rejected and wraps the 16-bit id). A package with no `playgo-*` file in `sce_sys` (PPSA03001, PPSA03490 and PPSA01285 here) answers ids 0 to 999 as installed (`LOCAL_FAST`) and an id from 1000 up with `SCE_PLAYGO_ERROR_BAD_CHUNK_ID`, so PPSA15388 (which asks exactly ids 0 to 999) loads its saves without a flag and PPSA03001's id walk (which asks until the first error) still ends. The 1000 bound is what PPSA15388 was seen to ask, not a console value; PPSA31327 asks only 0 to 5 and 10, and no title is known to ask 1000 or more here. `APS5_PLAYGO_UNLISTED_CHUNKS=installed` answers every such id as installed (`LOCAL_FAST`, which PPSA15388 needs to load its saves) and `=absent` answers `SCE_PLAYGO_ERROR_BAD_CHUNK_ID` (which ends PPSA03001's id walk), as the user's choice for that dump. A `sce_sys` that holds other `playgo-*` files (`playgo-ficm.dat`, `playgo-hash-table.dat`) without `playgo-chunk.dat` or `playgo-scenario.json`, or a `playgo-chunk.dat` without a `plgx` header and a nonzero count, throws naming the file, because no such dump is known. These answers are unverified on a console, as is the console's answer for an id outside a package's chunk table.
- [libScePlayGo](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - when the dump has no `playgo-chunk.dat` or `playgo-scenario.json`, `APS5_PLAYGO_UNLISTED_CHUNKS` may list installed chunk ids (for example `0,1`); the listed ids plus chunk 0 become the chunk set and every other unlisted id is absent. The dump cannot say which ids the title expects; no console run verifies the user's choice.
- [libScePlayGo](../../../core/libs/prx/libScePlayGo/Export.cpp) - `scePlayGoGetSupportedOptionalChunk` and `scePlayGoGetOptionalChunk` report every bit set for `type` 0 or 2 and bits 0 to 4 for `type` 1, i.e. every optional chunk (type 0 languages, type 1 scenarios) supported and installed, like `scePlayGoGetLanguageMask`. Native requests confirm types 0 through 2 and an eight-byte result; their meanings and bit layout are still determined by the external service, not this module; PPSA01748 calls both with type 0 and hides every text language listed in `playgo-scenario.json` `chunkSupportedLanguages` when the bitmask is 0. The console's answer for a package that ships no optional chunks is unverified.
- [scePlayGoPrefetchOptionalChunk](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - validates the handle, null option, types above 2 and scenario bits above 4, matching `scePlayGoRequestOptionalChunk`. With every optional chunk reported installed, there is nothing to prefetch. Borderlands 4 (PPSA01494), MXGP 26 (PPSA30839) and Super Meat Boy 3D (PPSA31162) each call it from two wrappers, one with type 0 and one with type 1, passing a stack copy of an eight-byte option and returning the result to their caller (read statically from each `eboot.bin`). The console's answer for background queueing and download priority remains unverified.
- [libScePlayGo](../../../core/libs/prx/libScePlayGo/Export.cpp) (libScePlayGo) - a non-null output that is unmapped or not writable returns `SCE_PLAYGO_ERROR_BAD_POINTER`, the code these exports return for a null output; this is a host-safety fallback and the console's answer is not measured. The output is checked when it is copied out, after the handle, size, chunk-list, type and option checks, so in `scePlayGoGetEta`, `scePlayGoGetProgress`, `scePlayGoGetLocus`, `scePlayGoGetRequiredDisc` and the optional-chunk getters a bad chunk list, type or option is reported first. A chunk id list that `scePlayGoGetChunkId` cannot write leaves the count unchanged.
