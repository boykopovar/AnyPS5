# libSceNpSignaling technical debt

### Functional

- [libSceNpSignaling](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - offline only, not measured on a PS5: the checks, their order, context ids 1 to 8 and the NpId rule (`term` 0, 3 to 16 characters, the first an ASCII letter or digit, the rest ASCII letters, digits, `_` or `-`) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/91e6afa69b0a64b0afaa0281b80f8fbb0cd88136/src/core/libraries/np/np_signaling/np_signaling.cpp#L118-L170) and its [state helpers](https://github.com/shadps4-emu/shadPS4/blob/91e6afa69b0a64b0afaa0281b80f8fbb0cd88136/src/core/libraries/np/np_signaling/np_signaling_state.cpp#L120-L170). `sceNpSignalingInitialize` creates the heap the module uses (`memorySize`, 0x20000 when zero, rounded up to 0x4000) but starts no thread, so the thread arguments are not checked, and callbacks are never called. `sceNpSignalingActivateConnection` returns `SCE_NP_ERROR_SIGNED_OUT` after shadPS4's checks up to `OWN_NP_ID`, without its rate limit, and creates no connection, so the connection calls answer `CONN_NOT_FOUND`

- [sceNpSignalingDeactivateConnection](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - not measured on a PS5: it has the same checks as `sceNpSignalingTerminateConnection` (not initialized, unknown context, then `CONN_NOT_FOUND`), after shadPS4's [call](https://github.com/shadps4-emu/shadPS4/blob/12a4564543ccec527f9723676d2180580d1d7a94/src/core/libraries/np/np_signaling/np_signaling.cpp#L378-L400). No connection is ever created, so none can be deactivated.

- [sceNpSignalingGetLocalNetInfo](../../../core/libs/prx/libSceNpSignaling/LocalNetInfo.cpp) (libSceNpSignaling) - not measured on a console: the valid network and NAT information path remains unsupported, throwing through `NotImplemented_nid_no_patch` and leaving output untouched. Signature, 24-byte structure layout and the validation checks (not initialized, null info, then `size != 0x18` returning `INVALID_ARGUMENT`, without looking up `ctxId`) are adapted from [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/2183807e592b36d4440384878165b43d930c1dee/src/core/libraries/np/np_signaling/np_signaling.cpp#L644-L657).

- [Offline query subset](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - the eight implemented query exports are not measured on a PS5: signatures and checks follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/d1d0b58cf94e5bfb6a2be406e140dcf1e314853f/src/core/libraries/np/np_signaling/np_signaling.cpp#L172-L819) with no connection or request. `CreateContextA` and `ActivateConnectionA` return `SCE_NP_ERROR_SIGNED_OUT` under the existing libSceNpManager offline model. Console error mapping and validation order remain unverified.

- [sceNpSignalingActivateConnection, sceNpSignalingActivateConnectionA, sceNpSignalingGetPeerNetInfo, sceNpSignalingGetConnectionFromNpId, sceNpSignalingGetPeerNetInfoResult and sceNpSignalingGetLocalNetInfo](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - returning `0x80552715` (`SCE_NP_SIGNALING_ERROR_INVALID_ARGUMENT`) with errno preserved for unreadable peer NpId, peer address or net info pointers via `GuestCopyIn_nid_no_patch` is a host-safety fallback; whether console hardware faults or returns an argument error on unmapped memory is unmeasured.

- [Unsettled connection and peer queries](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - `sceNpSignalingGetConnectionStatus`, `sceNpSignalingGetConnectionStatistics`, `sceNpSignalingGetConnectionFromPeerAddressA` and `sceNpSignalingGetPeerNetInfoA` have no established console contract for the offline case. Their typed declarations follow the pinned shadPS4 source, but the inactive result, zero counts, context-kind error and validation order are unverified. All four throw through `NotImplemented_nid_no_patch` before examining arguments or state and leave outputs untouched. Closes when: the return values, output writes and check order are established from the firmware module or console measurements.

- [sceNpSignalingGetMemoryInfo](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - read from the 11.00 module (`tOpqyDyMje4` at VA `0xbbe0`, whose body is at `0xc700`) and the 13.40 one (same export at VA `0xb750`, body at `0xc240`), not measured on a console. The record is three 64-bit fields: `maxSystemSize` at +0, `currentInUse` at +8 and `peakInUse` at +0x10; the shadPS4 order this declaration used before was wrong. The module builds a `MallocManagedSize` (`size` 0x28, `version` 1), calls `sceLibcMspaceMallocStats` on the heap that Initialize created and copies `maxSystemSize`, `currentInuseSize` and `maxInuseSize` into those fields; a failed stats call returns its error and writes nothing. `sceNpSignalingInitialize` maps the requested size (0x20000 when zero) rounded up to 0x4000 with `sceKernelMapNamedFlexibleMemory`, creates the mspace over it with `sceLibcMspaceCreate` and stores it, and Terminate destroys the mspace and unmaps the block; the host mirrors that lifecycle, so a fresh initialization reports the rounded heap size with no use. Contexts are host maps and allocate nothing from the mspace, so `currentInUse` and `peakInUse` stay 0 after a context is created, where the console allocates from the pool. A negative `memorySize` returns `0x80552703` here; the console's mapping error for it is unmeasured. An unwritable non-null output returns `INVALID_ARGUMENT` through a guarded copy, a host-safety choice not measured on the console.

- [sceNpSignalingGetPeerNetInfo](../../../core/libs/prx/libSceNpSignaling/Export.cpp) (libSceNpSignaling) - a request that passes the checks throws: no peer information request is staged offline. Initialization, null pointers, an invalid NpId (`INVALID_ARGUMENT`) and then the context (`CTX_NOT_FOUND`) are checked in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/98ef621decb6a35dba62e367a8a89186f5d49dcc/src/core/libraries/np/np_signaling/np_signaling.cpp#L688-L717)'s order. Not measured on a PS5.
