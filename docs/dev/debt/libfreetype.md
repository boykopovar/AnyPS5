# libfreetype technical debt

### Callable exports

- [Callable exports](../../../core/libs/prx/libfreetype/Export.cpp) - five callable NIDs appear in a 3.20-labelled `libfreetype` image and a later 13.60-labelled `libSceVshFreeType` image. The images have different module and library identities; matching NIDs do not establish forwarding or equivalent behavior. Neither version label is authenticated. The [verified NID name database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) names them `FT_Get_Color_Glyph_Layer`, `FT_Get_Var_Axis_Flags`, `FT_Palette_Data_Get`, `FT_Palette_Select` and `FT_Set_Default_Properties`, and the NID of each name matches. Each helper is named after its symbol and keeps the explicit alias. Except `FT_Get_Var_Axis_Flags`, listed under Library helpers, signatures and behavior are unknown; these declarations throw and implement no runtime functionality.

- [Older callable NIDs](../../../core/libs/prx/libfreetype/Export.cpp): The [verified NID name database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) names these exports `FTC_Manager_New`, `FT_Error_String`, `FT_Face_Properties`, `FT_Get_BDF_Charset_ID`, `FT_Get_BDF_Property`, `FT_Get_MM_Blend_Coordinates`, `FT_Get_MM_WeightVector`, `FT_Get_Sfnt_LangTag`, `FT_Get_WinFNT_Header`, `FT_Gzip_Uncompress`, `FT_New_Glyph`, `FT_Palette_Set_Foreground_Color`, `FT_Set_MM_WeightVector`, `FT_Set_Named_Instance`, `FT_Stream_OpenBzip2`, `FT_Stream_OpenGzip` and `FT_Stream_OpenLZW`, and the NID of each name matches. Each helper is named after its symbol and keeps the explicit alias. Signatures and behavior are unverified. These are throwing import-resolution placeholders; no functionality is implemented. No matching NIDs were found in the later module inventory.

### Library helpers

- [FT_Library_SetLcdGeometry](../../../core/libs/prx/libfreetype/src/LibraryHelpers.cpp): Console signature, backend options and interoperability between the separately inventoried modules are unmeasured. The adapter follows public FreeType and pinned backend [ftlcdfil.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftlcdfil.c#L170-L185), which is built without `FT_CONFIG_OPTION_SUBPIXEL_RENDERING`, so the geometry is stored on the guest library's native handle and used by later LCD renders through `libSceFreeType`. A console build with that option would return `FT_Err_Unimplemented_Feature` instead. Guest LP64 vectors are converted to host `FT_Vector`; on Windows a coordinate outside the 32-bit host `FT_Pos` range throws through `NotImplemented_nid_no_patch`.

- [FT_Get_Var_Axis_Flags](../../../core/libs/prx/libfreetype/src/LibraryHelpers.cpp): The console signature is unmeasured. The adapter passes the guest `FT_MM_Var` record to the pinned backend [ftmm.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftmm.c#L599-L620) unchanged, because its 32-byte layout matches the host's, and reads the 16-bit flag array that follows it. A refused host write to the flags output returns `FT_Err_Invalid_Argument` without changing it; this is host-boundary validation, not measured console behavior.

- [FT_Bitmap_Blend](../../../core/libs/prx/libfreetype/src/BitmapBlend.cpp): The console signature is unmeasured. The adapter passes guest `FT_Bitmap` records, whose layout matches the host's, to the pinned backend [ftbitmap.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftbitmap.c#L765-L1039) and copies the target record and offset back. Target buffers are allocated, grown and freed through the `libSceFreeType` library's host allocator, as its `FT_Bitmap_Done` expects. A refused host write to the target record, its offset or its existing pixels returns `FT_Err_Invalid_Argument` without calling FreeType, even for calls FreeType would leave unchanged; this is host-boundary validation, not measured console behavior. A face's glyph-slot bitmap as the target, and on Windows an offset outside the 32-bit host `FT_Pos` range, throw through `NotImplemented_nid_no_patch`.
