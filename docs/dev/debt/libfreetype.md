# libfreetype technical debt

### Callable exports

- [Callable exports](../../../core/libs/prx/libfreetype/Export.cpp) - the `FT_Set_Default_Properties` NID appears in a 3.20-labelled `libfreetype` image and a later 13.60-labelled `libSceVshFreeType` image. The images have different module and library identities; matching NIDs do not establish forwarding or equivalent behavior. Neither version label is authenticated. The [verified NID name database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) names this export and the NID matches. The helper follows the bundled FreeType API; the console signature and behavior remain unverified.

- [Older callable NIDs](../../../core/libs/prx/libfreetype/Export.cpp): The [verified NID name database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) names these exports `FTC_Manager_New`, `FT_Bitmap_Blend`, `FT_Error_String`, `FT_Stream_OpenBzip2`, `FT_Stream_OpenGzip` and `FT_Stream_OpenLZW`, and the NID of each name matches. The gzip, LZW and bzip2 stream helpers follow bundled FreeType; the remaining names are throwing import-resolution placeholders. Console signatures and behavior are unverified. No matching NIDs were found in the later module inventory.

### Functional

- [FT_Set_Default_Properties](../../../core/libs/prx/libfreetype/Export.cpp) (libfreetype) - the console signature and behavior are unverified. The bundled build reads the guest `FREETYPE_PROPERTIES` value and passes each bounded assignment to FreeType 2.15.0's property-string setter; invalid syntax stops parsing and property errors are ignored as in that backend. A null guest library with a property value throws. System-dependency builds throw when a guest property value is present because the string setter is not a public FreeType API. A test changes the TrueType interpreter version from 40 to 35 with the guest value and confirms a different host value is ignored.

- [FT_Stream_OpenGzip and FT_Stream_OpenLZW](../../../core/libs/prx/libfreetype/src/CompressedStreams.cpp) (libfreetype) - the console signatures, version, and stream behavior are unverified. The guest stream record follows FreeType's LP64 public layout; a Windows host stream has 32-bit `unsigned long`, so source size and position above `ULONG_MAX`, output reads above that range, and a null guest memory allocator throw. Guest read callbacks and memory allocators run through adapters; a source stream must stay alive until the output is closed. The bundled FreeType 2.15.0 decompresses with internal zlib and LZW. Tests cover a small in-memory gzip stream, a larger callback-backed source and streamed output, seeked reads, a literal-coded LZW stream, and allocation release on close. A compressed output stream cannot yet be passed into libSceFreeType's `FT_Open_Face`, which still rejects `FT_OPEN_STREAM`.

- [FT_Gzip_Uncompress](../../../core/libs/prx/libfreetype/src/Gzip.cpp) (libfreetype) - the console's FreeType version and build options are unverified. The call goes to the bundled FreeType 2.15.0 [`FT_Gzip_Uncompress`](https://github.com/freetype/freetype/blob/VER-2-15-0/src/gzip/ftgzip.c), built with its internal zlib, so it returns FreeType's errors: `Invalid_Argument` for a null memory, output or length and when `inflateInit2` fails, `Array_Too_Large` when the output is too small, `Invalid_Table` for corrupt data and `Out_Of_Memory` when `inflate` cannot allocate. A console FreeType built without zlib would return `Unimplemented_Feature` instead. zlib's allocations go through the guest memory record's `alloc` and `free`. Lengths are 64-bit, as in the console's LP64 `FT_ULong`. On Windows, where `FT_ULong` is 32-bit, a length above `ULONG_MAX` returns `Invalid_Argument` before FreeType runs. FreeType then truncates lengths to zlib's 32-bit `uInt`, on every host alike
- [FT_Stream_OpenBzip2](../../../core/libs/prx/libfreetype/src/CompressedStreams.cpp) (libfreetype) - the console's FreeType build options are unverified. The call goes to the bundled FreeType 2.15.0, built with `FT_DISABLE_BZIP2`, so [`FT_Stream_OpenBzip2`](https://github.com/freetype/freetype/blob/VER-2-15-0/src/bzip2/ftbzip2.c) returns `Unimplemented_Feature` without touching either stream. It shares the gzip and LZW stream adapter, so a null stream returns `Invalid_Stream_Handle` first. A console FreeType built with bzip2 would open the stream instead
- [FT_Get_MM_Blend_Coordinates, FT_Get_MM_WeightVector](../../../core/libs/prx/libfreetype/src/MultipleMasters.cpp) (libfreetype) - the console's FreeType version is unverified. Both take a face opened through libSceFreeType and call the bundled FreeType 2.15.0 functions on its host face, so results and padding are FreeType's: the blend coordinates fill all `num_coords` entries, the weight vector fills the requested length and returns the design count in `*len`, which is also written back on failure. Coordinates and weights cross as the console's 64-bit `FT_Fixed` and reach the guest only on success. FreeType is asked for at most 65536 entries, more than any face has axes or designs, and the guest entries beyond repeat its padding value. The test compares both with native FreeType on a variable TrueType font and a static one; no Adobe Multiple Master font is tested, so a successful weight vector is not exercised
- [FT_Face_Properties, FT_Palette_Set_Foreground_Color](../../../core/libs/prx/libfreetype/src/FaceSettings.cpp) (libfreetype) - the console's FreeType version and build options are unverified. Both take a face opened through libSceFreeType and call the bundled FreeType 2.15.0 functions on its host face. Properties are passed to FreeType one at a time, so, as in FreeType, entries after the first failing one are never read. Property tags cross as the console's 64-bit `FT_ULong`; a tag above 32 bits becomes 0 on Windows and is rejected as unknown, as on Linux. `FT_PARAM_TAG_LCD_FILTER_WEIGHTS` returns `Unimplemented_Feature` because subpixel rendering is disabled. A null face returns `Invalid_Face_Handle` from `FT_Face_Properties`, where FreeType would dereference it. Whether the host renderer honours these settings for guest glyphs is not tested
- [FT_Set_MM_WeightVector, FT_Set_Named_Instance](../../../core/libs/prx/libfreetype/src/MultipleMasters.cpp) (libfreetype) - the console's FreeType version is unverified. Both call the bundled FreeType 2.15.0 functions on the host face of a face opened through libSceFreeType, then refresh the guest face record, its size and its glyph slot through libSceFreeType's `FreeTypeSyncFace_nid_no_patch`. Weights cross as the console's 64-bit `FT_Fixed`; a weight outside 32 bits returns `Invalid_Argument` on Windows without calling FreeType. Only as many weights as the face has designs are read, the count FreeType's Type 1 driver reads; the count comes from `FT_Get_MM_WeightVector`. Only TrueType variation fonts are tested; FreeType has no TrueType weight vector setter, so a successful `FT_Set_MM_WeightVector` on an Adobe Multiple Master font is not exercised
- [FT_Palette_Data_Get, FT_Palette_Select, FT_Get_Color_Glyph_Layer](../../../core/libs/prx/libfreetype/src/Color.cpp) (libfreetype) - these NIDs come from the 3.20-labelled `libfreetype` image and the later 13.60-labelled `libSceVshFreeType` image; the console's FreeType version and signatures are unverified. All three call the bundled FreeType 2.15.0 functions on the host face of a face opened through libSceFreeType. `FT_Palette_Data`, `FT_Color` and `FT_LayerIterator` hold no `long`, so the guest layouts match on every host. The palette and palette data arrays point into the host face and stay valid until the face is closed, as in FreeType. The test uses a generated COLRv0 and CPALv1 font; COLRv1 paint functions are not exported here

### Font metadata

- [Metadata queries](../../../core/libs/prx/libfreetype/src/FontMetadata.cpp): Console signatures, backend version, error order and interoperability between the separately inventoried modules remain unmeasured. The four implemented BDF/property, charset, SFNT language-tag and FNT header queries follow public FreeType and pinned backend `37515cf56ba3349656049edbed89ffc6f6466f2d`, using the existing guest-face adapter. Windows `FT_ULong` fields are widened to guest LP64 fields. Returned strings and tag bytes belong to the face. Generated BDF/SFNT/FNT fixtures test data, errors and output preservation through both export forms against that backend; they establish adapter behavior only. Foreign native face handles, forwarding from `libSceVshFreeType` and title compatibility are not established.

- [Output guards](../../../core/libs/prx/libfreetype/src/FontMetadata.cpp): Refused host-write access returns `FT_Err_Invalid_Argument` without touching either charset output or the requested metadata record. This is host-boundary validation, not measured console behavior. Windows runtime tests use read-only guest direct-memory mappings, check complete output preservation and both partial charset-output failures, then restore write permission and verify successful queries.

### Library helpers

- [FT_Library_SetLcdGeometry](../../../core/libs/prx/libfreetype/src/LibraryHelpers.cpp): Console signature, backend options and interoperability between the separately inventoried modules are unmeasured. The adapter follows public FreeType and pinned backend [ftlcdfil.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftlcdfil.c#L170-L185), which is built without `FT_CONFIG_OPTION_SUBPIXEL_RENDERING`, so the geometry is stored on the guest library's native handle and used by later LCD renders through `libSceFreeType`. A console build with that option would return `FT_Err_Unimplemented_Feature` instead. Guest LP64 vectors are converted to host `FT_Vector`; on Windows a coordinate outside the 32-bit host `FT_Pos` range throws through `NotImplemented_nid_no_patch`.

- [FT_Get_Var_Axis_Flags](../../../core/libs/prx/libfreetype/src/LibraryHelpers.cpp): The console signature is unmeasured. The adapter passes the guest `FT_MM_Var` record to the pinned backend [ftmm.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftmm.c#L599-L620) unchanged, because its 32-byte layout matches the host's, and reads the 16-bit flag array that follows it. A refused host write to the flags output returns `FT_Err_Invalid_Argument` without changing it; this is host-boundary validation, not measured console behavior.
