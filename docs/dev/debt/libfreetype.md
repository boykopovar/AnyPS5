# libfreetype technical debt

### Callable exports

- [Callable exports](../../../core/libs/prx/libfreetype/Export.cpp) - five callable NIDs appear in a 3.20-labelled `libfreetype` image and a later 13.60-labelled `libSceVshFreeType` image. The images have different module and library identities; matching NIDs do not establish forwarding or equivalent behavior. Neither version label is authenticated. The [verified NID name database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) names them `FT_Get_Color_Glyph_Layer`, `FT_Get_Var_Axis_Flags`, `FT_Palette_Data_Get`, `FT_Palette_Select` and `FT_Set_Default_Properties`, and the NID of each name matches. Each helper is named after its symbol and keeps the explicit alias. Signatures and behavior are unknown; these declarations throw and implement no runtime functionality.

- [Older callable NIDs](../../../core/libs/prx/libfreetype/Export.cpp): The [verified NID name database](https://github.com/zecoxao/sce_symbols/blob/2883963a0a514ba6e77407a08ef4730a65e88254/aerolib.csv) names these exports `FTC_Manager_New`, `FT_Bitmap_Blend`, `FT_Error_String`, `FT_Face_Properties`, `FT_Get_BDF_Charset_ID`, `FT_Get_BDF_Property`, `FT_Get_MM_Blend_Coordinates`, `FT_Get_MM_WeightVector`, `FT_Get_Sfnt_LangTag`, `FT_Get_WinFNT_Header`, `FT_Gzip_Uncompress`, `FT_Library_SetLcdGeometry`, `FT_Palette_Set_Foreground_Color`, `FT_Set_MM_WeightVector`, `FT_Set_Named_Instance`, `FT_Stream_OpenBzip2`, `FT_Stream_OpenGzip` and `FT_Stream_OpenLZW`, and the NID of each name matches. Each helper is named after its symbol and keeps the explicit alias. Signatures and behavior are unverified. These are throwing import-resolution placeholders; no functionality is implemented. No matching NIDs were found in the later module inventory.

### Functional

- [FT_New_Glyph](../../../core/libs/prx/libfreetype/Export.cpp) - console signature, layout, allocation behavior and FreeType-version equivalence are unverified. NID `sZq9oSwMGSs` follows the verified name database above; the LP64 adapter follows bundled [FreeType 2.15.0](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftglyph.c) through the existing libSceFreeType guest library and glyph ownership map. Bitmap and outline glyphs use native allocation with guest records; class pointers stay native and opaque. SVG and custom renderer classes that the backend accepts throw, including allocation errors for those classes. Refused guest output writes return Invalid_Argument without allocating a glyph; this host policy is unmeasured on console. Existing glyph copy/destruction restrictions apply, and glyphs must be freed before their library.
