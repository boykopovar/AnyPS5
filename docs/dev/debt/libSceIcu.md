# libSceIcu technical debt

### Functional

- [Invariant character and version helpers](../../../core/libs/prx/libSceIcu/Version.cpp) are unverified on a console. `u_charsToUChars`, `u_UCharsToChars`, `u_versionFromString`, `u_versionFromUString` and `u_versionToString` follow ICU 78.1 [uinvchar.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uinvchar.cpp) and [putil.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/putil.cpp), unchanged since 65.1. Firmware 13.42 reports ICU 78.1 and exports none of them ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6400470698)); the [3.20 table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIcu.c) has all five. Version parts use the guest `strtoul`, truncated to eight bits; `u_versionToString` keeps ICU's dropped zero tens digit (105 becomes `15`). A null buffer with a positive conversion length throws; ICU dereferences it. Closes when: compared with the console.
- [Numeric platform helpers](../../../core/libs/prx/libSceIcu/Numeric.cpp) are unverified on a console. The 24 `uprv_` IEEE 754, rounding, extreme, overflow and pointer-limit exports follow ICU 78.1 [putil.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/putil.cpp) and [umath.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/umath.cpp), unchanged since 65.1, assuming the default `IEEE_754` and `U_MAX_PTR` configuration; which of them firmware 13.42 exports is not checked. `floor`, `ceil`, `fabs`, `modf`, `fmod`, `pow` and `log` are the guest libc's, so their precision is libc's. ICU's quirks are kept: `uprv_trunc` of negative infinity is positive infinity, NaN results are the canonical quiet NaN, `uprv_fmax(0.0, -0.0)` is `-0.0`, and `uprv_round` floors `x + 0.5`. A null `uprv_modf` integral pointer or overflow result pointer throws; ICU dereferences it. Closes when: compared with the console.
- [u_getVersion and u_errorName](../../../core/libs/prx/libSceIcu/ErrorName.cpp) follow ICU 78.1, the version firmware 13.42's module reports and exports both for ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6401310351)); only `u_getVersion`'s 78.1.0.0 was measured there. `u_errorName` returns the names in 78.1's [utypes.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/utypes.cpp), including its `U_BRK_VARIABLE_REDFINITION` spelling, and `[BOGUS UErrorCode]` for every other code; the names were not compared with the console. Both report 78.1 whatever firmware is emulated, although the 3.20 module was ICU 65 to 68 and has no names for the codes added since. Closes when: compared with the console.
- [Constrained field positions](../../../core/libs/prx/libSceIcu/ConstrainedFieldPosition.cpp) are unverified on a console. The seven `ucfpos_` exports firmware 13.42 has ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6401310351)) follow ICU 78.1 [formattedvalue.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/i18n/formattedvalue.cpp) and [capi_helper.h](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/capi_helper.h). A handle is a host object whose first four bytes hold ICU's magic `0x55434600`; the rest of its layout differs from ICU's. A set error changes nothing, a null handle sets `U_ILLEGAL_ARGUMENT_ERROR` and other memory `U_INVALID_FORMAT_ERROR`; `ucfpos_open` ignores the error unless allocation fails. No export fills a position yet, so the indexes stay 0. Null error pointers and index outputs throw where ICU dereferences them. Closes when: compared with the console.
- [Code point sets](../../../core/libs/prx/libSceIcu/Set.cpp) are unverified on a console. `uset_openEmpty`, `uset_close`, `uset_add`, `uset_addRange`, `uset_addAll`, `uset_contains`, `uset_getItemCount` and `uset_getItem`, which firmware 13.42 exports ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6401310351)), follow ICU 78.1 [uset.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uset.cpp) and [uniset.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uniset.cpp): code points are pinned to 0..10FFFF before adding, ranges merge, and `uset_getItem` checks a negative index before the set. Sets hold no strings, because no export here adds one (`uset_openPattern` is not implemented). Allocation failure throws instead of making the set bogus. Null or foreign sets, outputs and error pointers throw where ICU dereferences them. Closes when: compared with the console.
- [Enumeration dispatch](../../../core/libs/prx/libSceIcu/Enumeration.cpp) is unverified on a console. `uenum_close`, `uenum_count`, `uenum_next` and `uenum_unext`, which firmware 13.42 exports ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6401310351)), follow ICU 78.1 [uenum.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uenum.cpp) over the 56-byte `UEnumeration` of [uenumimp.h](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uenumimp.h), calling its callbacks with the guest ABI. `uprv_free` is the guest `free`, as ICU's default allocator is `free` and 13.42 exports no `u_setMemoryFunctions`. No export here creates an enumeration yet. A null status with a nonnull enumeration throws where ICU dereferences it. Closes when: compared with the console.
- [Character iterators](../../../core/libs/prx/libSceIcu/Iterator.cpp) are unverified on a console. `uiter_setString` and `uiter_setUTF8`, which firmware 13.42 exports ([#11013](https://github.com/boykopovar/AnyPS5/pull/11013#issuecomment-6401310351)), fill the 112-byte `UCharIterator` with guest-ABI callbacks ported from ICU 78.1 [uiter.cpp](https://github.com/unicode-org/icu/blob/release-78.1/icu4c/source/common/uiter.cpp), including its lazy UTF-8 index, split supplementary characters, packed UTF-8 state, wrapping index arithmetic and its forward-move quirk that overwrites a just-known index. Ill-formed UTF-8 decodes to U+FFFD per maximal subpart as `U8_NEXT_OR_FFFD` and `U8_PREV_OR_FFFD` do. Callbacks given a null iterator, and the no-op `setState` given a null error pointer, throw where ICU dereferences them. Closes when: compared with the console.
