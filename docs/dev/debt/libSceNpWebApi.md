# libSceNpWebApi technical debt

### Unknown function info

- [sceNpWebApiInitialize, sceNpWebApiTerminate, sceNpWebApiCreateHandle, sceNpWebApiDeleteHandle, sceNpWebApiCreatePushEventFilter, sceNpWebApiDeletePushEventFilter](../../../core/libs/prx/libSceNpWebApi/Export.cpp) (libSceNpWebApi, PS4) - signatures, id ranges (library contexts 1 to 0x7fff, handles and filters below 0xf0000000) and errors (`LIB_CONTEXT_NOT_FOUND`, `HANDLE_NOT_FOUND`, `PUSH_EVENT_FILTER_NOT_FOUND`, `INVALID_ARGUMENT` for a missing filter parameter) follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/np/np_web_api/np_web_api_internal.cpp); they are not checked on a console. The libHttp context and pool size are kept but not used, since no request is ever sent. Limbo (CUSA01664) creates a context, a handle and filters when its game starts.
- [sceNpWebApiCreateServicePushEventFilter](../../../core/libs/prx/libSceNpWebApi/Export.cpp) (libSceNpWebApi, PS4) - a filter for a PSN service needs the signed-in user, and no user is signed in to PSN, so a valid call returns `SIGNED_IN_USER_NOT_FOUND` after the context and handle checks, as shadPS4 does with its network disabled. `sceNpWebApiDeleteServicePushEventFilter` therefore never finds a filter.
- [sceNpWebApiCreateContext, sceNpWebApiDeleteContext, sceNpWebApiCreateRequest, sceNpWebApiDeleteRequest, sceNpWebApiAbortRequest, sceNpWebApiSendRequest](../../../core/libs/prx/libSceNpWebApi/Export.cpp) (libSceNpWebApi, PS4) - the online id is not looked up: as in [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/main/src/core/libraries/np/np_web_api/np_web_api_internal.cpp), a user context belongs to the initial user, so a library context holds at most one. No user is signed in to PSN, so `sceNpWebApiSendRequest` returns `NOT_SIGNED_IN` for a request that is not aborted, as shadPS4 does with its network disabled. Id layouts (`libCtxId << 16 | counter` for user contexts, `userCtxId << 32 | counter` for requests), check order and errors follow shadPS4, including `INVALID_ARGUMENT` for a method after DELETE from SDK 2.50; none is checked on a console. `sceNpWebApiTerminate` also deletes the user contexts and requests; shadPS4 returns after deleting the first user context.
- [sceNpWebApiRegisterPushEventCallback, sceNpWebApiUnregisterPushEventCallback, sceNpWebApiRegisterServicePushEventCallback, sceNpWebApiUnregisterServicePushEventCallback](../../../core/libs/prx/libSceNpWebApi/Export.cpp) (libSceNpWebApi, PS4) - registered callbacks are never called, since no push event arrives. A null function is rejected from SDK 1.00 and the filter must exist in the library context from SDK 2.50, as in shadPS4; this is not checked on a console. No service filter can be created, so from SDK 2.50 a service callback returns `SERVICE_PUSH_EVENT_FILTER_NOT_FOUND`. Callback ids come from the counter of handles and filters.
- [sceNpWebApiCreateContextA, sceNpWebApiGetMemoryPoolStats, sceNpWebApiCreateExtdPushEventFilter, sceNpWebApiDeleteExtdPushEventFilter, sceNpWebApiRegisterExtdPushEventCallbackA, sceNpWebApiUnregisterExtdPushEventCallback](../../../core/libs/prx/libSceNpWebApi/Export.cpp) (libSceNpWebApi, PS4) - `sceNpWebApiGetMemoryPoolStats` reports no pool memory in use where a PS4 Pro (firmware 10.71) reports 1920 bytes right after `sceNpWebApiInitialize`; `sceNpWebApiCreateContextA` accepts only the initial user, a second signed-in user is not measured, and an unknown library context answers `INVALID_LIB_CONTEXT_ID` because only -1 was measured; a null callback is not checked; the names of 0x8055291C and 0x8055291D are guesses for measured values. Without a PSN sign-in no extended filter exists, so the register, unregister and delete calls answer not found, as the console does offline.
