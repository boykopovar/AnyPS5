- [libSceAudiodecCpu codecs](../../../core/libs/prx/libSceAudiodecCpu/Export.cpp) - Argument checks and LPCM decode follow firmware 13.60 disassembly, unverified on console. Only 16- and 24-bit Blu-ray stereo LPCM decodes. These throw through `NotImplemented_nid_no_patch`: non-LPCM codecs (separate modules), DVD LPCM, non-stereo layouts (channel tables not recovered), frames larger than the 0x43800-byte input buffer, an AU shorter than its frame or a PCM buffer smaller than the output (the module copies without checking), and `InitDecoder` without AU or PCM. Header byte 7 (frame count) and 33-bit timestamp continuation in the param are inferred. The type mask when `sceKernelIsCronos` returns non-zero is not modelled.

- [libSceAudiodecCpu output wrap](../../../core/libs/prx/libSceAudiodecCpu/Export.cpp) - When a stereo Blu-ray frame decodes to more than the module's 0x43800-byte output buffer (69,120 floats), firmware 13.42 still reports success: it writes the full decoded byte count and reports it in `ui_pcm_size` and the BSI info, but every sample from 69,120 on repeats the sample 69,120 earlier instead of decoding the later input. Measured on the decrypted 13.42 modules for 145 to 255 frames at 48 kHz 16-bit (BunnyFl in the PR 10042 comments); 17 decodes matched on return value, sizes, BSI info and timestamp state and differed only in the wrapped samples. Applied per sample for every stereo rate and width; only 48 kHz 16-bit is measured, and a second wrap is unreachable because the input cap bounds the decoded output at 138,240 samples. The full write reaches only buffers the PCM-buffer refusal has sized for the whole decode
