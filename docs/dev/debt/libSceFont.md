Uninterpreted descriptor tails remain reserved; pool statistics expose capacity, current usage, available bytes, peak and signed change.

The [glyph support registration and drawup texture signatures](../../../core/libs/prx/libSceFont/src/Unimplemented.cpp) are recovered from native argument use. The drawup texture producers consume an opaque fill-object pointer, a mode, an output pointer and four rectangle floats (the pattern variant takes nine integer parameters instead of the rectangle); they are implemented in Graphics.cpp to the verified 4.03 bodies. `CreateWords` and `CreateGraphicsServiceWithEdition` consume the output pointer in the fourth general-purpose argument slot but do not read the third slot, whose source type is not established.

- [sceFontCreateGraphicsServiceWithEdition and sceFontCreateWords](../../../core/libs/prx/libSceFont/src/Unimplemented.cpp) take their handle output in the fourth integer argument slot. The third slot is not read by the supplied module and is represented as an opaque 64-bit value; its declared source type remains unknown.
- [Word dictionaries](../../../core/libs/prx/libSceFont/src/Words.cpp): building, depth limit, sort and error rules and longest-match selection are read from disassembly, not measured on a console. The text source is parsed once instead of twice. More than 65535 nodes return `SCE_FONT_ERROR_FUNCTIONAL_LIMIT`, where the native 16-bit indices would wrap. The shape-entry test on the next character is skipped since strings built here have no shape entry. The low flag byte and flag bits 43-45 are tested as read; strings built here leave them clear, so names are ours.
- [Font writing steps](../../../core/libs/prx/libSceFont/src/Text.cpp) (libSceFont) - every supported writing form (`0x10`, `0x11`, `0x12`) is horizontal, so a writing step's `advanceY` and the pen's vertical movement are zero and the step's `GlyphMetrics` keep the glyph's own width and height. This follows steps measured on PS4 11.00 firmware ("Ab c": `y` stays 0, `advanceY` is 0 on every step), not shadPS4's `FillWritingMetricsFromGlyph`, which copies the vertical advance. The drift came from advancing the pen by the vertical advance, not from the value of that advance: it stays reported by `sceFontGetCharGlyphMetrics` and its FreeType source is still unconfirmed on a title (see the metrics entry above). The step's width/height are not measured on the PS4 firmware; they keep the glyph's values.
