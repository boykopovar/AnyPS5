### Functional

- [NeoMode-only imports](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - the 19 imports inFAMOUS Second Son asks of `libSceGnmDriver` that only `libSceGnmDriverForNeoMode` exported are now exported here too: `sceGnmSetEmbeddedPsShader` and `sceGnmSetEmbeddedVsShader` reuse the same embedded shader producers, and the other 17 throw `NotImplemented_nid_no_patch` until their console behavior is measured (#17581).
- [Packet types](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - on the PS4 Gnm path a type-0 packet (a register write by base index and count) or a type-1 packet in a draw or constant command buffer throws with its type, header and dword position; neither is applied, because no title has shown what a type-0 payload carries here, and the AGC driver (PM4 type-0 packets in [libSceAgcDriver.md](libSceAgcDriver.md)) rejects them too. Seen in CUSA04865, which produces a header dword of 1 itself: its compute dispatch, through a 16-byte V# over an 8-byte `allocateFromCommandBuffer` block, stores 1 over the next packet's header after the title has rebuilt the buffer for the next frame, while the queue trails the title by several milliseconds; the message gives the header and position only, since a dword of 1 is also a valid type-0 write in general, and `APS5_GNM_SUBMIT_WAIT_IDLE=1` (Submission pacing, below) keeps the queue ahead of it.
- [Submission pacing](../../../core/libs/prx/libSceGnmDriver/Export.cpp) (libSceGnmDriver, PS4) - a submission is queued without waiting for earlier ones, so the GPU can trail the title by several milliseconds, far more than the console's command processor. A title that reuses command buffer memory or descriptor tables a frame later then races with work that has not run yet: CUSA04865 loses packet headers and binds descriptors from rebuilt tables. `APS5_GNM_SUBMIT_WAIT_IDLE=1` waits for all queued work before each `sceGnmSubmitCommandBuffers` and `sceGnmSubmitAndFlipCommandBuffers` that follows an earlier one, across `sceGnmSubmitDone` as well, so the GPU trails the title by at most one submission, which removes these races there; it is off by default because a submission whose packets wait on a label the title writes only after a later submission would never finish. The wait holds the submission lock, so a label written by another thread after it takes that lock hangs the same way.
