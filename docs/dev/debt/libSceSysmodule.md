- [sceSysmoduleLoadModuleByNameInternal](../../../core/libs/prx/libSceSysmodule/Export.cpp) (libSceSysmodule) - verified against firmware 4.03's `libSceSysmodule.sprx`: a null `fname` returns `SCE_KERNEL_ERROR_EINVAL`, otherwise the export formats `/<root>/<tier>/lib/<fname>.<ext>` and tries `sceKernelLoadStartModuleForSysmodule` on each candidate in order, returning the first positive result or the last error. The candidate roots are the `sceKernelGetFsSandboxRandomWord` prefix and the literals `system_ex` and `system`, the tiers are `priv_ex`, `common_ex`, `priv` and `common`, and the `.sprx` search precedes `.prx`. The caller's `args`, `argp`, `flags` and `res` forward to the loader; the option pointer stays null. Firmware's `sceKernelLoadStartModuleForSysmodule` ORs `0x10000` into the flags and bypasses the `sceKernelLoadStartModule` flags-must-be-zero gate, so a nonzero `flags` is accepted on console but rejected here, where the host loader has no flag semantics. On the host only `/<sandbox>/common/lib/` and `/system/common/lib/` translate to `libs/<name>.prx`; the other candidates fail to open and are skipped, which matches the console's missing-path fallthrough.
