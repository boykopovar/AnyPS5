# libSceImeDialog technical debt

### Silent stubs

- [sceImeDialogInit](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) draws a keyboard over each flipped frame ([KeyboardOverlay](../../../core/libs/prx/libSceAgcDriver/Execution/src/KeyboardOverlay.cpp)) that the first controller drives with [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/30f4170896ce974353a6f6486d0ecec179aec54b/src/core/libraries/ime/ime_kb_layout.cpp)'s bindings, and [ImeTextInput](../../../core/libs/prx/libSceVideoOut/src/ImeTextInput.cpp) forwards host keyboard typing from the game window while no IME panel is open. Text, Backspace, Delete, Left, Right, Home and End edit the text, Enter, R2 or Done accepts it (end status 0) and Escape or Circle cancels (end status 1). The title, placeholder and type are not shown or applied, and line breaks cannot be typed. While the dialog runs, key presses do not reach the keyboard-to-pad bindings of [PadInput](../../../core/libs/prx/libSceVideoOut/src/PadInput.cpp)

- [sceImeDialogGetPanelSize, sceImeDialogGetPanelSizeExtended](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - both report 1920 by 1080 for every input and take a null parameter as success. That size is an assumption that no console run has checked: [GuestImeDialog.cpp](../../../core/libs/tests/GuestImeDialog.cpp) pins it and commit af3c2024ed names no measurement. KytyPS5 (PS5, `src/libs/imeDialog.cpp`, commit 5e837a9beac82c031868eaad9348d6a48245fb99) and shadPS4 (PS4, `src/core/libraries/ime/ime_dialog.cpp`, commit 0614ce324be092791b758d79f93d9f1ca5b10a81) compute the size from the type and options instead, 793 by 528 for a one-line BasicLatin panel, in shadPS4 for an SDK above 0x16fffff, and shadPS4 gives 1920 by 1080 only with `ENABLE_ACCESSIBILITY`. fpPS4 (PS4, commit 04cefd43e6fddd1ab033e7980cd356d14c964905) has no such function. Which value is right is not decided. Twenty-two of the 53 local titles import `sceImeDialogGetPanelSizeExtended`.
- [sceImeDialogGetCurrentStarState, sceImeDialogInitInternal, sceImeDialogSetPanelPosition](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - not measured on a console; signatures and checks follow [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/a808e76/src/core/libraries/ime/ime_dialog.cpp). `sceImeDialogInitInternal` runs `sceImeDialogInit`, as shadPS4's two share one path apart from user flags this library does not keep. There is no movable panel, so `sceImeDialogSetPanelPosition` never succeeds: `DIALOG_NOT_IN_USE` without a dialog and `IME_SUSPENDING` while one is running or finished, the states in which shadPS4 refuses it too. The star state is always 0

### Functional

- [sceImeDialogGetPanelPositionAndForm](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - returning `0x80bc0002` (`ErrorNotOpened`) when the `form` pointer is unwritable via `GuestCopyOut_nid_no_patch` is a host-safety fallback preserving host errno; console behavior on unmapped pointers is not measured.

- [sceImeDialogInit, sceImeDialogGetResult](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - a param, extended param or input text buffer the host cannot read makes `sceImeDialogInit` return `0x80bc0031` or `0x80bc0017` and open no dialog; `0x80bc0031` is the code the library already returns for a null param. An output buffer the host cannot write ends the dialog with end status 2 (aborted) when Done, R2 or Enter accepts it, and nothing is written. Not measured on a PS5; the error codes and the buffer size are a host-safety choice. Closes when: measured on a PS5

- [Text written on Done](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - the typed text reaches the title's buffer once, when Done, R2 or Enter accepts it. [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/30f4170896ce974353a6f6486d0ecec179aec54b/src/core/libraries/ime/ime_dialog_ui.cpp#L1310-L1313) (PS4) writes it after every edit, and calls the title's text filter from `sceImeDialogGetStatus` while the dialog runs ([ime_dialog.cpp](https://github.com/shadps4-emu/shadPS4/blob/30f4170896ce974353a6f6486d0ecec179aec54b/src/core/libraries/ime/ime_dialog.cpp#L964-L966)) and again before the result. This library never calls the filter. A title that reads its buffer or relies on the filter while typing sees neither. Closes when: measured on a PS5
- [Keyboard redraw](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - the keyboard is drawn into the frames the title flips, from the dialog's state at each flip ([VideoOutDriver](../../../core/libs/prx/libSceVideoOut/src/VideoOutDriver.cpp)). A title that stops flipping while the dialog runs shows the last keyboard it flipped, and typing changes nothing on screen until it flips again. Closes when: a title is seen to wait on the dialog without flipping
- [Held-button repeat](../../../core/libs/prx/libSceImeDialog/src/PadKeyboard.cpp) (libSceImeDialog) - held Cross (on a character, Space, Backspace or arrow key), D-pad, Square, L1 and R1 repeat after 0.275 s and then every 0.050 s, Dear ImGui's `ImGuiIO` defaults `KeyRepeatDelay` and `KeyRepeatRate`, which [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/30f4170896ce974353a6f6486d0ecec179aec54b/src/core/libraries/ime/ime_ui_shared.cpp#L756-L757) (PS4) reads. The left stick repeats on shadPS4's own tilt-scaled timings. None of these is measured on a PS5. Closes when: measured on a PS5
- [Keyboard extras](../../../core/libs/prx/libSceImeDialog/src/PadKeyboard.cpp) (libSceImeDialog) - the language switch, `...` menu and R3 settings keys of [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/30f4170896ce974353a6f6486d0ecec179aec54b/src/core/libraries/ime/ime_kb_layout.cpp#L490-L492) (PS4) are left as empty cells, and there is no R3 control mode, no right-stick panel drag, no prediction pane, no top close panel ([kTopPanelDefaultElements](https://github.com/shadps4-emu/shadPS4/blob/30f4170896ce974353a6f6486d0ecec179aec54b/src/core/libraries/ime/ime_kb_layout.cpp#L966-L969)) and no copy or paste. Glyphs outside the pages, such as CJK text, are drawn as a box
- [sceImeDialogInit](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) shows a host composition at the caret in the keyboard text field, underlined with the selected part underlined twice, and keeps it out of the buffer the title reads. The overlay font has no CJK glyphs, so a composition and committed CJK text draw as the replacement box, which shows the length but not the characters. Closes when: the overlay gets a font with CJK coverage
- [sceImeDialogGetPanelPositionAndForm, sceImeDialogGetPanelSize](../../../core/libs/prx/libSceImeDialog/Export.cpp) (libSceImeDialog) - a null or unmapped form, width or height pointer returns `0x80bc0031` without writing; GetPanelSize probes both outputs by reading them before any write and restores the saved width if the height write fails. A form region spanning an unmapped boundary may be written partially: process_vm_writev gives no atomicity for the 28-byte copy. GetPanelPositionAndForm takes the dialog mutex and returns `0x80bc0002` for StatusNone, treating Running or Finished as open like [sceImeGetPanelPositionAndForm](../../../core/libs/prx/libSceIme/Export.cpp) while its session persists; neither fallback is measured on a PS5. Closes when: measured on a PS5
