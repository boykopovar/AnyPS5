# libSceJobManager technical debt

### Functional

- [sce::Job::JobManager](../../../core/libs/prx/libSceJobManager/Export.cpp) submits commands as work becomes runnable rather than encoding ahead with the rewind protocol recovered from PPSA06888's module (offsets 0x2210 and 0x2650). Commands are recycled after a completed wait. Command capacity is a separate bound from the dispatch count: the native size query measures one register and a 31-character marker, then its exhaustion callback at 0x29d0 traps instead of growing storage. The fallback throws. Original-module execution with the host AGC builders accepts two dispatches with 255 registers and 65,535-character markers, then traps on a third. Console timing equivalence remains unverified.
- [JobManager scheduling state](../../../core/libs/prx/libSceJobManager/Export.cpp) and nodes live on the host heap; only the header, compute commands and completion labels occupy the caller's block. Blocks smaller than 0x2d8 bytes throw. Worker spin and persistent-thread settings do not affect scheduling. A compute dispatch on a CPU sequence, a failing `sceAgcDriverAddEqEvent`, factory priorities above one and use after sequence destruction throw. Shutdown throws while a compute sequence has work in flight or a caller is blocked in a sequence wait. Worker creation and attribute failures throw where the original does not check.
- The [manager](../../../core/libs/prx/libSceJobManager/Export.cpp) omits the `sceRazorCpuJobManager*` profiler calls. Sequence and factory vtable order has been checked against original modules, but no calling title or PS5 timing equivalence has been tested.
