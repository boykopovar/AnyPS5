### Functional

- [notification variants](../../../core/libs/prx/libSceSysUtil/Export.cpp) (libSceSysUtil) - supplied `/system/common/lib/libSceSysUtil.sprx` SHA-256: `b0f5e18443cdcb3c35d3ddf688a813adbfd67af5c36ddce05c236e8de4e3e491`; firmware version unknown. Disassembly confirms request kinds 1-10 and 12-17 and the generic kind 0 request. Tests verify structured requests reach the host kernel and receive `SCE_KERNEL_ERROR_ENOTSUP`, while kind 0 is delivered by the host text handler. Structured delivery and console rendering remain unverified. String inputs use guest-safe copying and firmware limits; unreadable pointers return `SCE_KERNEL_ERROR_EFAULT` with `errno` preserved.
- [conditional debug notification requests](../../../core/libs/prx/libSceSysUtil/Export.cpp) (libSceSysUtil) - `sceSysUtilSendTrcCheckNotificationRequest` and `sceSysUtilSendNpDebugNotificationRequest` use registry key `0x0d49671adfd5eb34`; `sceSysUtilSendWebDebugNotificationRequest` uses `0x1c0b63438bdc7b40`. The PRX sends only when the key reads as `1`, otherwise returns `0`. It builds kinds `0x65`, `0x66` and `0x67`, passes flags to the kernel and copies at most 1023 message bytes. Tests cover disabled and enabled settings and unreadable enabled message pointers. The host kernel currently returns `SCE_KERNEL_ERROR_ENOTSUP` for these kinds.
- [sceSysUtilSendSystemNotificationParamInit](../../../core/libs/prx/libSceSysUtil/Export.cpp) (libSceSysUtil) - initializes a 0xa40-byte parameter structure, stores the supplied type, writes type-dependent sentinels for types 0 through 8 and sets tag `0xd59c4b6e` at +0xa38. Other type values still receive the tag without special fields, and null is a no-op, matching the supplied PRX. Tests verify type 3's sentinels and tag, null handling and an out-of-range type.
- [sceSysUtilSendSystemNotification2](../../../core/libs/prx/libSceSysUtil/Export.cpp) (libSceSysUtil) - validates the parameter initializer tag and dispatches types 0 through 13 to recovered request kinds and payload fields. Null, bad-tag and out-of-range parameters return `0x81670000`; unreadable host memory returns `SCE_KERNEL_ERROR_EFAULT`. Tests cover all type branches. The host kernel returns `SCE_KERNEL_ERROR_ENOTSUP` for structured kinds; type 4 sends kind 5, which the host renders as text.
- [sceSysUtilSendSystemNotificationWithText](../../../core/libs/prx/libSceSysUtil/Export.cpp) (libSceSysUtil) - follows @BunnyFl's [firmware 13.42 run](https://github.com/boykopovar/AnyPS5/pull/9081#issuecomment-6418015178) under an emulator with `sceKernelSendNotificationRequest` stubbed, not on console. Builds a 0xc30-byte request with kind 5 in the first dword, `type` at +0xc and the message at +0x2d, cut to 179 characters and empty for null, returning what `sceKernelSendNotificationRequest(0, request, 0xc30, 0)` returns. Unit tests cover notification delivery across types (-1, 0, 1, 2, 7) and valid, empty, null, or unreadable message text. An unreadable message pointer returns `SCE_KERNEL_ERROR_EFAULT` (`0x8002000e`) as a host-safety fallback; console invalid-pointer behaviour was not measured. Other request bytes were not reported and are zero. Lacking system UI, text goes to standard error; console display per `type` is unverified.
