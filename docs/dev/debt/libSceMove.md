# libSceMove technical debt

### Functional

- [libSceMove](../../../core/libs/prx/libSceMove/Export.cpp): the host implements only disconnected controllers. The native module confirms initialization errors, disconnected return 1 without output writes, invalid-handle error 0x80EE0004, and initialization then argument then handle validation for queries. Reset-light-sphere still omits the device ioctl and its failure mapping.
- [sceMoveOpen and sceMoveClose](../../../core/libs/prx/libSceMove/Export.cpp): native opening resolves a user/device through the input service, rejects duplicate device handles with 0x80EE0007, limits storage to eight slots with 0x80EE0005, and obtains handles from the device ioctl. The host generates monotonically increasing handles, accepts arbitrary type/index values, enforces the eight-slot capacity with 0x80EE0005, returns 0x80EE0007 for duplicate slots, and throws for other users. Closing an unknown handle returns the confirmed 0x80EE0004.
- [sceMoveReadStateRecent](../../../core/libs/prx/libSceMove/Export.cpp): a null data array is accepted for SDK versions through 0x03ffffff and rejected from 0x04000000 on, as the native module does; the count pointer and a nonnegative timestamp are required for every version. Connected state records and device-service failures remain unimplemented.
- [sceMoveIsReproductionModel, sceMoveReadStateRecentForTracker, sceMoveSetExtensionPortOutput, sceMoveSetLightSphereForTracker, sceMoveWriteCalibrationInfo](../../../core/libs/prx/libSceMove/Export.cpp): in 13.42 module disassembly (sha256 f528763dd75ee1124b5ae0d8a7d9bd13e6642f964818724877cfbee710ac1851), the initialization flag byte (0x10018) is checked first: these exports return 0x80EE0001 before argument/handle checks. Console runtime behavior is not measured, and initialized paths remain unimplemented placeholders throwing NotImplemented_nid_no_patch.
- [sceMoveGetBluetoothAddress, sceMoveGetCalibrationInfo and sceMoveGetDeviceId](../../../core/libs/prx/libSceMove/Export.cpp): for an open handle they throw; the console then reads the Bluetooth address through a device ioctl, or copies the calibration block or device id stored for the device, none of which the host has. Their errors follow the 13.42 module: 0x80EE0001 before initialization, then 0x80EE0003 for a null output pointer, then 0x80EE0004 for a handle that is not open. Read from the module's disassembly, not measured on a console.
