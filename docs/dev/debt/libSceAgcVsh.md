# libSceAgcVsh technical debt

### Unknown function info

- [sceAgcAcbAtomicGds, sceAgcSuspendPointAndCheckStatus](../../../core/libs/prx/libSceAgcVsh/Export.cpp) - kept as `NotImplemented_nid_no_patch` stubs. In the firmware 4.03 `libSceAgcVsh.sprx` both bodies are the module's reporter trap (call report, `int 0x41`, return 0, 0x2b bytes): `sceAgcAcbAtomicGds` has a real implementation in `libSceAgc` that the Vsh module deliberately disables, and `sceAgcSuspendPointAndCheckStatus` has no verified signature anywhere (same convention as [libSceAgc](libSceAgc.md)).
- 22 more exports whose firmware Vsh bodies are the same reporter trap (`sceAgcAcbCopyData`, `sceAgcAcbAcquireMem`, `sceAgcAcbAtomicMem`, `sceAgcAcbResetQueue`, `sceAgcAcbSetFlip`, `sceAgcAcbWaitRegMem`, `sceAgcDcbResetQueue`, `sceAgcDcbSetFlip`, `sceAgcDcbWaitUntilSafeForRendering`, `sceAgcSuspendPoint`, `sceAgcGetRegisterDefaults`, `sceAgcGetRegisterDefaultsInternal`, among others) are wired to the shared `libSceAgc` implementations here. The console traps when they are called through this module; the implementation files define them together with exports the module does serve, so the working bodies are linked instead. No title can depend on the trap (it kills the process on a retail console), so the divergence can only make calls that would fault on console succeed.
- 3 firmware exports have real bodies but no resolved name or host implementation: NIDs `Aozdh0bCcO0` (0x383 bytes at 0x20c0), `MGEQMJBhdtc` (0x99 at 0x5190) and `ddU6mOWyY40` (0x99 at 0x50f0). Two further trapped exports, `Xvcgh9xNNkY` and `rPtseVo5ToI`, are likewise unnamed. They are absent from the 3.20 export inventory the stub list was generated from, and from aerolib.
- The remaining 9 uncovered firmware symbols have no body (`va=0`): sub-library `#C#A` markers and absolute/data symbols, not callable functions.
- Of the 150 declared stubs the module carried, 118 were verified byte- or instruction-identical to their `libSceAgc` siblings before wiring (95 byte-identical, 23 differing only in relocation displacements and module-relative call targets) and 8 size-different bodies were decoded to the same contract; `sceAgcGetFusedShaderSize` (NID `nQT5kYLv0cg`, also exported by `libSceAgc`) was transliterated from the Vsh body: it validates a GsFront/GsBack or HsFront/HsBack half pair and returns `back->num_sh_registers * 8` bytes aligned to 4, or `0x8a6c0008` on a mismatched pair.
