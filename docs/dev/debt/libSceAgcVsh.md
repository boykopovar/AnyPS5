- 23 more exports whose firmware Vsh bodies are the same reporter trap (`sceAgcAcbAtomicGds`, `sceAgcAcbCopyData`, `sceAgcAcbAcquireMem`, `sceAgcAcbAtomicMem`, `sceAgcAcbResetQueue`, `sceAgcAcbSetFlip`, `sceAgcAcbWaitRegMem`, `sceAgcDcbResetQueue`, `sceAgcDcbSetFlip`, `sceAgcDcbWaitUntilSafeForRendering`, `sceAgcSuspendPoint`, `sceAgcGetRegisterDefaults`, `sceAgcGetRegisterDefaultsInternal`, among others) are wired to the shared `libSceAgc` implementations through the [module source list](../../../core/libs/prx/libSceAgcVsh/CMakeLists.txt). The console traps when they are called through this module; the implementation files define them together with exports the module does serve, so the working bodies are linked instead. No title can depend on the trap (it kills the process on a retail console), so the divergence can only make calls that would fault on console succeed.
- The built [module](../../../core/libs/prx/libSceAgcVsh/CMakeLists.txt) exports 300 named symbols against the 225 entries in the firmware module's export table: whole implementation files also re-export every sibling function they define, so roughly 75 extra NIDs resolve from `libSceAgcVsh` here that the console module does not serve. Import resolution binds `(module, library, NID)`, so the surplus can only satisfy an import firmware would reject; it cannot shadow a correct binding or reach a title that never imports it.

- The remaining 9 firmware symbols uncovered by the [module exports](../../../core/libs/prx/libSceAgcVsh/Export.cpp) have no body (`va=0`): sub-library `#C#A` markers and absolute/data symbols, not callable functions.
- Of the 150 declared [stubs](../../../core/libs/prx/libSceAgcVsh/Export.cpp) the module carried, 118 were verified byte- or instruction-identical to their `libSceAgc` siblings before wiring (95 byte-identical, 23 differing only in relocation displacements and module-relative call targets) and 8 size-different bodies were decoded to the same contract. The comparison ran against `libSceAgcVsh.sprx` from firmware 4.03 (SHA-256 `39791e6bd469e81c42afed5a4264ef1eb7c8ecee30aa8d2921dfaa111ea93302`): the SCE dynlib export table was enumerated per export and each body compared with the same NID's body in `libSceAgc.sprx`. `sceAgcGetFusedShaderSize` (NID `nQT5kYLv0cg`, also exported by `libSceAgc`) was transliterated from the Vsh body: it validates a GsFront/GsBack or HsFront/HsBack half pair and returns `back->num_sh_registers * 8` bytes aligned to 4, or `0x8a6c0008` on a mismatched pair. Unlike `sceAgcGetFusedShaderSize_0080`, which returns the merged geometry layout size for a GsFront/GsBack pair, the unversioned body has no geometry path and reads only the back half's register count — verbatim firmware behaviour (the 0x6b90 body branches only on the half types); the fused-size test pins it by leaving the size unchanged when the front half's register list grows.
