# libSceAgcVsh technical debt

### Unknown function info

- [sceAgcSuspendPointAndCheckStatus](../../../core/libs/prx/libSceAgcVsh/Export.cpp) - kept as a `NotImplemented_nid_no_patch` stub. In the firmware 4.03 `libSceAgcVsh.sprx` its body is the module's reporter trap (call report, `int 0x41`, return 0, 0x2b bytes), and it has no verified signature anywhere (same convention as [libSceAgc](libSceAgc.md)).
- 23 more exports whose firmware Vsh bodies are the same reporter trap (`sceAgcAcbAtomicGds`, `sceAgcAcbCopyData`, `sceAgcAcbAcquireMem`, `sceAgcAcbAtomicMem`, `sceAgcAcbResetQueue`, `sceAgcAcbSetFlip`, `sceAgcAcbWaitRegMem`, `sceAgcDcbResetQueue`, `sceAgcDcbSetFlip`, `sceAgcDcbWaitUntilSafeForRendering`, `sceAgcSuspendPoint`, `sceAgcGetRegisterDefaults`, `sceAgcGetRegisterDefaultsInternal`, among others) are wired to the shared `libSceAgc` implementations through the [module source list](../../../core/libs/prx/libSceAgcVsh/CMakeLists.txt). The console traps when they are called through this module; the implementation files define them together with exports the module does serve, so the working bodies are linked instead. No title can depend on the trap (it kills the process on a retail console), so the divergence can only make calls that would fault on console succeed.
- The built [module](../../../core/libs/prx/libSceAgcVsh/CMakeLists.txt) exports 300 named symbols against the 225 entries in the firmware module's export table: whole implementation files also re-export every sibling function they define, so roughly 75 extra NIDs resolve from `libSceAgcVsh` here that the console module does not serve. Import resolution binds `(module, library, NID)`, so the surplus can only satisfy an import firmware would reject; it cannot shadow a correct binding or reach a title that never imports it.
- `Aozdh0bCcO0` is implemented as [sceAgcVshUnknown_Aozdh0bCcO0](../../../core/libs/prx/libSceAgcVsh/Export.cpp) after the 4.03 firmware body (0x383 bytes at `va=0x20c0`, present only in `libSceAgcVsh.sprx`; `libSceAgc.sprx` has no such NID): a best-effort writer that reserves 39 dwords through `buffer->callback(buffer, reserved_dw + need, user_data)` and emits a fixed seven-packet stream (headers `0xc0032200`, `0xc0001200`, `0xc0033700`, `0xc0044000`x3, `0xc0071e00`) at the 4-aligned `cursor_up`, returns the first packet pointer, returns null on a null buffer or a failed first reserve, and independently skips each later packet whose own reserve fails. The firmware body invokes the grow callback with no null check and writes no NOP padding; the stream payload is fixed firmware data (Vsh-specific GPU state, not decoded beyond the header opcodes) so the true name is unknown.
- Two firmware exports with real bodies still have no resolved name or [host wiring](../../../core/libs/prx/libSceAgcVsh/Export.cpp): NIDs `MGEQMJBhdtc` (0x99 bytes at `va=0x5190`) and `ddU6mOWyY40` (0x99 at `va=0x50f0`). Both are jump-table dispatchers on `edi` (8 cases, selector `> 7` falls through to a default tail-call) whose cases test a module global `& ~0x1f == 0x840f00` (an SDK-version gate) and tail-jump to one of two internal bodies; `libSceAgc.sprx` exports the same two NIDs at `va=0x8670`/`0x8730` as 9-case variants against a different version global. Naming the 15+ reachable bodies per module is required before either can be wired.
- Two further firmware exports remain [unwired](../../../core/libs/prx/libSceAgcVsh/Export.cpp) and unnamed: `Xvcgh9xNNkY` (reporter-trap body in Vsh; `libSceAgc.sprx` serves a real body at `va=0x5280`) and `rPtseVo5ToI` (reporter-trap in Vsh; resolves by NID hash to `sceAgcAcbInitializeDefaultHardwareState`, which `libSceAgc.sprx` serves at `va=0x940` and [libSceAgc](../../../core/libs/prx/libSceAgc/Unimplemented.cpp) carries as an unimplemented export). All five NIDs are absent from the 3.20 export inventory that generated the [stub list](../../../core/libs/prx/libSceAgcVsh/Export.cpp), and `Aozdh0bCcO0`/`MGEQMJBhdtc`/`ddU6mOWyY40`/`Xvcgh9xNNkY` remain absent from aerolib.
- The remaining firmware symbols uncovered by the [module exports](../../../core/libs/prx/libSceAgcVsh/Export.cpp) have no body (`va=0`): sub-library `#C#A` markers and absolute/data symbols, not callable functions.
- Of the 150 declared [stubs](../../../core/libs/prx/libSceAgcVsh/Export.cpp) the module carried, 118 were verified byte- or instruction-identical to their `libSceAgc` siblings before wiring (95 byte-identical, 23 differing only in relocation displacements and module-relative call targets) and 8 size-different bodies were decoded to the same contract, against `libSceAgcVsh.sprx` from firmware 4.03 (SHA-256 `39791e6bd469e81c42afed5a4264ef1eb7c8ecee30aa8d2921dfaa111ea93302`). `sceAgcGetFusedShaderSize` (NID `nQT5kYLv0cg`) is transliterated from the Vsh body: validate a Gs/Hs front-back half pair and return `back->num_sh_registers * 8` aligned to 4, `0x8a6c0008` on mismatch. Unlike `sceAgcGetFusedShaderSize_0080` it runs no fused-layout validation; both still return the raw back-register count for a GS pair.
