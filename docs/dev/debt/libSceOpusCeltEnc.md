# libSceOpusCeltEnc technical debt

### Unknown function info

- [sceOpusCeltEncCtl, sceOpusCeltMultistreamEncCreate, sceOpusCeltMultistreamEncCtl and sceOpusCeltMultistreamEncCreateEx](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) answer only the checks firmware 13.42 makes before it uses the state, read from disassembly, not measured on a console, and throw through `NotImplemented_nid_no_patch` past them: the two Ctl calls dispatch requests 4000 to 4047 (and -1, or -1 and -2) through tables that were not read, and the multistream create calls need a multistream encoder, which this implementation does not create. The declarations carry only the arguments those checks read, and their names are mine.

### Functional

- [sceOpusCeltEncGetAjmContext](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) returns the 32-bit word at encoder state +0xD4 in the caller's output, as firmware 13.42 disassembly indicates; this is not a console measurement. A null state returns `0x813F0001`, before the null-output fast path; a null output returns 0 without reading the state. The libopus backend does not populate that AJM context word, so a newly created encoder has zero there, while a guest-written value is returned. Checked guest reads and writes preserve `errno`; inaccessible input/output throws as a host-safety fallback rather than claiming a console error code.

- [libSceOpusCeltEnc](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) is an AJM frontend on the console: apart from libc runtime support and `sceKernelUsleep` the module imports only `sceAjmi*` calls, Create runs `sceAjmiInstanceCreate` with codec 15 and the flags 0x200000009 mono or 0x200000011 stereo, `sceAjmiBatchJobControlBufferRa` with request 0x6001 over state +0x10 with size 0x38 and results at state +0xA0, then `sceAjmiBatchStartBuffer` and `sceAjmiBatchWait`, Encode hands the samples to `sceAjmiBatchJobRunBufferRa`, and Destroy calls `sceAjmiInstanceDestroy` [per module runs with stubbed AJM](https://github.com/boykopovar/AnyPS5/pull/10563#issuecomment-6412138282). Our encoders build libopus without AJM, so packets come from libopus and whether they equal the console's is unknown. Closes when: encoder packets are compared against console-produced ones or the library runs through our AJM

- [Create and CreateEx](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) zero-fill the 728-byte state and write the word table [measured on the modules](https://github.com/boykopovar/AnyPS5/pull/10563#issuecomment-6412138282): the instance id at +0x00, this implementation's id because our AJM does not run, 8 × channels at +0x08, channels at +0x10, rate at +0x14 and rate/50 at +0x40 and +0xC8, the bitrate at +0x1C and +0xC0 with the per-rate per-channel table 11000/19000 to 51000/99000, the constants 2, 0x451, 0x5E0, 10, 0x803, 1, 0xFFFFFC18 and 0x10, and the 0x17B2 marker at +0xCC. The console's live AJM may write further result bytes into +0xA0 and +0xD8. Closes when: a console run with live AJM settles those result bytes

- [Create and CreateEx](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) replacement rule is this implementation's choice: a create over a marked state retires the encoder its instance id names before any state write or allocation, so a later failure cannot strand an entry the state no longer names; explicit libopus error branches leave the state zeroed, while make-unique throwing after setupState or a later registry insert throw leaves the filled state without a live encoder. The console behaviour for its own allocation failure after a create over a live state is unmeasured, and the tests cannot force our failure paths because the library is a shared module against libopus, which has no allocator hook, while a process-wide memory limit fails an unknown allocation first. Closes when: a deterministic allocation-failure injection or a console measurement of the failed replace exists

- [Encode and EncodeFloat](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) refuse with the [measured codes](https://github.com/boykopovar/AnyPS5/pull/10563#issuecomment-6412138282): null state +0x01, null samples +0x02 before the state marker, a markerless state +0x16, null data +0x04 before the frame check and maxDataBytes 0 +0x05; maxDataBytes below zero is not refused and reaches our libopus backend, where a rejection throws. Frame sizes outside the durations 2.5, 5, 10, 20, 40 and 60 ms, the measured 120 to 2880 at 48000, give +0x03; we scale the counts by the rate word at +0x14 in 64 bits, so a guest-written word cannot wrap the product, while the module's rule for other rates and its multiplication width are unmeasured. Closes when: the frame rule and the console outcome for a buffer AJM rejects are measured

- [sceOpusCeltEncEncodeFloat](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) checks null state, null samples, frame 0 and the marker, then reserves the converted frame on the stack before its remaining checks; the reservation frame × channels × 4 bytes kills the console module for the [measured frame -1](https://github.com/boykopovar/AnyPS5/pull/10563#issuecomment-6412138282), and our implementation throws once it exceeds 8 MiB instead, so the failure reports. The bound beyond the measured deaths is our host stack model, not a console measurement. Closes when: the console's stack behaviour for such frames is measured

- [Create, CreateEx, Destroy, GetSize, Terminate and Initialize](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) refuse with base 0x813F0000, the null pointer +0x01, the sample rate +0x10, channels +0x0D, application +0x11, the marker in Destroy +0x16 and `Initialize(nullptr)` +0x19, all from the [firmware 13.42 export measurements](https://github.com/boykopovar/AnyPS5/pull/10563#issuecomment-6401539314); Destroy clears the marker and leaves the other bytes, GetSize returns 728 on channels 1 and 2 and refuses other counts with +0x0D. CreateEx context handling, duplicate initialization and termination with live encoders throw as the recovered decoder analogue does. Closes when: those paths are measured on the console

- [sceOpusCeltEncInitialize](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) (libSceOpusCeltEnc, implemented via [OpusEncoderLibrary](../../../core/libs/prx/libSceOpusCeltEnc/include/OpusEncoder.hpp)) - returning `0x813f0019` when `context` is unwritable via `GuestCopyOut_nid_no_patch` is a host-safety fallback with console behavior unmeasured.

- [sceOpusCeltEncEncodeWithPriority and sceOpusCeltEncEncodeFloatWithPriority](../../../core/libs/prx/libSceOpusCeltEnc/Export.cpp) answer only the checks firmware 13.42 makes before it encodes, read from disassembly, not measured on a console; past them they throw through `NotImplemented_nid_no_patch`, and the encoding path with its priority was not read. EncodeWithPriority refuses a null state +0x01, null samples +0x02, null data +0x04, maxDataBytes 0 +0x05, a priority outside 20 to 100 +0x15, a state without the 32-bit marker +0x16, then a frame size whose 32-bit product with 400, 200, 100, 50 or 25 is not the rate word at +0x14 and whose product with 50 is not three times it +0x03. EncodeFloatWithPriority checks the null state, null samples, frame size 0 (+0x03) and the marker, then reserves the converted frame on the stack.
