# libSceFontGs technical debt

### Functional

- [sceFontSelectGraphicsGnm](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - 11 of the 21 handlers, every draw handler among them, throw `sceFontSelectGraphicsGnm_backend_<opcode>` through `NotImplemented_nid_no_patch`, so a service can be created and a render sequence begun and ended, but nothing drawn. Index 0 returns the backend table laid out as in the PS4 10.71 module (0x34040), with a process-global instance slot (0x3ed60) and the enumerate function (0x47c0); other indices return `nullptr`. Ported: 0x47000001 (0x47e0), 0x47000002 (0x5ec0, a bare `ret`), 0x47000005 (0xdf40), 0x4700002d (texture-fill and render paths), 0x4700002e, 0x470000e2, 0x470000ec and 0x470000f0; 0x47000003 and 0x47000004 hold the module's constants. Off-console, the table matched the decrypted module except for its pointers, and the module's enumerate with libSceFont's fill (0x2c5c0) fills the same dispatch slots from both tables. Not checked on a console.

### Not console-verified

- [sceFontSelectGraphicsGnm opcode 0x47000001 shaders](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the nine compiled GCN shaders are not in the tree: init reads `libSceFontGs.sprx`, decrypted from the user's own console, from `ANYPS5_SYSTEM_MODULES` (default `anyps5-modules` beside the executable). It takes the PT_LOAD bytes at 0x341c0-0x3e7a4 and the shader table at 0x3e7a8 (kind, address, size per shader), checks each against a SHA-256 of the PS4 10.71 module, and decodes and uploads them as the module does. A missing file, an encrypted SELF, a non-ELF or another build stops init with a `std::runtime_error` naming the file; other firmware builds are not supported.
- [Gnm init constants](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - module rodata is not copied: rows, vectors, the 1920x1080 projection and the texture spec are values. Registers come from [gfx_7_2_d.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_d.h#L1231-L1790), shifts from [gfx_7_2_sh_mask.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_sh_mask.h#L11174-L12384), enum values from [gfx_7_2_enum.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_enum.h#L38-L1974). Channel selects follow the COMP_SWAP orders of Mesa [ac_translate_colorswap](https://gitlab.freedesktop.org/mesa/mesa/-/blob/482dee68a4bbce675c03e0f9587c13f342a8e999/src/amd/common/ac_formats.c#L565-L625); it lacks one-channel ALT and STD_REV.
- [sceFontGraphicsGnmSurfaceInit](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - Neo mode is not console-measured, and the tiling branch for a macro tile over 1 KiB (0x266bc) throws through `NotImplemented_nid_no_patch`; no accepted tile mode and element size reaches it. Only the paths SurfaceInit can reach are ported: one fragment, one mip level, depth 1, pitch 0, no flags, so helpers 0x22550 and 0x22910 and the fragment, mip, pitch and block-compressed tiling branches are left out. Transliterated from the PS4 10.71 body (offset 0x41e0) with its DataFormat, `Texture::init`, tiling and base-address helpers; it matched that machine code run off-console on about 55 million base and Neo configurations, and the console's own function in base mode on the six test configurations.
- [sceFontSelectGraphicsGnm opcode 0x47000001](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the init handler (0x47e0) is ported with the paths of its call tree that init reaches; the other branches of the shared Gnmx helpers (0xeda0, 0x10760, 0x25e90, 0x27580 and others) throw through `NotImplemented_nid_no_patch`. libSceGnmDriver has no `sceGnmSetVgtControl`, `sceGnmResetVgtControl` or `sceGnmDrawIndirect`, so libSceFontGs writes the PS4 10.71 libSceGnmDriver packets itself, in Neo mode too, where libSceGnmDriverForNeoMode writes other VGT packets. The shader objects stay process-global as in the module, which also reuses a stale fetch-shader state for its pixel shaders; the port keeps that. Off-console, the 0x20000-byte instance, the return value and the shader objects matched the decrypted handler running with libSceGnmDriver's own code, in base and Neo mode, at three bases and on a second init. Not checked on a console.
- [sceFontSelectGraphicsGnm opcode 0x47000005](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the surface texture handler (0xdf40) and its helpers (0x22d40, 0x23060, 0x232a0, 0x22c30, 0x25480, 0x25b10, 0x25430, 0x25ce0) follow the PS4 10.71 bodies, not checked on a console. It sets the base and clears the metadata address of the Gnm texture in the surface copy, builds the 8-dword T# at texture object +0x40, and gives one-channel formats the selects (1, 1, 1, channel) and RG8 (R, R, R, G). Where the macro tile lookup fails, the bank mask uses what the original leaves in `cl` (a popcount or the array mode); SurfaceInit's base setter now does the same. Off-console, it matched the decrypted handler on 3000000 random texture, object and base inputs, base and Neo bits included, and on 200000 textures built by SurfaceInit.
- [sceFontGraphicsGnmSurfaceInit tiling tables](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - `GnmTileModes` and `GnmMacroTileModes` are built from named GB_TILE_MODE/GB_MACROTILE_MODE fields with the shifts of [gfx_7_2_sh_mask.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_sh_mask.h#L4221-L4548) and the values of [gfx_7_2_enum.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_enum.h#L5159-L6224). The Neo ALT_PIPE_CONFIG (bits 27-31, P16 = 0x12) and alt bank fields (bits 8-13) are not in AMD headers; their layout matches RPCSX [tiler.hpp](https://github.com/RPCSX/rpcsx/blob/e8ae1481ab7ba04d5c6bef89dd852aabba2c88ff/rpcsx/gpu/lib/amdgpu-tiler/include/amdgpu/tiler.hpp#L94-L169). Thickness is the micro-tile depth per array mode, and a degraded tile mode is the first Thin or Thick entry of that array mode.
- [sceFontGraphicsGnmSurfaceInit format tables](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - `GnmElementBits` and `GnmComponentCounts` come from the channel widths in each IMG_DATA_FORMAT name of [gfx_7_2_enum.h](https://github.com/torvalds/linux/blob/d48723711bae9b8cdc56719c448ba42fef28cbee/drivers/gpu/drm/amd/include/asic_reg/gca/gfx_7_2_enum.h#L6049-L6113): BC formats are block bits over 16 texels, FMASK formats are their bit count with two components, GB_GR and BG_RG are 16 bits with three. The render-target number type keeps the texture channel type except Srgb 9 to 6 ([GnmConstant.h](https://github.com/Inori/GPCS4/blob/88480de36f983c66f7dd2c5951fead1a740d47a5/GPCS4/Graphics/Gnm/GnmConstant.h#L1760-L1810)).
- [sceFontGraphicsGnmDrawupFillTextureImage, sceFontGraphicsGnmDrawupFillTexturePattern, sceFontGraphicsSequenceGetGnmCommandsForChain and sceFontGraphicsSequenceGetGnmCommandsForSubmit](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - transliterated from the PS4 10.71 `libSceFontGs.sprx` bodies (offsets 0x40a0, 0x4150, 0x4580 and 0x4640; the names hash to `UsBLoyXsQZs`, `uksHKVEsxu4`, `NtbMKwRg6qg` and `DI4LrTUrD04`). They match the `libSceFontGs.native` AGC bridges except for the surface tag 0x48 and that the two sequence getters pass every error to `sceFontGraphicsReportError`. The sequence getters were matched by single PS4 runs on prepared sequences without a GPU submission; the drawup bridges and the PS5 exports with these NIDs were not checked on a console.
- [sceFontSelectGraphicsGnm opcode 0x4700002d](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the structure path (a parameter block or no 0x100, libSceFont 0x293d0) still throws through `NotImplemented_nid_no_patch`, as do the branches of the ported tree that no input reached. Ported: the prologue, the texture-fill call (flags 0x200, 0x2aa60) and the render call (flags with 0x100, 0x255c0) with 0x1a740 (flags 9 only), 0x13bf0, 0x15060 and 0x19250 (one body, user-data slots 8, 12 and 10), 0x182f0, 0x164d0 and 0x173e0 with their blend and buffer helpers, 0x1fbd0 and 0x200c0. Off-console, with an instance from the decrypted 0x47000001 and 0x4700002e following, 39820 render calls (1 to 3 per sequence, with and without buffers, base and Neo), 39946 with random blend words and 12138 texture-fill calls left the same instance, context, buffers and return values as the decrypted handler. Not checked on a console.
- [sceFontSelectGraphicsGnm opcode 0x4700002e](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the end handler (0x9650) and its tree (0x11d40, 0x12260, 0x11f60, 0x240a0) are ported. Off-console, on 8034 contexts the decrypted 0x4700002d had prepared (render, structure and texture-fill calls), the port and the decrypted handler left the same memory and return value, base and Neo; branches no input reached throw. Not checked on a console.
- [Gnm begin/end context](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - layout for the libSceFont ports: the caller fills +0 buffers present, +4 skip end (1), +5 flags (bit 1: extra call at +0x80[2]), +0x10/+0x14 command and constant bytes, +0x18/+0x20 buffers, +0x28 user constants, +0x30 draw list, +0x38 surface, +0x48/+0x50 record area, +0x70/+0x78 patch areas, +0x80 three call targets, +0x88..+0xe0 draw records. Begin writes +6, +0xc..+0x14, +0x54..+0x80 and owns +0x100 (command), +0x150 (aux) and +0x1f0 (state, 0xe90 bytes); end writes +0xc, +0x10, +0x14 and the record at +0x28..+0x52.
- [sceFontSelectGraphicsGnm opcodes 0x470000e2, 0x470000ec and 0x470000f0](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - the draw-state copy (0xc790 with 0x1f5b0), the draw-state pop (0xc610) and the command call (0xde50) follow the PS4 10.71 bodies; the copy dereferences the state's frame pointer (+0xd78) and its block chains without checks, as the module does. Off-console, 40190 render sequences with 1 to 5 random calls of the three handlers on crafted frames, depths and parameters, base and Neo, left the same memory and return values as the decrypted handlers. Not checked on a console.
