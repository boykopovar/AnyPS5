# libSceFontGs technical debt

### Unknown function info

- [`sceFontGraphicsGnmSurfaceInit`, `sceFontSelectGraphicsGnm` and four unnamed exports](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - parameter lists, return types and behaviour are unverified, so every entry throws through `NotImplemented_nid_no_patch`; the parameterless `int` declarations only resolve imports. The [PS5 13.60 export inventory](https://github.com/xdCloudy/PS5-13.60-Function-Stub-Library/blob/226383a7fa4b1275d6cebf61eb1c1e7ca7b58bcb/data/firmware-13.60/libscefontgs-b42f55c1c1.jsonl) names two of them and lists `DI4LrTUrD04`, `NtbMKwRg6qg`, `UsBLoyXsQZs` and `uksHKVEsxu4` without names; the pinned [module map](https://github.com/boykopovar/ps5-nid-map/blob/cc1d586fddab576a520f226da6b2632b031e6d09/data/Modules/libSceFontGs.inc) assigns all six to `libSceFontGs`. The six exports shared with `libSceFontGs.native` are left to that library.

- [sceFontSelectGraphicsGnm, UsBLoyXsQZs and uksHKVEsxu4](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - still throw. Read from the disassembly of the PS4 libSceFontGs.sprx on firmware 10.71, not from a PS5 module and not measured on a console; it draws through Gnm, and the PS5 exports with these NIDs may take AGC descriptors instead. `sceFontSelectGraphicsGnm` returns a static table for selector 0 and null otherwise. `UsBLoyXsQZs` and `uksHKVEsxu4` clear the returned object pointer and wrap `sceFontGraphicsDrawupFillTextureImageObject` and `sceFontGraphicsDrawupFillTexturePatternObject`. They take a texture descriptor that needs byte 0x0d = 0x48, a non-zero qword 0, dword 0x38 = 1 and dword 0x1c = 0, and pass its qword 0x28 and byte 0x0f. The image form also needs u and v of at least 0, non-negative extents, and u + du and v + dv of at most 16834.0. On success they set dword 0x10 of the new object to 1; a failed check returns `INVALID_PARAMETER`.

- [The four unnamed libSceFontGs exports](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - still throw and keep their NID placeholders. On PS4 firmware 10.71, `sceKernelDlsym` resolved these names at the module offsets of the four NIDs, and each name hashes to its NID: `UsBLoyXsQZs` is `sceFontGraphicsGnmDrawupFillTextureImage`, `uksHKVEsxu4` is `sceFontGraphicsGnmDrawupFillTexturePattern`, `DI4LrTUrD04` is `sceFontGraphicsSequenceGetGnmCommandsForSubmit` and `NtbMKwRg6qg` is `sceFontGraphicsSequenceGetGnmCommandsForChain`. These are PS4 names; the PS5 exports with these NIDs were not checked

- [sceFontGraphicsSequenceGetGnmCommandsForSubmit and sceFontGraphicsSequenceGetGnmCommandsForChain](../../../core/libs/prx/libSceFontGs/Export.cpp) (libSceFontGs) - still throw. Read from the disassembly of the same module and matched by single PS4 10.71 console runs on prepared sequences, without a GPU submission: both clear their outputs and return `INVALID_PARAMETER` when an output pointer is null, `0x8046009a` for a null sequence or one without magic 0x0F80 at 0, `0x804600b8` when bit 0 of byte 0x1b is set and `FATAL` when the inner pointer at 0x28 is null, and pass every error to `sceFontGraphicsReportError`. `ForSubmit(sequence, pointer*, count*)` returns the inner qword at 0x28 and dword at 0x30. `ForChain(sequence, pointer*, count*, pointer2*, count2*)` returns the qword at 0x28, the dword at 0x30 shifted right by 2, the qword at 0x38 and the dword at 0x34. The PS5 exports with these NIDs were not checked
