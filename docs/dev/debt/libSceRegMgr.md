### Additional callable exports

- [Additional callable exports](../../../core/libs/prx/libSceRegMgr/InventoryExports.cpp) - 1 entry present in both version-labelled images is an import-resolution declaration only. Neither label independently authenticates retail firmware provenance. Parameter lists, return types and behavior are unverified; parameterless `int` declarations are placeholders, not verified ABI contracts. Every entry throws through `NotImplemented_nid_no_patch`. ### Functional

- [String setter guest input](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - `sceRegMgrSetStr` and `sceRegMgrNonSysSetStr` copy their declared input buffer through `GuestCopyIn_nid_no_patch` before searching for a null terminator or changing registry state. An unreadable buffer returns `0x80820001` with `errno`, the previous registry value and its change mask preserved. Reading the full declared buffer, including bytes after any early terminator, is a host-safety fallback, not measured PS5 console behavior.
- [Binary setter guest input](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - `sceRegMgrSetBin` and `sceRegMgrNonSysSetBin` copy non-null guest buffers through `GuestCopyIn_nid_no_patch` before comparing or storing bytes. An unreadable input returns `0x80820001`, preserving `errno` and the previous registry value and change mask; this is a host-safety fallback, not verified PS5 console behavior.
- [sceRegMgrGetInt, sceRegMgrGetStr and sceRegMgrGetBin](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - returning `0x80820001` (`SCE_REG_MGR_ERROR_INVALID_PARAM`) for an unwritable non-null output pointer via `GuestCopyOut_nid_no_patch` with errno preserved after key lookup and type check is a host-safety fallback with console behavior unmeasured.
- [Registry store](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - entries are read and written through an in-memory process-local store without persistence. Callable prototypes for `sceRegMgrGetInt`, `sceRegMgrGetStr`, and `sceRegMgrGetBin` derive from [regmgr.h](https://github.com/ps5-payload-dev/regdump/blob/883524cc48c8497267ba7fc94ff0ac58880c4227/regmgr.h#L3713-L3729). Implemented getters return error codes for invalid parameters (`0x80820001`), missing keys (`0x80820002`), buffer sizing (`0x80820004`), and type mismatches (`0x80820006`) as unverified host implementation assumptions, as the cited regmgr.h does not establish error codes or validation behavior. Queries with non-positive keys `0` and `-1` take the missing-key path without key-range validation, pinning the unverified host assumption that non-positive keys are not rejected as invalid parameters. The 11.00 wrappers forward `sceRegMgrSetInt`, `sceRegMgrSetStr` and `sceRegMgrSetBin` with operation codes 1, 3 and 5 and a four-byte int or a pointer plus length; the host stores the value with the key's existing type, returns `0x80820006` for a different type and `0x80820001` for a null buffer, and creates the key on first write because the console's fixed registry schema is not available. Zero-length setter and getter paths, `sceRegMgrSetbin` and the init-level behavior remain unimplemented throwing `NotImplemented_nid_no_patch` because the kernel path is unmeasured.
- [Registry write paths](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - `sceRegMgrResetVal` (`eL7sMZaIdac`) follows the [voldemort](https://github.com/exhaustiblewizard/voldemort/blob/master/src/libs/libRegMgr.cpp) PS4 HLE, whose IDA notes record PS4 forwarding through `__sys_regmgr_call` cmd 11 resetting an entry to its factory default; the same NID resolves in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/cf6eede3f6588d779664e01874638f09484324b7/libSceRegMgr.c), unmeasured on PS5. Reset erases the entry, so Set→ResetVal→Get returns `0x80820002` here where the cited source returns success with the default. The setters are main's (#15057) and are not duplicated here.
- [Key widening](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - all store writes zero-extend a 32-bit key into the store's positive `int64_t` domain: main's #15057 setter wrappers (`static_cast<std::uint32_t>`) and this branch's `sceRegMgrResetVal` and `sceRegMgrIsChange` resolve identically, and the tests pin `0xC0808000`-range keys round-tripping with the `std::int64_t` getters. A key with bit 31 set matches the getters while its upper 32 bits are zero; getter keys below 0 or at/above 2^32 can never be stored, reset or consumed, which is consistent because the store cannot hold them.
- [Initial values](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - firmware 13.42 disassembly (sha256 591b1205…) shows the module forwarding `sceRegMgrGetIntInitVal` as (key, &result, command 7) to the regmgr call at 0x26b0 and returning its result: the factory defaults live in the system registry, the module has no table or zero fallback of its own, and for most keys the default is not 0. GetIntInitVal reads only the key and output registers (`edi`, `rsi`); the Str and Bin shapes are unverified. Zero/empty defaults are therefore not reported and the three retain `NotImplemented_nid_no_patch` until a defaults source exists.
- [Getter length edges](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - `sceRegMgrGetStr` requires a length strictly greater than the stored size (`len == size` returns `0x80820004`) where the [voldemort](https://github.com/exhaustiblewizard/voldemort/blob/master/src/libs/libRegMgr.cpp) PS4 GetStr succeeds, and `sceRegMgrGetBin` errors when the buffer is smaller than the stored size where voldemort copies the prefix; both divergences are accepted because the getters' provenance is the prototype-only PS5 regmgr.h, not voldemort.
- [Change tracking](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - `sceRegMgrIsChange` (`xhrI4zhlBuA`, same NID in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/cf6eede3f6588d779664e01874638f09484324b7/libSceRegMgr.c)): the PS5 module forwards to a kernel regmgr call with command `0x30` and the consumer id, so change detection is decided in the kernel. The consumer whitelist (`0x0d010001..0x0d010020` bits of mask `0x8000808b` plus `0x0d890080`), the 8-bit dirty mask and marking-on-write are a host model taken from the [voldemort](https://github.com/exhaustiblewizard/voldemort/blob/master/src/libs/libRegMgr.cpp) PS4 HLE, not module-checked behaviour: a setter or reset marks an entry's bits only when the stored value changes, and a query consumes only the querying consumer's bits. Unmeasured on PS5.
- [sceRegMgrNonSysGetInt, sceRegMgrNonSysSetInt, sceRegMgrNonSysGetStr, sceRegMgrNonSysSetStr, sceRegMgrNonSysGetBin, sceRegMgrNonSysSetBin, sceRegMgrCheckError, sceRegMgrNonSysCheckError and sceRegMgrIsInitOK](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - the 11.00 wrappers show the NonSys calls take a 64-bit key, a 32-bit type and an int value or a buffer plus length; the getters reject a null output (`0x800D0202`), and the string/binary calls reject a length above `0x800` (`0x800D0208`). The host reuses the same in-memory store as the system getters and setters, ignores the type word because the console schema is unavailable, and returns the store's `0x808200xx` codes for missing keys, type mismatches and short buffers; a zero-length getter returns `0x80820004`. `sceRegMgrCheckError` and `sceRegMgrNonSysCheckError` report no error and `sceRegMgrIsInitOK` reports the store ready, because the in-memory model has no service init. Not measured on a PS5.
- [Unverified registry APIs](../../../core/libs/prx/libSceRegMgr/Export.cpp) (libSceRegMgr) - export names and NIDs for initial-value getters, version queries, region queries and conversions, error checks, control/backup routines are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/cf6eede3f6588d779664e01874638f09484324b7/libSceRegMgr.c) and [NID database](https://github.com/zecoxao/sce_symbols/blob/9620e03b2964dbf0cfc1cb143ab24a65125091de/aerolib.csv), but their callable contracts and runtime behavior remain unverified and retain `NotImplemented_nid_no_patch`.
