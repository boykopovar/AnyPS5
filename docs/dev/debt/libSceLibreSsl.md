# libSceLibreSsl technical debt

### Functional

- [SSL_select_next_proto](../../../core/libs/prx/libSceLibreSsl/src/ProtocolSelection.cpp) (libSceLibreSsl) follows LibreSSL 3.4.1 [`ssl_lib.c`](https://github.com/libressl/openbsd/blob/d7513e7d4daf94905fd4cb0a5e5c89109d2874f7/src/lib/libssl/ssl_lib.c), which validates neither list: a zero-length entry is negotiated, no overlap returns `supported + 1` with the unchecked length byte `supported[0]`, read even for an empty supported list, and each pair of entries with equal length bytes is compared over that many bytes, past the end of a truncated list. [Firmware 13.42 host-PC evidence](https://github.com/boykopovar/AnyPS5/pull/9785#issuecomment-6406712390) of `libSceLibreSsl.sprx` (`0xda6d0`) reports the same status, pointer and length for 700,000 valid pairs and for the six unvalidated cases. Null outputs, a null supported list and a null peer list with a non-zero length throw, where the module faults; nothing is measured on a console.
- [SHA384_Init and SHA512_Init](../../../core/libs/prx/libSceLibreSsl/src/Digest.cpp) (libSceLibreSsl) - clear the 128-byte block buffer of the context, which LibreSSL 2.5.4 leaves as it was; digests are unaffected. `guest_libressl_oracle` (`ANYPS5_LIBRESSL_ORACLE`) compares the rest of the context with LibreSSL 2.5.4

- [SSL_set_fd and SSL_get_fd](../../../core/libs/prx/libSceLibreSsl/src/SslBio.cpp) (libSceLibreSsl) - nothing is checked on the console. `SSL_set_fd` creates the socket `BIO` of LibreSSL 2.5.4's [bss_sock.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/bio/bss_sock.c) with `BIO_NOCLOSE` and accepts any integer, as that release does; the 104-byte `BIO` and 80-byte `BIO_METHOD` are measured on a 2.5.4 x86-64 build. The `BIO` method callbacks throw, as every `BIO_*` export does. Once an engine exists, every later I/O call reads the descriptor back from the `BIO`, so `SSL_set_fd` moves the connection to the new socket; -1, a closed descriptor and a descriptor that is no longer a guest socket fail the call with `SSL_ERROR_SYSCALL` and `EBADF`, where the console reports `ENOTSOCK` for an open descriptor that is not a socket.
- [SSL_connect and SSL_accept](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - nothing is checked on the console. They follow [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) `ssl_lib.c`, `ssl_clnt.c` and `ssl_srvr.c`, the version in the [firmware 13.40 measurements](https://github.com/boykopovar/AnyPS5/discussions/8981#discussioncomment-19111214), but the handshake runs on a host mbedtls 3.6 TLS 1.2 engine over the guest socket: TLS 1.0, 1.1 and 1.3, renegotiation, session reuse, ALPN, OCSP and LibreSSL's default cipher list are absent and wire bytes differ. A call after a finished handshake restarts it with `SSL_clear`, on the same socket. The engine resolves the guest descriptor on every transfer and keeps no reference to the socket, so closing the descriptor closes the connection and later calls fail with `EBADF`.
- [SSL I/O socket transport](../../../core/libs/prx/libSceLibreSsl/src/TlsEngine.cpp) (libSceLibreSsl) - nothing is checked on the console. A `NativeOwner::transfer` function on the socket, as [#12688](https://github.com/boykopovar/AnyPS5/pull/12688) installs and its `sceSsl` adapter calls, carries every engine transfer and decides blocking, timeouts and cancellation; its POSIX version ignores cancellation while waiting and its timed send blocks on macOS, where `send` ignores `MSG_DONTWAIT`. Without one, as on main, the engine uses the native socket: blocking sockets block, non-blocking ones return at once, and a timeout polls for readiness first, as a guest `recv` does. An expired timeout and `EINTR` give `SSL_ERROR_WANT_READ` or `SSL_ERROR_WANT_WRITE` with `errno` 35 and 4, as [bss_sock.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/bio/bss_sock.c) does. The Windows poll is untested.
- [SSL_connect and SSL_accept unmodelled configurations](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - they throw for an SSL with no BIO, separate read and write BIOs, a descriptor that is not a guest socket, a message, info, verify or certificate-verify callback, an ALPN list, a status request, an `SSL_SESSION`, a verification depth, trusted certificates in the store, TLS 1.2 disabled by options or version limits, a server with `SSL_VERIFY_PEER`, a call after a failed handshake, and an engine failure other than the verification and no-shared-cipher cases. Nothing is checked on the console.
- [SSL_connect certificate verification](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - nothing is checked on the console. No export adds a trusted certificate, so [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) `X509_verify_cert` stops at its first error while building the chain and `verify_result` is 18 for a single self-signed certificate, 19 for a chain ending in a self-signed one and 20 otherwise, whatever dates or names the engine flags; 10 and 9 are unreachable. Self-signed means identical DER issuer and subject, where 2.5.4 also compares authority key identifiers. A nonzero verify mode fails the handshake on that result (-1, `SSL_ERROR_SSL`, `SSL_R_CERTIFICATE_VERIFY_FAILED` in state `SSL3_ST_CR_CERT_B`); `SSL_VERIFY_NONE` continues. The `SSL_ctrl` 55 name is sent as SNI and never matched against the certificate, as in 2.5.4.
- [SSL_accept without a certificate](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - nothing is checked on the console. No export gives an SSL a certificate or key, so the engine server fails the first ClientHello with -1, `SSL_ERROR_SSL` and `SSL_R_NO_SHARED_CIPHER` in state `SSL3_ST_SR_CLNT_HELLO_C`, as [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) `ssl_srvr.c` does when no cipher has a certificate. Every engine handshake failure on the server maps there, including bad versions or malformed hellos that 2.5.4 reports with other reasons; its alert bytes differ.
- [SSL_read, SSL_peek, SSL_write, SSL_pending and SSL_shutdown](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - nothing is checked on the console. Results, `rwstate`, BIO retry flags, `shutdown` bits, `errno` and queued errors follow [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) `ssl_lib.c`, `ssl_pkt.c` and `s3_lib.c`, with records produced by the host engine. `SSL_write` honours `SSL_MODE_ENABLE_PARTIAL_WRITE`, `SSL_MODE_ACCEPT_MOVING_WRITE_BUFFER` and `max_send_fragment`, but fragments are engine records. Peer data after our `close_notify` is dropped as in 2.5.4, so `SSL_shutdown` returns -1 with `SSL_ERROR_SYSCALL`; during or after a failed handshake it returns 1 without sending, as `SSL_in_init` makes it there.
- [SSL_read, SSL_peek, SSL_write and SSL_shutdown unmodelled cases](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - a peer fatal alert, any other engine failure and a call after a failed handshake throw, where [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) queues the alert reason. `s3->alert_dispatch` stays 0, the engine holding unsent alerts. The `BIO` callbacks still throw; the engine reads and writes the guest socket itself. Nothing is checked on the console.
- [SSL_get_error](../../../core/libs/prx/libSceLibreSsl/src/SslIo.cpp) (libSceLibreSsl) - nothing is checked on the console. It follows [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) `ssl_lib.c`: a result above zero, the error queue, `rwstate` with the BIO retry flags and reason, then a received `close_notify` in `SSL3` state decide the code. A null connection, a null BIO behind `rwstate` and a null `SSL3` state, which LibreSSL dereferences, throw.

### Functional

- [ASN1_INTEGER_get](../../../core/libs/prx/libSceLibreSsl/src/Asn1.cpp) has no console verification for nonpositive lengths. It follows [LibreSSL 2.5.4](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/a_int.c#L363-L389): valid integer types return zero without reading data when length is zero or negative; invalid types return -1 first. Later LibreSSL versions reject negative lengths through `ASN1_INTEGER_get_int64`; that later contract is not used for this library.

- [ASN1_INTEGER_get and ASN1_STRING_data/length/type/to_UTF8](../../../core/libs/prx/libSceLibreSsl/src/Asn1.cpp) are unverified on PS5. They follow [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1), reported for firmware 13.40 in [discussion #8981](https://github.com/boykopovar/AnyPS5/discussions/8981#discussioncomment-19111214). These throw where 2.5.4 has undefined behaviour: a null structure passed to `ASN1_STRING_data`, `ASN1_STRING_length` or `ASN1_STRING_type`, a null conversion output, missing nonempty data, oversized converted output and unrepresentable signed integers. As in 2.5.4, `ASN1_INTEGER_get(NULL)` returns 0 and `ASN1_STRING_to_UTF8` returns -1 for a null string, leaving the output alone; malformed input and allocation failure also return -1 and queue the ASN.1 error (129, 133, 134, 124, or 65, twice for a UTF8String copy). Conversion buffers come from the guest libc allocator.

- [SSL_alert_desc_string_long](../../../core/libs/prx/libSceLibreSsl/Alert.cpp) - Console execution and equivalence across other firmware revisions remain unverified. BunnyFl reports identical strings for 3,841 inputs across three runs against the firmware 13.42 module executed natively on a PC ([comparison](https://github.com/boykopovar/AnyPS5/pull/9870#issuecomment-6406774281)); this is not a console run. The mapping follows LibreSSL 2.5.4.

- [i2t_ASN1_OBJECT](../../../core/libs/prx/libSceLibreSsl/src/ObjectText.cpp) and the [object table](../../../core/libs/prx/libSceLibreSsl/src/ObjectTable.cpp) are unverified on PS5. The 956 objects and their search order are generated from [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/objects) `objects.txt` and `obj_mac.num` with its `objects.pl` and `obj_dat.pl`, the version string the module holds; LibreSSL 2.7 adds NIDs 956-967, so its `jurisdictionLocalityName`, `jurisdictionStateOrProvinceName` and `jurisdictionCountryName` OIDs print by name there and numerically here. `OBJ_obj2txt` follows 2.5.4 `obj_dat.c`, with objects added at run time left out because no export of this module adds one. A negative buffer length, and a null buffer with a positive length, throw instead of being passed on as a `size_t`

- [X509_STORE_new, X509_STORE_free and X509_STORE_set_flags](../../../core/libs/prx/libSceLibreSsl/src/X509Store.cpp) are unverified on PS5. The 136-byte store, 64-byte verify parameters, 56-byte parameter identity, 32-byte stacks and the results follow [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509) `x509_lu.c` and `x509_vpm.c`, the version in [firmware 13.40 measurements](https://github.com/boykopovar/AnyPS5/discussions/8981#discussioncomment-19111214). No export adds a certificate, CRL or policy object, so `X509_STORE_free` throws instead of freeing one and the object cache's comparator throws. A null store or verify parameters, and a null element array behind a positive count, throw where LibreSSL faults

- [X509_VERIFY_PARAM_set_hostflags and X509_VERIFY_PARAM_set1_ip_asc](../../../core/libs/prx/libSceLibreSsl/src/X509VerifyParam.cpp) are unverified on PS5. They follow [LibreSSL 2.5.4](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509/x509_vpm.c) `x509_vpm.c` and the `a2i_ipadd` parser of its [`v3_utl.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509v3/v3_utl.c), unchanged in 2.7, the first release whose symbols include `X509_VERIFY_PARAM_set1_host`, which the module also exports; IPv4 parts are read with the guest `sscanf` as the module would. LibreSSL 2.8 appends a `poisoned` field to the parameter identity, which these layouts lack. A null address text, and null verify parameters or identity once an address is accepted, throw where LibreSSL faults

- [X509_LOOKUP_file and X509_STORE_add_lookup](../../../core/libs/prx/libSceLibreSsl/src/X509Store.cpp) are unverified on PS5. The 80-byte method, the 32-byte lookup, the stack growth and the results follow LibreSSL 2.5.4 [`by_file.c`, `x509_lu.c`](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509) and `stack.c`, unchanged in 2.7. The file method's `ctrl`, which loads PEM certificates and CRLs, throws: there is no certificate model. Callbacks of a guest-supplied method (`new_item`, `shutdown`, `free`) throw instead of being called, and a null store, method or listed lookup throws where LibreSSL faults

- [X509_VERIFY_PARAM_set1_host](../../../core/libs/prx/libSceLibreSsl/src/X509Store.cpp) is unverified on PS5. It follows `int_x509_param_set_hosts` of [LibreSSL 2.7](https://github.com/libressl/openbsd/blob/OPENBSD_6_3/src/lib/libcrypto/x509/x509_vpm.c), the first release with this export, and copies the name with the guest `strndup`. LibreSSL 2.8 also marks the parameters as poisoned when the call fails, through a field the 2.5.4 to 2.7 layout lacks, so a failed call leaves no mark. Null verify parameters or identity throw where LibreSSL faults
