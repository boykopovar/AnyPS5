# libSceLibreSsl technical debt

- [EVP_PKEY_id](../../../core/libs/prx/libSceLibreSsl/src/PkeyId.cpp) returns the key's stored type, the first 32-bit field in LibreSSL 2.5.4's `EVP_PKEY` layout. Its signature and behavior follow [p_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/p_lib.c) and [evp.h](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/evp.h); PS5 behavior has not been independently measured. A null key throws where the reference dereferences it.
- [EVP_PKEY_free](../../../core/libs/prx/libSceLibreSsl/src/PkeyLifecycle.cpp) - PS5 behavior has not been independently measured. A key that holds non-RSA algorithm data, an engine or attributes throws and keeps its last reference, since no export can attach them yet. An RSA key is released with `RSA_free`. Reference counting and release follow LibreSSL 2.5.4 [p_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/p_lib.c).
- [EVP_PKEY_new](../../../core/libs/prx/libSceLibreSsl/src/PkeyLifecycle.cpp) - PS5 behavior has not been independently measured. The 56-byte LP64 layout and initial values follow LibreSSL 2.5.4 [evp.h](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/evp.h) and [p_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/p_lib.c). LibreSSL3 uses its own 32-byte constructor and release with references at offset 4. Objects from the two modules must not be mixed.
- [SSL_CTX_use_PrivateKey_ASN1](../../../core/libs/prx/libSceLibreSsl/src/SslCtx.cpp) - not measured on a PS5: type 0 (`EVP_PKEY_NONE`) fails before reading context/DER, preserving earlier errors then adding EVP unsupported-algorithm, ASN.1 unknown-key-type and SSL ASN.1 errors. OOM adds EVP malloc and ASN.1 EVP-library before SSL. Other types throw because decoding/installation are unimplemented. Follows pinned 2.5.4 [`ssl_rsa.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl/ssl_rsa.c#L619-L634), [`d2i_pr.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/d2i_pr.c#L81-L99), [`p_lib.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/p_lib.c#L187-L257) and [`ameth_lib.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/ameth_lib.c#L83-L111).

- [OBJ_create and OBJ_cleanup](../../../core/libs/prx/libSceLibreSsl/src/ObjectCreate.cpp) are unverified on PS5. - [RSA_sign](../../../core/libs/prx/libSceLibreSsl/src/Rsa.cpp) error publication is unverified on PS5. Its implemented early failures queue RSA/0xfff reasons 131 (MD5+SHA1 length), 117 (negative algorithm type), 116 (`NID_undef`, whose OID is empty), and 112 (DigestInfo or MD5+SHA1 larger than the key permits), following LibreSSL 2.5.4 [`rsa_sign.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/rsa/rsa_sign.c).
