# libSceSharePlay
## change [sceSharePlayGetCurrentConnectionInfo, sceSharePlayGetCurrentConnectionInfoA]
- [sceSharePlayGetCurrentConnectionInfo, sceSharePlayGetCurrentConnectionInfoA](../../../core/libs/prx/libSceSharePlay/Export.cpp) - returning `0x810E0001` for unwritable output pointers is a host-safety fallback with console behavior unmeasured. A PS5 (firmware 11.60, payload process; a title process may differ) loaded libSceSharePlay.sprx and, without `sceSharePlayInitialize`, answered `0x810E0004` to both functions for a valid 128-byte buffer, a NULL pointer and the unmapped address 0x10, writing nothing into the buffer, as this does before it reads the pointer; the answer for an unwritable pointer after initialization stays unmeasured.
## change [sceSharePlayGetCurrentConnectionInfoA]
- [sceSharePlayGetCurrentConnectionInfoA](../../../core/libs/prx/libSceSharePlay/Export.cpp) - the native module confirms a 72-byte result, initial zero fields and both user IDs -1. Initialization is checked before the output pointer. The host retains this initial disconnected state; native event draining, cached updates and service reconnection are unimplemented. A PS5 (firmware 11.60, payload process; a title process may differ) returned `0x810E0004` before `sceSharePlayInitialize` from this function for a valid 128-byte buffer, a null pointer and the address 0x10, so the initialization check comes before the output pointer there too (measured).
## change [sceSharePlayGetCurrentConnectionInfo]
- [sceSharePlayGetCurrentConnectionInfo](../../../core/libs/prx/libSceSharePlay/Export.cpp) - the 56-byte layout without account IDs is from [shadPS4's shareplay.h](https://github.com/shadps4-emu/shadPS4/blob/396c2a09a38d22eaa02aab32c1967263dceab95f/src/core/libraries/share_play/shareplay.h); the checks and values copy `sceSharePlayGetCurrentConnectionInfoA`, while shadPS4 leaves both user IDs 0 and checks nothing. Not measured on a console beyond this: a PS5 (firmware 11.60, payload process; a title process may differ) without `sceSharePlayInitialize` answered `0x810E0004` and wrote nothing into a valid 128-byte buffer, so the layout stays unmeasured.
