# shader

## change `v_cvt_pkrtz_f16_f32` rounds toward zero and never overflows

- [FP16_OVFL](../../../core/shader/recompiler/Translation/src/TranslationContext/OperandAccess.cpp) follows the shader's float mode as measured on RDNA2 (gfx1036) at IEEE=0 and IEEE=1 with f16 denormals kept and flushed: with `FP16_OVFL`=1 an f16 result that rounds to ±infinity is written as ±0x7bff unless a source operand is infinite, so `v_rcp_f16`, `v_rsq_f16` and `v_log_f16` of ±0 and `v_exp_f16` of 16 or more are clamped while an infinite input passes through, and `v_div_fixup_f16` keeps the infinity it writes for a zero denominator or an infinite numerator and clamps any other infinite quotient, a NaN one included. `v_cvt_pkrtz_f16_f32` rounds toward zero and never overflows. The sources are checked as the f32 values the translation computes with; the rule is applied to `v_fma_mix*_f16` with f32 sources and to `v_interp_p2_f16` without a measurement of infinite f32 sources or parameters. Round modes other than nearest even are not modelled, so the overflow threshold is the nearest-even one (65520). Against the output modifier of `v_mul_f16`, `v_add_f16` and `v_fma_f16` the clamp comes first: a result that overflows before `div:2` is clamped to ±0x7bff and then halved to ±0x77ff, and `mul:2` or `mul:4` overflowing a finite result give ±0x7bff, as measured on RDNA3.5 (gfx1151, Radeon 8060S, AMD Windows driver 32.0.22032.6002, [hardware oracle](../HW_ORACLE.md)) and pinned by [Fp16OverflowOmod](../../../core/libs/prx/libSceAgcDriver/tests/execution/Fp16OverflowOmod.cpp); the PS5's gfx1013 is unmeasured.
