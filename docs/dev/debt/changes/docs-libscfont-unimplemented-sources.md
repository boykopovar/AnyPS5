# libSceFont

## add Unknown function info

- [Throwing graphics, control and expansion-buffer exports](../../../core/libs/prx/libSceFont/src/Unimplemented.cpp) (libSceFont) - none of the 78 exports that call `NotImplemented_nid_no_patch` has a public implementation to adapt: shadPS4 [font.cpp](https://github.com/shadps4-emu/shadPS4/blob/b6f0c58dba9ee75b93477703032ae4f1e0de8f1c/src/core/libraries/font/font.cpp) declares 42 with empty bodies and omits the other 36, and KytyPS5 [libFont.cpp](https://github.com/KytyPS5/KytyPS5/blob/d2413fc2ebd91d1b7234197c2dd5bd48e1cb6a51/src/libs/libFont.cpp), SharpProspero [SceFont.Engine.cs](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/Font/SceFont.Engine.cs) and Orbital's [IDA type database](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json) name none of them.

- [Font graphics device and expansion-buffer layouts](../../../core/libs/prx/libSceFont/src/Unimplemented.cpp) (libSceFont) - `FontGraphicsDeviceParam` and `FontGlyphExpandBufferState` have no recovered layout, so `sceFontCreateGraphicsDevice` and `sceFontGetGlyphExpandBufferState` cannot be typed, and the graphics exports that take a device are unreachable until one can be created.

- [sceFontControl](../../../core/libs/prx/libSceFont/src/Unimplemented.cpp) (libSceFont) - every command still throws. The only command whose contract is known is `0x46fa00`, read from the PS4 `libSceFontFt.sprx` alias body (SHA-256 `ad78707187be911df1559f4799fef2af3d6c4d098dd95b33d3e22854cca15e2b`, `0x11680`-`0x11a1a`): `sceFontFtSetAliasFont` passes a 16-byte request `{destination, end, fontId, written}` and expects the answer to write the path of font `fontId` into `[destination, end)` and set `written`. The libSceFont body that answers it was not read, so `sceFontFtSetAliasFont` throws there and the alias-font path is unusable; the path source and the units of `written` are unmeasured.
