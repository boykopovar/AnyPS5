# libSceRtc

## change [sceRtcSetCurrentTick, sceRtcSetCurrentNetworkTick, sceRtcSetCurrentAdNetworkTick, sceRtcSetCurrentDebugNetworkTick]
- [sceRtcSetCurrentTick, sceRtcSetCurrentNetworkTick, sceRtcSetCurrentAdNetworkTick, sceRtcSetCurrentDebugNetworkTick](../../../core/libs/prx/libSceRtc/Export.cpp) (libSceRtc) - a valid tick sets a process-local clock that advances from a monotonic host clock; the host system clock is not changed. The console sets clock 0, 0x10, 0x12 or 0x11. Null pointers return `0x80B50002` and ticks before the Unix epoch return `0x80B50003`, from disassembly of libSceRtc.sprx on firmware 13.60, not measured on a console. A PS5 (firmware 11.60, payload process; a title process may differ) returned for a null pointer `0x80B50002` from `sceRtcSetCurrentTick`, 0 from `sceRtcSetCurrentNetworkTick` and from `sceRtcSetCurrentDebugNetworkTick`, and `0x80020016` with errno 22 from `sceRtcSetCurrentAdNetworkTick`, where this returns `0x80B50002` for all four. A null pointer cannot supply a tick: no tick value was passed, and whether the 0 results changed the console clock is not measured beyond the probe clock offset staying the same within a second.
