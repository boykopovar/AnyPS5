# libSceVideoOut

## change [The Add*Event and Delete*Event calls]

- [The Add*Event and Delete*Event calls](../../../core/libs/prx/libSceVideoOut/src/Event.cpp) (libSceVideoOut) - for the flip, vblank, set-mode, output-mode, pre-vblank-start and VRR-status pairs, a queue that is 0, deleted or not a queue gives 0x8029000c, and deleting an event that is not registered gives 0x8029000d. That is how firmware 13.42's `libSceVideoOut.sprx` maps `kevent`'s `errno` 9 and 2 in all twelve, read from disassembly, not run ([flip and set mode](https://github.com/boykopovar/AnyPS5/issues/15134#issuecomment-6755215803), [the other pairs](https://github.com/boykopovar/AnyPS5/issues/15134#issuecomment-6866512845)). Their 0x8029100c for `ENOMEM` is never produced. The output-mode pair gives 0x8029001b on a port whose bus type is not 0: the open path stores the ident at `+0x38` only for a bus type of 0 (the comparison at `0x10f7a`), the add reads it at `0x12cc0` and the delete at `0x13340`, and both reject a zero ident (`0x12dc7`, `0x13419`) after the handle lookup and before `kevent`. `VIDEO_OUT_ERROR_NOT_MAIN_BUS` carries that answer here; the name is ours. Not modelled: the 0x8029001b the pre-vblank-start and VRR-status pairs give on a port whose record `+0x10` is non-zero.

## change [sceVideoOutAddSetModeEvent, sceVideoOutDeleteSetModeEvent]

- [sceVideoOutAddSetModeEvent, sceVideoOutDeleteSetModeEvent](../../../core/libs/prx/libSceVideoOut/src/Event.cpp) (libSceVideoOut) - add and remove the output-mode registration, so a title that adds both gets one event, id 8. In firmware 13.42's `libSceVideoOut.sprx` ([disassembly](https://github.com/boykopovar/AnyPS5/issues/15134#issuecomment-6755215803)) both calls register one kernel ident and filter on a bus-type-0 port: the open path stores the same ident for set mode (`+0x30`, at `0x10f6e`) and output mode (`+0x38`, at `0x10f7f`). On another bus only the set-mode ident is stored, and `sceVideoOutAddOutputModeEvent` and `sceVideoOutDeleteOutputModeEvent` return 0x8029001b as `VIDEO_OUT_ERROR_NOT_MAIN_BUS` here, while the set-mode pair still succeeds. When the kernel posts the event and what its data holds are not in the module: it is armed at once with the current output mode, as the output-mode event already is.
