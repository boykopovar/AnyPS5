## change checked for a citable prototype

- [All 90 exports](../../../core/libs/prx/libSceDataTransfer/Export.cpp) (libSceDataTransfer) - checked for a citable prototype or behaviour source; none exists outside firmware (the readable 13.42 module, entry below). The PS4 firmware carries the same library ([SceData symbol list](https://github.com/a0zhar/PS4-SCE): 62 `sceDataTransfer*` names, 60 shared with the PS5, only `sceDataTransferHostAbort` and `sceDataTransferHostLaunch` PS4-only), but the public [OpenOrbis header](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain/blob/master/include/orbis/DataTransfer.h) declares 45 of the 60 shared names and both PS4-only ones as parameterless `void` placeholders without argument or return types, and no PS4 reimplementation has any of it (shadPS4 and KytyPS5 implement nothing here; aerolib carries no DataTransfer entry). Every export therefore stays a parameterless import-resolution placeholder; what each returns is in the "Firmware 13.42 module" entry.

## change orchestrates console-to-console migration

- [All 90 exports](../../../core/libs/prx/libSceDataTransfer/Export.cpp) (libSceDataTransfer) - the library orchestrates console-to-console migration: the `Request*PS4` and `Request*PS5` calls drive a transfer from a source console, the `Target*` calls serve the receiving one, and the `EventIs*`/progress calls report that session's state, over a private LAN protocol whose activation, SSO-ticket, reboot-handshake and eth0/IPv6-readiness steps no public source documents. Argument counts, output shapes and result codes are still unrecovered — the readable 13.42 module is read only up to its state test — and a host has no peer console to run the other endpoint against. Nothing past the state test can be implemented honestly before that module is analysed further or a console is measured; unknown: every signature and the whole session state machine.

## change [Firmware 13.42 module]

- [Firmware 13.42 module](../../../core/libs/prx/libSceDataTransfer/Export.cpp) (libSceDataTransfer) - only the state before `sceDataTransferInitialize` is modelled. In `system_ex/common_ex/lib/libSceDataTransfer.sprx` (sha256 `03aa74b36ea9aa3c086897424f36d2c931654a82f3a75fcfa33cf67f49ffd678`) 40 exports test the state pointer `0xc028` (zero-fill memory, written only by `sceDataTransferInitialize` at `0x1b7c` and cleared by `sceDataTransferTerminate` at `0x1d6f`) and return `0x81620000` while it is null, whatever their arguments; run under a CPU emulator, not measured on a console. `sceDataTransferInitialize` throws here, so they always give that answer; they must follow the state once it is implemented. The other 50 exports throw: 45 are not exported by the module, and `sceDataTransferInitialize`, `sceDataTransferTerminate` and the three `EventIs*Ready*` queries reach an import first
