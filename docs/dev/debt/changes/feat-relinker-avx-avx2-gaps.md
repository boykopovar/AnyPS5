# relinker

## change [256-bit integer lowering]

- [256-bit integer lowering](../../../core/relinker/codegen/src/x86/LaneSplitLowering.cpp) under `--to-avx` does not cover gathers, and each covered instruction runs about ten times slower than on an AVX2 host. It runs the lane-local integer instructions listed in `_shape` as two VEX.128 halves: VEXTRACTF128 into scratch YMM registers saved in a 256-byte frame below the red zone, the 128-bit form per half, then VINSERTF128; RFLAGS is not written. VMPSADBW takes the low half's offsets from immediate bits 2:0 and the high half's from bits 5:3, and VPBLENDVB splits its mask register too, as the SDM defines the 256-bit forms. The execution test compares each split with the 128-bit instruction on each half, and with the AVX2 instruction when the host has it, with aliasing, the other YMM registers and the red zone checked; memory sources are decoded but not executed.

## change [AVX2 twin lowering]

- [AVX2 twin lowering](../../../core/relinker/codegen/src/x86/Avx2TwinLowering.cpp) under `--to-avx` rewrites, in place and at the same length, the AVX2 instructions whose AVX form moves the same bits: VINSERTI128, VEXTRACTI128 and VPERM2I128 become VINSERTF128, VEXTRACTF128 and VPERM2F128, VPBLENDD becomes VBLENDPS, VBROADCASTI128 becomes VBROADCASTF128, the memory forms of VPBROADCASTD and VPBROADCASTQ become VBROADCASTSS and VBROADCASTSD (256-bit) or VMOVDDUP (128-bit), and the masked loads and stores VPMASKMOVD and VPMASKMOVQ become VMASKMOVPS and VMASKMOVPD, which the SDM defines with the same element masking and fault suppression. The integer and floating-point forms can differ in bypass latency between execution domains on some cores; the values are the same. Register-source broadcasts, VPBROADCASTB and VPBROADCASTW, VPERMQ, VPERMD, VPERMPS, VPERMPD, VPMOVMSKB, variable shifts, gathers and 256-bit integer arithmetic have no same-length AVX form and are not rewritten here; gathers are not lowered at all. The execution test runs each replacement on an AVX host and compares it with the SDM result of the AVX2 instruction and, for the masked moves, with the AVX2 instruction itself when the host has it; a masked load whose active elements end at a page boundary is checked not to fault.

## add Functional

- [VPMOVMSKB lowering](../../../core/relinker/codegen/src/x86/MoveMaskLowering.cpp) under `--to-avx` runs the 256-bit form as the VEX.128 form on the low half and on the upper half taken with VEXTRACTF128, storing each 16-bit mask with a 16-bit MOV into a slot below the red zone and loading the 32-bit result with MOV, which zero-extends it as the SDM entry for VPMOVMSKB does; one scratch YMM register is saved in a 176-byte frame and RFLAGS is not written. An RSP destination fails the conversion. The execution test checks every destination and source register, the other GPRs and YMM registers, RFLAGS and the red zone against the SDM result, and against the host instruction where it has AVX2.
- [Variable shift lowering](../../../core/relinker/codegen/src/x86/VariableShiftLowering.cpp) under `--to-avx` runs VPSLLVD, VPSLLVQ, VPSRLVD, VPSRLVQ and VPSRAVD, in their 128-bit and 256-bit forms, one element at a time: each count is zero-extended into the low quadword of a scratch register with VPMOVZXDQ and VPSRLDQ, the uniform VPSLLD, VPSLLQ, VPSRLD, VPSRLQ or VPSRAD shifts the whole source by it, and VBLENDPS or VBLENDPD keeps that element. The uniform shifts give zero, or the sign for VPSRAD, for any count above the element width, as the SDM defines the variable forms; the 256-bit form does the same on the upper half taken with VEXTRACTF128. Seven scratch YMM registers are saved in a 352-byte frame below the red zone and RFLAGS is not written; each shift becomes 20 to 45 instructions. The execution test compares each form with the SDM result and, where the host has AVX2, with the instruction itself, for register aliasing, counts at and above the element width and memory counts, including one that ends at a page boundary.
