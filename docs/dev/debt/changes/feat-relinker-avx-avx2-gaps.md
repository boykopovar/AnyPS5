# relinker

## change [256-bit integer lowering]

- [256-bit integer lowering](../../../core/relinker/codegen/src/x86/LaneSplitLowering.cpp) under `--to-avx` runs each covered instruction runs about ten times slower than on an AVX2 host. It runs the lane-local integer instructions listed in `_shape` as two VEX.128 halves: VEXTRACTF128 into scratch YMM registers saved in a 256-byte frame below the red zone, the 128-bit form per half, then VINSERTF128; RFLAGS is not written. VMPSADBW takes the low half's offsets from immediate bits 2:0 and the high half's from bits 5:3, and VPBLENDVB splits its mask register too, as the SDM defines the 256-bit forms. The execution test compares each split with the 128-bit instruction on each half, and with the AVX2 instruction when the host has it, with aliasing, the other YMM registers and the red zone checked; memory sources are decoded but not executed.

## change [AVX2 twin lowering]

- [AVX2 twin lowering](../../../core/relinker/codegen/src/x86/Avx2TwinLowering.cpp) under `--to-avx` rewrites, in place and at the same length, AVX2 instructions whose AVX form moves the same bits; integer and floating-point forms can differ in bypass latency on some cores. VINSERTI128, VEXTRACTI128 and VPERM2I128 become their F128 forms, VPBLENDD VBLENDPS, VBROADCASTI128 VBROADCASTF128, memory VPBROADCASTD and VPBROADCASTQ VBROADCASTSS and VBROADCASTSD or VMOVDDUP, VPMASKMOVD and VPMASKMOVQ VMASKMOVPS and VMASKMOVPD, and 256-bit VMOVNTDQA VMOVDQA, which drops the non-temporal hint, so a load from write-combining memory is slower. The execution test compares each replacement with the SDM result on an AVX host, the masked moves also with the AVX2 instruction and at a page end.

## change applies the BMI1, BMI2, CLWB and RDPID lowerings

- `--to-avx` ([matcher](../../../core/relinker/codegen/src/x86/Amd64OnlyInstructionMatcher.cpp)) applies the BMI1, BMI2, CLWB and RDPID lowerings of `--to-rosetta` and adds TZCNT, LZCNT and MOVBE, for hosts with AVX but without AVX2, such as the Sandy Bridge and Ivy Bridge CPUs of 2011 and 2012 Macs. F16C, FMA, PDEP, PEXT, RDRAND and RDSEED are not lowered; every AVX2 opcode in the SDM's VEX tables has a lowering, but no title has been run with them, so a title that reaches one of them still raises an illegal instruction; Sandy Bridge has neither RDRAND nor RDSEED, so the `--to-rosetta` RDSEED-to-RDRAND rewrite would not help there. It requires `--macos`: the Linux and Windows runtimes stop at start-up when the host lacks BMI1, BMI2, LZCNT, MOVBE or AVX2 and do not yet read which of them a conversion lowered.

## add Functional

- [VPMOVMSKB lowering](../../../core/relinker/codegen/src/x86/MoveMaskLowering.cpp) under `--to-avx` runs the 256-bit form as the VEX.128 form on the low half and on the upper half taken with VEXTRACTF128, storing each 16-bit mask with a 16-bit MOV into a slot below the red zone and loading the 32-bit result with MOV, which zero-extends it as the SDM entry for VPMOVMSKB does; one scratch YMM register is saved in a 176-byte frame and RFLAGS is not written. An RSP destination fails the conversion. The execution test checks every destination and source register, the other GPRs and YMM registers, RFLAGS and the red zone against the SDM result, and against the host instruction where it has AVX2.
- [Variable shift lowering](../../../core/relinker/codegen/src/x86/VariableShiftLowering.cpp) under `--to-avx` runs VPSLLVD/Q, VPSRLVD/Q and VPSRAVD, 128- and 256-bit, as 20 to 45 instructions: per element, the count zero-extended by VPMOVZXDQ and VPSRLDQ feeds the uniform VPSLL, VPSRL or VPSRA shift, which gives the SDM result for counts above the element width too, and VBLENDPS or VBLENDPD keeps that element. Seven scratch YMM registers are saved in a 352-byte frame below the red zone; RFLAGS is not written. The execution test compares each form with the SDM result and, on an AVX2 host, the instruction, including memory counts at a page end.
- [Gather lowering](../../../core/relinker/codegen/src/x86/GatherLowering.cpp) under `--to-avx` - a fault on an active element is delivered inside the stub before the destination and mask are written, not after the elements already gathered as the SDM describes; running the instruction again restarts the gather. 32-bit addressing (`0x67`) fails the conversion. All eight gathers run per element without branches: VPEXTRD with MOVSXD or VPEXTRQ and LEA build the address in a saved GPR, and a one-element VMASKMOVPS or VMASKMOVPD reads it, so masked-off elements touch no memory; VBLENDVPS or VBLENDVPD merges the result and the mask is cleared. RFLAGS is not written. The execution test compares every form with the SDM result and, on an AVX2 host, the instruction, and checks masked-off elements on a guard page.
