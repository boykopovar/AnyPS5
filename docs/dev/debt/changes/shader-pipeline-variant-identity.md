# shader

## add Functional

- [Null and bound descriptor variants](../../../core/shader/recompiler/Optimization/src/DescriptorBindingBuilder.cpp) (shader recompiler) - a program whose buffer or sampled image slot is null in some dispatches and bound in others can be specialized twice: a null V# bakes zero fields, and a null T# bakes zero swizzles and folds none of its components, so the null and the bound variant can each cost one driver compile (30 to 65 s for the largest compute modules measured) until the pipeline journal replays both. One module for both needs those fields read at run time, which keeps the buffer address and image component code of every program unfolded; that size and compile-time cost is not measured. Closes when: null and bound slots share one module at a measured cost, or the second compile is shown not to matter.
- [Formatted loads through a null host-resolved V#](../../../core/shader/recompiler/SpirvBackend/src/SpirvRuntimeBuffer.cpp) (shader recompiler) - a `buffer_load_format_*` through a host-resolved V# that is null (NUM_RECORDS 0, or a zero base) reads 0 in every component, also where its DST_SEL is SEL_1: `EmitRuntimeBufferLoad` returns zero before the DST_SELs are read, so such a V# specializes with zero fields. A GPU-resident V# is valid when its type bits are clear, its ADD_TID bit is clear outside compute and its base is nonzero, whatever its NUM_RECORDS, so one with a nonzero base, zero records and a supported format reaches the out-of-range path, where SEL_1 gives 1 or 1.0; that path predates the null specialization. RDNA2 (gfx1036) returns 0 in all four components of an out-of-range `buffer_load_format_xyzw` with DST_SEL X,Y,Z,W (#2241); SEL_1 out of range, a null V# and gfx1013 (the console) are not measured. Closes when: measured on hardware.
- [Specialized SPIR-V normalization](../../../core/shader/recompiler/SpirvBackend/src/SpirvSpecialization.cpp) (shader recompiler) - `NormalizeSpirvConstants` merges and renumbers scalar constants only, so two variants whose live code differs in any other id, for example after a SPIRV-Tools pass numbers its new ids differently, keep separate modules. An instruction whose operands it cannot classify by the SPIR-V grammar (an opcode of 4096 or more that the recompiler does not emit, a memory access mask with unknown bits, or an `OpSpecConstantOp` opcode outside the core list) is copied unchanged, keeps every constant whose id equals one of its words, and keeps its other words out of the canonical ids, so such modules collapse less. Closes when: ids are renumbered canonically and every extension opcode is decoded.
