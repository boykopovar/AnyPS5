# libSceNgs2.native

## change [libSceNgs2.native command, query, stream and enumeration exports]

- [libSceNgs2.native command, query, stream and enumeration exports](../../../core/libs/prx/libSceNgs2.native/Export.cpp) (libSceNgs2.native) - checks follow @BunnyFl's [13.42 disassembly](https://github.com/boykopovar/AnyPS5/issues/19400#issuecomment-6849148427), not a console. Inferred: system slots and queries, float store, grain limit, custom module count and stream handle validation. `sceNgs2ModuleQueueEnumItems` locks the selected queue ring, copies up to `max` items circularly, and returns the full count. The count and first index widths are inferred as 64-bit from their 8-byte field spacing. Lock commands can throw from job threads after earlier records apply, and unlocked command validation state can change. Placeholders throwing NotImplemented_nid_no_patch: StreamCreate/WithAllocator, StreamDestroy, StreamRunCommands, StreamQueryInfo, ModuleEnumConfigs, and queries 0xf04004, 0xf04070, 0xf14070.

## add Unknown function info

- [sceNgs2RackQueryInfo 0xf14002, stream and module config exports](../../../core/libs/prx/libSceNgs2.native/Export.cpp) (libSceNgs2.native) - from the same 13.42 disassembly, not a console. 0xf14002 writes the custom module's creation record, as sceNgs2CustomRackGetModuleInfo does. Rack creation keeps only the low 16 bits of the state offset, the u16 the module entry holds, so both report the cut value; whether the console's sceNgs2CustomRackGetModuleInfo reads that entry was not read. the module takes the state size from its module object's `+0xa8`, not read, so a module created with state size 0 may report its default size. The Stream exports throw past their checks: a stream is run by a system-side worker that was not read. Creation needs a system field (`+0x670`, `0x804a8405` when null) whose setter was not read, Destroy waits on the stream and runs an unread step (`0x1eb70`), and that worker sets the state bits, positions and error StreamQueryInfo reports. Query 0xf14070 returns the module objects 0xf14002 reads, and ModuleEnumConfigs the module's static config records; neither layout was read.
