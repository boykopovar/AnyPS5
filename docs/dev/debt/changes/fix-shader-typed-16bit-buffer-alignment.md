# shader

## change [V# bases off a DWORD boundary]

- [V# bases off a DWORD boundary](../../../core/shader/recompiler/SpirvBackend/src/SpirvMemory/SpirvMemoryInstructions.cpp) (shader recompiler) - raw accesses use the exact bytes, as measured on gfx1035 (Linux, alignment mode UNALIGNED), which differs from the console's mode DWORD: on a PS5 (13.40, measured 2026-10-19 by a gfx1013 kernel run from inside a retail title) a raw `buffer_load_dword` with the V# base 1 byte past a dword, or an aligned base and `voffset` 1, returned the aligned dword (0x44332211, not 0x55443322). `s_buffer_load` reads `(base & ~3) + (offset & ~3)`, as on the console. Formatted accesses off their element's alignment return zero and drop stores whatever the alignment mode, as section 8.1.7 of the RDNA2 ISA requires and gfx1036 measures (see the formatted buffer entries below); the console's formatted behaviour is unmeasured. Atomics are described by the entry after this one. Closes when: raw buffer accesses drop the two low address bits as on the console

## add Functional

- [Buffer atomics off a DWORD boundary](../../../core/shader/recompiler/SpirvBackend/src/SpirvMemory/SpirvMemoryInstructions.cpp) (shader recompiler) - atomics use the byte address `base + offset`, base's low two bits included: measured on RDNA2 (gfx1031, AMD Windows driver 32.0.21045.5002, HIP) with `buffer_atomic_add`, `_swap` and `_cmpswap`, bases 0 to 3 bytes past a DWORD boundary and offsets 0 to 7, an aligned address updates that DWORD and any other stops the dispatch, which the recompiler reports as an unaligned access fault. Closes when: unaligned buffer atomics are measured on the console

- [Formatted buffer loads off their element's alignment](../../../core/shader/recompiler/SpirvBackend/src/SpirvRuntimeBuffer.cpp) (shader recompiler) - a `tbuffer_load_format_*` or `buffer_load_format_*`, d16 forms included, returns zero for every fetched component when the byte address (V# base, index * stride, `soffset`, offset, immediate) is not a multiple of `min(element bytes, 4)`, with DST_SEL constants 0 and 1 still applied; a d16 load keeps its unfetched half. Measured on RDNA2 (gfx1036, AMD Windows driver 32.0.21043.5001, [hardware oracle](../HW_ORACLE.md); IEEE 0, DX10 clamp 1, denorm32 0, denorm16 3, round32/16 0, fp16 overflow 0) in raw and structured V#s for 8, 8_8, 8_8_8_8, 16, 16_16, 16_16_16_16 and 32 UINT (pinned by TypedBufferAlignment) and, for tbuffer loads in raw V#s, 24 more formats. RDNA2 ISA section 8.1.7 requires formatted ops aligned whatever the alignment mode; gfx1013 is not measured. Closes when: the console's rule is measured

- [Formatted buffer stores off their element's alignment](../../../core/shader/recompiler/SpirvBackend/src/SpirvRuntimeBuffer.cpp) (shader recompiler) - a `tbuffer_store_format_*` or `buffer_store_format_*`, d16 forms included, writes nothing when the byte address is not a multiple of `min(element bytes, 4)`. Measured on the same RDNA2 setup in a raw V# at offsets 0 to 7: `tbuffer_store_format_x`, `xy`, `xyz`, `xyzw` and the d16 forms on 22 formats from 8 to 128 bits (1408 rows) and `buffer_store_format_*` with the V# format on 9 formats (576 rows), all matching the rule; FormattedStoreUnaligned and RuntimeFormattedStore pin it. Stores through a structured V# and stores past the range are not measured. Closes when: the console's formatted store alignment is measured and structured stores are pinned

- [Formatted alignment paths without a test](../../../core/shader/recompiler/SpirvBackend/src/SpirvRuntimeBuffer.cpp) (shader recompiler) - the table-driven runtime-format path and the BDA path (`gpuDescriptor`) apply the same alignment gate, but no execution test reaches them. Not pinned: formats the assembler could not name (4_4, 5_6_5, 4_4_4_4, 1_5_5_5, 5_5_5_1), d16 loads of 32-bit formats, swizzled or `add_tid` V#s, and DST_SEL on a tbuffer load. On main a tbuffer load through a V# whose format field differs from the instruction's returned zero while RDNA2 ignores the V# format, so TypedBufferAlignment sets both to the same format. Closes when: these are measured and pinned in an execution test
