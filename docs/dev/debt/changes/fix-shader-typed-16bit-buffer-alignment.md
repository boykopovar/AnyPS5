# shader

## add Functional

- [Formatted buffer accesses off their element's alignment](../../../core/shader/recompiler/SpirvBackend/src/SpirvRuntimeBuffer.cpp) (shader recompiler) - a typed or descriptor-format buffer load returns zero for every component and a store writes nothing when the byte address (V# base, index * stride, `soffset`, offset and immediate) is not a multiple of `min(element bytes, 4)`, as measured on RDNA2 (gfx1036, AMD Windows driver 32.0.21043.5001, [hardware oracle](../HW_ORACLE.md); IEEE 0, DX10 clamp 1, denorm32 0, denorm16 3, round32/16 0, fp16 overflow 0) for the 8, 8_8, 8_8_8_8, 16, 16_16, 16_16_16_16 and 32 UINT formats and the 16-bit UNORM, SNORM, SINT, FLOAT and USCALED, 16_16 and 8_8 UNORM, 10_11_11, 11_11_10, 10_10_10_2 and 2_10_10_10 formats, in raw and structured V#s, through `tbuffer_load_format_*` and `buffer_load_format_*` including the d16 forms, and for `tbuffer_store_format_x/xy`. gfx1013 is not measured, and raw accesses on the console are measured to differ from this driver's alignment mode. The element size of formats the assembler could not name (4_4, 5_6_5, 4_4_4_4, 1_5_5_5, 5_5_5_1), the BDA path (`gpuDescriptor`) and the table-driven runtime-format path are not executed by a test, and `tbuffer_load_format_*` with a V# whose format field differs from the instruction's returns data on RDNA2 but zero in the recompiler. Closes when: the console's typed alignment rule is measured and the unexecuted formats and paths are pinned in an execution test
