# libSceAgcDriver

## change [11_11_10 float blending and partial writes]

- [11_11_10 float blending and partial writes](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (libSceAgcDriver) - not measured on a console: a blended or partial write into a one-sample 11_11_10 float target goes through the pixel-interlock merge, so the pixel shader blends in fp32 with the stored word, a destination alpha of 1 and MIN and MAX ignoring the factors, and packs the result toward zero once. ZERO gives 0 and ONE the operand unchanged, even for an infinite or NaN operand. The CB's blend precision and rounding for this format are unknown. The merge reads the target through an `r32ui` storage image (`r16ui` for a 4_4_4_4 partial write, which needs `shaderStorageImageExtendedFormats`), so a device without `shaderStorageImageReadWithoutFormat` runs it too. A constant or dual-source factor, a multisampled or volume target, or a device without `fragmentShaderPixelInterlock` throws. A one-sample merge into a mip or a range of 2D array slices (11_11_10, 4_4_4_4 or an unclamped normalized blend) addresses that mip of the array's resident image at the view's first slice plus `gl_Layer`, clamped to the view's last slice as the console clamps the render target index to `SLICE_MAX`.

## change [Unclamped normalized color targets]

- [Unclamped normalized color targets](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (libSceAgcDriver) - CB_COLOR_INFO targets with BLEND_CLAMP clear (bit 15) on UNORM and SNORM formats are accepted. With blending the pixel shader reads the target through its storage image under pixel interlock, evaluates the blend equation on the unclamped export, and stores the clamped result, because Vulkan clamps blend inputs to the normalized range. The result is not measured on a console. The final float to normalized rounding is Vulkan's. The shader reads the target through a storage image declared with the target's format when that has a SPIR-V storage format (R8, RG8, RGBA8, R16, RG16 and RGBA16, UNORM and SNORM; all but RGBA8 need shaderStorageImageExtendedFormats), so a device without shaderStorageImageReadWithoutFormat runs it; BGRA8, which has no SPIR-V storage format, and any other format are read without a format and are refused on such a device. A merge shares one descriptor heap with the draw's other storage images of its numeric class and dimension, so when merged targets of one draw differ in format, or a guest storage image shares the heap, a device that lacks formatless access declares one aliased heap variable per format, and the Khronos validation layer reports `Undefined-Value-StorageImage-FormatMismatch-ImageView` warnings because it checks every array element against each variable; a device with formatless access declares that heap without a format. A separate heap binding per format would avoid the warning and changes the runtime ABI. The path needs fragmentShaderPixelInterlock (refused without it), recorded draws and a single-sample resident target, and refuses dual-source blending, multisampled, packed, reversed and alternate component order targets, a signed target whose write mask skips a component (the shader rewrites it through a float, so the code -128 would become -127), and a packed target's partial write in the same draw.
