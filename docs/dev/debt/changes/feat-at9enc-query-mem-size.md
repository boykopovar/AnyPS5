# libSceAt9Enc

## change [libSceAt9Enc]

- [libSceAt9Enc](../../../core/libs/prx/libSceAt9Enc/Export.cpp) (libSceAt9Enc, sysmodule id `0x000000d1`) has no encoder, so `sceAt9EncClearContext`, `sceAt9EncCreateEncoder`, `sceAt9EncEncode` and `sceAt9EncFlush` still throw. `sceAt9EncQueryMemSize` validates its 0x34-byte parameter block and computes the required size from the 13.42 module's lookup tables and allocation formula; this was read from disassembly, not run on a console. PPSA03332 imports the exports and fails to load (`libSceAt9Enc.prx: cannot open shared object file`) when the library is absent. The names are from the aerolib NID list, and the name reads as the ATRAC9 encoder, unconfirmed

## change [sceAt9Enc*]

- [sceAt9Enc*](../../../core/libs/prx/libSceAt9Enc/Export.cpp) (libSceAt9Enc) - the signatures follow [Orbital](https://github.com/AlexAltea/orbital/blob/cc408367da6a6ebbf5ac1ac559fefeadc73b2831/tools/ida/db_types.json), which gives `int32_t sceAt9EncClearContext(void *pAt9EncWorkArea, int32_t *pInternalResult)`, `int32_t sceAt9EncCreateEncoder(void *pAt9EncWorkArea, struct *pAt9EncParam, int32_t memSize, int32_t *pInternalResult)`, `int32_t sceAt9EncEncode(void *pAt9EncWorkArea, const void *pInputBuf, void *pOutputBuf, uint32_t inputBufSize, uint32_t outputBufSize, uint32_t *pOutputDataByte, uint32_t *pUsedBufSize, int32_t *pInternalResult)`, `int32_t sceAt9EncFlush(void *pAt9EncWorkArea, void *pOutputBuf, uint32_t outputBufSize, uint32_t *pOutputDataByte, int32_t *pInternalResult)` and `int32_t sceAt9EncQueryMemSize(struct *pAt9EncParam, int32_t *pMemSize, int32_t *pInternalResult)`. The query's block size and fields used by its validator and sizing formula are established by module disassembly; public field names and semantic meanings remain unknown

## change [The argument checks]

- [The argument checks](../../../core/libs/prx/libSceAt9Enc/Export.cpp) (libSceAt9Enc) - the five exports return `0x81210001` for the arguments firmware 13.42 rejects first. `sceAt9EncQueryMemSize` now copies its 0x34-byte block, validates its size, mode, bitrate, sample rate and options, and computes memory size for valid values; invalid parameter blocks return `0x81210000` with `pInternalResult = -999`. On the host, unreadable input or unwritable outputs return `0x81210001` as a memory-safety fallback; this pointer behavior is not measured against a console. The other four exports still throw after their known argument checks. In `libSceAt9Enc.sprx` (SHA-256 `b238426de61e97a7261da2924c7731f2a44c193a96a673624a6efb6df3c6b62c`), read from disassembly and not run on a console, `sceAt9EncCreateEncoder` checks a work area that is null or not 8-byte aligned, `pAt9EncParam` and `pInternalResult`; `sceAt9EncEncode` checks the work area the same way, `pInputBuf`, `pOutputBuf`, `pOutputDataByte` and `pUsedBufSize`; `sceAt9EncFlush` checks the work area, `pOutputBuf`, `pOutputDataByte` and `pInternalResult`; `sceAt9EncClearContext` checks the work area and `pInternalResult`. The error's name is unverified
