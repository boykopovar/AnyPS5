# libSceLibreSsl

## change [PKCS12_PBE_add, SSL_load_error_strings]
- [PKCS12_PBE_add, SSL_load_error_strings](../../../core/libs/prx/libSceLibreSsl/Export.cpp) (libSceLibreSsl) - partly measured on a PS5 (below); each returns without an observable effect and queues no error. `SSL_load_error_strings` builds no string table ([ssl_err.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl/ssl_err.c#L483-L490)). `PKCS12_PBE_add` is empty in LibreSSL 2.5.4 ([p12_crpt.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/pkcs12/p12_crpt.c#L67-L70)). A PS5 (firmware 11.60, payload process; a title process may differ) returned from both calls without a signal and `ERR_peek_error` returned 0 before and after each of them, in two runs; `ERR_reason_error_string` and `ERR_lib_error_string` did not resolve in `libSceLibreSsl.sprx` under the bare name, so the claim about the string table is unmeasured.
