# libc

## change [Wide-character conversions]

- [Wide-character conversions](../../../core/libs/prx/libc/src/Multibyte.cpp) (libc) - The wide `wcsto*` functions parse the ASCII prefix of the guest string, as the C locale accepts only ASCII white space and digits. The multibyte conversions follow the C locale of the console's `libSceLibcInternal.sprx`: UTF-8 of at most three bytes, so `_Getmbcurmax` returns 3, overlong forms and encoded surrogates decode, and four-byte forms are invalid. `__mb_cur_max` stays 1 like the console's variable; `___mb_cur_max` is not in that module and also stays 1, unverified. Other locales are not supported. With a null destination, `wcstombs` returns the byte count; the console's count is wrong when the capacity argument equals the running count, because it reads past the terminator. Zero-capacity nonnull-output behavior in [wcstombs](../../../core/libs/prx/libc/src/WideConversion.cpp) follows [reported libSceLibcInternal disassembly, firmware 11.00/13.40](https://github.com/boykopovar/AnyPS5/pull/21567#issuecomment-6917764699): at 0x89260, the capacity gate at 0x89283 to 0x89298 precedes the source read. This branch and errno preservation were not independently measured on a console.
