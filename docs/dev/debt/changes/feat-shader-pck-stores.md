# shader

## change [MIMG PCK2/PCK4 loads]

- [MIMG PCK2/PCK4 loads](../../../core/shader/recompiler/SpirvBackend/src/SpirvImageEmitter.cpp) (`image_load[_mip]_pck2/pck4`, opcodes 0x70, 0x71, 0x73 and 0x74) were measured on RDNA2 (gfx1035) with the [hardware oracle](../HW_ORACLE.md) for 2D images with identity swizzle. With data mask 0x1, they write one dword: the raw bits of the N texels (PCK2: 2, PCK4: 4) from `x & ~(N - 1)` on row y, concatenated (element k at bit `k * texel bits`) and zero-extended. The dword is zero when the mip level is past the last level, `x + N - 1` is outside the level's width (unaligned x, unsigned), or y is outside its height. Data only comes back when N texels fit in 32 bits: R8, R16 or RG8 for PCK2, R8 for PCK4. Wider texels (R32, RG16, RGBA8) and masks other than 0x1 write zeros on hardware. Those masks throw at decode, and formats outside UNORM/UINT/SINT R8, R16 and RG8 throw. #1314's earlier measurement saw only zeros because it used masks 0x3 and 0xf.

## add Functional

- [MIMG PCK2/PCK4 stores](../../../core/shader/recompiler/SpirvBackend/src/SpirvImageEmitter.cpp) (opcodes 0x76, 0x77, 0x79 and 0x7a) throw for UNORM, SINT and FLOAT formats, masks other than 0x1, texels too wide for N to fit 32 bits and image tables, although RDNA2 hardware writes raw bits or nothing there; 128-bit formats were not run (0x76 hung a GPU in #1314). In 64KB_Z_X with 8-bit texels, an element the hardware writes into the padding rows below the image is dropped; tiled surfaces are measured only at mip 0 of 2D images. Measured on gfx1036 (Radeon 610M): under the load's bounds, element k (bits `k * texel bits`) goes to the byte address of (x, y) plus `k * texel bytes` while it stays in that dword. On linear surfaces and every GFX10 thin swizzle mode but 64KB_Z_X with 8-bit texels, this is texel `x + k`, so x is not aligned down as in the loads; there a dword is a 2x2 block in Morton order, and the T#'s SW_MODE selects that mapping.
