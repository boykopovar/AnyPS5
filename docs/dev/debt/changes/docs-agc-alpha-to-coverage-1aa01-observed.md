# libSceAgcDriver

## change [Alpha-to-coverage `0x1aa01`]

- [Alpha-to-coverage `0x1aa01`](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (AGC driver) - `DB_ALPHA_TO_MASK = 0x1aa01` throws `dithered or rounded alpha-to-coverage is unsupported`. It differs from the accepted undithered `0xaa01` by bit 16 (`0x10000`), which the accepted dithered `0x18701` also has: [radeonsi](https://gitlab.freedesktop.org/mesa/mesa/-/blob/bffd91947efc1932da99aca69fc540d6d4201b0c/src/gallium/drivers/radeonsi/si_state.c#L371-L381) programs `OFFSET_ROUND(1)` only with the dithered offsets and `OFFSET_ROUND(0)` for `0xaa01`, so it never programs this combination. PPSA12361 reaches it on main 74acfad65b on an RTX 4080 SUPER (`run_024721.err` lines 3484-3486) and an RX 6400 (`run_025512.err` lines 2667-2671). In one of two runs of PPSA12361 on main with the fix of #19904 (a host run, not a console probe) a draw set it with two raster samples: `PA_SC_AA_CONFIG` 0x00108001, `DB_EQAA` 0x00001111 and `PA_SC_AA_MASK` 0x0000cc44, read by a local diagnostic line that is in no change. Reading it as `0xaa01` for a one-sample draw was tried and does not unblock the title. What the console covers for this value is not measured, so it stays unsupported.
