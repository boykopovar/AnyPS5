# libSceIcu

## change [Null locale in the locale getters]

- [Null locale in the locale getters](../../../core/libs/prx/libSceIcu/LocaleCore.cpp) - `uloc_getLanguage`, `uloc_getCountry`, `uloc_getScript`, `uloc_getBaseName`, `uloc_canonicalize` and `uloc_getParent` resolve a null locale through `uloc_getDefault` as ICU does ([uloc.cpp](https://github.com/unicode-org/icu/blob/84e1f26ea77152936e70d53178a816dbfbf69989/icu4c/source/common/uloc.cpp#L1684-L1690)), so they share its divergences. After BCP 47 language-tag conversion, `uloc_getBaseName` and `uloc_canonicalize` also replace an unconverted `i-default` ID, with any subtags after it, by the default locale as ICU does ([uloc.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/uloc.cpp#L1865-L1868)); the default is parsed first: the base name uses the input's charset when it has one, and the canonical ID uses the input's keywords when it has them. A system default that is itself an `i-default` ID is canonicalized without recursing. `uloc_getISO3Language` and `uloc_getISO3Country` resolve a null locale the same way ([uloc.cpp](https://github.com/unicode-org/icu/blob/84e1f26ea77152936e70d53178a816dbfbf69989/icu4c/source/common/uloc.cpp#L1945-L1949)). Closes when: compared with the console.

## change [LocaleCore.cpp]

- [LocaleCore.cpp](../../../core/libs/prx/libSceIcu/LocaleCore.cpp) implements eleven public ICU C entry points: `uloc_getLanguage`, `uloc_getCountry`, `uloc_getScript`, `uloc_getBaseName`, `uloc_canonicalize`, `uloc_getKeywordValue`, `uloc_getParent`, `uloc_getISO3Language`, `uloc_getISO3Country`, `uloc_getISOLanguages` and `uloc_getISOCountries`. These use typed System V guest signatures with 32-bit length/status fields, copy and overflow semantics, case normalization, locale components, and keyword lookup. `uloc_getParent` truncates at the last `_` of the whole ID and applies the `und_` shift of [ICU 68.2](https://github.com/unicode-org/icu/blob/84e1f26ea77152936e70d53178a816dbfbf69989/icu4c/source/common/uloc.cpp#L1642-L1674). The ISO 3166 and ISO 639 answers follow [ICU 68.2](https://github.com/unicode-org/icu/blob/84e1f26ea77152936e70d53178a816dbfbf69989/icu4c/source/common/uloc.cpp#L1945-L1980), whose `LANGUAGES`, `LANGUAGES_3`, `COUNTRIES` and `COUNTRIES_3` tables, including their obsolete-code second lists, are copied verbatim, and `uloc_getISOLanguages` and `uloc_getISOCountries` return those tables ([uloc.cpp](https://github.com/unicode-org/icu/blob/84e1f26ea77152936e70d53178a816dbfbf69989/icu4c/source/common/uloc.cpp#L2083-L2098)). Release-active guest tests and Linux ASan/UBSan/leak checks cover bounded buffers, malformed keyword items, and status propagation; 22,647 additional input/capacity combinations were differential-checked against *native desktop ICU 74*. This is a source-compatible subset, not an assertion of PS5 firmware 68 binary equivalence. Long/host-specific aliases, obscure locale grammar, data-driven locale operations, and arbitrary malformed input remain unverified. Neither PS5 hardware calls nor a console trace was available.

## add Functional

- [ISO code locale exports](../../../core/libs/prx/libSceIcu/LocaleCore.cpp) - `uloc_getParent`, `uloc_getISO3Language`, `uloc_getISO3Country`, `uloc_getISOLanguages` and `uloc_getISOCountries` previously threw through parameterless legacy stubs. They follow [ICU 68.2](https://github.com/unicode-org/icu/blob/84e1f26ea77152936e70d53178a816dbfbf69989/icu4c/source/common/uloc.cpp#L1642-L2098) with the `LANGUAGES`, `LANGUAGES_3`, `COUNTRIES` and `COUNTRIES_3` tables copied verbatim, obsolete-code second lists included, and `uloc_getISOLanguages` and `uloc_getISOCountries` return those tables. A deprecated three-letter language answers through the second lists like ICU 68, which the two-letter-shortening locale getters do not. No console ABI or behavior verification; the ISO answers compose with the locale getters, whose own divergences apply. Closes when: compared with the console.
