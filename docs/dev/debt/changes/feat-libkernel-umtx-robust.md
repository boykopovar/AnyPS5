# libkernel

## change [_umtx_op]

- [_umtx_op](../../../core/libs/prx/libkernel/SyncOnAddress/src/SyncOnAddress.cpp) (libkernel) - legacy lock and `SHM` operations throw, as do robust `MUTEX_WAKE2`, `SET_CEILING`, unlocking or `CV_WAIT` on an owned priority-protected umutex, and misaligned objects; robust lists of threads not started by `scePthreadCreate` are ignored at exit. Priority inheritance is not applied and an owned PI mutex relocks where FreeBSD gives `EDEADLK`; `CVWAIT_CHECK_UNPARKING` is ignored. A PS5 (firmware 13.40) relocks an owned mutex uncounted and frees it with one unlock, fails a priority-protected one with `EINVAL` (robust ones unmeasured), leaves `URWLOCK_READ_WAITERS` set after a reader times out and uses `scePthreadGetthreadid` owners. Operations 0, 1, 7 and 27 answer as measured; 27 with valid arguments and higher operations are unmeasured. The rest follows FreeBSD 11's [kern_umtx.c](https://github.com/freebsd/freebsd-src/blob/5ed7eb0d97ba4436218e810f61bd059acba984c2/sys/kern/kern_umtx.c).
