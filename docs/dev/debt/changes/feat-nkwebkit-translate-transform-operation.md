# libSceNKWebKit

## add Functional

- [TranslateTransformOperation layout and vtable](../../../core/libs/prx/libSceNKWebKit/src/TranslateTransformOperation.cpp) (libSceNKWebKit) - not compared with a console module: its WebKit revision is unverified. The firmware exports disagree with the pinned [TranslateTransformOperation.h](https://github.com/neonmodder123/PS5-WebKit-11.x/blob/80f77e94c63ee7202eec3d4b5b1a021dd89011ba/Source/WebCore/platform/graphics/transforms/TranslateTransformOperation.h) (`blend` takes `double` and `bool` where the pinned class takes a `BlendingContext`; the size getters export as `x`/`y`/`z(FloatSize)` where the pinned class has `xAsFloat`/`yAsFloat`/`zAsFloat`), so the 12-slot vtable laid out per its [TransformOperation.h](https://github.com/neonmodder123/PS5-WebKit-11.x/blob/80f77e94c63ee7202eec3d4b5b1a021dd89011ba/Source/WebCore/platform/graphics/transforms/TransformOperation.h) is unverifiable. The 16-byte base and 40-byte object assume a release `RefCounted` (no `m_isOwnedByMainThread`).
- [TranslateTransformOperation behaviour](../../../core/libs/prx/libSceNKWebKit/src/TranslateTransformOperation.cpp) (libSceNKWebKit) - not compared with a console module. `blend` reads the firmware `double` as `BlendingContext::progress` with Replace semantics and computes the float blend in double before rounding, where the console's float blend is unverified. `Length` does not model CalculationValue reference counting, so the constructors, `create`, `clone`, the destructor and the Length-returning `x`/`y`/`z` throw through `NotImplemented_nid_no_patch` when a member is Calculated; the calculated branch of `blendMixedTypes`, `dump` and `operator==` of calculated lengths, and `floatValueForLength` in the size getters, `isIdentity` and `selfOrCopyWithResolvedCalculatedValues` also throw. `dump` throws on an out-of-range operation type where the pinned stream operator prints nothing.
