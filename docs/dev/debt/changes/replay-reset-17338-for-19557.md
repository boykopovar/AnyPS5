# libSceAgcDriver

## add Opt-in draw paths

- [Frame replay on Linux needs the kernel write watch](../../../core/libs/prx/libSceAgcDriver/tools/FrameReplay.cpp) (libSceAgcDriver) - `agc_frame_replay` registers every captured watched range with the guest write watch, which needs `PAGEMAP_SCAN` and asynchronous userfaultfd write protection (Linux 6.7 or newer, and kernel headers that define them at build time). Without them the replay stops with the reason (the failing build, kernel feature or ioctl, and the errno of a failed call or registration) and does not fall back to comparing, because native multisample depth and the page-wise `--repeat` reset need the watch. Closes when: replay has a measured comparison path for ranges the watch cannot cover.
- [CPU writes to a depth plane under a host import](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DepthSurface.cpp) (libSceAgcDriver) - on Linux a host import over a depth surface's memory keeps those pages compared rather than write-watched, so a title's CPU store into the depth, stencil or HTILE plane of a resident depth surface is not seen by the surface, which keeps using its image. `agc_frame_replay --repeat` works around it for its own restores by retiring every depth surface whose planes or HTILE overlap a page the reset compares; a title running live gets no such retirement. Closes when: a CPU store under a host import reaches the depth surfaces over it (write-watched import pages or a compare at the next use).
- [Guest memory transaction excludes submissions and mapping changes by contract](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/EntryPoints.cpp) (libSceAgcDriver) - `AgcDriverGuestMemoryTransaction` stops storage-image stores and GPU-lock holders but holds back neither submissions nor mappings; the caller must quiesce every submitter and mapper first (`agc_frame_replay` joins its call and wait-releasing threads). Its accepted-serial check runs after the body, so it only detects a violation afterwards, misses a `Submit` still copying commands and never sees unordered CPU flips, which are not counted; the reset fails when `GuestAllocationsGeneration` changed, and a worker can fault on a page unmapped under it first. Closes when: a caller runs guest threads during the transaction, which then holds submissions back and pins the mappings it touches.
