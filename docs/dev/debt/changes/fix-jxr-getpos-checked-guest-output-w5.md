# libSceJxr

## change [WMPAlloc, WMPFree and the memory stream]

- [WMPAlloc, WMPFree and the memory stream](../../../core/libs/prx/libSceJxr/Export.cpp) (`CreateWS_Memory`, `EOSWS_Memory`, `ReadWS_Memory`, `WriteWS_Memory`, `SetPosWS_Memory`, `GetPosWS_Memory`): console code and layouts are unverified. They follow pinned jxrlib [strcodec.c](https://github.com/4creators/jxrlib/blob/f7521879862b9085318e814c6157490dd9dbbdb4/image/sys/strcodec.c#L246-L447) on the LP64 `WMPStream` layout, allocating with guest `calloc(1, cb)` and `free`; that the module is built from jxrlib is inferred from the export names. The `Close` callback is jxrlib's `CloseWS_Memory`, which the export inventory lacks. Where jxrlib dereferences null, `std::invalid_argument` is thrown: a null `ppv`, stream or `poffPos`, and a null buffer when a read or write copies at least one byte. `GetPosWS_Memory` now copies its position through a checked guest write and preserves `errno`; an inaccessible non-null output throws the same invalid-argument exception as a null output instead of crashing the host. This is a host safety fallback, not console-verified behavior, and may partially modify a guest mapping if a write spans inaccessible pages. Other memory-stream guest inputs and outputs are not comprehensively checked. Closes when: the console's functions are disassembled or measured on a PS5
