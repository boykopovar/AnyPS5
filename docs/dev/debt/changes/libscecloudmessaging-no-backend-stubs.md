# libSceCloudMessaging

## change [libSceCloudMessaging inventory exports]

- [libSceCloudMessaging message exports](../../../core/libs/prx/libSceCloudMessaging/Export.cpp) - `SceCloudMessaging::CreateMessage` and `SceCloudMessaging::SendMessageAsync` still throw. The parameterless declarations are import-resolution placeholders and the mangled-name encoded signatures are not treated as verified ABI contracts. No cloud backend is reachable, and reporting a created or sent message without one would be a silent stub that affects title logic. `SceCloudMessaging::Initialize`, `SceCloudMessaging::Terminate`, `SceCloudMessaging::RegisterMessaging` and `SceCloudMessaging::UnregisterMessaging` return 0 as no-ops: no host backend is started, no state is kept, so there is nothing to tear down and a repeat init is idempotent. All six names and NIDs remain confirmed in the complete [PS5 13.60 export inventory](https://github.com/xdCloudy/PS5-13.60-Function-Stub-Library/blob/bfec40deb4c47a17d7603ee2bc79aa6862c0c56b/data/firmware-13.60/libscecloudmessaging-1d0153bc23.jsonl) and the pinned [module map](https://github.com/boykopovar/ps5-nid-map/blob/cc1d586fddab576a520f226da6b2632b031e6d09/data/Modules/libSceCloudMessaging.inc).
