# libSceNgs2

## change [sceNgs2ParseWaveformUser, sceNgs2SystemEnumHandles, sceNgs2SystemEnumRackHandles]
- [sceNgs2ParseWaveformUser, sceNgs2SystemEnumHandles, sceNgs2SystemEnumRackHandles](../../../core/libs/prx/libSceNgs2/PendingExports.cpp) (libSceNgs2) - implemented in `libSceNgs2.native/src/System.cpp` from the firmware 11.00 module at `0x10810`, `0xf270` and `0xf0d0`. `sceNgs2ParseWaveformUser` passes a type-2 read descriptor to the module helper at `0xfac0`, which calls the handler as `handler(user_data, offset, data, size)` and expects an `int32_t`; in the module a negative return becomes `0x804A0408`, as does a null handler, and a null output becomes `0x804A0053`. The 256 MiB RIFF cap, which returns `SCE_NGS2_ERROR_INVALID_WAVEFORM_DATA`, and buffering the whole RIFF body after the 12-byte header are this implementation's safety choices, not measured on a console. The enumerators return the count of live systems or racks and fill up to the requested count; a null output with a nonzero count returns `0x804A0053` and an unknown system `0x804A0230`. A PS5 (firmware 11.60, payload process; a title process may differ) gave the same results for the cases it was asked, without creating a system: a handler returning -1 and a null handler `0x804A0408`, a null output `0x804A0053`, `sceNgs2SystemEnumHandles` with no system 0 and the array unchanged, `sceNgs2SystemEnumHandles` with a null array and a count of 4 `0x804A0053`, and `sceNgs2SystemEnumRackHandles` with the system 0 `0x804A0230`, none of them faulting; what a handler that succeeds leads to was not measured. No dump imports these NIDs.
