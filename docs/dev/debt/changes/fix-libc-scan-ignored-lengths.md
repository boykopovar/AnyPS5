# libc

## add Functional

- [sscanf_s and vsscanf_s](../../../core/libs/prx/libc/src/Formatting.cpp) (libc), and plain `sscanf` formats scanned in process, ignore the length modifiers that the `libc.prx` of 99 titles (PPSA08194 and PPSA34008 among them) ignores: `L` on an integer conversion or `%n` stores an `int`, and a floating conversion stores a `float` unless its length is `l` (`double`) or `L` (`long double`), so `%llf`, `%jf`, `%zf` and `%tf` store a `float`. The stream forms keep the host's handling.

## change the numbering is not confirmed on the console

- [_WStoul](../../../core/libs/prx/libc/src/Strings.cpp), [_Iswctype](../../../core/libs/prx/libc/src/RuneLocale.cpp), [swscanf_s and swscanf](../../../core/libs/prx/libc/src/ScanningWide.cpp) (libc) - `_WStoul` is `wcstoul`; a base other than 0 or 2 to 36 returns 0, stores the start of the string in the end pointer and leaves `errno` unchanged, as Dinkumware's `xstoul.c` does, unverified on the console. `_Iswctype` takes the class numbers of Dinkumware's [xwcc.h](https://github.com/superna9999/ti-cgt6x/blob/cgt6x_7_3_4/include/xwcc.h) (1 `alnum` to 11 `xdigit`, 12 `blank`) and throws for any other value, including the FreeBSD masks `wctype` returns; the numbering is not confirmed on the console's `libc.prx`. `swscanf_s` follows C11 7.29.2.2 and K.3.9.1.5, but reads the size argument as `unsigned int` like `sscanf_s` where K.3.9.1.5 specifies `rsize_t`; the console's width is unverified. A runtime-constraint violation (null buffer, format or receiving pointer) only returns `EOF`, and a too small string or scanset array gets a null first element as in `sscanf_s`. A literal at end of input returns the number of assignments, including zero, rather than `EOF` as FreeBSD does, as reported from the console scanner in #8479; `%%` at end of input still returns `EOF`. A literal mismatch is a matching failure, where FreeBSD's `vfwscanf` reports an input failure. An incomplete floating exponent such as `1e+` converts its mantissa, as reported from the console scanner in #8479; other incomplete exponent forms are not separately verified. Short `%c` assignments follow FreeBSD 11.4; only `%lc` buffer results have contributor-reported native measurements of one bundled build in [#9321](https://github.com/boykopovar/AnyPS5/issues/9321#issuecomment-6342217421), not console or other-version verification. Zero-capacity wide-field input consumption, empty-input precedence and general narrow byte-capacity rules remain unverified. Short narrow-destination fields whose capacity is below the width still throw after consuming input but before writing, unlike the reported undersized ASCII case. Wide-destination limits and zero-capacity return/output use [contributor-reported native calls to three bundled builds](https://github.com/boykopovar/AnyPS5/pull/9863#issuecomment-6357861510), not console measurements; stream parity remains unverified. An integer field that is only a prefix, such as `0x`, does not convert; FreeBSD's `vfwscanf` pushes back the `x` and converts the `0`. Integers out of range are truncated from `strtoll`/`strtoull`. `%p` follows FreeBSD 11's [vfwscanf.c](https://github.com/freebsd/freebsd-src/blob/4ab2e064d7950be84256d671a7ae93f87cc6aa36/lib/libc/stdio/vfwscanf.c#L610-L615): a hexadecimal integer with an optional `0x`, converted as unsigned and stored as a pointer; a length modifier on it is ignored, as in FreeBSD and the console's scanner. `%S` and `%C`, with any length modifier or `*`, end the scan as a matching failure, as the console's Dinkumware scanner in PPSA21564's `libc.prx` treats them as invalid conversions; this was read from the module, not run on a console, and whether input ending before them is an input failure instead is unverified. Scanset ranges, `%s`, `%c` and `%[` with a length other than `l` (read as narrow), `L` on an integer conversion (an `int`), any length on `%p`, and unknown conversions and unterminated sets (a matching failure) follow the `libc.prx` of PPSA07923 and PPSA05916. Unknown conversions at end of input, such as `%y` on empty input, are unmeasured; their matching-failure result is unverified. A zero field width is no width, `%n` ignores a width and `%*n` stores nothing, as the `libc.prx` of 99 titles does. A floating conversion with a length other than `l` or `L` stores a `float`, as the `libc.prx` of 99 titles does. It throws for other unknown integer length modifiers, and narrow `%s`, `%c` or `%[` input that the C-locale `wcrtomb` cannot convert. `swscanf` runs the same scanner without the size arguments of `%s`, `%c` and `%[`, as FreeBSD's [swscanf.c](https://github.com/freebsd/freebsd-src/blob/d106002967eff712894ab8b5337bbbff106ce5e0/lib/libc/stdio/swscanf.c) passes its arguments to `vswscanf`, so everything above except the sizes applies to it; it also keeps the null buffer, format and receiving pointer checks returning `EOF`, where C leaves those undefined. Neither variant is confirmed on a PS5 title
