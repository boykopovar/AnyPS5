# libSceCesCs
## change [sceCesRefersUcsProfileCp864]
- [sceCesRefersUcsProfileCp864](../../../core/libs/prx/libSceCesCs/SingleByte.hpp) (libSceCesCs) - title-process behavior is unverified. A PS5 (firmware 11.60, payload process) matched Microsoft's [CP864.TXT](https://unicode.org/Public/MAPPINGS/VENDORS/MICSFT/PC/CP864.TXT) through `sceCesSbcToUtf32` for all 256 bytes (250 successes, CRC32 0xca172948 over the return-code and scalar pairs), as this does. Byte 0x25 maps to U+066A, and U+0025 has no byte. The six undefined bytes (0x9B, 0x9C, 0x9F, 0xA6, 0xA7 and 0xFF) return `UNASSIGNED_CODE` and write scalar 0. On measured conversion errors `sceCesUtf32ToSbc`, `sceCesUcs2ToSbc` and `sceCesSbcToUcs2` also write 0. `sceCesSbcToUtf8` leaves the output bytes unchanged and writes length 0 for 0x9B and 0xFF.
