# shader

## add Functional

- [Swizzled buffer addressing](../../../core/shader/recompiler/SpirvBackend/src/SpirvRuntimeBuffer.cpp) (shader recompiler) - the address of an untyped `buffer_load_*` and `buffer_store_*` through a V# with word 1 bit 31 and a nonzero stride is measured on RDNA2 (gfx1036, AMD Windows driver 32.0.21043.5001, [hardware oracle](../HW_ORACLE.md); IEEE 0, DX10 clamp 1, denorm32 0, denorm16 3, round32/16 0, fp16 overflow 0) in wave32 and wave64 with a source buffer whose dwords are all distinct, and pinned in [BufferSwizzledAddress](../../../core/libs/prx/libSceAgcDriver/tests/execution/BufferSwizzledAddress.cpp) for index strides 8, 16, 32 and 64, strides 16 and 32, byte, short, dword, dwordx2 and dwordx4 accesses, instruction offsets and ADD_TID. ELEMENT_SIZE (word 3 bits 20:19) has no effect and the element is 4 bytes. Not measured on gfx1013 (the console). Swizzling applies only with IDXEN or with ADD_TID and no IDXEN; ADD_TID adds the lane to the index only without IDXEN. A multi-dword access with IDXEN reads and writes contiguous bytes from the swizzled address of its first dword; without IDXEN (ADD_TID) each dword is swizzled at its own offset. Out-of-range behaviour is not changed: on the same GPU a swizzled or index-less access with `NUM_RECORDS` 4 or 16 in OOB_SELECT 0 to 3 reads data where the recompiler reads zero, and OOB_SELECT 2 and 3 on an unswizzled stride-16 V# with `NUM_RECORDS` 4 does too. Typed (MTBUF and formatted MUBUF) swizzled accesses, graphics stages, SOFFSET and stores without IDXEN are not measured. Closes when: the bounds of swizzled and index-less accesses are measured per OOB_SELECT and implemented (the structured stride rule is [#21924](https://github.com/boykopovar/AnyPS5/pull/21924)).
