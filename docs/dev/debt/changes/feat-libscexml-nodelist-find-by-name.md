# libSceXml

## change [NodeList]

- [NodeList](../../../core/libs/prx/libSceXml/src/NodeList.cpp) and the three `Document` reads that fill one, `getChildNodes`, `getAttributes` and `getElementsByTagName` (libSceXml) - the argument lists come from the mangled names, which carry them; the behaviour is not measured on a console. Each list is a host-side vector of `NodeId` values behind a 72-byte block from the initializer's allocator, the size the other objects here allocate, and the block is freed by `terminate` or the destructor. Not modelled:
  - `initialize` returns `0x80850002` without an initializer and `0x00850003` when the list is already running; `clear` and the insertions return `0`, and every one of them on a list that was never initialized returns `0x80850002`.
  - `removeItem` removes the first item whose three `NodeId` fields are equal and returns `0`, or `0x80850201` when no item matches; that status is the module's node-not-found code, but that this export uses it is inferred. `insertFirst`, `insertLast` and `removeItem` accept duplicates and null `NodeId`s, which may differ from the module.
  - `item` and `operator[]` return a copy of the stored `NodeId`, or the zeroed one past the end; the return being a `NodeId` by value is inferred from the store, not read from the module, and the Itanium ABI returns it through the hidden pointer the declarations leave to the compiler. `getLength` is 0 and `isAvailable` is false on a list that is not running.
  - The three `Document` reads replace the list's contents with the children, the attributes or the descendants whose node name equals the given string, in document order, and return `0`, or `0x80850002` when the document or the list is not initialized; a null or empty name empties the list, and the starting node is not one of its own matches, both unmeasured. A null list throws, as every null object here does.
  - `findItem(const String*)` returns, through the hidden result pointer, the first item whose node name, as `Document::getNodeName` reads it, equals the name's characters up to their terminator (the size is ignored), or the null `NodeId`; a list that was never initialized gives the null `NodeId`, a null name or name buffer throws, and null items are skipped. This follows a decrypted PS4 `libSceXml.sprx`, where the search compares each node's name with `strcmp`; it is not compared with a PS5 module.
  - `findItem(NodeId)` still throws. The reverse-engineered [Vita `sce::Xml::Dom::NodeList`](https://github.com/shoui520/psp2/blob/4c42e80892418c1743c98fd5f71b389f92243824/sys/internal/usermode/src/bXCe/node_list.cpp) searches for a matching node handle, while the decrypted PS4 module appends the node to the list and returns a `NodeId` built from a document pointer the list keeps. The two candidate behaviours conflict and neither is measured against PS5 firmware. Closes when: measured on a PS5.
  - `Document::getXmlMeta` still throws. In the PS4 module it returns a `NodeId` with flag 1 for a declaration record this model does not keep.
