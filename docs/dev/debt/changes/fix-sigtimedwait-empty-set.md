# libkernel

## change [sigtimedwait]

- [sigtimedwait](../../../core/libs/prx/libkernel/System/src/Signals.cpp) (libkernel) waits on a process-wide pending set instead of throwing: a signal raised while blocked stays pending and is taken by `sigwait`, `sigwaitinfo` or `sigtimedwait`, delivered to the handler when `_sigprocmask` unblocks it, or delivered by `pause`. Every `kill`, `raise` and `pthread_kill` queues its own entry for the number, up to 1024 entries (our limit; a PS5 payload process (firmware 11.60, 2026-11-08) gave 20 waits for 25 sends and was not tried beyond that): the waits take entries sent by `raise` and `pthread_kill` before those sent by `kill`, and a handler runs once per entry when the signal is unblocked. Repeated expiries of the alarm timer merge into one entry. The console's order among entries of one kind and a title process were not measured. The set covers all 128 signals and the lowest number that is pending and in the set is selected (FreeBSD specifies the lowest number only among real-time signals). An empty set fails with `EINVAL` in `sigwaitinfo`, `sigwait` and `sigtimedwait` with a `NULL` timeout, where FreeBSD 11.4 ([`kern_sigtimedwait`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_sig.c#L1248-L1345)) waits: `sigwait` until the thread is cancelled, `sigwaitinfo` and `sigtimedwait` until cancelled or interrupted by a caught signal without `SA_RESTART`, and neither ends a wait here. Selection, `EAGAIN` on timeout (also for an empty set), `EINVAL` for a `tv_nsec` outside 0 to 999999999 while nothing is pending and `NULL` timeout blocking indefinitely follow FreeBSD's [sigtimedwait(2)](https://man.freebsd.org/cgi/man.cgi?query=sigtimedwait). `sigwait` returns 0 with the number in its output, as POSIX specifies, and `sigwaitinfo` and `sigtimedwait` return the number, as FreeBSD does. The guest `siginfo_t` follows FreeBSD 11's `sys/sys/siginfo.h`: 80 bytes, `si_signo` at 0, `si_code` at 8, `si_pid` at 12, `si_uid` at 16, `si_addr` at 24, `si_value` at 32 and `si_band` at 40; only `si_signo`, `si_code` and `si_pid` (the guest pid) are written, with `SI_USER` for `kill` and `SI_LWP` for `raise` and `pthread_kill`, `si_uid` stays 0 because no uid is modelled, and the console's layout is not verified. PPSA85300 imports `sigtimedwait` and fails to load without it; its only call site is VLC's `vlc_writev` ([filesystem.c](https://github.com/videolan/vlc/blob/6de05adcbaf2e8b85fe86aad4169393098628119/src/posix/filesystem.c#L243-L278)), which polls with a zero timeout to drain a `SIGPIPE` only after `writev` fails with `EPIPE`. The waits are not cancellation points and an unblocked caught signal does not interrupt them with `EINTR`, where FreeBSD's `sigwaitinfo` and `sigtimedwait` may return it. On Linux guest 13 is the host's `SIGPIPE` (see `read, write and vector I/O`): with a handler and 13 blocked, a write that fails with `EPIPE` leaves 13 pending for VLC's drain, and with 13 ignored nothing is pending, as FreeBSD 11.4's [`tdsendsignal`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/kern_sig.c#L2174-L2189) discards an ignored signal before it looks at the mask; under the default disposition the host's default action ends the process even while 13 is blocked, where FreeBSD keeps it pending. Nothing is raised on Windows, so the drain finds nothing there
