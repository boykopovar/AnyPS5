# libSceTextToSpeech

## change [sceTextToSpeechGetStatusImpl, sceTextToSpeechInitImpl and `L-pHC7qtEug`]

- [sceTextToSpeechGetStatusImpl, sceTextToSpeechInitImpl and `L-pHC7qtEug`](../../../core/libs/prx/libSceTextToSpeech/Export.cpp) (libSceTextToSpeech) - only the argument checks are modelled and the calls throw past them, except `sceTextToSpeechInitImpl` for a PS4 title (below); what they do then, the names of the second argument and the layout behind it are unknown (types from register use). Firmware 13.42's `libSceTextToSpeech.sprx` (SHA-256 `76c4b8869383ea1b92a4e13c9239bee045a63ba2ab7ff452c464d22c3d5f7cee`), read from disassembly and run under a CPU emulator on x86-64, not on a console: a first argument above 2 (unsigned), or not 1 or 2 for `L-pHC7qtEug`, returns `0x814900FF`; then a null second argument returns `0x81490014` (`sceTextToSpeechGetStatusImpl`), `0x81490010` (`sceTextToSpeechInitImpl`) or `0x8149001A` (`L-pHC7qtEug`), before any call.

## add Unknown function info

- [sceTextToSpeechInitImpl](../../../core/libs/prx/libSceTextToSpeech/Export.cpp) (libSceTextToSpeech, PS4) - AnyPS5 runs no text-to-speech server, so past the argument checks a PS4 title gets `0x814900FF`: `libSceTextToSpeech.sprx` of PS4 firmware 13.52 (0x11240, read from disassembly, not measured on a console) returns it when `sceKernelOpenEventFlag("SceTtsServerEventFlag")`, the poll of bit 1 (mode 0x21) or the close fails, before it reads the parameter. With a server it needs bits 0x100 and 0x2000000 of the flag (else `0x81490004`), refuses a second initialization (`0x81490023`), builds a 0x11918-byte engine (`0x81490001` if that fails), clears the parameter's dword at 4 for ids 0 and 1 and starts the engine with that dword and the pointer at 8; none of that is modelled. A PS5 title still throws. CUSA24767 01.71 calls it once at start.

## change [sceTextToSpeechCancelImpl, sceTextToSpeechCloseImpl

- [sceTextToSpeechCancelImpl, sceTextToSpeechCloseImpl, sceTextToSpeechOpenImpl, sceTextToSpeechPauseImpl, sceTextToSpeechResumeImpl, sceTextToSpeechSpeakContinuousImpl, sceTextToSpeechSpeakImpl, sceTextToSpeechTermImpl and NID `6ZLFpZLuqEk`](../../../core/libs/prx/libSceTextToSpeech/Export.cpp) (libSceTextToSpeech) - `sceTextToSpeechInitImpl` never initializes the library (it throws, or fails for a PS4 title); these answer as firmware 13.42 does then, claiming only the 32-bit first argument and result. From disassembly of `libSceTextToSpeech.sprx` (SHA-256 `76c4b8869383ea1b92a4e13c9239bee045a63ba2ab7ff452c464d22c3d5f7cee`), not run on a console: a first argument above 2 (unsigned), or not 1 or 2 for Pause, Resume and `6ZLFpZLuqEk`, or not above 0 (signed) for SpeakContinuous, returns `0x814900FF`; otherwise the state word at `0x18048` is read, and while it is 0 they return `0x81490020`. It starts zero and only `sceTextToSpeechInitImpl` (`0x319f`) sets it from 0.
