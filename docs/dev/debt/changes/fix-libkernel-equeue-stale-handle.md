# libkernel

## change [sceKernelCreateEqueue and sceKernelGetKqueueFromEqueue]

- [sceKernelCreateEqueue and sceKernelGetKqueueFromEqueue](../../../core/libs/prx/libkernel/Equeue/Equeue.cpp) (libkernel) - an equeue is a kqueue descriptor, as in firmware 13.42 `libkernel_sys.sprx`, which creates a kqueue and a named object and returns `(id << 32) | descriptor`, waits with `kevent` on the descriptor and deletes the named object before closing it (disassembly, not run on a console). The id here is a counter, not a named object. Pinning an equeue handle refuses a handle whose id half does not match the queue registered at its descriptor, so a stale handle whose descriptor number was recycled answers `EBADF` from the add, trigger and delete event calls, `sceKernelWaitEqueue`, `sceKernelDeleteEqueue` and the file event calls, as on the console the named object is deleted before the descriptor closes and a stale handle cannot match a live queue. `kevent` on an equeue's descriptor collects events with the `sceKernel*Equeue` loop and `sceKernelWaitEqueue` on a descriptor from `kqueue` with the kevent loop (see the kqueue and kevent entry), where the console has one queue; which loop the console follows for the other caller is unknown. A null `eq` returns `EINVAL`, where that module writes through it. A PS5 payload process (firmware 11.60, 2026-11-07) refused a name of 32 or more characters with `ENAMETOOLONG` and left the output unset, and accepted names of 0, 9 and 31 characters, as here; a title process was not measured
