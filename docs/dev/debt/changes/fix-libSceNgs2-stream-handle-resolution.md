# libSceNgs2.native

## change [libSceNgs2.native command, query, stream and enumeration exports]

- [libSceNgs2.native command, query, stream and enumeration exports](../../../core/libs/prx/libSceNgs2.native/Export.cpp) (libSceNgs2.native) - checks follow @BunnyFl's [13.42 disassembly](https://github.com/boykopovar/AnyPS5/issues/19400#issuecomment-6849148427), not a console. Inferred: system slots and queries, float store, grain limit, custom module count and stream handle validation. Stream handles are not backed by any object, so sceNgs2StreamDestroy, sceNgs2StreamRunCommands and sceNgs2StreamQueryInfo answer 0x804a8204 for every handle, null or not, before the out buffer info, the command records and the info id. `sceNgs2ModuleQueueEnumItems` locks the selected queue ring, copies up to `max` items circularly, and returns the full count. The count and first index widths are inferred as 64-bit from their 8-byte field spacing. Lock commands can throw from job threads after earlier records apply, and unlocked command validation state can change. Placeholders throwing NotImplemented_nid_no_patch: StreamCreate/WithAllocator, ModuleEnumConfigs, and queries 0xf04004, 0xf04070, 0xf14070. StreamCreate/WithAllocator stop after the option checks, the 0x804a8021 buffer check and the system handle check: the system field at +0x670 (0x804a8405) and its setter were not read, and the 0x368-byte stream object, its two 0x28 * num_blocks rings and the carved buffers' contents are unread, so a stream cannot be live and Destroy's live path (the +0x268 wait, internal step 0x1eb70, the 64-byte buffer info copy and the free callback, which still returns 0 on a step error) is unreachable and unverified.

## add Unknown function info

- [sceNgs2RackQueryInfo 0xf14002, stream and module config exports](../../../core/libs/prx/libSceNgs2.native/Export.cpp) (libSceNgs2.native) - from the same disassembly. 0xf14002 copies the custom module's creation record. Rack creation keeps the low 16 bits of the state offset, the u16 the module entry holds, so sceNgs2CustomRackGetModuleInfo reports them too, PS4 library included. The console's sceNgs2CustomRackGetModuleInfo was not read, so it is not known whether it reports that entry. The console takes the state size from the module object's `+0xa8`, not read, so a module created with state size 0 may report a default. Stream exports throw past their checks: an unread system-side worker runs each stream. Creation needs a system field (`+0x670`) whose setter was not read, Destroy runs an unread step (`0x1eb70`), and the worker sets what StreamQueryInfo reports. Query 0xf14070 returns the module objects and ModuleEnumConfigs the static config records; neither layout was read.
