# shader

## change [read-only image slots]

- AMD image descriptors with `TYPE=0` are treated as null for [read-only image slots](../../../core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp) even when the base and other words are nonzero: `image_load` on a gfx1035 with such a T# returns 0,0,0,0, and the same descriptors were seen in direct reads in PPSA01341 on an RTX 4070. Written non-atomic slots outside an image table are treated as null too; atomic image slots and entries of an image table keep faulting, and the reserved types 2-7 also fault. Measured on RDNA2 (gfx1036, AMD Windows driver 31.0.22044.1) in wave32, separate from the implementation: through a 2D T# with `TYPE=0` or `TYPE=1` over a writable nonzero base, `image_store` with 32_FLOAT and 32_UINT leaves memory unchanged, and `image_atomic_add`, `image_atomic_swap`, `image_atomic_umax` and `image_atomic_cmpswap` with 32_UINT leave memory and the data register unchanged, without a fault, where the same words with `TYPE=9` write and, with `glc`, return the pre-op value; wave64 matches for the stores (driver 32.0.21045.29003, [hardware oracle](../HW_ORACLE.md)); image-table entries, wave64 atomics, other descriptor types, formats and atomic opcodes are not measured. `TYPE=1` is treated as null in the same read-only slots: gfx1035 reads it as zeros too, and gfx1010 returns zeros for `image_sample_lz`, `image_sample_b`, `image_load` and `image_get_resinfo` with format 22 (#5828); on RDNA2 (gfx1036, AMD Windows driver 31.0.22044.1) in wave32 a 2D T# with `TYPE=0` or `TYPE=1` and a readable nonzero base returns zeros without a fault for `image_load` and `image_sample_lz` with formats 32_FLOAT, 8_UNORM, 16_SSCALED, 2_10_10_10_SNORM and 16_UNORM, for `image_sample_b` and `image_get_resinfo` with the first four, and for depth-compare reads (`image_sample_c_lz`, `image_sample_c`) with 32_FLOAT and 16_UNORM, where the same words with `TYPE=9` return the texels, sizes and compare results; in wave64 `image_load`, `image_load_mip`, `image_sample_lz` and `image_get_resinfo` with 32_FLOAT and 32_UINT return zeros too ([ImageNullTypeWave64](../../../core/libs/prx/libSceAgcDriver/tests/execution/ImageNullTypeWave64.cpp)); other descriptor types, other formats, wave64 depth-compare reads and other `image_sample_c*` forms are not measured. gfx1013 behavior is unverified
