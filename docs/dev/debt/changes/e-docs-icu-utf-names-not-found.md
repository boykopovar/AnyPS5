# libSceIcu
## change [UTF-32 to UTF-16 conversion]
- [UTF-32 to UTF-16 conversion](../../../core/libs/prx/libSceIcu/Utf32.cpp) has no console behavior verification: on a PS5 (firmware 11.60, payload process; a title process may differ) `dlsym` on `libSceIcu.sprx` found `u_strFromUTF32` and `u_strFromUTF32WithSub` neither under its bare name nor under the suffixes _40 to _90 (`u_isUWhiteSpace` was found that way), so the behavior cannot be measured there. `u_strFromUTF32` and `u_strFromUTF32WithSub` follow ICU 78.1 [ustrtrns.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustrtrns.cpp), including the preflight length, a supplementary code point that does not fit being counted while later BMP code points still are written, and the `U_ILLEGAL_ARGUMENT_ERROR`, `U_INVALID_CHAR_FOUND`, `U_BUFFER_OVERFLOW_ERROR` and `U_STRING_NOT_TERMINATED_WARNING` codes. A null `UErrorCode` and a result longer than `INT32_MAX` throw where ICU dereferences or overflows. The NIDs come from the 3.20 inventory and their presence on current firmware is unproven beyond that result (see ICU export availability). Closes when: compared with the console in a title process.

The `UBool` argument is read as one signed byte. The NID comes from the 3.20 inventory and its presence on current firmware is unproven beyond that result (see ICU export availability).
