# libSceLibreSsl3

## change [SSL and SSL_SESSION retains, SSL_CTX version bounds and SSL_get_client_random]

- [SSL and SSL_SESSION retains, SSL_CTX version bounds and SSL_get_client_random](../../../core/libs/prx/libSceLibreSsl3/src/Ssl.cpp) - the SSL_METHOD, SSL_CTX, SSL, SSL3_STATE and SSL_SESSION offsets follow [LibreSSL 4.0.0 ssl_local.h](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libssl/ssl_local.h) and are not measured on the console. No SSL constructor uses them: `SSL_new`, and `SSL_CTX_new` with a libSceLibreSsl method, run libSceLibreSsl's 2.5.4 code, by dependency lookup on Linux and macOS and parent export forwarding on Windows. 2.5.4 puts the SSL and SSL_SESSION counters at 168 and 160 and SSL s3 at 48, and the method and SSL_CTX version bounds in internal structs, so every call here would misread a 2.5.4 object. Signed-counter overflow at INT32_MAX and null objects, methods and SSL3 state, undefined upstream, throw without mutation. Closes when: the offsets are measured on the firmware module and SSL constructors use these layouts.

## change [TLS_method and TLS_server_method]

- [TLS_method and TLS_server_method](../../../core/libs/prx/libSceLibreSsl3/src/Ssl.cpp) - not checked on a console. Both return the same static method with `dtls` 0, `server` 1, version `0x0304` and the `0x0301`-`0x0304` range of [LibreSSL 4.0.0 `ssl_methods.c`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libssl/ssl_methods.c#L246-L264), which `SSL_CTX_set_min_proto_version` and `SSL_CTX_set_max_proto_version` read. The 16-byte `LibreSsl3SslMethod` has none of the upstream handshake callbacks or `enc_flags`, so `SSL_CTX_new` throws for it instead of passing it to libSceLibreSsl, whose 2.5.4 `SSL_CTX_new` would read its `internal` pointer 24 bytes past the object; no context or connection can be built from it yet. Closes when: the method layout is measured on the firmware module and a context constructor uses it.
