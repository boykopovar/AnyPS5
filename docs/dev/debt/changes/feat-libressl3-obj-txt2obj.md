# libSceLibreSsl3

## add Functional

- [OBJ_txt2obj](../../../core/libs/prx/libSceLibreSsl3/src/ObjectFromText.cpp) (libSceLibreSsl3) - not measured on a console. The signature and the two passes follow [LibreSSL 4.0.0 `obj_dat.c`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/objects/obj_dat.c) and [`a_object.c`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/asn1/a_object.c): with `no_name` clear, a short name (`OBJ_sn2nid`) or a long name of the built-in table returns that table entry, otherwise the text is read as dotted arcs - the first two arcs combined as `40 * first + second` and every arc in base 128 - and the object carries allocated data with the dynamic and dynamic-data flags, so `ASN1_OBJECT_free` releases it. Arcs are decoded to arbitrary length instead of through `BN`, and text with a first arc above 2, an empty arc or trailing characters is rejected, leaving `ASN1_R_INVALID_OBJECT_ENCODING` (13, 216) in the error queue where LibreSSL's `a2d_ASN1_OBJECT` reports its own reasons; an allocation failure pushes `ERR_R_MALLOC_FAILURE` (65) from the OBJ library. A returned named object points into the built-in table, so freeing it is a no-op rather than LibreSSL's undefined behaviour.
