# libkernel

## change [kqueue and kevent]

- [kqueue and kevent](../../../core/libs/prx/libkernel/Equeue/src/Kqueue.cpp) (libkernel) follow FreeBSD 11's [`kern_event.c`](https://github.com/freebsd/freebsd-src/blob/34bd34750187bae02a0086402c78c031c59dd8b3/sys/kern/kern_event.c) (`kqueue_kevent`, `kqueue_register`, `kqueue_scan`, the timer and user filters) over the event queue; nothing here is taken from a console except what the kevent measurements entry lists. The descriptor is a host null device registered as the kqueue: `dup` and `dup2` share the queue, its pending events and registrations; `close` and `sceKernelClose` close it on the last descriptor, following FreeBSD 11.4’s [`kern_dup`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/kern_descrip.c#L812-L959). Duplication of a kqueue has not been measured on PS5. Read and write events are supported on guest sockets only, plus `EVFILT_READ` on the read end and `EVFILT_WRITE` on the write end of a pipe (see the kevent on a pipe entry) and the timer, user, signal and [vnode](../../../core/libs/prx/libkernel/Equeue/src/FileEvent.cpp) filters, `EVFILT_FS`, which takes `EV_CLEAR` as FreeBSD 11.4's [`filt_fsattach`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/vfs_subr.c#L4952-L4958) sets it and never fires, as nothing here signals a filesystem event, and a read event on the host stream on descriptor 0, which never triggers, as `select` never reports descriptor 0 readable; PPSA34015 registers descriptor 0 for reading in a new kqueue at start-up and does not check the result; other filters except `EVFILT_AIO`, `EVFILT_LIO`, `EVFILT_SENDFILE`, `EVFILT_PROCDESC` and `EVFILT_PROC` on the process itself with `NOTE_EXIT` or no notes (see the kevent measurements entry), `EV_CLEAR` on a socket or a pipe on Windows (see the kevent EV_CLEAR entry) and every change to an existing timer except `EV_DELETE` and the `EV_ADD` re-adds that the kevent measurements entry describes throw. A `NOTE_NSECONDS` period above one second with a fraction is kept to the nanosecond, where 11.0 converts the fraction with the microsecond macro. `EV_DISABLE`, `EV_DISPATCH` and `EV_FORCEONESHOT` follow kern_event.c: a disabled knote stays registered, stops polling or firing and is not reported, a trigger raised while it is disabled is kept and reported after `EV_ENABLE`, where `knote` would drop it, `EV_DISPATCH` reports once and then disables the knote, and `EV_FORCEONESHOT` is ignored on a new knote while on an existing one it sets `EV_ONESHOT` and fires the knote; a negative `nevents` fails with `EINVAL`. A new user event keeps its `fflags` unmasked and is not triggered by `NOTE_TRIGGER`, because `filt_userattach` reads the already cleared `kn_fflags`. The timer limit `kq_calloutmax` (`ENOMEM`) is not enforced, and closing a kqueue wakes a thread waiting on it in `kevent` with `EBADF`, where `kqueue_drain` makes the close wait for that thread. A level-triggered event is reported once per call and moved behind the other events, as in `kqueue_scan`; the `sceKernel*Equeue` calls keep their own collection loop. `NOTE_LOWAT` on a socket sets the low-water mark as FreeBSD 11's [`filt_soread` and `filt_sowrite`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/sys/kern/uipc_socket.c) do, and a later change of the knote replaces it as `kqueue_register` replaces `kn_sdata`: a read event fires once the buffered bytes reach the mark, or at end of file or on a listening socket. A read mark above 1 is taken on stream sockets only: on a datagram socket Linux's `FIONREAD` reports the next datagram where FreeBSD's `sbavail` counts every queued byte, so it throws. A write event fires once the send buffer's free space reaches the mark, as `filt_sowrite` does with `sbspace`; the host reports that space as `SO_SNDBUF` less `SIOCOUTQ` on Linux and as `SO_SNDBUF` alone elsewhere, so off Linux it does not shrink while data is queued. The host must also report the socket writable (`POLLOUT`) before the free space is compared, so a socket the host does not yet call writable stays silent even when its free space reaches the mark. A write mark above 1 is taken on stream sockets only, as for reads, and an `EV_CLEAR` write event with a mark above 1 on a Linux TCP socket throws: Linux wakes `EPOLLOUT` waiters only after a send or poll found the socket not writable ([`tcp_check_space`](https://github.com/torvalds/linux/blob/v6.8/net/ipv4/tcp_input.c#L5639)), so the edge knote would wait forever once it found the free space below the mark, where FreeBSD 11's [`tcp_input.c`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/sys/netinet/tcp_input.c#L2836-L2844) calls `sowwakeup` on every ACK that frees send space. A read mark below 1 is always met, as in `filt_soread`, except on a listening socket, where `filt_solisten` ignores marks; a write mark below 1 throws.
