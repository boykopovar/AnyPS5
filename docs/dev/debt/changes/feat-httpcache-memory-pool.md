# libSceHttpCache

## change `RemoveTag`, `ClearCacheInfo` and both `WithMemoryPool` forms

- [libSceHttpCache](../../../core/libs/prx/libSceHttpCache/Export.cpp) - `SetQuota` and a non-null `RegisterCacheInfoUrl` throw through `NotImplemented_nid_no_patch` once their arguments pass; `RemoveTag` and `ClearCacheInfo` have unresolved signatures and throw outright. Cached entries carry the tag of the request that stored them: `CreateRequestWithTag` records a tag of up to 31 bytes with the same user and cache checks as `CreateRequest`, and rejects a null, empty or longer tag with `0x817a0012`; `Clear` erases the stored entries of one user that carry the same tag, and `ClearAllUserTags` erases every tagged entry of the listed users while untagged entries survive. A null, empty or longer tag is `0x817a0012`, an unknown cache is `0x817a0011`, and a system or unregistered user clears nothing and succeeds, as `ClearAll` does. Whether the console keys a tag to a user, replaces a tag on a later store of the same key, or rejects tags at these lengths has not been measured; the tag lifetime is this host's choice. `Init` ignores its pool size, so the pool allocation failure is not reproduced, and storing never fails, so the console's file errors are not reproduced.

## add Functional

- [sceHttpCacheRetrieveWithMemoryPool and sceHttpCacheRevalidateWithMemoryPool](../../../core/libs/prx/libSceHttpCache/Export.cpp) (libSceHttpCache) - a call with something to copy (`Retrieve` result 1 or 2, or a `Revalidate` response) throws through `NotImplemented_nid_no_patch`, because firmware 13.42's pool size (`0x1aba0`) and pool copy (`0x1aff0`) were not read; so does a null request or header with a non-null `result`, which the firmware passes on unparsed. Before that they follow the [reading](https://github.com/boykopovar/AnyPS5/issues/21850#issuecomment-6939803983) (disassembly only): the request lookup, the null `pool`/`requiredSize` and input/`result` checks, the same parse and core calls as the plain forms (cores not read), and a return of 0 that writes only `*result` when nothing is found. An unreadable input or unwritable `result` returning `0x817a0012` is a host-safety fallback. Closes when: `0x1aba0`, `0x1aff0` and `RetrieveWithMemoryPool` after `0x39431` are read.
