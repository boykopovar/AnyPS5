## add Functional

- [sceHttpCacheRetrieveWithMemoryPool and sceHttpCacheRevalidateWithMemoryPool](../../../core/libs/prx/libSceHttpCache/Export.cpp) (libSceHttpCache) - pool size queries and copies follow the documented 13.42 revalidation reading and static disassembly of a supplied PRX whose firmware version is unidentified. A size query (null pool) reads the request and writes only `requiredSize`, so a null `nextRequest` or `response` is accepted there; the 13.42 wrapper reading in [issue #21850](https://github.com/boykopovar/AnyPS5/issues/21850#issuecomment-6962993274) gives query mode as `*requiredSize = size` and does not mention `nextRequest` in it; with a pool, `nextRequest` is written first and a usable stale response is appended; a null `response` or a short pool then throws. A null request still throws. Revalidation with a null header and non-null `result` reaches its core as empty input. Invalid guest pointers return `0x817a0012` as a host-safety fallback. The supplied image was not measured on a console.
