# libSceHttpCache

## change `RemoveTag`, `ClearCacheInfo` and both `WithMemoryPool` forms

- [libSceHttpCache](../../../core/libs/prx/libSceHttpCache/Export.cpp) - `SetQuota`, a non-null `RegisterCacheInfoUrl` and `RemoveTag` throw after validation; `ClearCacheInfo` and `RemoveTag` signatures remain unverified. `RevalidateWithMemoryPool` follows the 13.42 wrapper reading in [issue #21850](https://github.com/boykopovar/AnyPS5/issues/21850#issuecomment-6962993274): it queries the required size or clears and fills the pool with response headers and strings, rejecting a missing response destination or undersized pool. `RetrieveWithMemoryPool` still throws for pool sizing and filling because its output layout was not read. Cached entries retain request tags; `CreateRequestWithTag` rejects null, empty or over-31-byte tags, `Clear` removes one user's matching tagged entries, and `ClearAllUserTags` removes tagged entries for listed users. Tag limits, keying and replacement behavior are not measured. `Init` ignores pool size and stores do not reproduce file errors.

## add Functional

- [sceHttpCacheRetrieveWithMemoryPool and sceHttpCacheRevalidateWithMemoryPool](../../../core/libs/prx/libSceHttpCache/Export.cpp) (libSceHttpCache) - `RevalidateWithMemoryPool` follows the complete 13.42 wrapper reading in [issue #21850](https://github.com/boykopovar/AnyPS5/issues/21850#issuecomment-6962993274), including size queries, pool bounds, response output and header/string copies. `RetrieveWithMemoryPool` shares its plain form's core, returns after writing results other than 1 or 2, and rejects a missing response or undersized pool; its pool sizing/fill beyond address `0x39431` remains unread and throws. It also throws for a null request with non-null `result`. A null revalidation header with non-null `result` reaches the core as empty input. Invalid guest pointers return `0x817a0012` as a host-safety fallback.
