# libSceHttpCache

## change `RemoveTag`, `ClearCacheInfo` and both `WithMemoryPool` forms

- [libSceHttpCache](../../../core/libs/prx/libSceHttpCache/Export.cpp) - `SetQuota`, a non-null `RegisterCacheInfoUrl` and `RemoveTag` throw through `NotImplemented_nid_no_patch` once their arguments pass. Cached entries carry the tag of the request that stored them: `CreateRequestWithTag` records a tag of up to 31 bytes with the same user and cache checks as `CreateRequest`, and rejects a null, empty or longer tag with `0x817a0012`; `Clear` erases the stored entries of one user that carry the same tag, and `ClearAllUserTags` erases every tagged entry of the listed users while untagged entries survive. A null, empty or longer tag is `0x817a0012`, an unknown cache is `0x817a0011`, and a system or unregistered user clears nothing and succeeds, as `ClearAll` does. Whether the console keys a tag to a user, replaces a tag on a later store of the same key, or rejects tags at these lengths has not been measured; the tag lifetime is this host's choice. `Init` ignores its pool size, so the pool allocation failure is not reproduced, and storing never fails, so the console's file errors are not reproduced.

## add Functional

- [sceHttpCacheRetrieveWithMemoryPool and sceHttpCacheRevalidateWithMemoryPool](../../../core/libs/prx/libSceHttpCache/Export.cpp) (libSceHttpCache) - sizing or copying a found response, any `Retrieve` result of 2, and a null request or header with a non-null `result` throw through `NotImplemented_nid_no_patch`: firmware 13.42's sizing (`0x1aba0`, `0x40e50`), pool copy (`0x1aff0`) and cores were not read. The rest follows the [reading](https://github.com/boykopovar/AnyPS5/issues/21850#issuecomment-6939803983) (disassembly only): the lookup, the null `pool`/`requiredSize` and input/`result` checks, the plain forms' parse and core, 0 writing only `*result` when nothing is found, and `0x817a0012` after `*result` for a found response with a pool but no `response`, keeping the lookup's update (the plain forms here undo it). `0x817a0012` for unreadable input or an unwritable `result` is a host-safety fallback. Closes when: the sizing, copy and core routines are read.
