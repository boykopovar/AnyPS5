## add Functional

- [SSL_CTX_set_default_verify_paths](../../../core/libs/prx/libSceLibreSsl3/src/SslCtxDefaultVerifyPaths.cpp) (libSceLibreSsl3) - nothing is checked on the console. LibreSSL 4.0.0 [ssl_lib.c](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libssl/ssl_lib.c) implements it as `X509_STORE_set_default_paths`, which only records a file lookup and a hash-dir lookup for `X509_get_default_cert_file()` and `X509_get_default_cert_dir()` and returns 1 before anything is read; this export is eager instead and loads the file during the call. `SSL_CERT_FILE` and `SSL_CERT_DIR` are read first through the guest libc `getenv_nid_postfix`; when unset or empty, the file is the first of `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/cert.pem`, `/opt/homebrew/etc/openssl@3/cert.pem`, `/usr/local/etc/openssl@3/cert.pem`, `/usr/local/etc/openssl/cert.pem` and `/usr/local/etc/ssl/cert.pem` that `access_nid_postfix` reports, in that order, and the directory is `/etc/ssl/certs` when it exists. The file and the directory are passed to `X509_STORE_load_locations` in separate calls, so a bundle that cannot be read does not stop the directory being registered, and the export returns 1 only when at least one of them loaded, 0 for a null context, a null `certStore` or neither. Certificates inside the directory still load lazily on the first lookup, as in the reference, but a directory that does not exist during the call is not counted and makes the call return 0. The candidates are guest paths resolved through the guest root (the run directory), not host paths, so `/etc` is the guest filesystem's; the host system trust store is never consulted. Console paths, the console's own default certificate files and the guest-root mapping are unverified. Closes when: compared with the console.
