# libSceXml

## change [The `String`, `SimpleData`, `SerializeParameter`, `NodeId` and `Node` value operations and the handle constructors]

- [The `String`, `SimpleData`, `SerializeParameter`, `NodeId` and `Node` value operations and the handle constructors](../../../core/libs/prx/libSceXml/Export.cpp) (libSceXml) - follow `libSceXml.sprx` of firmware 13.60, read from disassembly, not measured on a console. `NodeId::operator void*` returns null for every `NodeId`, and the `NodeId` constructor and copies leave its padding bytes untouched. The handle constructors only clear the implementation pointer. Exports that read the objects `initialize` builds still throw, because nothing creates those objects yet: the `Sax::Parser` setters, and `Node::getOwnerDocument`, whose return type is not established. `Node::getAttributes` and `Node::getChildNodes`, in both forms, are a bare return in the module, and the deleting `MemAllocator` destructor is `ud2`, so they still throw too.

## add Functional

- [Node reads](../../../core/libs/prx/libSceXml/src/Node.cpp) (libSceXml) - read from a decrypted PS4 `libSceXml.sprx`, not compared with a PS5 module or measured on a console. `getFirstChild`, `getLastChild`, `getNextSibling` and `getParentNode` return a `NodeId` through a hidden result pointer: the node `Document::getFirstChild`, `getLastChild`, `getSibling` and `getParent` give for the node's document and position, whose lookups they call. `getNodeName` and `getNodeValue` return a `String` the same way and switch on the `Document::getNodeType` value: type 0 gives `xml` and `version="1.0"`, type 1 the attribute name and value, type 4 the element name and its text, and other types no name and their text. Every read gives a null result when the node has no document and throws after its builder parsed again or terminated.
