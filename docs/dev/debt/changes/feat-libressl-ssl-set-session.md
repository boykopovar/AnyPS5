# libSceLibreSsl

## change [SSLv23_client_method, SSLv23_server_method, TLS_client_method, DTLSv1_client_method and DTLSv1_server_method]

- [SSLv23_client_method, SSLv23_server_method, TLS_client_method, DTLSv1_client_method and DTLSv1_server_method](../../../core/libs/prx/libSceLibreSsl/src/SslMethod.cpp) (libSceLibreSsl) - nothing is checked on the console. The static `SSL_METHOD` objects, their version ranges (TLS 1.0 to 1.2, DTLS 1.0) and slots follow [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl) `t1_meth.c`, `t1_clnt.c`, `t1_srvr.c` and `d1_*.c`; the 160-byte internal method block is measured on a 2.5.4 x86-64 build. Through a method object `ssl_dispatch_alert`, `num_ciphers`, `get_cipher`, `get_cipher_by_char`, `put_cipher_by_char`, the `SSL3_ENC_METHOD` `enc` function, `ssl_get_message`, `ssl_read_bytes` and `ssl_write_bytes` throw when called, and so do the handshake, read, write, shutdown and pending slots until an export implements them. `get_ssl_method` returns `t1_clnt.c`'s and `t1_srvr.c`'s unexported one-version TLS methods.

## add Unknown function info

- [SSL_set_session](../../../core/libs/prx/libSceLibreSsl/src/SslSession.cpp) (libSceLibreSsl) - nothing is checked on the console. It follows LibreSSL 2.5.4 [`ssl_sess.c`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl/ssl_sess.c#L715-L757) and, for the method switch, [`SSL_set_ssl_method`](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl/ssl_lib.c#L2269-L2293). The session's `ssl_version` (offset 0) and `verify_result` (offset 136) follow the `ssl_session_st` layout on LP64. Setting a session over the connection's last reference to its old session throws through `SSL_SESSION_free` before the connection's session changes, with the new session's count restored, but after the method switch. A null connection or context throws where LibreSSL dereferences it.
