# libkernel

## change [socketpair]

- [socketpair](../../../core/libs/prx/libkernel/Socket/src/Udp.cpp) (libkernel) - the pair is the host's `AF_UNIX` pair on Linux and macOS and, on Windows, a loopback TCP connection for `SOCK_STREAM` or two connected UDP sockets for `SOCK_DGRAM` and `SOCK_SEQPACKET`; `SOCK_SEQPACKET` throws on macOS, which has none, and on Windows for a record over 65507 bytes; its Windows send buffer counts bytes, not mbufs, and still polls writable when full, where `SB_STOP` makes the console report it unwritable. A datagram sent to a full receiver is dropped on Windows, where the console fails it with `ENOBUFS` at once. `AF_UNIX` paths are not resolved: `bind`, and a `connect` or addressed `sendto` that FreeBSD 11.4 passes to `unp_connect`, report `EAFNOSUPPORT`, and `connect` on a datagram end keeps it connected where FreeBSD disconnects it first. On Windows `poll` on a stream end reports no `POLLHUP` after the peer's `close`, where `unp_drop` makes the console report `POLLIN` with `POLLHUP`
