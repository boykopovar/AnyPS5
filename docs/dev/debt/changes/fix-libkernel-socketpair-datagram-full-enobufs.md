# libkernel

## change [socketpair]

- [socketpair](../../../core/libs/prx/libkernel/Socket/src/Udp.cpp) (libkernel) - the pair is the host's `AF_UNIX` pair on Linux and macOS and, on Windows, a loopback TCP connection for `SOCK_STREAM` or two connected UDP sockets for `SOCK_DGRAM` and `SOCK_SEQPACKET`; `SOCK_SEQPACKET` is `SOCK_DGRAM` on macOS and throws on Windows for a record over 65507 bytes; on both the send buffer counts bytes, not mbufs (+16 per record on macOS), and polls writable when full, unlike the console (`SB_STOP`). A datagram sent to a full receiver is dropped on Windows, where the console fails it with `ENOBUFS` at once. `AF_UNIX` paths are not resolved: `bind`, and a `connect` or addressed `sendto` that FreeBSD 11.4 passes to `unp_connect`, report `EAFNOSUPPORT`, and `connect` on a datagram end keeps it connected where FreeBSD disconnects it first. On Windows `poll` on a stream end reports no `POLLHUP` after the peer's `close`, where `unp_drop` makes the console report `POLLIN` with `POLLHUP`
