# libc

## add Unknown function info

- [std::numeric_limits constants](../../../core/libs/prx/libc/src/NumericLimits.cpp) (libc and libSceLibcInternal) - the 67 exported static members (`digits`, `digits10` and `is_signed` of the integer types, `is_modulo` of `bool`, and `digits`, `digits10`, `max_digits10` and the exponent bounds of the floating types) are not read from a console module. They are the values ISO C++ [numeric.limits.members] fixes for the PS5 types: LP64 integers, signed `char`, the 16-bit unsigned `wchar_t` of [clang's PS4/PS5 target](https://github.com/llvm/llvm-project/blob/llvmorg-17.0.6/clang/lib/Basic/Targets/OSTargets.h#L543), IEEE `float` and `double`, 80-bit x87 `long double`. Their `st_size` in the module is unmeasured. The `_Num_base`, `_Num_int_base`, `_Num_float_base` and `_Num_ldbl_base` members stay missing: `has_denorm_loss`, `tinyness_before`, `traps` and the integer `is_modulo` differ between Dinkumware releases and need a reading.

## change [Remaining PPSA10665 libc.prx catalog]

- [Remaining PPSA10665 libc.prx catalog](../../../core/libs/prx/libc/src/LocaleSupport.cpp) (libc) - of the 2,677 exports in that module's dynamic table, the unimplemented remainder after this change is the Dinkumware data class plus the stream and heap queries: facet `id`s and vtables beyond the ones already exported, the `_Num_base`, `_Num_int_base`, `_Num_float_base` and `_Num_ldbl_base` constants, `std::` typeinfo objects and guard variables, `_Files`, `_Locale`, `_Tolotab`, `_Touptab`, `_Cl_charnames`, `_Cl_wcharnames`, `_Getcat`, `time_get::get`, `__cleanup`, `_Tls_setup_*`, `sceLibcForceTlsDestructor`, `_ZSt18_String_cpp_unused`, `_PJP_C_Copyright`, `_PJP_CPP_Copyright`, `fcloseall`, `sceLibcMspaceIsHeapEmpty`, `sceLibcPafMspaceIsHeapEmpty` and about 100 NIDs pointed at RVA 0. They need the TLS/facet object model this library does not have, an unimplemented stream registry, unknown firmware bytes or unmeasured heap answers, so none are stubbed.
