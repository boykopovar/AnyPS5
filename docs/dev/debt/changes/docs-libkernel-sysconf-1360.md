# libkernel

## change sysconf

- [sysconf](../../../core/libs/prx/libkernel/System/src/SystemConfiguration.cpp) (libkernel) - `_SC_NPROCESSORS_CONF`, `_SC_NPROCESSORS_ONLN` and `_SC_PHYS_PAGES` report the host's processor count and memory in 16 KiB pages, where a fat PS5 payload process (12.70) read 16, 16 and 139888 and a PS5 Pro one (13.60) 170220 - the page count follows the model's guest memory; every other value here reproduced on 13.60. `_SC_CHILD_MAX`, `_SC_OPEN_MAX` and `_SC_STREAM_MAX` follow the guest `RLIMIT_NPROC` and `RLIMIT_NOFILE`; (payload, 11.60): 1604, 256 after lowering `RLIMIT_NPROC`, 1443 when set back; here `setrlimit` stores `RLIMIT_NPROC` clamped to 1443; `_SC_OPEN_MAX` and `_SC_STREAM_MAX` followed the `RLIMIT_NOFILE` soft limit there (13952, 64 and 12555); the 32767 bound on `_SC_STREAM_MAX` was not tried above 13952. `_SC_CLK_TCK` returns the 128 that process read, though no `times` rate matches; CPython in PS5MC (PPSA99420) needs >= 1. `_SC_CPUSET_SIZE` (122) returns 8 on both, which report 16 processors: it does not follow the count. A failed `getrlimit` or host count 0 gives -1 `EIO`, unseen on console. What a title process gets was not measured
