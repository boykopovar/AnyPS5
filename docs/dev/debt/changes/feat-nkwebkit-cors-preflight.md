## add Functional

- [WebCore::validatePreflightResponse](../../../core/libs/prx/libSceNKWebKit/src/CrossOriginAccessControl.cpp) (libSceNKWebKit) - not compared with a console module. Only in the 3.20 inventory; follows [CrossOriginAccessControl.cpp at WebKit 73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/loader/CrossOriginAccessControl.cpp#L258-L279), whose access check message has no status code. The request is read with the 3.20 `LegacyResourceRequestBase` layout, because its constructors are inline in the caller. The response and the origin are read the way the module's own exported constructors and setters fill them (status code, `httpHeaderField`, `SecurityOrigin::toString`); a 3.20 caller that fills a response from its own inline code is not modelled. Closes when: compared with a console module.
- [WebCore::CrossOriginPreflightResultCache](../../../core/libs/prx/libSceNKWebKit/src/CrossOriginPreflightResultCache.cpp) (libSceNKWebKit) - `singleton`, `clear`, `appendEntry` and `canSkipPreflight`, not compared with a console module. They follow the 2020 [CrossOriginPreflightResultCache.cpp](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/loader/CrossOriginPreflightResultCache.cpp). The map is host state: `singleton` returns 8 zero bytes and another `this` throws. `appendEntry` reads the item its caller built inline (expiry at 0, policy at 8, `HashSet` tables at 16 and 24; derived from the pinned headers, not measured) and frees it at once instead of when the entry leaves the map. Where the source dereferences a null string or item the exports throw `std::invalid_argument`. Closes when: compared with a console module.
- [Common header numbers in the CORS preflight exports](../../../core/libs/prx/libSceNKWebKit/src/CrossOriginPreflightResultCache.cpp) (libSceNKWebKit) - `canSkipPreflight` and `validatePreflightResponse` exist only in the 3.20 inventory, but they name the common headers of a request with the module's table, the 11.x one, as the shared `HTTPHeaderMap` exports that store headers by name do. The 2020 table has no `Clear-Site-Data`, so a 3.20 caller that stored a header by its own enumerator from 16 (`Connection`) on is read as another name. Closes when: the module knows which generation of caller it serves.
