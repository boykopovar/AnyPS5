# libfreetype

## change [FT_Set_Default_Properties]

- [FT_Set_Default_Properties](../../../core/libs/prx/libfreetype/Export.cpp) (libfreetype) - the console signature and behavior are unverified. The bundled build reads the guest `FREETYPE_PROPERTIES` value and passes each bounded assignment to FreeType 2.15.0's property-string setter, as [ftinit.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftinit.c#L111-L183) does; invalid syntax stops parsing and property errors are ignored. A null guest library becomes a null library, which [ft_property_do](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftobjs.c#L5329-L5353) rejects, so nothing changes. System-dependency builds throw when a non-null library meets a guest property value because the string setter is not a public FreeType API. A test changes the TrueType interpreter version from 40 to 35 with the guest value and confirms that a null library and a different host value change nothing.

## change [FT_Stream_OpenGzip and FT_Stream_OpenLZW]

- [FT_Stream_OpenGzip and FT_Stream_OpenLZW](../../../core/libs/prx/libfreetype/src/CompressedStreams.cpp) (libfreetype) - the console signatures, version, and stream behavior are unverified. The guest stream record follows FreeType's LP64 public layout; a Windows host stream has 32-bit `unsigned long`, so source size and position above `ULONG_MAX` and output reads above that range throw. Guest read callbacks and memory allocators run through adapters; a source stream must stay alive until the output is closed. The bundled FreeType 2.15.0 decompresses with internal zlib and LZW. Tests cover a small in-memory gzip stream, a larger callback-backed source and streamed output, seeked reads, a literal-coded LZW stream, and allocation release on close. A compressed output stream cannot yet be passed into libSceFreeType's `FT_Open_Face`, which still rejects `FT_OPEN_STREAM`.

## add Functional

- [Gzip and LZW output records](../../../core/libs/prx/libfreetype/src/CompressedStreams.cpp) (libfreetype) - the console's FreeType version is unverified. An output changes only where 2.15.0 [ftgzip.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/gzip/ftgzip.c#L607-L705) and [ftlzw.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/lzw/ftlzw.c#L341-L392) write it: a failed header check leaves it, open or not; a passed one clears it to its memory without closing it. A record passed as stream and source is cleared too, so the second header check fails with `Invalid_Stream_Operation`. Without a file record FreeType still installs read and close, and gzip succeeds if its small-file buffer fails too; reading that output throws, as FreeType dereferences the missing record, as does a small-file buffer allocated after it failed. An output that overlaps its source without being it throws once cleared.
- [Gzip and LZW memory and source reads](../../../core/libs/prx/libfreetype/src/CompressedStreams.cpp) (libfreetype) - the console's FreeType version is unverified. The memory record and its callbacks are read only when 2.15.0 [ftutil.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftutil.c#L64-L174) calls them, and a null one it calls throws there, so a failing header check needs no memory and gzip needs no `realloc`. A nonzero result of a guest zero-count read is the seek error [FT_Stream_Seek](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftstream.c#L55-L87) reports; a guest read returning more than it was asked for throws. Tests cover unused and missing callbacks, aliased, reopened and overlapping records, failed allocations and refused seeks.

## change [FT_Stream_OpenBzip2]

- [FT_Stream_OpenBzip2](../../../core/libs/prx/libfreetype/src/CompressedStreams.cpp) (libfreetype) - the console's FreeType build options are unverified. The bundled FreeType 2.15.0 is built with `FT_DISABLE_BZIP2`, so the export returns `Unimplemented_Feature` for every input, null and aliased streams included, without reading or writing either stream, as that build's [`FT_Stream_OpenBzip2`](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/bzip2/ftbzip2.c#L520-L532) does. A FreeType whose options define `FT_CONFIG_OPTION_USE_BZIP2`, such as a system one, opens the stream through the gzip and LZW stream adapter instead. A console FreeType built with bzip2 would open the stream too
