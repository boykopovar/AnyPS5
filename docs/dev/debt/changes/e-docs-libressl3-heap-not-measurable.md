# libSceLibreSsl3
## change [HKDF]
- [HKDF](../../../core/libs/prx/libSceLibreSsl3/src/Hkdf.cpp) (libSceLibreSsl3, NID `uJ2ZXq4z3As`) - A PS5 (firmware 11.60, payload process; a title process may differ) returned 0 from all 7 calls with public RFC 5869 inputs and queued an EVP `ERR_R_MALLOC_FAILURE`, and `CRYPTO_malloc(32)` returned NULL in `libSceLibreSsl3.sprx` and in `libSceLibreSsl.sprx` (2026-11-17), so the behavior cannot be measured from a payload process. The signature, extraction and streamed expansion follow [LibreSSL 4.0.0 hkdf.c](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/hkdf/hkdf.c) and its [HMAC](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/hmac/hmac.c), whose null key is an empty key; the salt length is converted to `int` as that source does. Hashing goes through libSceLibreSsl's HMAC exports. A failed extraction queues `ERR_R_CRYPTO_LIB` and a 256th output block queues `EVP_R_TOO_LARGE` after 255 blocks are written, both in the libSceLibreSsl queue without file or line. A null output with a nonzero length, which the source writes through, throws. The source's `CBB` and `HMAC_CTX_new` allocation failures are not reproduced.
## change [HMAC_CTX_new and HMAC_CTX_free]
- [HMAC_CTX_new and HMAC_CTX_free](../../../core/libs/prx/libSceLibreSsl3/src/Hmac.cpp) (libSceLibreSsl3) - A PS5 (firmware 11.60, payload process; a title process may differ) returned NULL from `HMAC_CTX_new` and from `CRYPTO_malloc(32)` in `libSceLibreSsl3.sprx` and NULL from `CRYPTO_malloc(32)` in `libSceLibreSsl.sprx` (2026-11-17), so it cannot be measured from a payload process. `HMAC_CTX_new` returns a zeroed guest-heap block of `sizeof(HmacContext)` bytes, the layout the forwarded `HMAC_CTX_init`, `HMAC_Init_ex`, `HMAC_Update`, `HMAC_Final` and `HMAC_CTX_cleanup` of libSceLibreSsl operate on, and initialises it with `HMAC_CTX_init`; a failed allocation returns null. `HMAC_CTX_free` returns for a null context and otherwise calls `HMAC_CTX_cleanup` and releases the block. The size of the console's own `HMAC_CTX` is not measured; the context is valid only as an opaque pointer for those exports. Closes when: the console's `HMAC_CTX` size and `HMAC_CTX_new` allocation are measured
## change [ASN1_TIME_new and X509_gmtime_adj]
- [ASN1_TIME_new and X509_gmtime_adj](../../../core/libs/prx/libSceLibreSsl3/src/TimeNew.cpp) (libSceLibreSsl3) - A PS5 (firmware 11.60, payload process; a title process may differ) returned NULL from `X509_gmtime_adj(NULL, 0)` in `libSceLibreSsl3.sprx` with an ASN1 malloc failure queued, and from `CRYPTO_malloc(32)` there and in `libSceLibreSsl.sprx` (2026-11-17), so this cannot be measured from a payload process; `ASN1_TIME_new` was found in neither module. As in [LibreSSL 4.0.0](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/asn1/a_time_tm.c) `a_time_tm.c` and `tasn_new.c`, `ASN1_TIME_new` returns a zeroed 24-byte string from the guest heap with type -1 and the multi-string flag, queueing two ASN1 malloc failures when the allocation fails, and `X509_gmtime_adj` writes the host wall clock plus the offset as UTCTime for 1950 to 2049 and GeneralizedTime otherwise, reusing the given string or a new one, and returns null without an error outside years 0 to 9999. The console clock and the heap the guest frees these with are unverified. Closes when: compared with the console in a title process.
