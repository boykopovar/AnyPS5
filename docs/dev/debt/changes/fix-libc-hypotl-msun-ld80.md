# libc

## change [acoshl, asinhl, atanhl, expm1l, hypotl, log1pl, log2l, lgammal, tgammal, jnf and ynf]

- [acoshl, asinhl, atanhl, expm1l, log1pl, log2l, lgammal, tgammal, jnf and ynf](../../../core/libs/prx/libc/src/Math.cpp) (libc) return the host C library's results (the float Bessel functions through its double ones), not those of the console's own code, so the last bits can differ (`ynf` follows the console at `+-0`). `tgammaf` delegates to the host's double `tgamma` as FreeBSD 11 does ([`s_tgammaf.c`](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/msun/src/s_tgammaf.c)), except above 171.63 (`x / 0`) and below -190 (a signed zero without underflow), where it follows msun's `b_tgamma.c` as the bundled `libc.prx` does, then restores the sign of a zero result for negative non-integer inputs from the parity of `floor(-x)`; nine title-bundled `libc.prx` builds return that sign for underflowing inputs, where Windows UCRT can return the opposite sign ([#9707](https://github.com/boykopovar/AnyPS5/issues/9707)). As in the console's `libSceLibcInternal.sprx` (SDK 4.5x build of `J03950001`, 0x56410), `lgammal` does not store the sign in `signgam`. [hypot3, hypot3f and hypot3l](../../../core/libs/prx/libc/src/Math.cpp) follow that module (0x51D30, 0x520D0, 0x52420): the first NaN of x, y and z is returned unchanged, any infinity gives positive infinity, a zero argument gives the two-argument hypot of the other two, and otherwise the largest magnitude is combined with the hypot of the other two

## add Functional

- [hypotl](../../../core/libs/prx/libc/src/Math.cpp) (libc) - other SDK versions and the system `libSceLibcInternal` are not compared. It is FreeBSD msun's [`e_hypotl.c`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/lib/msun/src/e_hypotl.c) for ld80, as in the `libc.prx` build `J03093718` bundled with PPSA21564 (0x48b90), whose 2^16382 scale factor is the pseudo-NaN `0x7fff:4000000000000000`: if the argument with the smaller exponent field (`y` on a tie) is nonzero with a zero exponent field and the other is below 2^-16311, the result is the default NaN `0xc000000000000000:ffff` with `FE_INVALID`. Like that binary, which has no control-word instruction, it runs at the caller's x87 precision: at 64, 53 and 24 bits, in each rounding mode, it gives that binary's bits, `errno` and exception flags and leaves the control word unchanged for 20,000,000 pairs, non-canonical ones included; an infinite argument gives infinity even when the other is a NaN, as C11 F.10.4.3 requires
