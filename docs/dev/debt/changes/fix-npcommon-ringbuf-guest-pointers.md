# libSceNpCommon

## change [sce::np::RingBuf and RingBufMemory]

- [sce::np::RingBuf and RingBufMemory](../../../core/libs/prx/libSceNpCommon/RingBuf.cpp) (libSceNpCommon) - throw `std::invalid_argument` where the module asserts and calls `sceNpPanic`: `Init` on a buffer that has storage or with a null or empty one, a null `CheckoutForWrite` size, a `CheckinForWrite` past the end, a `Write` of nothing into a full buffer, a null or empty `Peek`, and read pointers that disagree with the data size. Otherwise they follow `libSceNpCommon.sprx` of firmware 13.60, read from disassembly, not measured on a console, including that `CheckinForRead` does not check its size and that `Expand` moves the data after the read pointer only when the write pointer is below it. Expanding a full buffer keeps both pointers together, so the next write takes it for empty, starts at the beginning over the queued data, and the following read asserts; a buffer must not be full when it is expanded. They also throw `std::invalid_argument`, with `errno` kept, where the object, its storage, its allocator or a caller buffer or size pointer is not readable or writable guest memory; the module dereferences those pointers directly, so this is a host-safety fallback.
