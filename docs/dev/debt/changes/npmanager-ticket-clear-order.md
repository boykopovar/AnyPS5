# libSceNpManager

## change The deleting destructors and NpTicket teardown

- [The deleting destructors and NpTicket teardown](../../../core/libs/prx/libSceNpManager/Destructors.cpp) (libSceNpManager) call `_ZN3sce2np6ObjectdlEPv` for the deleting destructor of `NpOnlineId`, `NpId`, `User`, `NpTitleToken`, `NpAccessToken` and `NpTicket`, as firmware 11.00 `libSceNpManager.sprx` does. `NpTicket` keeps its allocator at 0x08, data at 0x10 and size at 0x18; its destructors and `Clear` release the data through `_sceNpAllocatorExFree` and `Clear` zeroes the data and size. The module imports both allocator-free variants and the relocation table could not be resolved, so the exact variant at the destructor's call site is inferred from the `SceNpAllocatorEx` fields. Whether firmware `NpTicket::Clear` zeroes `data` and `size` before or after invoking `_sceNpAllocatorExFree` is unmeasured; the host releases first and zeroes afterwards (matching `DestroyTicket`), so a re-entrant `Clear` from inside a guest release callback would observe the live `data` pointer. The non-deleting destructors of the five value classes are outside this change.
