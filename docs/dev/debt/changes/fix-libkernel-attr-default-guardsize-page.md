# libkernel

## change [scePthreadAttr setters and getters](../../../core/libs/prx/libkernel/Pthread/src/Attr.cpp) (libkernel)

- [scePthreadAttr setters and getters](../../../core/libs/prx/libkernel/Pthread/src/Attr.cpp) (libkernel) - a new attribute holds a 1 MiB stack size here and 64 KiB on the console, because host code runs on guest threads; a null attribute pointer to `scePthreadAttrInit` and a null output of `scePthreadAttrGetaffinity` throw, where the console crashed. Measured on a PS5 (firmware 13.60): a null or uninitialized attribute, and a null output of the stack size, detach state, scheduling parameter, policy and inheritance getters, return `EINVAL`; a policy other than 1 and 3, an inheritance other than 0 and 4, or a priority outside 256 to 767 (or a null parameter) returns `ENOTSUP` (`0x8002002D`); a detach state other than 0 and 1 and a stack size below 16384 return `EINVAL`; any affinity mask is accepted; a new attribute holds policy 1, inheritance 4 and a guard size of 16384 bytes (the guest page; here it was 4096), as a PS5 Pro payload process (13.60) reads them right after `pthread_attr_init` and `scePthreadAttrInit`. A new attribute reads every affinity bit set (`0xffffffffffffffff`) here, as it did on a PS5 payload process (firmware 11.60, run `2026-11-14T035513Z_R1_libkernel_attr_detach_affinity`); the affinity a thread created from such an attribute gets was not measured and stays the available mask
