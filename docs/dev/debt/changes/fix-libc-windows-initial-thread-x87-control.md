# libc

## change [acosl]

- [acosl](../../../core/libs/prx/libc/src/Math.cpp) (libc) runs at the caller's x87 precision, as the binary does, so on a Windows initial thread at 53 bits (see `asinl`) it returns the binary's 53-bit result, not the console's 64-bit one. It follows the `acosl` of the `libc.prx` bundled with PPSA21564 (0x3e5a0): FreeBSD msun's [`e_acosl.c`](https://github.com/freebsd/freebsd-src/blob/9f0432041b8fb69832f10c32da50a67f34feeb61/lib/msun/src/e_acosl.c) with the ld80 `invtrig.c` coefficients that `asinl` uses, where `_Feraise(FE_INVALID)` raises `FE_INVALID` and sets `errno` to `EDOM` for |x| > 1, the infinities and NaN before `(x - x) / (x - x)`. 20 million random arguments in (-1, 1) give the same bits as that code run natively on Linux at 64-, 53- and 24-bit precision; the host `acosl` differed on 1,603,469 of them at 64 bits. Other SDK versions and the system `libSceLibcInternal` are not compared

## change [_LLog]

- [_LLog](../../../core/libs/prx/libc/src/DinkumwareInternals.cpp) (libc) runs at the caller's x87 precision, as the binary does, so a Windows initial thread at 53 bits (see `asinl`) gets the binary's 53-bit result, not the console's 64-bit one. It follows the `_LLog` of the `libc.prx` bundled with PPSA21564 (0x3fd50): Dinkumware's `_LDunscale` split, the 8-term `_LPoly` table and the split `ln 2`, `log10 e` and `log2 e` constants taken from the binary, with `_Feraise` raising `FE_DIVBYZERO` and `ERANGE` for a zero mantissa, pseudo-zeros included, and `FE_INVALID` and `EDOM` below zero. 4 million random arguments under bases 0, 1, -1, 7 and -9 give the same bits, `errno` and flags as that code run natively on Linux at 64-, 53- and 24-bit precision; the host `logl`, `log10l` and `log2l` differed on 869,197, 2,000,696 and 306,649 at 64 bits. Its `logl`, `log10l` and `log2l` call `_LLog` with 0, 1 and -1, and this libc forwards them there too. Other SDK versions are not compared

## change [asinl]

- [asinl](../../../core/libs/prx/libc/src/Math.cpp) (libc) follows the `asinl` of the `libc.prx` bundled with PPSA28319 (disassembly), FreeBSD msun's [`e_asinl.c`](https://github.com/freebsd/freebsd-src/blob/9f0432041b8fb69832f10c32da50a67f34feeb61/lib/msun/src/e_asinl.c) with the ld80 [`invtrig.c`](https://github.com/freebsd/freebsd-src/blob/9f0432041b8fb69832f10c32da50a67f34feeb61/lib/msun/ld80/invtrig.c) coefficients, which the binary holds as the same 80-bit constants. For |x| > 1, the infinities and NaN, Sony's error helper raises `FE_INVALID` and sets `errno` to `EDOM` before returning `(x - x) / (x - x)`, so a NaN argument also sets `EDOM`; msun sets no `errno`. 20 million random arguments in (-1, 1) give the same bits as that code run on a Windows host. A Windows initial thread outside `EnterGuestMainStack` runs at 53 bits, where `asinl(0.75)` has mantissa `…e000`, not `…e041`. The system `libSceLibcInternal` that RetroArch (PPSA99169) imports is assumed to have the same code

# libkernel

## change [Guest thread x87 control word]

- [Guest thread x87 control word](../../../core/libs/prx/libkernel/Pthread/src/Thread.cpp) (libkernel) - not measured on a console, and only on Windows does the emulator load `0x037f` into the initial thread, when the entry stub enters through libc's `EnterGuestMainStack` (`libc.prx` imported, or unscoped imports); otherwise the initial thread keeps the host's start word, `0x27f` on Windows and `0x037f` on Linux and macOS unless the host changed it. A new guest thread starts with `0x037f` (64-bit precision, every exception masked) whatever its creator uses. That is FreeBSD 11's start state, whose [`cpu_copy_thread`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/sys/amd64/amd64/vm_machdep.c#L428-L446) leaves a new thread's FPU state uninitialized so that its first FPU instruction loads `fpu_initialstate` (`__INITIAL_FPUCW__`), and the control word of the libSceFiber option that starts fibers with the default FPU state
