# libSceSystemService

## add Silent stubs

- [sceLncUtilInitialize](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - connects to no launcher service, since AnyPS5 has no shell that launches, suspends or ends applications: every call returns success and keeps no state
- [sceAppMessagingTryReceiveMsg](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - reports that no message is waiting (`NO_MESSAGE`, 0x80C50005) and writes nothing to the buffer: AnyPS5 has no shell or other application that sends the title messages, and `sceAppMessagingSendMsg` throws, so nothing is ever queued. A null buffer returns `NULL_POINTER` (0x80C50004)

## add Unknown function info

- [sceLncUtilInitialize](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - not confirmed on a PS5: that a title starts with the launcher client uninitialized. On a PS4 a launch made before the call failed with `NOT_INITIALIZED` (0x80940001) ([daemon writeup](https://github.com/LightningMods/PS4-daemon-writeup/blob/dc404caac0cc0c8063f577a40996e929b3738552/writeup.md#L133-L149)), and [Orbis Suite](https://github.com/OSM-Made/Orbis-Suite/blob/67be2f38902df5010144f17f35d1a823ebb4238f/Playstation/Loader/Main.cpp#L27-L32) treats any result other than 0 as a failure. The `int (void)` signature follows [StubMaker](https://github.com/OSM-Made/StubMaker/blob/25b8aca9a2dee800b86fadf2d153782edd77403c/Include/LncUtil.h#L8)
- [sceLncUtilInitialize](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - not confirmed on a PS5: what sets the launcher client's initialized state on a console. Every call returns 0 here because a retail console reading of two successive calls on firmware 13.40 gave 0 and 0, and the 13.42 module keeps a reference count whose later calls return 0 and has no 0x80940018 (Lnc_errors.h names it). The caller's first-call-versus-later-call difference, if any, is not modelled
- [sceAppMessagingTryReceiveMsg](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - its error values are the PS4 ones, which [StubMaker](https://github.com/OSM-Made/StubMaker/blob/25b8aca9a2dee800b86fadf2d153782edd77403c/Include/Defs/AppMessagingDefs.h#L7-L14) credits to psdevwiki, and are not confirmed on a PS5; neither is the order of the null check and the empty-queue answer, nor whether the console writes the buffer when no message is waiting. The `(SceAppMessage*)` signature follows [StubMaker](https://github.com/OSM-Made/StubMaker/blob/25b8aca9a2dee800b86fadf2d153782edd77403c/Include/AppMessaging.h#L13), and its 8216-byte message (sender, type, 8192-byte payload, payload size, timestamp) matches the layout [etaHEN](https://github.com/etaHEN/etaHEN/blob/dafa13b562ddb137a4b4a97b9aaa287c0c57cc9c/Source%20Code/shellui/include/external_symbols.hpp#L23-L30) declares for `sceAppMessagingReceiveMsg` on a PS5
