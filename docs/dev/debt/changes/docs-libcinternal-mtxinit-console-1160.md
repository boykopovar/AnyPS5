# libSceLibcInternal

## change [_Mtxinit, _Mtxlock, _Mtxunlock, _Mtxdst]

- [_Mtxinit, _Mtxlock, _Mtxunlock, _Mtxdst](../../../core/libs/prx/libSceLibcInternal/Mutex.cpp) (libSceLibcInternal) follow the PS4 code of [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/860d73b7e99559106a3ffa3d3d69f0f9237e115e/src/core/libraries/libc_internal/libc_internal_threads.cpp#L10-L62) and [fpPS4](https://github.com/red-prig/fpPS4/blob/04cefd43e6fddd1ab033e7980cd356d14c964905/src/libcinternal/ps4_mtx_internal.pas#L47-L99): the argument points to a pointer-sized libkernel mutex handle, `_Mtxinit` creates it recursive, a zeroed handle becomes an error-checking mutex on its first lock as with the POSIX calls, and each returns 0 on success and 1 on any failure. A null handle pointer throws in libkernel. The `SceLibcI_` name goes to `scePthreadMutexInit`, which drops it. A payload process on firmware 11.60 (a title process may differ) measured it: second lock 0 and third unlock 1 (recursive), second lock of a zeroed handle 1, lock on a destroyed handle 1, unlock by another thread 1, a lock held by another thread is waited for, a null handle pointer faults; AnyPS5 was not run on these, the handle layout is unmeasured
