# libSceCesCs
## change [EUC-JP (CP51932) conversions]
- [EUC-JP (CP51932) conversions](../../../core/libs/prx/libSceCesCs/Export.cpp) (libSceCesCs): `sceCesUcsProfileInitEucJpCp51932` marks the caller's sheet with an 8-byte tag and returns it as the profile. Decoding follows the console (see the `sceCesEucJpToUtf8` entry), with the Microsoft code page 932 table read through the JIS row/cell arithmetic ([JisX0208.hpp](../../../core/libs/prx/libSceCesCs/JisX0208.hpp)); the console does not decode or encode JIS X 0212 either way (U+02D8 answered `0x805C0020`). Encoding takes the lowest cell of a character. A PS5 (firmware 11.60, payload process; a title process may differ) returned the sheet pointer from `sceCesUcsProfileInitEucJpCp51932` on a zero-filled 2048-byte sheet and left its last non-zero byte at offset 116, so the console writes more than this 8-byte tag; the bytes behind the sheet stayed intact and its layout is not read. Signatures follow [orbital](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json).
## change [Shift-JIS (CP932) conversions]
- [Shift-JIS (CP932) conversions](../../../core/libs/prx/libSceCesCs/Export.cpp) (libSceCesCs): decoding matches a payload process on a PS5 (firmware 13.60) for every two-byte input through `sceCesMbcsStrToUcs2Str`, in result, lengths and output. `sceCesUcsProfileInitSJis1997Cp932` tags the caller's sheet and returns it as the profile. The string conversions decode ASCII, half-width katakana (`0xA1`-`0xDF`) and two-byte sequences (`0x81`-`0x9F` and `0xE0`-`0xFC` lead, `0x40`-`0x7E` and `0x80`-`0xFC` trail) through the CP932 table ([JisX0208.hpp](../../../core/libs/prx/libSceCesCs/JisX0208.hpp)), including the IBM extensions `0xFA40`-`0xFC4B`. The user-defined area `0xF040`-`0xF9FC` and unassigned cells answer `UNASSIGNED_CODE`, an invalid lead or trail `INVALID_ENCODE`, a cut sequence `SRC_BUFFER_END`. A PS5 (firmware 11.60, payload process; a title process may differ) gave the same results for 14 probed cases of `sceCesSJisToUtf8` and `sceCesSJisToUcs2`: `A`, `0xB1`, `0x82A0`, `0x889F`, `0x8140`, a cut `0x81`, `0x81` with trail `0x20`, `0x8540` and the single bytes `0xA0`, `0xFD`, `0xFE` and `0xFF`. `sceCesUcsProfileInitSJis1997Cp932` returned the sheet pointer on a zero-filled 2048-byte sheet and left its last non-zero byte at offset 116, so the console writes more than the tag. Signatures follow [orbital](https://github.com/AlexAltea/orbital/blob/master/tools/ida/db_types.json).
## change [sceCesEucJpToUtf8 and sceCesEucJpToUcs2]
- [sceCesEucJpToUtf8 and sceCesEucJpToUcs2](../../../core/libs/prx/libSceCesCs/Export.cpp) (libSceCesCs) with the CP51932 profile follow a payload process on a PS5 (firmware 13.60): every two-byte input and every `0x8F` three-byte input gives the console's result, length and output (the test pins a hash of both sweeps). Bytes below 0xA0 other than 0x0E, 0x8E and 0x8F convert to themselves; JIS X 0212 is not decoded, so `0x8F` forms return `0x805C0020` in rows X 0212 leaves empty and `0x805C0014` elsewhere; a null profile returns `0x805C0004`, and the lengths are cleared first and then set as the console sets them. Their signatures follow the Orbital type database linked above. The console reads any other profile pointer as a sheet, where these return the invalid-parameter error: a PS5 (firmware 11.60, payload process; a title process may differ) converted `A` with the Shift-JIS profile (return 0), so whether it reads the profile for ASCII is open, and agreed in seven probed `sceCesEucJpToUtf8` cases (`A`, `0xA4A2`, `0x8EB1`, `0xA1C0`, `0x8FB0A1` with `0x805C0014` and size 3, a lone `0xFF` with `0x805C0014` and a lone `0xA4` with `0x805C0011`).
## change [Shift-JIS and EUC-JP scalar conversions]
- [Shift-JIS and EUC-JP scalar conversions](../../../core/libs/prx/libSceCesCs/Export.cpp) (libSceCesCs) - a PS5 (firmware 11.60, payload process; a title process may differ) agreed with the prior implementation in 44 of 61 probed cases of `sceCesSJisToUtf8`, `sceCesSJisToUcs2`, `sceCesUtf8ToSJis`, `sceCesUcs2ToSJis`, `sceCesEucJpToUtf8`, `sceCesSJisCodeToJisX0208` and `sceCesJisX0208ToSJisCode`, among them the codes `0x805C0011`, `0x805C0014`, `0x805C0015` and `0x805C0020` and null length pointers, and differed in 17. On a PS5 (firmware 11.60), `sceCesUtf8ToSJis` of `F0 90 80 80`, `ED A0 80`, `F4 90 80 80` and `C0 80` (`0x805C0020`, `0x805C0015`, `0x805C0020`, `0x805C0015`) set the length of the UTF-8 read to 4, 3, 4 and 2 and the size to 0, as this now does for illegal and unassigned characters, leaving the output bytes unchanged.
  Remaining differences: `sceCesSJisToUtf8` of `0x82A0` set size 2 and length 3 for a null output (`0x805C0030`) and 0 and 0 for a null source (`0x805C0010`) or a null profile, which answered `0x805C0004` where this answers `INVALID_PARAMETER`. `sceCesSJisCodeToJisX0208` answered `0x805C0024` for `0x0020` and `0x805C0014` for `0xA0A0`, both with ku and ten 0. `sceCesJisX0208ToSJisCode` answered `0x805C0015`, not `INVALID_ENCODE`, for the cells (0,1), (1,0), (95,1), (1,95) and (93,95), with code 0 except `0xF040` for (95,1). The other encoding's profile converted `A` (return 0) in both directions, and a profile of 2048 `0xAA` bytes raised SIGBUS. The UTF-16 and UTF-32 forms, `sceCesEucJpToUtf16` and their length pointers are unverified against the console and assumed: a surrogate or a value above U+10FFFF `INVALID_ENCODE`, a code point outside the BMP `UNASSIGNED_CODE`. Signatures follow the Orbital type database linked above; the CP932 and CP51932 table and profile assumptions above apply.
