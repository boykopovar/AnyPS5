# libSceCesCs
## change [Unicode scalar conversions]
- [Unicode scalar conversions](../../../core/libs/prx/libSceCesCs/Unicode.cpp) (libSceCesCs) - console error precedence, optional length pointers and length units are unverified. Signatures follow the [Orbital type database](https://github.com/AlexAltea/orbital/blob/b321fcdbd700cc02da1cb1ad25412781d5ec73c6/tools/ida/db_types.json); names are in the aerolib table pinned by `tools/nid_names.py`. Encoding follows [Unicode section 3.9](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/). Each call converts one scalar, including zero and U+FEFF, without a terminator or byte-order detection; lengths count bytes for UTF-8 and 16-bit units for UTF-16. Native forms use host byte order (supported hosts are little-endian). Errors follow the existing CES converters, not console measurements, and failure leaves outputs unchanged (the console sets the lengths on failure in the Shift-JIS conversions, see their entry). A PS5 (firmware 11.60, payload process; a title process may differ) did not find any of these 14 names, `sceCesUcs2ToUtf8` to `sceCesUtf32leToUtf8`, with `dlsym` under the bare name or the suffixes `_40` to `_90` in `libSceCesCs.sprx` (the control `sceCesUcsProfileInitSJis1997Cp932` was found), so no console behaviour is known; in which module the console holds them is open.
