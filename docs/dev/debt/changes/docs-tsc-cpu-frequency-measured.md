# libkernel

## change [sceKernelGetMainSocId and sceKernelGetCpumode]

- [sceKernelGetMainSocId and sceKernelGetCpumode](../../../core/libs/prx/libkernel/System/src/Process.cpp) (libkernel) both return 0, and [sceKernelGetCpuFrequency](../../../core/libs/prx/libkernel/Time/Time.cpp) returns the host TSC frequency measured for `sceKernelGetTscFrequency`, where a payload process on a CFI-2014 PS5 (firmware 13.60) got 0x840f80, 1 and 800000000. A payload process on a PS5 (firmware 13.590.001, model not recorded) got 3200000000 from `sceKernelGetCpuFrequency` in two runs, while `sceKernelGetTscFrequency` and `machdep.tsc_freq` both gave 1596300174, and `rdtsc` advanced 1596301737 to 1596307347 ticks in each of six 1 s `CLOCK_MONOTONIC` windows. So the console does not return its TSC rate from `sceKernelGetCpuFrequency` there, the 800000000 above is a different value from the same call, and the equality of the two functions that `GuestCurrentCpu` requires is not measured on a console. The SoC id may differ between console models, and the CPU mode of a title may differ from a payload's (shadPS4 takes the PS4's from the param.sfo flags), so neither is copied. `sceKernelGetMainSocId` ignores a pointer argument there, as here. PPSA99203 only logs them (`[console] main SoC id: result=%#x out=%#x`, `CPU: %llu Hz, cpumode %d`)
