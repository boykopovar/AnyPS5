# libSceLibreSsl3

## add Functional

- [X509V3_EXT_conf_nid NID 0](../../../core/libs/prx/libSceLibreSsl3/src/X509V3ExtConfNid.cpp) (libSceLibreSsl3) - with `ext_nid` 0, a `DER:` or `ASN1:` value is parsed before the extension object is looked up: a value that does not parse queues its own reasons and `EXTENSION_VALUE_ERROR`, such as `ILLEGAL_OBJECT` for `ASN1:OID:UNDEF`, and one that parses queues `EXTENSION_NAME_ERROR` alone. LibreSSL 3.4.1 [`v3_generic_extension`](https://github.com/libressl/openbsd/blob/078b3d1df8ca2011c1605cd40418c58fa0f5b143/src/lib/libcrypto/x509/x509_conf.c#L278-L296) first fails `OBJ_txt2obj("UNDEF")` and queues `FIRST_NUM_TOO_LARGE` and `EXTENSION_NAME_ERROR` whatever the value. Of 48 such values compared with 3.4.1, 23 queue the value's reasons, 15 lack only `FIRST_NUM_TOO_LARGE` and 10 throw as documented. Not checked on a console. Closes when: the extension object is looked up first.
- [X509V3_EXT_conf_nid object names](../../../core/libs/prx/libSceLibreSsl3/src/X509V3ExtConfNid.cpp) (libSceLibreSsl3) - `ASN1:OBJECT`, `ASN1:OID` and extendedKeyUsage names are those of libSceLibreSsl's 2.5.4 table and of the newer objects in [Objects.cpp](../../../core/libs/prx/libSceLibreSsl3/src/Objects.cpp), not LibreSSL 3.4.1's. NID 943 and 944 keep their 2.5.4 names, so 3.4.1's `id-tc26-gost-3410-12-512-paramSetA`, `id-tc26-gost-3410-12-512-paramSetB`, `GOST R 34.10-2012 (512 bit) ParamSet A` and `B` fail here. 76 names that 3.4.1 does not know, the 2.5.4 names of NID 943 and 944 and those of NID 1016 to 1055 such as `ACME Identifier`, encode where 3.4.1 fails. Not compared with 4.0.0. Not checked on a console. Closes when: the names the console module knows are measured.
