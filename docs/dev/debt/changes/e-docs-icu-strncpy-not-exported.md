# libSceIcu
## change [UTF-16 copying](../../../core/libs/prx/libSceIcu/Copy.cpp)
- [UTF-16 copying](../../../core/libs/prx/libSceIcu/Copy.cpp): on PS5 (firmware 11.60, payload process; a title process may differ) the loaded `libSceIcu` module has neither `u_strncpy` nor `u_strncat` (`dlsym` found neither), so their behavior there cannot be measured; the console ICU version and the exact copy/concatenation behavior of the other exports are unverified. These five exports follow [ICU 78.1 ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp): `u_strncpy` stops at the first copied NUL without padding, and `u_strncat` appends up to the positive count of code units followed by NUL. The latter follows the implementation, despite its header's conflicting count-minus-one prose. Nonpositive counts leave the destination untouched, without reading either pointer. Code units, including unpaired surrogates, are copied without Unicode validation. As in the reference, callers supply sufficient storage and valid nonoverlapping ranges; invalid positive-count pointers and overlapping `u_memcpy` are outside its contract.
