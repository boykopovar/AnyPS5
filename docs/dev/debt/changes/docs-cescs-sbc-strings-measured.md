# libSceCesCs
## change [UTF-16 and UTF-32 forms of the single-byte and MBCS string conversions]
- [UTF-16 and UTF-32 forms of the single-byte and MBCS string conversions](../../../core/libs/prx/libSceCesCs/Export.cpp) (libSceCesCs) - string conversions, endian-qualified and pointer UTF-32 variants, and unmeasured profiles remain unverified. Native single-character `sceCesSbcToUtf16`, `sceCesSbcToUtf32`, `sceCesUcs2ToSbc` and `sceCesUtf16ToSbc` match measured PS5 firmware 11.60 payload behavior: failed single-character encodes clear the output byte with Cp1252 and ISO 8859-1; `sceCesUtf16ToSbc` reports consumed UTF-16 units on error (1 for a lone surrogate, 2 for U+1F600); `sceCesUcs2ToSbc` reports `ILLEGAL_CODE` for U+D800 with Cp1252, Cp1254, Cp1258, ISO 8859-1 and ISO 8859-15; `sceCesUtf16ToSbc` reports `ILLEGAL_CODE` for a lone low surrogate with those profiles; zero-capacity native `sceCesSbcToUtf16` reports `DST_BUFFER_END` and writes length 1; null profiles and unassigned Cp1252 bytes clear output on error.
## change [Single-byte profiles]
- [Single-byte profiles](../../../core/libs/prx/libSceCesCs/SingleByte.hpp) (libSceCesCs) - console tables for these 31 profiles are unverified, except ISO 8859-1 where a PS5 (firmware 11.60 payload process, re-measured on 13.60) returned U+0000 to U+00FF for all 256 bytes through `sceCesSbcToUcs2`, `sceCesSbcToUtf16` and `sceCesSbcToUtf32`. Each profile is accepted by `sceCesSbcToUtf8`, `sceCesUtf8ToSbc` and MBCS context conversions, leaving 0x00-0x7F unchanged and using public high-half tables: ISO 8859-1, -2, -4, -5, -9, -10, -13, -14, -15, -16; code pages 437, 737, 775, 850, 852, 855, 860-864, 865, 866; KOI8-R, KOI8-U; and 1253, 1254, 1255, 1256, 1257, 1258. Unassigned bytes are in the next entry.
