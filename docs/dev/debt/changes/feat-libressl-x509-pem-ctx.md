# libSceLibreSsl

## change [SSL_CTX_add_client_CA](../../../core/libs/prx/libSceLibreSsl/src/SslCtx.cpp)

- [SSL_CTX_add_client_CA](../../../core/libs/prx/libSceLibreSsl/src/SslCtx.cpp) - not measured on a PS5; the `X509_NAME` copy pushed on the context's client CA stack can never be released, because there is no `X509_NAME_free` export and `SSL_CTX_free` is a stub, so only the context release of [#12729](https://github.com/boykopovar/AnyPS5/pull/12729) frees it. Subject duplication is structural (entries, objects, strings, `bytes`, canonical encoding) because `i2d_X509_NAME` does not exist: 2.5.4 reaches it through `X509_NAME_dup`, an `i2d` then `d2i` round trip per [ssl_cert.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl/ssl_cert.c#L518-L548) and [a_dup.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/a_dup.c#L98-L118). A null certificate returns 0 before the stack is read, and null contexts or missing internal state throw where that source computes the field address.

## change [SSL_CTX_load_verify_locations](../../../core/libs/prx/libSceLibreSsl/src/SslCtx.cpp)

- [SSL_CTX_load_verify_locations](../../../core/libs/prx/libSceLibreSsl/src/SslCtx.cpp) - not measured on a PS5; a non-null `path` throws, because the certificate directory lookup of 2.5.4 [x509_d2.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509/x509_d2.c#L99-L105) and [by_dir.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509/by_dir.c#L115-L186) is not modelled. A `file` goes through `X509_STORE_add_lookup` into the context's certificate store and returns 0 when the read fails, as that file and [ssl_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libssl/ssl_lib.c#L2781-L2785) do; two null sources return 0 without touching the store.

## change [PEM_read_X509](../../../core/libs/prx/libSceLibreSsl/src/PemX509.cpp)

- [PEM_read_X509](../../../core/libs/prx/libSceLibreSsl/src/PemX509.cpp) is not measured on a PS5; encrypted records stay unimplemented: a non-empty header throws where [pem_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/pem/pem_lib.c#L481-L539) reads `Proc-Type` and `DEK-Info` and `PEM_do_header` decrypts, so the password callback is never used. The FILE-to-BIO forwarding follows [pem_x509.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/pem/pem_x509.c#L69-L73) and the file BIO is borrowed and freed without closing the stream. A null FILE queues PEM buffer-library failure, an empty file queues `PEM_R_NO_START_LINE`, and a BIO allocation failure queues BIO then PEM malloc failure. Closes when: the console export is measured on a PS5

## change [PEM_read_bio_X509](../../../core/libs/prx/libSceLibreSsl/src/PemReadBioX509.cpp)

- [PEM_read_bio_X509](../../../core/libs/prx/libSceLibreSsl/src/PemReadBioX509.cpp) is not measured on a PS5; encrypted records throw, and the `Expecting: %s` data that 2.5.4 attaches to `PEM_R_NO_START_LINE` is not kept, because the error queue holds codes only. A `CERTIFICATE` or `X509 CERTIFICATE` record now reaches `d2i_X509`, and a payload that decoder rejects queues PEM reason `ERR_R_ASN1_LIB` (13) as [pem_oth.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/pem/pem_oth.c#L71-L86) does. The reader follows 2.5.4 [pem_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/pem/pem_lib.c#L272-L305) (`PEM_bytes_read_bio`, `check_pem`) and the base64 decoder of [encode.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/encode.c#L217-L423).

## change [PEM_read_bio_X509_AUX](../../../core/libs/prx/libSceLibreSsl/Export.cpp)

- [PEM_read_bio_X509_AUX](../../../core/libs/prx/libSceLibreSsl/src/X509Aux.cpp) is not measured on PS5; an `X509_CERT_AUX` holding `other` auxiliary information throws, because the `X509_ALGOR` items of that field are not modelled, and no export reads the trust, reject, alias or key id items back. A `TRUSTED CERTIFICATE` record decodes the certificate and the items that follow it, replacing `*a` only on success as [x_x509.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/x_x509.c#L309-L335) and the `X509_CERT_AUX` template of [x_x509a.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/x_x509a.c#L74-L112) do, and `X509_free` releases the decoded item as that file's destroy callback does. Encrypted records throw as the `PEM_read_bio_X509` entry describes.

## change [X509_LOOKUP_file and X509_STORE_add_lookup](../../../core/libs/prx/libSceLibreSsl/src/X509Store.cpp)

- [X509_LOOKUP_file and X509_STORE_add_lookup](../../../core/libs/prx/libSceLibreSsl/src/X509Store.cpp) are unverified on PS5; the file method's `ctrl` of `by_file.c` loads PEM certificates only. An `X509 CRL` or private key record in the file, and the `X509_FILETYPE_ASN1` and `X509_FILETYPE_DEFAULT` modes that file reads, throw; certificates the file already added stay in the store where it returns 0 and keeps them. The 80-byte method, the 32-byte lookup and the stack growth follow [x509_lu.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509/x509_lu.c#L71-L91) and `stack.c`: a failed lookup allocation returns null there without a code, a guest method's `new_item`, `shutdown` and `free` are called as it does, and a null store, method or listed lookup throws where LibreSSL faults. A lookup stack with `num_alloc <= 0` or a negative count throws where LibreSSL would call `realloc` with a bad size

## add Functional

- [X509_get_pubkey](../../../core/libs/prx/libSceLibreSsl/src/X509Pubkey.cpp) is not measured on a PS5; elliptic curve parameters given as an explicit `SEQUENCE` throw, because the `d2i_ECParameters` call of [ec_ameth.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ec_ameth.c#L145-L157) is not modelled, and so do the curves the module's mbedtls mapping does not provide, where `EC_GROUP_new_by_curve_name` throws instead of returning null as the `pub_decode` table of [x_pubkey.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/x_pubkey.c#L177-L229) expects. A `dsaEncryption` SubjectPublicKeyInfo throws because no `EVP_PKEY` algorithm method holds a DSA key; any other algorithm returns null after queueing (6,0xfff,156) and (11,0xfff,111).
- [EC_POINT_oct2point and EC_GROUP_new_by_curve_name](../../../core/libs/prx/libSceLibreSsl/src/Ec.cpp#L507-L560) are not measured on a PS5: they return 0 or null without queueing `EC_R_INVALID_ENCODING` (16,0xfff,102) in `ecp_simple_oct2point`, or `EC_R_UNKNOWN_GROUP` for an unassigned curve NID. A public key whose point is rejected in `X509_get_pubkey` therefore leaves the queue at (16,0xfff,16) (16,0xfff,142) (11,0xfff,125) where 2.5.4 [ec_asn1.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ec_asn1.c#L1539-L1565) and [ec_ameth.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ec_ameth.c#L186-L213) queue one more code first.
- [X509_load_crl_file and PEM_X509_INFO_read_bio](../../../core/libs/prx/libSceLibreSsl/Export.cpp) remain parameterless stubs, and the module exports no `X509_load_cert_file`, `X509_STORE_load_locations` or `X509_INFO_new`. The loader behind `SSL_CTX_load_verify_locations` follows [by_file.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/x509/by_file.c#L237-L266) and [pem_info.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/pem/pem_info.c#L95-L305) in [X509StoreLoad.cpp](../../../core/libs/prx/libSceLibreSsl/src/X509StoreLoad.cpp#L255-L387), freeing items via `X509_INFO_free` with per-element unwind guards, and throws on an `X509 CRL` or a private key record, because `X509_STORE_add_crl` rejects a non-null CRL and no private key decoder exists.
