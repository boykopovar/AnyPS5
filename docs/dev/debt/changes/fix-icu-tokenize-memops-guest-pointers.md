# libSceIcu

## change [UTF-16 set searches and tokenization]

- [UTF-16 set searches and tokenization](../../../core/libs/prx/libSceIcu/Tokenize.cpp) have no console verification; ICU versions on other firmware are unverified. Signatures and behavior follow ICU 78.1's [ustring.h](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/unicode/ustring.h) and [ustring.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustring.cpp). `u_strtok_r` preserves that source's one-code-unit delimiter overwrite, including the trailing surrogate left after splitting at a supplementary delimiter. Strings are read with `GuestCopyIn_nid_no_patch` in page-bounded chunks only as far as the search goes, `u_memrchr32` copies its counted range in, and the continuation and delimiter writes go through `GuestCopyOut_nid_no_patch`. Invalid null inputs, unreadable strings or continuations and unwritable continuations or delimiter positions throw, because the console's behaviour on unmapped memory is unmeasured; the continuation is written before the delimiter, so an initial continuation assignment is retained if a later delimiter write is rejected. Set-search offsets beyond `INT32_MAX` throw.

## change [Bulk UTF-16 writes]

- [Bulk UTF-16 writes](../../../core/libs/prx/libSceIcu/Utf16Search.cpp) and [`u_memcpy`](../../../core/libs/prx/libSceIcu/Copy.cpp) copy the source range in with `GuestCopyIn_nid_no_patch` and write the destination with `GuestCopyOut_nid_no_patch`; an unreadable source or an unwritable destination, including a read-only view on every host, throws, because the console's invalid-pointer behavior is unverified. Windows logical read-only guest-view rejection has a runtime regression but has not been executed locally on Windows. A destination range that becomes unwritable partway may be partly written before the throw.
