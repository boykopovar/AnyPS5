# libSceAgcDriver

## change [Device-local staging]

- [Device-local staging](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (libSceAgcDriver) - a written or atomic buffer element in a host import, also one an address-based build reaches by pointer, is staged in device memory around the dispatch or recorded draw. The copy-back stores only bytes the shader changed and the import still holds at copy-in value, so a CPU store in between survives and wins where both changed a byte, whichever the console stores last. The whole range is copied back over CPU stores at a range's unaligned ends, for an offset not 4-byte aligned, without a shadow copy, device addresses or the copy-back pipeline, with `APS5_NO_CHANGED_COPY_BACK`, on NVIDIA's Windows driver unless `APS5_CHANGED_COPY_BACK` (shader stores into an import ran at 1.5 against the copy's 19 GiB/s on an RTX 4080 SUPER; AMD and Intel unmeasured), and when a synchronous draw stores a GPU-copied region from the CPU. A CPU store during the copy-back can be lost.

## add Functional

- [GPU copies of draw inputs](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Draw.cpp) (libSceAgcDriver) - where vertex ranges are copied, not bound in place, a range behind a pending GPU write is copied out of its host import into device memory behind that write (`GpuCopiedDrawInput`). The GPU reads it at the copy's place in the batch, not at each draw as an in-place binding does; draws reuse the copy until a GPU write is noted over the range or the write tracker sees a CPU store, so a guest store made while the write is pending is seen only once collected. Index buffers, zero-padded fetches and ranges under a label, behind a copied writer, outside a watched host import or refused device memory keep the CPU copy and its wait. A range the tracker does not cover is never copied, though an owned-block proof could serve it. Unmeasured in a title. Closes when: measured in a title that skins meshes in compute.

## add Functional

- [Single-key uploads behind a pending write](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Texture.cpp) (libSceAgcDriver) - a storage image under comp-to-single DCC keys whose texels recorded GPU work still writes is cleared from a pending word fill of the whole surface, or detiled on the GPU from its host import, without reading the texels. Memory the write tracker does not watch, a surface without a host import and a mip or layer not at a 256-byte offset still read them on the CPU after that work. A refresh whose keys did not change still compares the texels with the snapshot a CPU upload kept, and a later flush of the image that is not GPU-ordered still waits for the writers of its range, so the wait can move there. Unmeasured in a title. Closes when: measured in a title that clears its targets to single keys every frame.

## add Functional

- [Staging shadow budget](../../../core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp) (libSceAgcDriver) - cached builds keep their staging shadows, so the resource cache evicts the least recently used builds whose shadows no newer entry shares while the distinct shadows exceed half of the live shadow bound (`StagedByteBudget`, `StagingShadowLimit`); a refused region is bound in place until the bound has room or another build holds a shadow of its range. Only compute builds without a lease share a shadow per guest range. The bound is an eighth of the device-local heap budget and the cache's share half of it, both from one title on NVIDIA's Windows driver before shadows were shared (PPSA36301, RTX 4080 SUPER, 15277 MiB budget: a sixteenth with no cache bound filled 954 MiB in a minute and bound later regions in place, about 10 ms per dispatch; a 477 MiB share rebuilt a frame's builds, 10 to 12 frames per second against 17 to 18 with 1000 MiB). Other titles are unmeasured.

## add Functional

- [Input twins](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (libSceAgcDriver) - a compute dispatch reads a read-only region from a device-local copy refreshed only when the write tracker, a write note, a driver store or pending work says the range changed: a guest store the write watch misses is never read, one made within a collect epoch after the range was collected is read from the queue's next epoch on (a memoised verdict, like the draw proofs), and a store anywhere in a 64 KiB tracker block the range touches refreshes it. Draws, ranges outside a host import and regions a build writes are bound in place; a region written between every two uses is given up after eight copies. Only NVIDIA's Windows driver takes it (PPSA36301 on an RTX 4080 SUPER). The bound, a sixteenth of the heap budget beside the staging shadows' eighth, holds that title's skinning inputs (about 2.5 MiB per dispatch, up to 51 per frame) several times; other titles are unmeasured.

## add Functional

- [Staged copy-back handover](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Recorder.cpp) (libSceAgcDriver) - a CPU store into the written range of a staged region, made between two dispatches that stage it without waiting for the first, is not read by the second, which reads the first one's shadow; the copy-back overwrites it either way; bytes outside the written ranges still come from guest memory. The handover is left out where the copy-back is the changed-bytes compute pass (a pending copy-back landing under its taker would stale the copy-in baseline), for address-based builds and recorded draws, and for a use whose region bounds, import or written ranges differ. A dispatch keeps the pending copy-backs of ranges it does not touch only when it binds only guest buffers, shader data and the GDS; one with image bindings, an HTILE clear or a lease lands them all, as does every other command. Measured on one title with NVIDIA's Windows driver; tests force the buffer copy-back.

## add Functional

- [Shape user words](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawLookup.cpp) (libSceAgcDriver) - a draw without a cache entry reuses a remembered stage of its shape across a moved user word only when the word is a base the SRT walk never read as a value, a buffer V# word held in user SGPRs (found by value), a word the stage only forwards, or a vertex table pointer whose tables decode again to the same inputs but for V# bases and record counts, which are patched. It captures the stage again when a table read through a pointer or an unmoved vertex table holds another word, when a pointer's high word or low two bits change, when re-decoded inputs differ otherwise, when the walk reads a table pointer it cannot relocate, and for a GCN fetch subroutine word; relocation aliases refuse every move on a stage with vertex inputs. A shape keeps `APS5_DISPATCH_VARIANTS` draws, lost with their entries. `[draw-cache] shape user words` counts each case; no title is measured.

## add Functional

- [Direct prints under the GPU mutex](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Texture.cpp) (libSceAgcDriver) - only the texture cache budget, the `[texture]` totals, the `[staging] adaptive` decisions and `APS5_TRACE_DISPATCH_IO` are queued for another thread. The driver's other `std::fprintf(stderr, ...)` calls still write on the calling thread, one write per call, and some run while the GPU mutex is held, the `APS5_TRACE_*` lines of `Texture.cpp` among them. A line built by several calls (`[fill-cover]`, the `[gpu]   ` import list) is several writes that another thread can cut. How long one write to a console or a redirected file holds the mutex is not measured. Labels: code, no-test, windows.

## add Opt-in draw paths

- [Draw proofs](../../../core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp) - a reused resource or target proof sees a CPU store only at the next collect epoch, as the collect memo does; the full check could see it earlier when another thread walked the page, so `APS5_VERIFY_DRAW_PROOFS` may count such a store as a difference. Any GPU-lock hold by a thread other than the committer breaks every proof, so dispatches on other queues between draws void them. Templates with BDA, staged copies, depth copies, reuse lookups or compared unwatched memory keep the full check. `sameColorTarget` lists the `ColorTarget` fields by hand.

## add Opt-in draw paths

- [Shared collect epoch](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawPipeline.cpp) - the draw finisher and the committer run each job and item in the collect epoch the queue worker held when it queued it, so a walk made since that epoch began answers their collects: a CPU store landing between that walk and the commit, with no ordering point of the queue in between, is seen from the worker's next ordering point on, as for a draw recorded inline later in that epoch. Epoch-keyed memos on shared objects (resource proofs, storage image and mirror refreshes, input twin verdicts, untracked compares) can now pass between the worker, the finisher and the committer within one epoch: one taken under the GPU lock by a thread other than the committer carries the `ProofSerial` its lock moved; twin verdicts and untracked compares rely on their own serials. Only focused tests and `APS5_VERIFY_DRAW_PROOFS` cover it; `APS5_NO_SHARED_COLLECT_EPOCH=1` restores separate epochs.
