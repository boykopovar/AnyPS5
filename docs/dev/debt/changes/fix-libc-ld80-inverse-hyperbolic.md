# libc

## change [acoshl, asinhl, atanhl, expm1l, hypotl, log1pl, log2l, lgammal, tgammal, jnf and ynf]

- [expm1l, hypotl, log2l, lgammal, tgammal, jnf and ynf](../../../core/libs/prx/libc/src/Math.cpp) (libc) return the host C library's results (the float Bessel functions through its double ones), not those of the console's own code, so the last bits can differ (`ynf` follows the console at `+-0`). `tgammaf` delegates to the host's double `tgamma` as FreeBSD 11 does ([`s_tgammaf.c`](https://github.com/freebsd/freebsd-src/blob/stable/11/lib/msun/src/s_tgammaf.c)), except above 171.63 (`x / 0`) and below -190 (a signed zero without underflow), where it follows msun's `b_tgamma.c` as the bundled `libc.prx` does, then restores the sign of a zero result for negative non-integer inputs from the parity of `floor(-x)`; nine title-bundled `libc.prx` builds return that sign for underflowing inputs, where Windows UCRT can return the opposite sign ([#9707](https://github.com/boykopovar/AnyPS5/issues/9707)). As in the console's `libSceLibcInternal.sprx` (SDK 4.5x build of `J03950001`, 0x56410), `lgammal` does not store the sign in `signgam`; `hypotl` returns infinity for an infinite argument even when the other is a NaN, as C11 F.10.4.3 requires. [hypot3, hypot3f and hypot3l](../../../core/libs/prx/libc/src/Math.cpp) follow that module (0x51D30, 0x520D0, 0x52420): the first NaN of x, y and z is returned unchanged, any infinity gives positive infinity, a zero argument gives the two-argument hypot of the other two, and otherwise the largest magnitude is combined with the hypot of the other two

## add Functional

- [log1pl, acoshl, asinhl and atanhl](../../../core/libs/prx/libc/src/Math.cpp) (libc) run at the caller's x87 precision, as the binary does, so a guest thread that starts at 53 bits (see `asinl`) gets the binary's 53-bit result, not the console's 64-bit one. They follow the `libc.prx` bundled with PPSA08194 (relinked: 0x40a80, 0x40990, 0x41620, 0x42110), which builds them from `_LLog` (its `logl`), `sqrtl` and `_Feraise`, with the cutoffs `2^-66` (`log1pl`, `asinhl`), `2^-33` (`atanhl`) and `2^67` (`acoshl`, `asinhl`) and the 80-bit `ln 2` taken from the binary. A million arguments per function, special values and cutoffs included, give the same bits, `errno` and flags as that code run natively on Linux at 64-, 53- and 24-bit precision; the host results differed on 190,953, 64,097, 265,456 and 136,769 at 64 bits. Unordered operands such as pseudo-infinities take the binary's branches. Other SDK versions are not compared
