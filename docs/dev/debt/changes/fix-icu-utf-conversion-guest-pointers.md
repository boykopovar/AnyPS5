# libSceIcu

## change [UTF-8 macro helpers]

- [UTF-8 macro helpers](../../../core/libs/prx/libSceIcu/Utf8.cpp) have no console ABI or behavior verification. Their names and NIDs are in the [PS5 3.20 inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIcu.c); behavior follows ICU 78.1 [utf_impl.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/utf_impl.cpp). These are macro bodies, not complete UTF-8 operations: append encodes ASCII with two bytes, and null-error-pointer failures write the legacy length-dependent error characters. Null, unreadable or (for the index) unwritable index pointers and buffers, negative positions, reversed bounds and overflowing index or capacity arithmetic throw instead of reproducing undefined behavior. Negative forward lengths denote NUL-terminated input. Cross-firmware export availability and native behavior outside the macros' preconditions remain unverified.

## change [UTF-8 and UTF-16 conversions]

- [UTF-8 and UTF-16 conversions](../../../core/libs/prx/libSceIcu/UtfConversions.cpp): exact PS5 version equivalence is unverified. The five conversion exports follow ICU 78.1 [ustrtrns.cpp](https://github.com/unicode-org/icu/blob/049e0d6a420629ac7db77256987d083a563287b5/icu4c/source/common/ustrtrns.cpp), including strict/substitution handling, lenient malformed-byte output, error preservation and buffer termination. A null error pointer and lengths whose result cannot fit the signed 32-bit ICU API throw; ICU requires a valid error pointer and does not define useful overflow behavior there. Source and destination must not overlap, as required by ICU. Inaccessible guest memory throws, as ICU defines no error for it. A refused output write guard throws before any output is modified, except in `u_strFromUTF8Lenient`, whose source and destination are copied in 4 KiB chunks: an unreadable source or unwritable destination is detected when reached, after earlier chunks are written.
