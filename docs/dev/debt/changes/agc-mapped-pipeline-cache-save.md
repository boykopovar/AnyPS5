# libSceAgcDriver

## add Functional

- [Pipeline cache saves from a buffer](../../../core/libs/prx/libSceAgcDriver/Graphics/src/PipelineCache.cpp) (libSceAgcDriver) - by default a pipeline cache save has the driver copy the whole cache into a host buffer before the file is written, so host memory rises by the size of the cache for the length of each save. On Windows a save of 64 MiB or more is put off while that would take free memory under a reserve; Linux and macOS have no such check. Only Windows can write a save through a mapped file instead, and only with `APS5_PIPELINE_CACHE_MAPPED_SAVE_MB` set. The driver then fills the mapped file under the snapshot lock at the disk's speed, so pipeline creations wait for the length of a large save; how long that is on a slow disk is not measured. The mapped save was measured on one title and one NVIDIA GPU.
- [Storage errors during a mapped pipeline cache save](../../../core/libs/prx/libSceAgcDriver/Graphics/src/MappedCacheFile.hpp) (libSceAgcDriver) - the mapped save is off unless `APS5_PIPELINE_CACHE_MAPPED_SAVE_MB` is set, because a storage error while the driver writes into the mapped file, or while the save reads it back for the checksum, raises an in-page error that nothing handles, so the process ends; the previous cache file is kept and the temporary file is removed by the cache housekeeping. A save from a buffer gets such an error as a failed write. Making the mapped save the default needs a failure path for that fault: the driver's `vkGetPipelineCacheData` cannot be unwound from a fault handler, so the handler would have to put memory the driver can finish writing into in the view's place and mark the save failed, and the checksum read and header write need the same. Not tested: no storage error was injected.
