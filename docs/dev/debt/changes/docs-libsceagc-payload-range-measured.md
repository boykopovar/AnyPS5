# libSceAgc

## change [sceAgcGetDataPacketPayloadRange]
- [sceAgcGetDataPacketPayloadRange](../../../core/libs/prx/libSceAgc/Misc/src/PacketInfo.cpp) (libSceAgc) - signature, the `{base, size in bytes}` output and the type 0 range (header + 1, one dword longer than the type 1 payload) from KytyPS5 only, matching `sceAgcGetDataPacketPayloadAddress_0090`; prosper returns header + 2 for both types from that address function. A null or unwritable output pointer throws (rejecting unwritable memory is a host-safety fallback). A PS5 (firmware 11.60, payload process; a title process may differ) gave, for a packet header with a count field of 3, the base header + 1 and 16 bytes for the type 0 and header + 2 and 12 bytes for the type 1; for a header with all count bits set, header + 2 and 65532 bytes for the type 1 and a size of 0 and a base that is probably null for the type 0 (the probe logged the base minus the packet address, not the base); and a fault with SIGSEGV for a null output pointer, where this throws. The cases after that fault were not run. For a count field of 3 the console result matches KytyPS5 (type 0 header + 1) and not prosper's header + 2 for both types.
