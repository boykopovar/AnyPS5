# libkernel

## change [sceKernelPrintBacktraceWithModuleInfo](../../../core/libs/prx/libkernel/Unimplemented.cpp)

- [sceKernelPrintBacktraceWithModuleInfo](../../../core/libs/prx/libkernel/System/src/Backtrace.cpp) (libkernel) - measured on a PS5 Pro payload process (13.60) in three calls across three sessions: returns 0 and prints `backtrace:`, one line per caller frame `[d]    0x<address> => (<symbol>|NoName)<module>+0x<offset>` with a module for every frame, `NoName` for unresolved symbols, and a final frame with address 0. The host prints the same shape from its native stack: Linux/macOS use `backtrace`/`dladdr`, Windows walks frames with the project's `_Unwind_Backtrace` wrapper and looks up modules and exports through the PE headers; addresses are host addresses and module names are host file names, so NID-patched exports print NIDs where the console names symbols. Output goes to host stderr. Exact spacing, address width, frame index and count, offset base and terminator text, title-process output, the console stream and any arguments are unverified; extra arguments are ignored.
