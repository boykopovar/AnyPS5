# libkernel

## add Functional

- [ioctl on a pipe](../../../core/libs/prx/libkernel/File/src/DescriptorControl.cpp) (libkernel) - `FIOSETOWN` and `FIOGETOWN` throw, as the pipe's `SIGIO` owner is not kept, and `TIOCSPGRP` and `TIOCGPGRP` fail with `ENOTTY` like every termios request, where FreeBSD 11.4's [`pipe_ioctl`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/sys_pipe.c#L1346-L1419) sets and reads that owner. Descriptors 0 to 2 are not taken as pipes, whatever the host attaches to them, so other requests there still throw. Above them, any other request without a case for every descriptor fails with `ENOTTY`, as the `default` of `pipe_ioctl` does, after an input argument is copied in (`EFAULT` if it cannot be read) unless `IOC_VOID` passes it by value, as `sys_ioctl` does; a FIFO takes the same path, as [`fifo_open`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/fs/fifofs/fifo_vnops.c#L252) gives it the pipe operations

## change any other well-formed request not listed here

- [ioctl, _ioctl](../../../core/libs/prx/libkernel/Socket/src/Udp.cpp) (libkernel) - `FIONREAD` on a directory throws (a payload on PS5 13.60 got 65536), as does any other well-formed request not listed here or in the `ioctl on` entries. On a socket only `FIONBIO`, `FIONREAD`, `FIOCLEX` and `FIONCLEX` are handled; another request fails with `EADDRNOTAVAIL` on an `AF_INET` or `AF_INET6` socket when its group is not `i`, `r` or `f` (`TIOCGWINSZ` measured), as FreeBSD's `soo_ioctl` hands it to `in_control`, and with `ENOTTY` otherwise (`i` and `r` go elsewhere there, `f` is unmeasured). Other descriptors follow FreeBSD's `kern_ioctl`, `vn_ioctl` and `pipe_ioctl`: `FIONBIO`, `FIOCLEX`, `FIONCLEX`, `FIONREAD` on files and pipes, `ENOTTY` for termios requests. An input or output request with length 0 fails with `ENOTTY` on every descriptor; only `0x8000667f` was measured; `sys_ioctl` checks just direction and length. Stremio Plus (PPSA74126) imports `_ioctl` for its `tc*` functions
