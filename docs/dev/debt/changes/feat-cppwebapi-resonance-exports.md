# libSceNpCppWebApi

## add Functional

- [sce::Np::CppWebApi container glue of the bundled PPSA31544 module](../../../core/libs/prx/libSceNpCppWebApi/Export.cpp) (libSceNpCppWebApi) - the `Vector<IntrusivePtr<...>>` `begin`/`end`/`size`, `Iterator`/`ConstIterator` `pp`/`de`/`ne`/`D2` and `IntrusivePtr` `pt`/`de`/`D1` over the `Activities::V1` `UserActivities`, `Activity` and `GetUsersActivitiesResponse` types, plus the `Transaction`/`TransactionBase` lifecycle methods over the `GetUsersActivitiesResponse`, `TitleCloudStorage::V1` and `InGameCatalog::V5` `Container`-list responses, were measured on the module bundled with PPSA31544 (FF Resonance, `0x2d9850`, `0x3ea840`-`0x40b3c0`). `RequestPlayerSession::setExpirationTime` stores the value at +0x11c with its is-set byte at +0x120 and `setNonPsnSupported` stores +0x121/+0x122, so these two keep state unlike the other request setters. `Transaction::C1` zeroes the 16-byte object; `finish`, `getResponseHeaders`, `setResponseInformationOption` and `setOnFinishedCallback` return `TransactionNotStarted` while the impl/context words stay null, the module's `0x80553508` path; `start` validates the context (`0x80553503`/`0x80553502`) then fails offline. This build keeps `Vector<IntrusivePtr>` element bounds at object +0x18/+0x28, but raw vectors in that layout never reach the exports because every vector the title iterates is a host body from a response accessor, so the raw fallback keeps the PPSA21564 offsets. Nothing here ran on a console.
