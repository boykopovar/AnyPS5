# shader

## change [3D image accesses bound to a 2D or 2D-array T#]

- [3D image accesses bound to a 2D or 2D-array T#](../../../core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp) follow CouchRiv's [hardware oracle](../HW_ORACLE.md) measurement on RDNA2 (gfx1036, #2023) and adriadam10's (gfx1035, #2140), not the PS5's gfx1013. On a 2D T#, `image_sample_lz` ignores r and reads the (u,v) texel, `image_load` and `image_load_mip` read the (x,y) texel when z is 0 and return zero otherwise, and `image_get_resinfo` returns (width, height, 1, levels). On a 2D-array T#, these accesses behave like dim 2D-array: r or z is the layer, and `image_get_resinfo` returns the layer count as its third component. Every other access of such an image, including samples with an LOD, bias, derivatives, offset or comparison, gathers and `image_get_lod`, keeps throwing because it is not measured. DIM 3D `image_store` and `image_store_mip` at mip 0 were measured on RDNA2 (gfx1036, driver 31.0.22044.1) with the hardware oracle, `dmask` 0x1 on an 8x8 32_FLOAT T#: on a 2D T# a lane writes its (x,y) texel when z is 0 and nothing when z is 1; on a two-layer 2D-array T# z is the layer and z 2 writes nothing. The recompiler implements the store through a 2D-array T#, which drops a layer past the array, and through a 2D T#, which drops every lane whose z is not 0. It applies the same rule to other formats, multi-component `dmask`s, mip levels above 0 and a z other than 0 and 1 on a 2D T#; none of those is measured.
