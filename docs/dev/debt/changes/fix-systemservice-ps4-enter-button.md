# libSceSystemService

## change parameters 1 to 5, 100 to 111, 200 to 213, 300 and 400 answer

- [sceSystemServiceParamGetInt](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - parameters 1 to 5, 100 to 111, 200 to 213, 300 and 400 answer (see Integer system parameters), and 1000 for a PS4 title; every other parameter, and a null value pointer, returns 0x80A10003 without writing the value. Inside a retail title on a PS5 (firmware 13.40, measured 2026-10-19 through ptrace remote calls in the game process) parameters 0, 6, 7 (game parental level), 8 to 20, 401, 999, 1000 (enter button assignment) and 1001 to 1008 returned 0x80A10003, as did a null value pointer; 1 to 5 and 400 answered, and 100 answered the value 0. A sweep of parameters 0 to 2048 in the same way on 2026-10-23 also found 101 to 111, 200 to 213 and 300 answering, each writing 4 bytes; every other parameter, and a null value pointer for 100 to 111, returned 0x80A10003 and left the value as it was. One title (PPSA13356, call at 0xAF350) asks for parameter 1 and does not read the result.

## add Unknown function info

- [sceSystemServiceParamGetInt](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService, PS4) - parameter 1000 (enter button assignment) answers 1 (cross) for a PS4 title, whatever the console's setting would be. `libSceSystemService.sprx` of PS4 firmware 13.52 (0x4140, read from disassembly, not measured on a console) reads it with `sceRegMgrNonSysGetInt(0x22666251fe7becff)`, writes 0 (circle) when that read fails, and returns 0; which value a console holds was not measured. A null pointer returns 0x80A10003 as in the firmware, and so does an unwritable one, where the console would fault. A PS5 title still gets 0x80A10003 with the value unwritten, as measured on a PS5. CUSA24767 01.71 sets circle, then asks for parameter 1000; with the value unwritten it used circle as its enter button. Closes when: measured on a PS4.
