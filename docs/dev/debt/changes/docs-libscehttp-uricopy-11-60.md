# libSceHttp

## change [sceHttpUriCopy]
- [sceHttpUriCopy](../../../core/libs/prx/libSceHttp/src/Uri.cpp) (libSceHttp) - unverified: whether the strings are written before the size check, which a short pool hides by ending cleared. The rest follows a payload process on a PS5 (firmware 13.60): the arguments are (out, src, pool, prepare, require) as in the disassembly; the whole output and all `prepare` pool bytes are cleared before the source is read, so a source that is the output or lies in the pool copies as empty; the scheme, hostname, path, username and password are copied in that order with terminators, a null one as empty, and the port, while the query, fragment and opaque flag stay 0; a short pool returns 0x80431022 and leaves `require` alone; a null source returns 0x80433060, and no output or pool with a null `require` 0x804311FE. A payload process on firmware 11.60 gave the same results for a source with the scheme `http`, the username `u`, the password `p`, the hostname `example.invalid`, the port 8080 and the path `/a/b`, with a pool of 256 bytes and of 4 bytes, with a null `require`, with a null source, and with no output or pool both with and without `require`; the question of the strings being written before the size check is still not answered by it.
