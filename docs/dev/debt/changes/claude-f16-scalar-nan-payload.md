# shader

## change [f16 NaN results with IEEE_MODE clear]

- [f16 NaN results with IEEE_MODE clear](../../../core/shader/recompiler/Translation/src/FloatInstructions.cpp) are the device's when the startup probe (`ProbeFloat16HostNans`) finds them equal to the selected ones above: those of the native `v_pk_add_f16`, `v_pk_mul_f16`, `v_pk_fma_f16` and `v_pk_fmac_f16`, whose second operand is replaced by the first when the first is a NaN (a driver may swap the operands), and the default NaN of the native `v_fma_f16`, `v_fmac_f16`, `v_fmamk_f16` and `v_fmaak_f16`. With the probe passing, `v_add_f16`, `v_sub_f16`, `v_subrev_f16` and `v_mul_f16` also pass the first NaN source as both operands to the native instruction, making the result independent of the driver's operand choice; with the probe failing, they give the first NaN source (source 0 for add/sub/mul, the second operand for subrev after the swap in `float16Binary`) quieted by `quietNan16`, then the second, then 0xfe00 for a NaN result from no-NaN inputs. The probe compares 4096 operand triples of 16 special halves in both lanes, with and without `op_sel`, `neg` and clamp, without FLOAT_MODE and in two FP16_OVFL modes, through a compute shader; the graphics stages rely on the same device behaviour. IEEE_MODE=1 keeps the selection (a Radeon RX 7900 XTX returns a signalling NaN source unchanged there, where RDNA quiets it), and so does a literal NaN source, which a driver may fold. `APS5_NO_HOST_F16_NANS` skips the probe. Scalar NaN propagation measured by three contributors on NVIDIA RTX 5080 (Windows, Khronos validation 1.4.363), NVIDIA RTX 3060 (Windows 11, WinLibs GCC 16.2.0), AMD RX 7900 GRE (RADV NAVI31, gfx1100, Linux Mesa 26.2.6), AMD Ryzen 7800X3D iGPU (RADV RAPHAEL, gfx1036) and AMD RX Vega 56 (RADV VEGA10, gfx900): 0 of 270336 host/device differences with the fix. The PS5's gfx1013 is not measured directly.
