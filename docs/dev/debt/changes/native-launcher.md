# TechnicalDebt

## add Build

- [Native Windows launcher](../../../../tools/launcher/Main.cpp) - ported from the user-supplied, first-party `AnyPS5_Launcher_0.1_Source_Kit.zip` (SHA-256 `af6c792675cf20e9dceecef1a40933309d9c6297011ae2a2066c83d8811304d3`, MIT, copyright 2026 Chris). There is no published upstream commit for this archive. The original notice is retained in `tools/launcher/LICENSE`. The native library format does not import the prototype's JSON settings; existing users must add their prepared launch files and settings. The native UI does not display artwork; the web UI uses local PNG icons. Closes when: JSON settings migration and local artwork are supported.

## add Functional

- [Launcher process monitoring and export](../../../../tools/launcher/Launcher.cpp) - Windows job objects track detached descendants while the launcher or helper remains alive; process-tree completion reports the wrapper exit code, not each descendant's exit code. Scripts waiting for input can outlive their game. The native launcher never infers gameplay from process status. Portable export does not rewrite arbitrary absolute paths inside scripts or environment strings and refuses symlinks; these require user review. Closes when: per-descendant result reporting and verified path migration are implemented.

- [Desktop helper](../../../../tools/launcher/DesktopHelper.cpp) - monitoring is not recovered after a helper restart; already launched games continue independently and the web UI requires explicit closure confirmation before another launch. Folder picking runs on the helper's desktop thread, so network heartbeats pause while its modal picker is open. A delivered web command whose result was lost is not replayed, to avoid duplicate game launches. Closes when: process monitoring can be recovered safely and folder selection has independent heartbeat handling.

- Automatic preparation supports extracted ELF64 x86-64 and decrypted SELF inputs, standard module directories and statically referenced PRX dependencies in other folders, at most 250,000 resources and main executables up to 2 GiB. Encrypted/package inputs, executable/module directory overlaps, incompatible shared-module layouts and dynamically loaded external modules without static dependency declarations require external preparation. Companion ELF/SELF images are converted through the existing multi-executable workflow; unsupported console syscall instructions remain errors and require engine implementation rather than disabling syscall validation. Import validation establishes loader dependencies, not implemented behavior or gameplay compatibility. An interrupted worker can leave a reserved staging directory; discovery skips it. Closes when: these input layouts and recovery cleanup have general implementations with integration coverage.
