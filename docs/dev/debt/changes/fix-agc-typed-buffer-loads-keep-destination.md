# shader

## change [Buffer descriptor type]

- [Buffer descriptor type](../../../core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp) - a buffer V# whose TYPE (word 3 bits 30-31) is not 0 throws `buffer descriptor uses an unsupported type`, except for vector stores, single-dword vector loads and read-only raw multi-dword vector loads through TYPE 2 or 3. Measured on a PS5 (CFI-1115B, firmware 12.20): through TYPE 2 or 3 with FORMAT 0 or a valid format, `buffer_store_dword` and `buffer_store_format_x` wrote nothing and did not fault, also with an unmapped base; loads and GLC atomics left the destination VGPR unchanged. Such loads are recompiled to keep their destination and the V# is bound as null. Raw `buffer_load_dwordx2`, `x3` and `x4` preservation is additionally measured on RX 6650 XT (gfx1032) through the hardware oracle, in wave32 and wave64 with mapped valid-format descriptors; the PS5 gfx1013 multi-dword behavior is not measured. TYPE 0 with FORMAT 0 returned 0 for loads and wrote nothing. TYPE 1 faulted the GPU for every access and throws. Atomics through TYPE 2 and 3 still throw. Unmeasured, still throwing: `tbuffer_*`, FORMAT above 77, GCN shaders, V#s loaded at run time, D16 loads, formatted multi-component loads, raw multi-dword loads through a buffer also written by the shader, and multi-dword or multi-component stores. Closes when: those cases are measured on a PS5.
