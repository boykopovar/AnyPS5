# libSceNKWebKit

## add Functional

- [WebCore::SharedBufferDataView layout](../../../core/libs/prx/libSceNKWebKit/include/SharedBufferViewExports.hpp) (libSceNKWebKit) - not compared with a console module. The 16-byte layout (`m_positionWithinSegment`, then the `Ref<DataSegment>`) follows the member order in [SharedBuffer.h@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/SharedBuffer.h#L250-L270).
- [WebCore::SharedBuffer views, comparison and hex](../../../core/libs/prx/libSceNKWebKit/src/SharedBufferViews.cpp) (libSceNKWebKit) - `getSomeData`, `operator==`, `operator!=`, `toHexString` and the nine `SharedBufferDataView` exports follow [SharedBuffer.cpp@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/SharedBuffer.cpp#L130-L349). `toHexString` writes uppercase digits, which is the default of `hex` in [HexNumber.h@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WTF/wtf/HexNumber.h#L59). `getSomeData` throws `std::out_of_range` where WebKit has `RELEASE_ASSERT(position < m_size)`. `hintMemoryNotNeededSoon` does nothing, as on every port without Cocoa memory hints.
- [WebCore::SharedBuffer file loading](../../../core/libs/prx/libSceNKWebKit/src/SharedBufferViews.cpp) (libSceNKWebKit) - `createWithContentsOfFile` maps the file through the existing `MappedFileData` export and falls back to `createFromReadingFile`, which reads it with `open`, `fstat` and `read` like [SharedBufferPOSIX.cpp@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/posix/SharedBufferPOSIX.cpp#L37-L72). A file larger than `UINT_MAX` bytes throws `std::length_error` instead of crashing in `Vector`.
