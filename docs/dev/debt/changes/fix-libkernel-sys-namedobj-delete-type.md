# libkernel_sys

## change Deleting a live id with another type than it was created with throws

- [__sys_namedobj_delete](../../../core/libs/prx/libkernel_sys/NamedObject.cpp) (libkernel_sys) - Deleting a live id with another type than its own fails with `ESRCH`, leaving it, as the 13.60 kernel's syscall 558 (kernel-13.60 @ 0xffffffff9eeb73c0) looks the id up with the type's low 16 bits ORed with 0x1000 and answers a miss with 3 (@ 0xffffffff9eeb7445); the create handler stores types the same way, so types differing only in bit 0x1000 match. A PS5 payload process (firmware 11.60) did the same; titles not measured. [fpPS4](https://github.com/red-prig/fpPS4/blob/8157760fd67a5ad02a53925701325fff2ded2c05/sys/kern/kern_namedobj.pas#L103-L157) answers `ESRCH` and [RPCSX](https://github.com/RPCSX/rpcsx/blob/e8ae1481ab7ba04d5c6bef89dd852aabba2c88ff/kernel/orbis/src/sys/sys_sce.cpp#L665-L715) deletes it. Errors return -1 with errno, as FreeBSD 11.4's [`__sys_` stubs](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libc/amd64/SYS.h#L39-L50) do

## change [__sys_namedobj_create]

- [__sys_namedobj_create](../../../core/libs/prx/libkernel_sys/NamedObject.cpp) (libkernel_sys) - It fails with `EAGAIN` once ids 1 to 65535 are live: RPCSX's [bound](https://github.com/RPCSX/rpcsx/blob/e8ae1481ab7ba04d5c6bef89dd852aabba2c88ff/kernel/orbis/include/orbis/thread/Process.hpp#L108) and the 16 bits firmware 13.42's libkernel keeps for the id ([#10385](https://github.com/boykopovar/AnyPS5/pull/10385#issuecomment-6415603047)); fpPS4 goes on to `0x7FFFFFFF`, and the console's limit is unknown. On a PS5 payload process (firmware 11.60) the first ids were 32, 33 and 34 and a released one came back with a generation in the bits from 13 up (8224 after releasing 32), not lowest first; titles not measured. The name (`EINVAL` when null, `ENAMETOOLONG` from 32 characters, `EFAULT` when unreadable, all measured) and the object pointer are not kept, and libkernel's `*_setname` calls do not register here.
