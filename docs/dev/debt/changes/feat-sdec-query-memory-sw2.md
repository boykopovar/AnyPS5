# libSceVdecSavc2

## remove sceSdecCreateSw2 and sceSdecQueryMemorySw2](

## add Functional

- [sceSdecQueryMemorySw2](../../../core/libs/prx/libSceVdecSavc2/Export.cpp) (libSceVdecSavc2) follows [readings of firmware 13.42's libSceVdecSavc2.sprx](https://github.com/boykopovar/AnyPS5/issues/21865#issuecomment-6955028344), run natively, not measured on a console: the argument, depth, instance-count, level and size checks (3, setting `*tooBig` to 1 when non-null on a frame-size overflow), `*dpbFrames` and the three sizes (including the SDK `0x6500000` switch via `sceKernelGetCompiledSdkVersion`) follow the module's closed forms. The `.native.sprx` variant has different sizes and is not modelled. Host choices: an unreadable or unwritable pointer or a zero width/height without a frame override gives 3 instead of faulting, and a refused query leaves the memory record unwritten. Unread paths (levels outside H.264 Table A-1, negative dimensions, and field mode with more than 8 instances where the firmware overruns its stack array) throw.
- [sceSdecCreateSw2](../../../core/libs/prx/libSceVdecSavc2/Export.cpp) (libSceVdecSavc2) makes the checks of [the 13.42 reading](https://github.com/boykopovar/AnyPS5/issues/21865#issuecomment-6955213912), then throws, since decoding is unsupported. Null arguments, a non-zero first config word, a missing or `<= 0x37`-byte first block, a zero `r+0x10`, `r+0x04 > 2`, `r+0x08 > 16` in mode 2, `r+0x18` outside `{-1, 0x100..0x2ff}`, `r+0x20 > 0x7f` and the query's config checks return 3; memory whose alignments or sizes do not match a `flag = 1` query for the same configuration and SDK version returns 4. Not modelled: the `.native.sprx` wrapper, and the 1 and 2 returns for an exhausted or busy decoder header. An unreadable argument returns 3 as a host-safety fallback.
