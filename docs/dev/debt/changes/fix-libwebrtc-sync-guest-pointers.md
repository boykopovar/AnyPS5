# libwebrtc

## change rtc::RecursiveCriticalSection and rtc::CritScope

- [rtc::RecursiveCriticalSection and rtc::CritScope](../../../core/libs/prx/libwebrtc/src/RecursiveCriticalSection.cpp) (libwebrtc) - never write `thread_` or `recursion_count_` or check the owning thread, as builds without `RTC_DCHECK_IS_ON` do; whether the module is one is unknown. A non-zero return from a guest pthread call throws; constructor and destructor validate guest section writability via `GuestWritable_nid_no_patch` before `pthread_mutex_init` or `pthread_mutex_destroy`, while `Enter`, `Leave`, and `CritScope` keep direct pointer access on lock acquire and release paths to avoid per-call syscall overhead. Otherwise the POSIX path of [recursive_critical_section.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/deprecated/recursive_critical_section.cc), the same at both branches, with its WebRTC copyright notice and BSD licence at the top of the file: a recursive guest mutex in the first 8 bytes of the 24-byte layout of `recursive_critical_section.h`. Closes when: compared with the console.

## change webrtc::TaskQueueBase::Current and CurrentTaskQueueSetter

- [webrtc::TaskQueueBase::Current and CurrentTaskQueueSetter](../../../core/libs/prx/libwebrtc/src/TaskQueueBase.cpp) (libwebrtc) - adapted from [task_queue_base.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/api/task_queue/task_queue_base.cc), with its WebRTC copyright notice and BSD licence at the top of the file. A thread-local pointer starts null on every thread; the 8-byte setter copies `previous_` to and from guest memory through `GuestPtr`, stores the current queue in `previous_` before updating the thread-local queue, and its destructor restores `previous_`. The file's `thread_local` and pthread-key variants behave the same. A null or inaccessible setter, which upstream writes through, throws `std::invalid_argument` without modifying the current queue. Closes when: compared with the console.

## change rtc::LogMessage statics and webrtc::PendingTaskSafetyFlag::SetNotAlive and alive

- [rtc::LogMessage statics and webrtc::PendingTaskSafetyFlag::SetNotAlive and alive](../../../core/libs/prx/libwebrtc/src/LogMessage.cpp) (libwebrtc) - follow [logging.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/logging.cc) and [pending_task_safety_flag.h](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/api/task_queue/pending_task_safety_flag.h), the same at M127 and M134, with the WebRTC notice at the top of each file. Unverified on the console: the severity defaults to `LS_NONE` (a `NDEBUG` build), `LogSink` holds `next_` at 8 and `min_severity_` at 16 (`RTC_LOG_ENABLED()`), `alive_` sits at 4 (accessed through `GuestPtr` in `PendingTaskSafetyFlag.cpp`) and the `RTC_DCHECK_RUN_ON` checks are off. A null or already registered sink, and a null or inaccessible flag, throw. Closes when: the build flags are known and the behaviour is compared with the console.

## change webrtc::PendingTaskSafetyFlag::Create

- [webrtc::PendingTaskSafetyFlag::Create](../../../core/libs/prx/libwebrtc/src/PendingTaskSafetyFlag.cpp) (libwebrtc) - nothing is checked on the console. Adapted from [pending_task_safety_flag.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/api/task_queue/pending_task_safety_flag.cc), whose WebRTC notice and BSD licence head the file, the same at M127: the 8-byte flag (`RefCountedNonVirtual` count at 0, `alive_` at 4, an empty `main_sequence_` in a `NDEBUG` build) comes from guest `operator new` with count 1 and `alive_` true written through `GuestPtr`, and the `scoped_refptr` is written through the hidden result pointer via `GuestPtr` after checking `GuestWritable_nid_no_patch`, which is returned. A null or inaccessible result throws `std::invalid_argument`. Closes when: compared with the console.

## change rtc::ThreadManager::Instance and CurrentThread

- [rtc::ThreadManager::Instance and CurrentThread, rtc::Thread::Current and IsCurrent](../../../core/libs/prx/libwebrtc/src/ThreadManager.cpp) (libwebrtc) - nothing is checked on the console. Adapted from the POSIX branch of [thread.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/thread.cc), the same at M127: one manager made on first use through guest `operator new` and never freed, holding a guest `pthread_key_create` key initialized and read via `GuestPtr`, and the current thread read with `pthread_getspecific`. The manager's other members (`message_queues_`, `crit_`, `processing_`) and the console's object size are not modelled; only these exports read the object. `SetCurrentThread` still throws: it calls `EnsureIsCurrentTaskQueue` or `ClearCurrentTaskQueue` on the `Thread`, whose layout is not known, so `Current` returns null until a thread is wrapped. A null or inaccessible manager throws `std::invalid_argument`. Closes when: compared with the console.
