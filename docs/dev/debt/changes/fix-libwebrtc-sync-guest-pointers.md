# libwebrtc

## change rtc::RecursiveCriticalSection and rtc::CritScope

- [rtc::RecursiveCriticalSection and rtc::CritScope](../../../core/libs/prx/libwebrtc/src/RecursiveCriticalSection.cpp) (libwebrtc) - never write `thread_` or `recursion_count_` or check the owning thread, as builds without `RTC_DCHECK_IS_ON` do; whether the module is one is unknown. A non-zero return from a guest pthread call throws, and guest section and scope pointers are copied and validated through `GuestPtr` and `GuestWritable_nid_no_patch` (throwing `std::invalid_argument` on null or inaccessible memory before locking or storing). Otherwise the POSIX path of [recursive_critical_section.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/deprecated/recursive_critical_section.cc), the same at both branches, with its WebRTC copyright notice and BSD licence at the top of the file: a recursive guest mutex in the first 8 bytes of the 24-byte layout of `recursive_critical_section.h`. Closes when: compared with the console.

## change webrtc::TaskQueueBase::Current and CurrentTaskQueueSetter

- [webrtc::TaskQueueBase::Current and CurrentTaskQueueSetter](../../../core/libs/prx/libwebrtc/src/TaskQueueBase.cpp) (libwebrtc) - adapted from [task_queue_base.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/api/task_queue/task_queue_base.cc), with its WebRTC copyright notice and BSD licence at the top of the file. A thread-local pointer starts null on every thread; the 8-byte setter copies `previous_` to and from guest memory through `GuestPtr`, stores the current queue in `previous_` before updating the thread-local queue, and its destructor restores `previous_`. The file's `thread_local` and pthread-key variants behave the same. A null or inaccessible setter, which upstream writes through, throws `std::invalid_argument` without modifying the current queue. Closes when: compared with the console.

## change rtc::ThreadManager::Instance and CurrentThread

- [rtc::ThreadManager::Instance and CurrentThread, rtc::Thread::Current and IsCurrent](../../../core/libs/prx/libwebrtc/src/ThreadManager.cpp) (libwebrtc) - nothing is checked on the console. Adapted from the POSIX branch of [thread.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/thread.cc), the same at M127: one manager made on first use through guest `operator new` and never freed, holding a guest `pthread_key_create` key initialized and read via `GuestPtr`, and the current thread read with `pthread_getspecific`. The manager's other members (`message_queues_`, `crit_`, `processing_`) and the console's object size are not modelled; only these exports read the object. `SetCurrentThread` still throws: it calls `EnsureIsCurrentTaskQueue` or `ClearCurrentTaskQueue` on the `Thread`, whose layout is not known, so `Current` returns null until a thread is wrapped. A null or inaccessible manager throws `std::invalid_argument`. Closes when: compared with the console.

## change SequenceCheckerImpl(bool) constructor

- [webrtc::webrtc_sequence_checker_internal::SequenceCheckerImpl(bool) constructor](../../../core/libs/prx/libwebrtc/src/SequenceChecker.cpp) (libwebrtc) - the 32-byte layout assumes a build without `RTC_DCHECK_IS_ON`, where `RTC_NO_UNIQUE_ADDRESS` leaves `Mutex`'s owner record no space: `lock_`, a guest `pthread_mutex_t`, at 0, `attached_` at 8, `valid_thread_` at 16 and `valid_queue_` at 24. With `RTC_DCHECK_IS_ON` the owner record holds a `bool` and a `pthread_t` and moves the last three 16 bytes on; whether the module is such a build is unknown. A non-zero return from a guest pthread call throws, and a null or inaccessible checker validated with `GuestWritable_nid_no_patch` and populated via `GuestPtr` throws `std::invalid_argument`. Otherwise follows [sequence_checker_internal.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/synchronization/sequence_checker_internal.cc) and the `MutexImpl` constructor of [mutex_pthread.h](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/rtc_base/synchronization/mutex_pthread.h), the same code at both branches, with their WebRTC copyright notices and BSD licence at the top of the file: a default guest mutex, `attached_` from the argument, `valid_thread_` from `pthread_self` and `valid_queue_` from `TaskQueueBase::Current`. Closes when: the build flags are known and the layout is compared with the console.
