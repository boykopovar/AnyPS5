# libSceAgcDriver

## change [sceAgcDriverGetRegShadowInfo, sceAgcDriverGetRegShadowInfoAgr]
- [sceAgcDriverGetRegShadowInfo, sceAgcDriverGetRegShadowInfoAgr](../../../core/libs/prx/libSceAgcDriver/Export.cpp) (libSceAgcDriver) - a null argument returns 0x8A6D0003 before anything else is read, as firmware 13.42's libSceAgcDriver does (read to the return, disassembly only, not measured on a console); every other call throws. In the module the other path depends on the driver context that the module constructor fills at load: when its field at +8 is nonzero the call returns 0x8A6D0001, otherwise it copies a 0x28-byte register-shadow record. Both that field and the records come from a kernel query and imported calls the constructor makes, so they are not settled here. `sceAgcDriverIsEsvmProcess` reads bit 16 of the same queried value and still throws. A PS5 (firmware 11.60, payload process; a title process may differ) returned `0x8A6D0003` for a null argument from both functions, without a fault; the driver context, `0x8A6D0001` and the 0x28-byte record were not measured.
