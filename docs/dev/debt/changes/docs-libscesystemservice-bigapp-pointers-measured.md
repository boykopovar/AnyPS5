# libSceSystemService

## change [sceLncUtilGetAppIdListOfBigApp and sceSystemServiceGetAppIdListOfBigApp]
- [sceLncUtilGetAppIdListOfBigApp and sceSystemServiceGetAppIdListOfBigApp](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - returning `0x80940005` (`LNC_UTIL_ERROR_INVALID_ARGUMENT`) when the `appIds` or `count` pointers are unwritable via `GuestCopyOut_nid_no_patch` is a host-safety fallback preserving host errno. A PS5 (firmware 11.60, payload process; a title process may differ) returned `0x80940005` from both functions with a null `count` and with a null `appIds` and a capacity of 1, writing nothing and printing the module's pointer-check message, as this does for a null pointer; with `count` at the unmapped address 0x10 `sceLncUtilGetAppIdListOfBigApp` did not return within the probe's limit in two runs and the probe wrote nothing afterwards, not even its watchdog line; `appIds` at 0x10 and the unmapped cases of `sceSystemServiceGetAppIdListOfBigApp` were not tried, so what the console does for an unmapped pointer is not measured.
