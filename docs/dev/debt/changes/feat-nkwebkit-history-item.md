# libSceNKWebKit

## change [WebCore::HistoryItem]

- [WebCore::HistoryItem](../../../core/libs/prx/libSceNKWebKit/src/HistoryItemAbi.hpp) - layout follows pinned [HistoryItem.h](https://github.com/neonmodder123/PS5-WebKit-11.x/blob/80f77e94c63ee7202eec3d4b5b1a021dd89011ba/Source/WebCore/history/HistoryItem.h) (release, non-Cocoa, non-iOS, 8-bit `ShouldOpenExternalURLsPolicy`) and is not checked against PS5. The first two [CachedPage](https://github.com/neonmodder123/PS5-WebKit-11.x/blob/80f77e94c63ee7202eec3d4b5b1a021dd89011ba/Source/WebCore/history/CachedPage.h) fields are assumed to be a page pointer and `MonotonicTime` double at offsets 0 and 8; only that prefix is modelled. Expiry compares with `WTF::MonotonicTime::now`. `copy`, other constructors and the destructor throw. The changed hook is in the HistoryItem changed hook entry. The 4-byte `PruningReason` at 168, `BackForwardItemIdentifier` at 176 and `std::optional<PolicyContainer>` at 192 follow the pinned member order and sizes, not console measurements.

## change [WebCore::Process identifier]

- [WebCore::Process identifier](../../../core/libs/prx/libSceNKWebKit/src/WebCoreProcess.cpp) (libSceNKWebKit) - the generation-protection check is not modelled: in firmware 13.42 `identifier()` (`0x207100`) crashes before generating when the byte at `0x3369ef8` is 1, and no store to that byte by address was found in the module's code, so what sets it is unknown. The object-identifier counter it draws from is shared in the module with the `HistoryItem` constructors, seven other exports and internal code; the implemented `HistoryItem` constructors take the identifier as an argument and do not use the counter, so identifiers are unique only among implemented callers. The rest follows `system_ex/common_ex/lib/libSceNKWebKit.sprx` 13.42 (SHA-256 `e63acdc164592330a287cf6914c265336b27a357098a449c1609f8f82e104409`; `setIdentifier` at `0x2e3bb0`), read from disassembly, not run. Closes when: measured on a console.

## add Unknown function info

- [HistoryItem construction and mutation](../../../core/libs/prx/libSceNKWebKit/src/HistoryItem.cpp) - not run on a console. The four-argument constructors, `setDocumentState`, `addChildItem`, `setStateObject` and `setFormData` follow pinned [HistoryItem.cpp](https://github.com/neonmodder123/PS5-WebKit-11.x/blob/80f77e94c63ee7202eec3d4b5b1a021dd89011ba/Source/WebCore/history/HistoryItem.cpp) and `Vector` growth. Replacing a non-null `stateObject` or `formData` with a different pointer throws; upstream derefs the old value. `setStateObject` calls the changed hook per pinned source; 13.42 disassembly tail-jumps only six setters. `Ref`/`RefPtr` arguments use the caller's slot, then nulled. The module mangles `setDocumentState` with `WTF::String`, not `AtomString`. Closes when: compared with a console module.
