# shader

## add Functional

- [Run-time texel offsets in WGSL](../../../core/shader/recompiler/WgslBackend/src/WgslEmitter.cpp) (WebAssembly) - WGSL takes only constant texel offsets, so a sample or gather whose offset is computed moves its coordinates by the offset divided by the size of the level it samples: level 0, or the explicit LOD rounded toward zero. That matches the hardware for single-level textures and gathers; an implicit-LOD sample of a mipmapped texture uses level 0's texel size whatever level the hardware selects
- [Quad permutations in WGSL](../../../core/shader/recompiler/WgslBackend/src/WgslEmitter.cpp) (WebAssembly) - DPP `quad_perm` in a pixel program reads the other pixels of its 2x2 quad with WebGPU's `quadBroadcast`, the pixel's place in the quad taken from its framebuffer position. Other DPP patterns, row and bank masks, and DPP outside pixel programs throw
- [Wave-synchronous LDS in WGSL](../../../core/shader/recompiler/WgslBackend/src/WgslEmitter.cpp) (WebAssembly) - a one-wave compute program that writes LDS gets a workgroup barrier between an LDS write and the next access as the SPIR-V backend does, and its branches are flattened so every barrier is in uniform control flow: all invocations run both sides and only memory writes and merged values follow the branch. A program that returns from inside a branch throws
- [Derivatives in WGSL](../../../core/shader/recompiler/WgslBackend/src/WgslEmitter.cpp) (WebAssembly) - every WGSL module turns off WGSL's derivative uniformity analysis, so implicit-LOD samples and derivatives inside branches compile as they do in the SPIR-V backend. Their results in branches that pixels of one quad take differently are what the GPU gives
- [Lane reads in WGSL](../../../core/shader/recompiler/WgslBackend/src/WgslEmitter.cpp) (WebAssembly) - the WGSL backend runs one guest lane per invocation, so `v_readfirstlane` returns the invocation's own value. That is the hardware result for a value the wave holds uniformly and for loops that serve one lane value per iteration; code that relies on another lane's value differs
- [Barycentric emulation in WGSL](../../../core/shader/recompiler/WgslBackend/src/WgslEmitter.cpp) (WebAssembly) - WebGPU has no geometry stage and no barycentric builtin in core WGSL, so a pixel shader that reads its I/J VGPRs or raw vertex parameters other than through host-interpolated `v_interp_p1_f32`/`v_interp_p2_f32` pairs throws
