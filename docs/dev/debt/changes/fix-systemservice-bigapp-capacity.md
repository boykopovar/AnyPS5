# libSceSystemService

## change [sceLncUtilGetAppId, sceLncUtilIsAppLaunched, sceLncUtilGetAppIdListOfBigApp, sceSystemServiceGetAppIdListOfBigApp]

- [sceLncUtilGetAppId, sceLncUtilIsAppLaunched, sceLncUtilGetAppIdListOfBigApp, sceSystemServiceGetAppIdListOfBigApp](../../../core/libs/prx/libSceSystemService/Export.cpp) (libSceSystemService) - only the running title answers. `sceLncUtilGetAppId` returns its app ID as `sceSystemServiceGetAppId` does, `sceLncUtilIsAppLaunched` reports it launched, and both big-app lists write its app ID as their only entry with a count of 1, because AnyPS5 runs one title and cannot start another. A null or non-9-character title ID returns -1 from `sceLncUtilGetAppId` and 0x80940005 from `sceLncUtilIsAppLaunched`, and a null output, list or count returns 0x80940005, before any request, as firmware 13.42's `libSceSystemService.sprx` does ([emulator run](https://github.com/boykopovar/AnyPS5/pull/10801#issuecomment-6403075212)). These calls answer as if the LncUtil client were initialized; for valid arguments without it, 13.42 returns 0x80940001. After the argument checks above, a valid call before `sceLncUtilInitialize` now returns 0x80940001 (`LNC_UTIL_ERROR_NOT_INITIALIZED`); `sceLncUtilInitialize` sets the flag that lets every later call answer. `sceLncUtilTerminate` throws and when the console clears the flag is not measured, so it is never cleared here. Another 9-character title ID throws: the module passes it on as a request, so whether the console reports another installed title as not launched is unknown. A payload process on firmware 11.60 answered capacity 0 to 3 with 0 and a count of 0 and capacity 4, 8 and 16 with 0x80940005, writing nothing (the module reported that the entry-count check failed); here capacity 0 and 4 or more answer so, and capacity 1 to 3 keep the count of 1, since the console's count depends on a title context not measured. The signatures are the ones the pending exports recovered
