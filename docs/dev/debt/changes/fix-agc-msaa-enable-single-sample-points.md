# libSceAgcDriver

## change [MSAA_ENABLE on a single-sample target]

- [MSAA_ENABLE on a single-sample target](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (AGC driver) - `PA_SC_MODE_CNTL_0.MSAA_ENABLE` with `PA_SC_AA_CONFIG.MSAA_NUM_SAMPLES = 0` is drawn like the same state without the bit when sample 0 of the four `PA_SC_AA_SAMPLE_LOCS_PIXEL_*_0` registers is at the pixel center and the draw rasterizes filled triangles, lines, points or rectangles (`VGT_PRIMITIVE_TYPE` 1, 2, 3, 7 or 17 as well as the triangle types) with alpha-to-coverage and conservative rasterization off. [RADV](https://gitlab.freedesktop.org/mesa/mesa/-/blob/745709a000482a4a24c91faef5c5a40bd653a863/src/amd/vulkan/radv_cmd_buffer.c#L13606-13609) programs this state for one-sample custom sample locations on GFX10 and later, where the bit makes the rasterizer use the programmed location of sample 0 ([061bc615](https://gitlab.freedesktop.org/mesa/mesa/-/commit/061bc6151a11597f720535f00e79a5752e24aff6)); that the bit changes nothing else for such a draw is inferred from that and is not measured on hardware. For lines the bit may also select the console's multisample (rectangular) line rule instead of the aliased one, so which pixels a line covers under this state is unmeasured. For points the bit may likewise select a multisample point rule (GL rasterizes multisampled points as circles unless point sprites are on), so which pixels a point larger than one pixel covers under this state is unmeasured. PPSA03541 reaches a rect-list draw in this state, PPSA31246 a line list, and CUSA01709 a point list.
