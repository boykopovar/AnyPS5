# libSceLibreSsl3

## add Functional

- [X509_CRL issuer names](../../../core/libs/prx/libSceLibreSsl3/src/X509Crl.cpp) (libSceLibreSsl3) - the issuer is decoded as `x_name.c`, `tasn_dec.c` and `asn1_lib.c` of the pinned LibreSSL 078b3d1d (3.4.1) do, compared with its `d2i_X509_CRL` and `X509_CRL_get0_by_cert`: first error reason, values, flags, `bytes`, `canon_enc` and lookups. Only the first error reason is queued, where LibreSSL queues 102 and 58 after it. `X509_CRL_get0_by_cert` throws for a `modified` certificate issuer instead of re-encoding it. The UTF-8 conversion and canonical encoding repeat those of `X509StoreLoadLocations.cpp` until both decoders share one. Closes when: compared with the console.
- [X509_CRL fields outside the issuer](../../../core/libs/prx/libSceLibreSsl3/src/X509Crl.cpp) (libSceLibreSsl3) - compared with the pinned LibreSSL on 20 000 CRLs with BER forms outside the issuer, 30 000 with mutations outside it and 100 000 with byte mutations, `d2i_X509_CRL` still fails there with 102 on an indefinite length, which LibreSSL decodes; 123 on a missing field (LibreSSL: 121); 168 on an end-of-contents pair outside an algorithm parameter (159); 168 on a time with another universal tag (140) or class (139); 62 on an empty INTEGER or one with a redundant leading byte, which 3.4.1 accepts; and 132 on time contents that 3.4.1 accepts, such as day 32, because the time check follows LibreSSL 4.0.0. 22, 19 and 540 inputs of these sets that `main` rejected with LibreSSL's first reason by chance now reach one of these gaps or those of the next entry. Closes when: these fields are decoded as the issuer is.
- [X509_CRL field boundaries](../../../core/libs/prx/libSceLibreSsl3/src/X509Crl.cpp) (libSceLibreSsl3) - in the same sets, `d2i_X509_CRL` fails with 148 on an unknown element after `lastUpdate` or `revocationDate`, where LibreSSL fails with 168 because the last field of a template is never optional; with 148 on an optional field whose header is invalid and whose identifier octet is not the expected tag, where `asn1_check_tlen` fails with 123 or 155 before comparing the tag; and with 62 on an extension `critical` BOOLEAN of another length than one, where `asn1_ex_c2i` fails with 106. Closes when: optional fields report header errors and `critical` is decoded as other BOOLEAN values are.
- [X509_CRL algorithm parameters](../../../core/libs/prx/libSceLibreSsl3/src/X509Crl.cpp) (libSceLibreSsl3) - `d2i_X509_CRL` throws for an algorithm parameter that LibreSSL keeps in an `ASN1_TYPE` this model lacks: SEQUENCE, SET, a one-byte BOOLEAN, a constructed or non-string universal tag, a tag number from 31, or a context, application or private class. It fails with 159 on an end-of-contents pair, 106 on a BOOLEAN of another length, 144 on a NULL with contents, and 214 or 215 on a BMPString or UniversalString of invalid length, as LibreSSL does. Where `main` returned NULL, it throws on 63, 21 and 93 inputs of the three sets above: LibreSSL accepts 63, 21 and 89 of them, and rejects 4 for a later fault (155, 168, 220) found only by decoding past the parameter. The throw leaks the partly decoded CRL. Closes when: these parameter types are decoded.
