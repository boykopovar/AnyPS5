# libSceFont

## change [sceFontRendererGetOutlineBufferSize, sceFontRendererResetOutlineBuffer, sceFontRendererSetOutlineBufferPolicy]

- [sceFontRendererGetOutlineBufferSize, sceFontRendererResetOutlineBuffer, sceFontRendererSetOutlineBufferPolicy](../../../core/libs/prx/libSceFont/src/Library.cpp) (libSceFont) - the default size (`0x4000`), the clearing of the size on an invalid renderer, the `max(current, basal)` growth clamped to a non-zero limit, `SCE_FONT_ERROR_INVALID_PARAMETER` when basal exceeds a non-zero limit, and the size kept by reset follow the shadPS4 port and are not measured on a console. The ignored `bufferPolicy` argument is not pinned. On a PS5 (FW 11.60) `sceFontRendererSetOutlineBufferPolicy` returns `SCE_FONT_ERROR_INVALID_RENDERER` for NULL and `SCE_FONT_ERROR_INVALID_PARAMETER` for a zeroed block or the unmapped address 0x10, for every policy and size pair tried; this library does the same without dereferencing an unreadable pointer. How the console reaches it and the result with a valid renderer (needs `sceFontCreateRenderer`) are not measured. The other two functions return `SCE_FONT_ERROR_INVALID_RENDERER` for a zeroed block but read the pointer unguarded, where the console faults on 0x10. Closes when: measured on a PS5
