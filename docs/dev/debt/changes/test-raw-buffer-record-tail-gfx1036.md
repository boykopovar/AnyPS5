# shader

## change [Guest memory load guards]

- [Guest memory load guards](../../../core/shader/recompiler/SpirvBackend/src/SpirvMemory/SpirvMemoryInstructions.cpp) (shader recompiler) - a guest load whose lane is inactive or whose address is out of bounds is still performed and its result replaced by 0 with `OpSelect`, instead of a selection per guard, when the load can be pointed at a location nothing writes: scratch reads its own element 0; storage buffers (direct buffers, GDS) read element 0xfffffffe, which `robustBufferAccess2` turns into a zero load with no memory access, so the extra read cannot race with a write the guarded program would not have raced with ([Vulkan memory model](https://docs.vulkan.org/spec/latest/appendices/memorymodel.html#data-race)). Without `robustBufferAccess2` ([VulkanDevice.cpp](../../../core/libs/prx/libSceAgcDriver/Execution/src/VulkanDevice.cpp) enables it when the device has it) those loads keep their selections; LDS loads, stores, atomics, formatted and physical-address (BDA) accesses always do. LDS keeps the branch because NVIDIA's compiler predicates a branched LDS load at no cost, while the select form costs about 2.5 instructions per dword and splits a `ds_read_b128` into four loads (RTX 4060 measurements by @karanvora2599 in #4048); Intel's static counts favour the select only for wide reads, and run time was not measured on either. The aligned high word of a misaligned-capable buffer read re-reads the low word's own element. A selection guard costs four blocks per lane half and the host compiler's time grows with the block count: PPSA11142's merged PSP vertex program (3176 ISA words, wave64) emitted 16,983 blocks and 1,710 conditional branches, 5,907 and 868 with the selects. `agc_guarded_memory_loads` traces the emitted loads in both device modes. When the device also reports `robustStorageBufferAccessSizeAlignment` 1, a direct buffer load leaves out the comparison with the descriptor's `OpArrayLength` (which reads the descriptor) and the device returns the zero past the descriptor range: the host rounds a guest buffer's or a draw snapshot's descriptor range of 4 bytes or more down to whole dwords, which no direct access reaches past, and the misaligned-base high word keeps its comparison with the length. The guest bound and the guards of stores, atomics, GDS, LDS and BDA are unchanged. The flag is part of the shader cache key and `APS5_NO_EXACT_ROBUST_LOADS` (any value) keeps the comparison. A dword that straddles the end of a raw range, including a 1 to 3 byte one, reads 0 on RDNA2 (gfx1036), as here; byte and short loads differ (below).

# libSceAgcDriver

## add Functional

- [Byte and short loads in a partial last dword](../../../core/libs/prx/libSceAgcDriver/Graphics/src/ShaderAddressResources.cpp) (libSceAgcDriver) - read 0 through the direct-buffer path on an RTX 5090, where RDNA2 returns the bytes: the host range counts whole dwords (with `APS5_NO_EXACT_ROBUST_LOADS` also below 4 bytes); AMD's Vulkan driver returns them. On gfx1036 (driver 32.0.21045.29003, [hardware oracle](../HW_ORACLE.md), wave32 and wave64) a raw V# (stride 0, `OOB_SELECT` 3) returns a byte or short load when `offset + size <= NUM_RECORDS` and dword k of a dword load when `offset + 4k + 4 <= NUM_RECORDS`, else 0 with no partial bytes; `OOB_SELECT` 0 returns 0, 1 and 2 skip the offset check. [BufferRawRecordTail](../../../core/libs/prx/libSceAgcDriver/tests/execution/BufferRawRecordTail.cpp) pins this at aligned offsets except these loads. Closes when: they read their bytes on every device.
