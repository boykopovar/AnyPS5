# libfreetype

## change [FT_Bitmap_Blend]

- [FT_Bitmap_Blend](../../../core/libs/prx/libfreetype/src/BitmapBlend.cpp): The console signature is unmeasured. Guest bitmap records use the host layout and blending delegates to the pinned backend [ftbitmap.c](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftbitmap.c#L765-L1039). The source and target records, target offset and source pixels (4 KiB chunks) are read, and the record and offset written, through checked guest copies. Glyph-slot targets synchronize their host slot through the same owner registry as `FT_Bitmap_Copy`; allocated buffers use the library's host allocator. An unreadable record, offset or source pixel range, and a refused or unwritable target record, offset or existing pixels, return `FT_Err_Invalid_Argument` without calling FreeType, including no-op calls; this is host-boundary validation, not measured console behavior. On Windows, offsets outside the host's 32-bit `FT_Pos` range still throw.
