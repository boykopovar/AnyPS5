# libSceNKWebKit

## add Unknown function info

- [WebCore::SharedBuffer mapped-file constructors](../../../core/libs/prx/libSceNKWebKit/src/SharedBuffer.cpp) (libSceNKWebKit) - not compared with a console module. The `SharedBuffer(FileSystem::MappedFileData&&)` C1 and C2 exports take the caller's mapping into the buffer's single `DataSegment` and set the size from it, as [SharedBuffer.cpp@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/SharedBuffer.cpp) builds `m_segments.append({0, DataSegment::create(WTFMove(fileData))})`; an empty mapping still becomes one empty mapped segment, because [SharedBuffer.h](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/SharedBuffer.h) appends unconditionally. The moved-from `MappedFileData` is left null and zeroed, so only the buffer unmaps, through the existing `WTF::FileSystemImpl::MappedFileData` destructor export when the last segment reference drops. The 48-byte buffer and 32-byte segment are the same layout the other `WebCore::SharedBuffer` exports use, and a mapping is capped at the 32-bit size field of the existing `WTF::MappedFileData` layout. Null objects throw `std::invalid_argument` instead of faulting. Closes when: compared with a console module.
