# libSceLibreSsl

## add Unknown function info

- [EC error queue](../../../core/libs/prx/libSceLibreSsl/src/Ec.cpp) (libSceLibreSsl) - no console check. The EC, ECDSA and ECDH exports queue the reason codes of [LibreSSL 2.5.4](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto) `ec_key.c`, `ec_curve.c`, `ecp_oct.c`, `ecs_ossl.c` and `ech_key.c` for the failures this port returns. Not queued: the ASN.1 errors of a signature that does not decode; allocation, `BN` and arithmetic failures, which throw; `EC_POINT_new` and `EC_POINT_oct2point`; a peer point at infinity of another curve in `ECDH_compute_key`. LibreSSL built without `OPENSSL_BN_ASM_MONT` clears the queue when `EC_GROUP_new_by_curve_name` loads a non-NIST prime; the port keeps it. libSceLibreSsl3 forwards these exports, so its callers get the 2.5.4 `ERR_LIB_ECDSA` and `ERR_LIB_ECDH` codes where 4.0.0 queues `ERR_LIB_EC` ones

## change [EC_GROUP_new_by_curve_name, EC_GROUP_free, EC_GROUP_get_degree, EC_KEY_new, EC_KEY_new_by_curve_name, EC_KEY_free, EC_KEY_set_group, EC_KEY_get0_group, ECDSA_size]

- [EC_GROUP_new_by_curve_name, EC_GROUP_free, EC_GROUP_get_degree, EC_KEY_new, EC_KEY_new_by_curve_name, EC_KEY_free, EC_KEY_set_group, EC_KEY_get0_group, ECDSA_size](../../../core/libs/prx/libSceLibreSsl/src/Ec.cpp) (libSceLibreSsl) - not checked on the console. They follow LibreSSL 2.5.4's [ec](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec) and [ecs_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ecdsa/ecs_lib.c) over mbedtls, which has 11 of LibreSSL's 90 curves (NIDs 409, 415, 711 to 716, 928, 932, 934). The other 79 throw; other positive NIDs return null and queue `EC_R_UNKNOWN_GROUP`. Keys use libSceLibreSsl3's EC layout and `EC_KEY_new`'s defaults. `EC_KEY_set_group` to another curve throws on a key that has a public or private key. Setting a key's own group keeps it, where LibreSSL frees it first. Null groups and keys throw where LibreSSL dereferences them

Setting a key's own public key copies it, where LibreSSL frees it first. Null points and keys throw where LibreSSL dereferences them

## change [EC_POINT_mul]

- [EC_POINT_mul](../../../core/libs/prx/libSceLibreSsl/src/Ec.cpp) (libSceLibreSsl) - not checked on the console. It follows LibreSSL 2.5.4's [ec_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ec_lib.c#L1051-L1066) and [ec_mult.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ec_mult.c#L335-L377) on the curves above: the result is a scalar times the generator plus a scalar times the point, a term without its scalar or point is left out, and with neither the result is at infinity. Scalars are taken modulo the group order, which gives LibreSSL's points for negative scalars and scalars above the order, since every point on these curves has that order. A point off the curve throws, where LibreSSL computes with it; a point of another curve throws as above. No error code is queued: the ones LibreSSL has here are for points of another method and for internal failures
