# libkernel

## change [Regular file mappings]

- [Regular file mappings](../../../core/libs/prx/libkernel/DirectMemory/PosixMemory.cpp) (libkernel) - on Linux `mmap` maps a regular file's descriptor shared or private like a shared memory object, with the same access checks; SQLite's WAL index (`-shm`) in Dusklight PPSA99305 needs it. FreeBSD 11 `mmap(2)` and shadPS4's `MemoryManager::MapFile` map regular files; the console's behaviour is not measured. Other descriptors (pipes, sockets, directories, devices) still fail with `EOPNOTSUPP`. On Windows a shared mapping is a view of a file section (`CreateFileMappingW` on the descriptor's handle, read-write when the descriptor is, otherwise read-only), so writes through the descriptor and the mapping see each other. This also maps anonymous `shm_open` objects and JIT shared memory descriptors, which are temporary files on Windows. A shared mapping may end inside the 16 KiB page that holds the end of the file, as POSIX [`mmap`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/mmap.html) allows (llama.cpp in PS5LM Plus PPSA99581 maps a whole model file this way): the section keeps the file's size, so the file never grows, the view ends with the 4 KiB host page that holds the end of the file, which Windows fills with zeros past it, and the rest of the guest page is private zero pages. As POSIX requires, the bytes past the end read zero and are never written to the file; bytes written to those private pages are seen only through that mapping, not through other mappings of the file, and a file that grows later does not show its new bytes there. Guest pages wholly past the end of the file, in shared and private mappings and in a mapping that starts past the end, stay reserved without host memory, so an access faults. The guest gets `SIGSEGV` with `SEGV_ACCERR`, trap 12 and no present bit in the error code, as on FreeBSD 11.4, where [`vm_fault_hold`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/vm/vm_fault.c) refuses a page index at or past the vnode object's size with `KERN_PROTECTION_FAILURE` and [`trap()`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/amd64/amd64/trap.c) turns that into `SIGSEGV` with `SEGV_ACCERR` under the default `machdep.prot_fault_translation`; POSIX specifies `SIGBUS`. On Linux, where the host kernel raises `SIGBUS` with `BUS_ADRERR` for such a page of a mapped file or shared memory object, the guest gets the same `SIGSEGV`; a host `SIGBUS` with another code, such as a machine-check memory error, still reaches it as `SIGBUS`. `mprotect` records a new protection on those pages without making them accessible, and a file that grows later does not fill them. A shared mapping of a write-only descriptor fails with `EOPNOTSUPP`; FreeBSD 11.4's `vn_mmap` maps a write-only descriptor without `PROT_READ`, and Linux refuses it with `EACCES`. A `PROT_EXEC` mapping is a view of a section created on a second handle that `ReOpenFile` opens with execute access, so a file whose ACL does not grant the user execute fails with `EACCES`, where FreeBSD maps it unless the file system is mounted `noexec`. A read-write alias (`GuestArenaMapAlias`) of a mapped page that holds the end of the file throws. `mprotect` above the view's protection (writing through a read-only descriptor, or adding `PROT_EXEC`) fails with `EACCES` before anything changes; FreeBSD allows `PROT_EXEC` on a readable descriptor. Shrinking the file with `ftruncate` fails with `EINVAL` while any shared mapping of it exists, even one that does not cover the removed part, because the section keeps the file's size at `mmap`; FreeBSD truncates. A read-write alias of a view (`GuestArenaMapAlias`, used when the GPU imports guest memory) of a read-only file section fails, as the alias is mapped `PAGE_READWRITE`. Views of the same file made by separate `mmap` calls are separate sections, so write tracking does not treat them as aliases of each other. A private mapping on Windows is a copy of the file read at `mmap`, which POSIX allows (later changes to the file need not show); a write-only descriptor fails with `EOPNOTSUPP`.
