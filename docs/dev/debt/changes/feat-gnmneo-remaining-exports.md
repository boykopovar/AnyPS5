## add Functional

- [firmware 10.71 returns](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - follow PS4 firmware 10.71 `system/common/lib/libSceGnmDriverForNeoMode.sprx` (sha256 of the decrypted ELF `fd3e06cd7d130b675334cd0e1dfb52d2aab0d6960624d51d2db8ffd7842cf07b`), read from disassembly, not run on a console. `sceGnmGetGpuInfoStatus`, `sceGnmGetProtectionFaultTimeStamp`, `sceGnmGetGpuBlockStatus`, `sceGnmGetShaderStatus`, `sceGnmGetShaderProgramBaseAddress`, `sceGnmGetLastWaitedAddress` and `sceGnmInsertThreadTraceMarker` return 0 there without reading an argument (vaddr 0x5e0 to 0x630 and 0x41b0). `sceGnmGetCoredumpMode` writes 0 and returns 0, or returns 1 for a null output (0x6d0). `sceGnmDestroyWorkloadStream` returns 0 for streams 1 to 15 and 1 for others (0x850), with no state, matching `sceGnmCreateWorkloadStream` here. Their parameter lists are read from the registers the bodies use; the types are unverified
- [coredump queries](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - `sceGnmIsCoredumpValid` (0x690) and `sceGnmGetCoredumpProtectionFaultTimestamp` (0x6b0) read a coredump area the 10.71 module maps at initialisation and return 0 while it is unmapped. AnyPS5 maps none, so both return 0
- [TCA units](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - in 10.71, `sceGnmGetNumTcaUnits` (0x760) and `sceGnmLogicalTcaUnitToPhysical` (0x6f0) read a GPU configuration word with ioctl `0xc004811f` on the GC device. Bit 0 set gives 1 unit and the map `0xf1`; clear, or a failed ioctl, gives 2 units and the map `0x10`, read 4 bits per logical unit. AnyPS5 has no GC device and answers as the failed ioctl does. The 2-unit answer is not the same on every firmware: on PS5, [as reported](https://github.com/boykopovar/AnyPS5/pull/16238#issuecomment-7007786846), 13.40 returns the constant 2 without reading the word, while 11.00 keeps the 10.71 logic and can also answer 1.
- [draw packets from firmware 10.71](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - `sceGnmDrawOpaqueAuto` (0x1c70) and `sceGnmDrawIndexMultiInstanced` (0x1d20) write the words, size checks and -1 refusals of PS4 firmware 10.71 `system/common/lib/libSceGnmDriverForNeoMode.sprx` (sha256 of the decrypted ELF `fd3e06cd7d130b675334cd0e1dfb52d2aab0d6960624d51d2db8ffd7842cf07b`), read from disassembly, not run on a console. Both set the predicate bit from flag bit 0, as that module does; the shadPS4-derived writers above do not. Not compared with console output, and nothing in AnyPS5 consumes a GNM command buffer yet
- [workload submits](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - in PS4 firmware 10.71 `libSceGnmDriverForNeoMode.sprx`, `sceGnmSubmitCommandBuffersForWorkload` (0xf80) and `sceGnmSubmitAndFlipCommandBuffersForWorkload` (0x1410) return `0x80D11000` for null address or size arrays, a ccb size array without addresses, a dcb size of 0, or a size of `0x3ffffd` or more, and skip the checks for a count of 0. They then ask the GC device whether the queue accepts work (ioctl `0xc0088101`) and return `0x80D110FF` when it does not. `sceGnmRequestFlipAndSubmitDoneForWorkload` (0x17c0) returns `0x80D11001` for a command size below `0x100` words, and the same `0x80D110FF` from that ioctl, before it writes the command. AnyPS5 has no GC device and nothing consumes a GNM command buffer, so a valid submit returns `0x80D110FF` as on a refused ioctl and the buffers are not read. Parameter lists are read from the registers the bodies use
- [sceGnmMapComputeQueueWithPriority](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - as in PS4 firmware 10.71 `libSceGnmDriverForNeoMode.sprx` (0x3f40), returns `0x80D17000` for a pipe above 6, `0x80D17001` for a queue above 7, `0x80D17002` for a ring size that is not a power of two, `0x80D17003` for a ring base with a nonzero low byte and `0x80D17004` for an unaligned read pointer or a priority above 1, in that order. The module then maps the queue with an ioctl and returns `0x80D170FF` when it fails; here it always does, since AnyPS5 runs no GNM compute queue
- [flip option](../../../core/libs/prx/libSceGnmDriverForNeoMode/Export.cpp) (libSceGnmDriverForNeoMode) - in PS4 firmware 10.71 `system/common/lib/libSceGnmDriverForNeoMode.sprx` (sha256 of the decrypted ELF `fd3e06cd7d130b675334cd0e1dfb52d2aab0d6960624d51d2db8ffd7842cf07b`), read from disassembly, not run on a console, `R3TYO7Tdv5o` (0x1a10) and `ut57TBmRQN0` (0x1a60) set and clear a module flag under the module mutex and return the unlock result, and `sKhoi2ectC0` (0x1ab0) returns it. The workload flip paths read the flag at their next flip. Here the flag is kept and returned, the ioctl `0xc0048117` the setters issue on an initialised device is not made, and nothing reads the flag at a flip. Names unknown
