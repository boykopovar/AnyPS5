# shader

## change [v_ldexp_f64]

- [v_ldexp_f64](../../../core/shader/recompiler/Translation/src/Float64Instructions.cpp) follows the `FLOAT_MODE` f16/f64 denormal field; the PS5's gfx1013 is not measured. A denormal src0 is flushed to a zero of its sign when bit 0 is clear (0 and 2), and a result whose exact scaled value |src0 * 2^n| is below the minimum normal 2^-1022 is flushed to a zero of its sign when bit 1 is clear (0 and 1), with tininess tested before rounding, so `0x3fffffffffffffff * 2^-1023` gives 0 in modes 0 and 1 and 0x0010000000000000 in modes 2 and 3. A signaling NaN src0 is quieted only with IEEE=1. Measured on RDNA3 (gfx1101, Radeon RX 7700 XT) with the hardware oracle at IEEE=0 and IEEE=1 over 5264 rows (658 per mode: the inputs above scaled by exponents around the denormal boundary) and 4096 random rows: no mismatch. RDNA2 (gfx1036) matches this at IEEE=0 and 1 over 16 inputs x four denormal modes x two IEEE settings. In the directed round modes (`FLOAT_MODE` f16/f64 round field 1 to 3, declared or set by `s_round_mode`) it rounds the exact scaled value once in that mode: an overflow gives the largest finite value of its sign instead of an infinity when the mode rounds toward zero for that sign, and a denormal result is rounded in the mode rather than to nearest even. Measured on RDNA1 (gfx1010, RX 5700 XT, AMD Windows driver 32.0.21045.5002) over 1838 inputs in all four round modes, all four denormal modes and IEEE 0 and 1, and over 11028 rows with `s_round_mode`: no mismatch with that model, nor over 32 more rows at the minimum normal, subnormal and overflow boundaries in the three directed modes, f16/f64 denormal modes 0 and 3 and IEEE 0 and 1. In the directed modes the result is computed from the significand and exponent bits with integer operations, so it does not depend on the device keeping f64 subnormals when it cannot request `DenormPreserve 64`; round to nearest still scales with `OpFMul` and does. Shaders without a known float mode keep the previous lowering.
