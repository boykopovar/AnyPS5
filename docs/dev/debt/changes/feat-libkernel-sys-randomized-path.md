# libkernel_sys

## remove | `__sys_randomized_path` |

## add Functional

- [`__sys_randomized_path`](../../../core/libs/prx/libkernel_sys/AdditionalExports.cpp) (libkernel_sys) implements the read side of the process randomized-path syscall as `(const char *set, char *get, size_t *len)`: with `set == nullptr`, a non-null `get` and `len` read the caller's capacity from `*len`, replace it with the full sandbox-word length, copy at most `capacity - 1` bytes and NUL-terminate when capacity is nonzero. A null `get` or `len` returns 0 without touching the other argument. Unreadable or unwritable guest pointers return -1 with `EFAULT` as a host-safety fallback. A non-null `set` still throws because changing the process randomized path is not modelled. The argument order and getter behavior follow [Obliteration's `sys_randomized_path` implementation](https://github.com/obhq/obliteration/blob/0831845b724f925b2d8cb546cfb5a630736508b3/legacy/src/process/mod.rs) (syscall 602), while [decanter's reverse-engineering note](https://github.com/yerasuu/decanter/blob/15405de508234fc40b8bbbbed01c397c58e9e875/docs/missing-hle-spec.md) for `sceKernelGetFsSandboxRandomWord` reports that it calls `__sys_randomized_path(0, static_buffer, &len)` and returns null only when that syscall fails. [fpPS4](https://github.com/red-prig/fpPS4/blob/04cefd43e6fddd1ab033e7980cd356d14c964905/kernel/ps4_kernel_file.pas) independently maps `sceKernelGetFsSandboxRandomWord` to `__sys_randomized_path`, without establishing the syscall ABI. AnyPS5 returns its existing fixed sandbox word, not a per-process random value. Console setter behavior, pointer-fault precedence and title behavior remain unmeasured.
