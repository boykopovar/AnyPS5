# libSceUserService

## change [sceUserServiceRegisterEventCallback and sceUserServiceUnregisterEventCallback]
- [sceUserServiceRegisterEventCallback and sceUserServiceUnregisterEventCallback](../../../core/libs/prx/libSceUserService/Export.cpp) - only login/logout transitions have a host event source. Firmware 13.60 `libSceUserService.sprx` at `0x34d0` checks initialization, ignores null callbacks with success and stores unique callback/user-data pairs. At `0x35f0`, unregister checks initialization first, rejects null with `0x80960005` and succeeds for absent pairs. These sites establish the tested null, duplicate and pre-initialization behavior; they were read from disassembly/decompilation; only the pre-initialization answers below were measured on a console. On a PS5 (firmware 11.60, payload process; a title process may differ), in one run, Unregister with a null callback, Register with a static callback (refused) and Unregister of that callback returned `0x80960002` before `sceUserServiceInitialize` (prototype `(callback, userData)` assumed); nothing was measured after an initialization.
