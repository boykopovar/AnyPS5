# libSceFreeType

## change [FT_Alloc, FT_QAlloc and FT_Free]

- [FT_Alloc, FT_QAlloc and FT_Free](../../../core/libs/prx/libSceFreeType/src/MemoryAllocation.cpp) (libSceFreeType) - console signatures and callback/error behavior are unverified; the LP64 guest adapter follows the legacy allocator contract in [FreeType 2.4.12](https://github.com/freetype/freetype/blob/cecf93ef90c660a8b0b45e5adbbfb5ea443fb6b9/src/base/ftutil.c#L49-L89). Null records or outputs make the allocating helpers throw; the reference implementation dereferences them. The record and the output are read and written through checked guest copies: an unreadable record, an unreadable `FT_Free` output or an unwritable output throws before any callback runs; the console's response is unmeasured. FT_Free ignores null records, output pointers and blocks. The Ol provider implements its own Alloc and Free; the Ot QAlloc helper still throws.

## change [FT_Realloc and FT_QRealloc]

- [FT_Realloc and FT_QRealloc](../../../core/libs/prx/libSceFreeType/src/MemoryAllocation.cpp) (libSceFreeType) - console signatures and callback/error behavior are unverified; the LP64 guest adapter follows the legacy reallocation contract in [FreeType 2.4.12](https://github.com/freetype/freetype/blob/cecf93ef90c660a8b0b45e5adbbfb5ea443fb6b9/src/base/ftutil.c#L91-L165): negative current or size report `Invalid_Argument` and keep the output, zero size releases through the free callback and clears the output, sizes above `INT_MAX` report `Array_Too_Large` and keep the output, an empty current takes the zeroing allocation path, a failed growth callback reports `Out_Of_Memory` while keeping the previous block, and only `FT_Realloc` clears the grown region. Null records or outputs make the helpers throw; the reference implementation dereferences them. The record and the output are read and written through checked guest copies: an unreadable record, or an unreadable or unwritable output, throws before any callback runs; the console's response is unmeasured. The matching exports of the distinct physical `libSceFreeTypeOt` provider forward to these wrappers.

## change [FT_Stroker_ParseOutline]

- [FT_Stroker_ParseOutline](../../../core/libs/prx/libSceFreeType/src/Stroker.cpp) (libSceFreeType) - console signature and FreeType version are unverified; the adapter forwards to bundled [FreeType 2.15.0](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/ftstroke.c#L2050-L2264), which returns `Invalid_Outline` for a null outline where [2.4.12](https://github.com/freetype/freetype/blob/cecf93ef90c660a8b0b45e5adbbfb5ea443fb6b9/src/base/ftstroke.c#L2062-L2063) returns `Invalid_Argument`. An unreadable outline record returns the null-outline error. Null or unreadable arrays with contours and contour ends at or past `n_points` throw before the stroker is rewound, as does a coordinate outside `int32_t` in a stroked contour: [`ft_trig_prenorm`](https://github.com/freetype/freetype/blob/37515cf56ba3349656049edbed89ffc6f6466f2d/src/base/fttrigon.c#L131-L142) truncates differences to 32 bits and is undefined when that leaves zero. On Windows (32-bit `FT_Pos`) such coordinates anywhere also throw; curve midpoints use 32 bits
