## add Functional

- [X509_sign](../../../core/libs/prx/libSceLibreSsl3/src/X509Sign.cpp) (libSceLibreSsl3) - nothing is checked on the console. It follows `X509_sign` in LibreSSL 4.0.0 [x_all.c](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/x509/x_all.c) and [`ASN1_item_sign_ctx`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/asn1/a_sign.c): the signature algorithm NID is the first object-table entry whose `OBJ_find_sigid_algs` digest and key NIDs match the digest and `EVP_PKEY_base_id`, both the certificate-info and certificate algorithm identifiers are set from it with a NULL parameter for RSA keys, the signature is stored in the certificate bit string with the no-unused-bits flag, and the signature length is returned. Signing goes through the existing `EVP_SignFinal` path, so it inherits that path's gaps. Unlike LibreSSL it does not mark the certificate-info encoding modified and does not re-encode it: the cached encoding is signed as-is, so a certificate info whose encoding is modified or absent, or whose existing `signature` algorithm differs from the derived one, throws `NotImplemented_nid_no_patch`, and a certificate info with a different digest cannot be signed until `i2d_X509` re-encodes. Key types or digests the EVP path cannot sign (EC keys in this tree) and key types without a signature algorithm object (HMAC) throw. A digest or key that is null, and a missing certificate-info or signature structure, return 0. Replaced algorithm parameters and previous bit-string data are released or replaced through the application heap. Signing twice replaces the signature instead of being rejected.
