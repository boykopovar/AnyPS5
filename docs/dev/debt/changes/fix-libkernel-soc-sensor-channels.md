# libkernel

## change [sceKernelGetCpuTemperature, sceKernelGetSocSensorTemperature]

- [sceKernelGetCpuTemperature, sceKernelGetSocSensorTemperature](../../../core/libs/prx/libkernel/System/src/ThermalSensors.cpp) (libkernel) - channels 3 to 63 report channel 0's value, where a payload process on a PS5 (firmware 13.590.001) answered every channel from 0 to 63 with a reading of 35 or 36 °C while channel 0 read 35 (channels 3 to 5, 7 to 9 and 61 gave 35, channels 6, 30, 60, 62 and 63 gave 36; a payload on 11.60 read 34, 38 and 38 °C from channels 3, 62 and 63), so which sensor each channel reads is not modelled, and a channel the host has no sensor for returns `EINVAL`, where payload processes on PS5 read 49 to 54 °C (firmware 13.60) and 34 to 38 °C (12.70 reporting 13.09) from channels 0 to 63; a null or unwritable output with a valid channel and an available reading returns `EFAULT` (`0x8002000e`) as a host-safety fallback, where a payload process faults (channel 0). Channel 64 writes a fixed -49, as in a payload process; a title process, unwritable outputs and a null output on channel 64 are unmeasured. A channel outside 0 to 64 returns `EINVAL` before the output is read, and `errno` is set. Values come from the host: on Linux `/sys/class/hwmon` and `/sys/class/thermal`, on Windows ACPI thermal zones and the first drive. Channel 0 is the CPU/package value, 1 the first other value and 2 an NVMe value; `sceKernelGetCpuTemperature` reports channel 0. PPSA99058 and PPSA99420 call both
