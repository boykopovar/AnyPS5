# libSceNet

## change on a `sceNetSocket` socket only `FIONBIO` and `FIONREAD` are handled

- [sceNetIoctl](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) - on a `sceNetSocket` socket only `FIONBIO` and `FIONREAD` are handled, though FreeBSD 11.4's [`soo_ioctl`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/sys_socket.c#L156-L262) handles more; not measured on a console. [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/60c42b925c3d1e00008621b8587819999260ec31/src/core/libraries/net/net.cpp#L1839) (PS4) returns `EINVAL` for other requests. `FIONBIO` sets `SO_NBIO`, assumed to be `soo_ioctl`'s `SS_NBIO`. `FIONREAD` asks the host, which on Linux counts only the next datagram where `soo_ioctl` counts all; on macOS a non-stream socket uses `SO_NREAD` (next datagram), as macOS's `FIONREAD` counts more. A PS4 Pro counts payload plus 16 bytes per datagram (#9932). Libkernel's own sockets go to its `ioctl`; other descriptors get `EBADF`.

## add Functional

- [sceNetIoctl requests it does not handle](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) - assumed, not measured, to be the `ioctl` system call on a kernel socket. The requests FreeBSD 11.4's `kern_ioctl` and `soo_ioctl` answer, other than `FIONBIO` and `FIONREAD`, fail with `ENOTTY` instead, as do `u` 106 to 109 on `AF_INET6`, which `in6_control` answers. First, a malformed request fails with `ENOTTY` and an `IOC_IN` argument is copied in (`EFAULT`), as [`sys_ioctl`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/sys_generic.c#L709-L739) does. `i`, `r` and `f` requests fail with `ENOTTY` (FreeBSD sends `i` and `r` elsewhere; `f` is unmeasured). Others fail with `EADDRNOTAVAIL` on `AF_INET`, as `in_control` does with no interface (measured on a libkernel socket), and `EOPNOTSUPP` on `AF_INET6`, as [`in6_control`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/netinet6/in6.c#L244-L270) does; libkernel's `ioctl` gives `EADDRNOTAVAIL` there
