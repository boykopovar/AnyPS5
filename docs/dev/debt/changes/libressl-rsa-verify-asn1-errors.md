# libSceLibreSsl

## change [EVP_DigestVerifyInit and EVP_DigestVerifyFinal]

- [EVP_DigestVerifyInit and EVP_DigestVerifyFinal](../../../core/libs/prx/libSceLibreSsl/src/DigestVerify.cpp) (libSceLibreSsl) - unverified on PS5. Results, reason codes and offsets follow pinned LibreSSL 2.5.4 [m_sigver.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/m_sigver.c) and its `pmeth_lib.c`. With an RSA key, init creates the key context, raises the key references, writes `pctx` and defaults to SHA-1 when `type` is null; a null key with no key context still returns 0 without reading `type` or `engine`. Final copies the context, finalizes the digest and verifies through `RSA_verify` with PKCS#1 v1.5, including corrupt, truncated and wrong-digest signatures. An `ENGINE`, a non-RSA key, a key context this library did not create and RSA-PSS and X9.31 padding throw: no export reaches them.

## change [RSA_verify](

- [RSA_verify](../../../core/libs/prx/libSceLibreSsl/src/Rsa.cpp) (libSceLibreSsl) - nothing is checked on the console. It follows [LibreSSL 2.5.4](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/rsa/rsa_sign.c) `RSA_verify` and `int_rsa_verify`: the method's `rsa_verify` under `RSA_FLAG_SIGN_VER`, the signature length, `RSA_public_decrypt` with PKCS#1 v1.5 padding, the 36-byte `NID_md5_sha1` case and the `X509_SIG` decode with its trailing-data, parameter, object and digest checks, and the `rsa_sign.c` and `rsa_pk1.c` reason codes for those failures. A DigestInfo that the `X509_SIG` decode rejects queues the [tasn_dec.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/asn1/tasn_dec.c) errors of library 13 in LibreSSL's order, `ERR_R_NESTED_ASN1_ERROR` once for each enclosing item and template, without the `Field=` and `Type=` error data. `OBJ_obj2nid` is modelled by the 15 digest objects of that version's object table, so a digest type and an object both outside them, `NID_undef` included, throw, and a signature OID registered with `OBJ_create` throws. The BER forms of the `d2i_RSA_PUBKEY` entry throw here too, as do a null key, a null method under `RSA_FLAG_SIGN_VER`, and a null digest or signature that LibreSSL reads
