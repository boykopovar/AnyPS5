## add Functional

- [WebCore::SharedBuffer layout](../../../core/libs/prx/libSceNKWebKit/src/SharedBufferAbi.hpp) (libSceNKWebKit) - not compared with a console module. The 3.20 names (nested `DataSegment`, `Vector<char>` overloads) match [SharedBuffer.h@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/SharedBuffer.h#L70-L247); the pinned 11.x [SharedBuffer.h](https://github.com/neonmodder123/PS5-WebKit-11.x/blob/80f77e94c63ee7202eec3d4b5b1a021dd89011ba/Source/WebCore/platform/SharedBuffer.h#L263-L310) puts `SharedBuffer()`, `SharedBuffer(MappedFileData&&)` and `data()` on the `FragmentedSharedBuffer` layout instead. The 48-byte buffer and 32-byte segment (variant index byte at 24) assume a release build and the [PlayStation options](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/cmake/OptionsPlayStation.cmake#L143-L164) (no CF, GLib, Soup or GStreamer). Closes when: compared with a console module.
- [WebCore::SharedBuffer storage exports](../../../core/libs/prx/libSceNKWebKit/src/SharedBuffer.cpp) (libSceNKWebKit) - the 29 `create`, constructor, destructor, `append`, `clear`, `combineIntoOneSegment`, `copy`, `data`, `dataAsUInt8Ptr`, `size`, `isEmpty`, `begin`, `end` and `DataSegment::data` and `size` exports follow [SharedBuffer.cpp@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/SharedBuffer.cpp#L39-L332), with segment growth, `shrinkToFit` and `clear` from [Vector.h@73a35b43](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WTF/wtf/Vector.h#L1050-L1251), all memory from `WTF::fastMalloc`. They throw where WebKit crashes or has undefined behaviour: a null object, null bytes with a nonzero length, a `Vector<char>` or segment count past the `WTF::Vector` limits, combining more than `UINT_MAX` bytes, and a valueless or unknown `DataSegment` alternative.
- [WebCore::SharedBuffer remaining exports](../../../core/libs/prx/libSceNKWebKit/Export.cpp) (libSceNKWebKit) - the 11.x `SharedBuffer(MappedFileData&&)` constructors and `decoder` still throw `NotImplemented_nid_no_patch`; the 11.x constructors build the pinned revision's `FragmentedSharedBuffer` layout, which nothing here models yet. `tryCreateArrayBuffer` throws because nothing here implements `JSC::ArrayBuffer`.
