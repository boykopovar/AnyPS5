# libkernel

## change does not consult the target thread's signal mask

- [sceKernelRaiseException](../../../core/libs/prx/libkernel/System/src/Exception.cpp) (libkernel) leaves the raise pending on a target thread that blocks the signal, as FreeBSD's `tdsendsignal` does for a signal sent to one thread, and runs the handler on that thread when it unblocks the signal through `sigprocmask`, `_sigprocmask`, `pthread_sigmask` or the mask of `sigsuspend`, which then returns -1 with `errno` set to `EINTR`, once for any number of raises made meanwhile. The target checks its mask again when the delivery runs on it, so a raise that reaches it after it blocked the signal again is held as well. The end of a running handler's hold on the signal does not deliver it; the next mask change does. A held raise is not reported by `sigpending` and is not taken by `sigwait`, `sigwaitinfo` or `sigtimedwait` on the target thread, as FreeBSD would do; only an unblock delivers it. The console's behaviour is not verified
