# shader

## change [Buffer descriptor type]

- [Buffer descriptor type](../../../core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp) - a buffer V# whose TYPE (word 3 bits 30-31) is not 0 throws `buffer descriptor uses an unsupported type`, except for vector stores through TYPE 2 or 3. Measured on a PS5 (CFI-1115B, firmware 12.20): through TYPE 2 or 3 with FORMAT 0 or a valid format, `buffer_store_dword` and `buffer_store_format_x` wrote nothing and did not fault, also with an unmapped base; loads and GLC atomics left the destination VGPR unchanged, which a null V# can't reproduce, so they throw. TYPE 0 with FORMAT 0 returned 0 for loads and wrote nothing. TYPE 1 faulted the GPU for every access and throws. Multi-dword and multi-component stores through TYPE 2 and 3 (`buffer_store_dwordx2` to `dwordx4`, `buffer_store_format_xy` to `xyzw` and their D16 forms) are dropped like single-dword stores: measured only on a PC RDNA2 GPU (gfx1036), where they wrote nothing in wave32 and wave64 with FORMAT 0, 10, 20 and 77, and the single-dword stores and loads above behaved as on the PS5. Unmeasured and still throwing for TYPE 2 and 3: `tbuffer_*`, scalar loads, FORMAT above 77, GCN shaders and V#s loaded at run time. Closes when: those cases and the multi-dword stores are measured on a PS5.
