# shader

## change [Buffer descriptor type]

- [Buffer descriptor type](../../../core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp) - a buffer V# whose TYPE (word 3 bits 30-31) is not 0 throws `buffer descriptor uses an unsupported type`, except for vector stores and for read-only vector loads through TYPE 2 or 3. Measured on a PS5 (CFI-1115B, firmware 12.20): through TYPE 2 or 3 with FORMAT 0 or a valid format, `buffer_store_dword` and `buffer_store_format_x` wrote nothing and did not fault, also with an unmapped base; single-dword loads and GLC atomics left the destination VGPR unchanged. TYPE 0 with FORMAT 0 returned 0 for loads and wrote nothing. TYPE 1 faulted the GPU for every access and throws. Multi-dword and multi-component stores through TYPE 2 and 3 (`buffer_store_dwordx2` to `dwordx4`, `buffer_store_format_xy` to `xyzw` and their D16 forms) are dropped like single-dword stores: measured only on a PC RDNA2 GPU (gfx1036), where they wrote nothing in wave32 and wave64 with FORMAT 0, 10, 20 and 77. Vector loads through TYPE 2 and 3 recompile to keep their destinations with a null V#: single-dword loads as measured on the PS5, and read-only raw loads of 2 to 4 dwords as measured only on an RX 6650 XT (gfx1032), where every destination was preserved in wave32 and wave64 with mapped valid-format descriptors. Preservation variants with MUBUF LDS remain refused. Unmeasured and still throwing for TYPE 2 and 3: D16 and formatted multi-component loads, multi-dword loads from buffers that are also written, `tbuffer_*`, atomics, scalar loads, FORMAT above 77, GCN shaders and V#s loaded at run time. Closes when: those cases, the multi-dword stores and the multi-dword loads are measured on a PS5.
