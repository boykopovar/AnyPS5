# libSceNet

## add Functional

- [sceNetSocket types 6 and 10](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) - peer sockets have no virtual-port routing or peer framing: connect, send and a receive that returns data on both types, and bind, listen and accept on type 10, throw; a receive with nothing queued fails as the host socket does. Type 6 binds a host UDP socket on `sin_port` and keeps `sin_vport` (bytes 8-9) for `sceNetGetsockname`, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/443b954bea3e8fef664dcc96252a3390f614bf06/src/core/libraries/net/net_translate.cpp#L211-L236) maps a datagram address; a second type 6 socket on the same port gets the host's `EADDRINUSE`. `SO_TYPE` and `sceNetGetSockInfo` report 6 or 10, and type 6 with a non-zero protocol fails with `EPROTONOSUPPORT`, as on a PS4 on firmware 10.71 ([#5836](https://github.com/boykopovar/AnyPS5/pull/5836#issuecomment-6352779503)); the console's peer buffer sizes and sockinfo state are not reproduced.
- [SO_USECRYPTO and SO_USESIGNATURE](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) - the flags protect nothing, as there is no peer framing. On a peer socket an integer is stored and read back as 0 or 1, as [shadPS4](https://github.com/shadps4-emu/shadPS4/blob/443b954bea3e8fef664dcc96252a3390f614bf06/src/core/libraries/net/net.cpp#L2419-L2428) does; other sockets keep `EOPNOTSUPP`, where a PS5 accepts `0x20000` ([#18108](https://github.com/boykopovar/AnyPS5/pull/18108)) and shadPS4 returns `EPROCUNAVAIL`. Peer sockets are not measured on a console. PPSA01289 recreates its peer socket while `0x20000` fails.
