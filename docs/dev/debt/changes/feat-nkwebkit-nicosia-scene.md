Only in the 3.20 inventory; they follow the 2020 [NicosiaScene.cpp](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/graphics/nicosia/NicosiaScene.cpp) and [NicosiaSceneIntegration.cpp](https://github.com/WebKit/WebKit/blob/73a35b43be7ae44c084885bd3fa4b403e59723c8/Source/WebCore/platform/graphics/nicosia/NicosiaSceneIntegration.cpp). The objects have the layout of the pinned headers for the caller's inline `accessState` and `deref` (reference count at 0, lock at 8, then the members), and the layer set is a WTF hash set copied as `HashTable`'s copy constructor does. Derived, not measured. Closes when: compared with a console module.
- [Nicosia::SceneIntegration gaps](../../../core/libs/prx/libSceNKWebKit/src/NicosiaScene.cpp) (libSceNKWebKit) - `createUpdateScope` stays a stub: it returns a `std::unique_ptr` and `UpdateScope`'s destructor, which flushes the layers, is not exported. The three locking functions take the caller's `WTF::Lock` byte on its fast path; where the source parks they yield and retry, a lock that already has parked threads throws `std::runtime_error`, and a thread that parks while one of them holds the lock is not woken, `WTF::Lock::lockSlow` and `unlockSlow` being stubs. Null arguments throw `std::invalid_argument` where the source dereferences them. Closes when: the lock slow paths are implemented and `createUpdateScope` is read from a console module.
