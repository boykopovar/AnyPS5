## change [Scan-resistant sampled texture admission]

- [Scan-resistant sampled texture admission](../../../core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp) - when the sampled texture cache is 100%-125% of budget, first use of an uncached texture in a present is uncached (used then released) if LRU was used in the current or previous present, and a repeat use in that present is uncached if LRU is from the current present (so multi-use textures still evict unused-this-present entries, while excess textures re-create each use). Above 125% or after 2 unused presents, entries evict normally (after a budget drop the cache can stay at up to 125% of it); a repeat use can evict a previous-present entry then hit a current-present LRU. The 2-present window is an unmeasured heuristic. Measured once (A-B-A, 1 title ~33000 textures/frame, 5.4 GiB budget, RTX 4090, 3600 s each): 932/968/941 frames, post-frame-620 evictions 2.72M->1.17M, creations unchanged (~5.8M); other titles/GPUs unmeasured, and slightly over-budget sets thrash.

## change [Settled dma-buf imports]

- [Settled dma-buf imports](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (libSceAgcDriver) - on Linux, dma-buf imports >= 1 MiB run a 4-byte copy on the settle queue (`settleImport`, buffer shared with its queue family) so kernel GPU page mapping happens then rather than on first submission (~2 s for 3 GiB on RADV). Map-time imports stall the guest mapping thread (0.47-2.2 s for 3 GiB in Hades PPSA03355; 0.49-4.3 s for 4.5 GiB in ASTRO BOT PPSA21567 on RADV, both at startup; gameplay maps stall); submission-time imports settle under the GPU mutex. Imports < 1 MiB, devices lacking a separate copy-capable settle queue (pay on first submit), and host-pointer imports (e.g. lavapipe shared memory) are unsettled.
