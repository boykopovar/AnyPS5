# libwebrtc

## add Public source implementations

- [webrtc::AudioDeviceBuffer::StartPlayout, StartRecording, StopPlayout and StopRecording](../../../core/libs/prx/libwebrtc/src/AudioDeviceBuffer.cpp) (libwebrtc) - adapted from [audio_device_buffer.cc](https://webrtc.googlesource.com/src/+/8d78f5de6c27b2c793039989ea381f1428fb0100/modules/audio_device/audio_device_buffer.cc), whose notice and BSD licence head the file, with the same guards: starting an already started side or stopping a stopped one returns, and the others store `playing_` and `recording_`, the `bool`s at offsets 56 and 57 of the measured layout. The task-queue work is not reproduced: each start's stats reset, the periodic logging started and stopped with the pair, the `play_start_time_`, `rec_start_time_` and `only_silence_recorded_` fields and the `RTC_LOG` lines stay out, as they live past the modelled prefix and run on the guest task queue. A null buffer, which upstream dereferences, throws. The upstream methods return `void`; the exports return 0 on success, including the idempotent path, so a caller that tests the status sees success, but the console's return type and status values are not measured. Closes when: those are reproduced and compared with the console.
