# libSceMouse technical debt

### Unknown function info

- [sceMouseGetDeviceInfo, sceMouseSetHandType, sceMouseSetPointerSpeed and the extension calls](../../../core/libs/prx/libSceMouse/Export.cpp) (libSceMouse) - argument lists and checks follow @BunnyFl's [firmware 13.42 disassembly](https://github.com/boykopovar/AnyPS5/issues/15088#issuecomment-6580877653) of `libSceMouse.sprx` (SHA-256 `e07cd04766ea48f5216e40fd4397758f640a7200cfa7edb6a00255326bd33c61`), not a console. Past their checks they throw:
  - `GetDeviceInfo(int32, void*)`, `SetHandType(handle, uint32)` and `SetPointerSpeed(handle, uint32)` end in a mouse driver ioctl, which isn't modelled. `GetDeviceInfo`'s first check, a closed device fd, is taken as not initialised here.
  - `ExtensionSetCursor(handle, int32)` stores a cursor value for the open handle and `ExtensionGetCursor(handle, void*)` returns it through a guarded copy. What the console driver does with the value is unknown; the host keeps it only for the open slot, and a write to unreadable guest memory returns `MOUSE_ERROR_INVALID_ARG`, a host-safety choice not measured on the console.
  - `ExtensionRead(handle, void*, uint32 size, int32 num)` and `ExtensionReadState(handle, void*, uint32 size)` run `sceMouseRead`'s checks with the extension flag, after their size checks (0x30 and 0x40) and `ReadState`'s 64-byte clear; the 0x30-byte extension record and the state the slot keeps at +0x100 are unknown. `ReadState` guards the clear with `GuestCopyOut_nid_no_patch` and returns `MOUSE_ERROR_INVALID_ARG` for an unwritable non-null pointer, a host-safety choice not measured on the console.

- [sceMouseDisconnectAll, sceMouseVirtualDeviceAddDevice, sceMouseVirtualDeviceDeleteDevice and sceMouseVirtualDeviceGetCursor](../../../core/libs/prx/libSceMouse/InventoryExports.cpp) - the names and NIDs are recorded in the [13.60 export inventory](https://github.com/xdCloudy/PS5-13.60-Function-Stub-Library/blob/e495d3cf24aea17cefda59decdfda9e3e4e3e5ff/data/firmware-13.60/libscemouse-acdd5b5e23.jsonl). Signatures and behavior remain unknown; the parameterless `int` declarations only resolve imports and every call throws. Not measured on a console.

- [sceMouseConnectPort, sceMouseDeviceOpen, sceMouseDisconnectDevice, sceMouseDisconnectPort, sceMouseMbusInit and sceMouseSetProcessPrivilege](../../../core/libs/prx/libSceMouse/Export.cpp) (libSceMouse) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceMouse.c); the no-argument prototypes follow [shadPS4's PS4 stubs](https://github.com/shadps4-emu/shadPS4/blob/f68923fe807f657348e6719ce658bcbd0a2b1c72/src/core/libraries/mouse/mouse.cpp#L34-L146), not measured on a console. These declarations have no parameters solely to resolve known imports and make no ABI claim. Each returns `MOUSE_ERROR_NOT_INITIALIZED` (`0x80df0005`) before initialization and throws afterwards.

### Functional

- [sceMouseExtensionScalePosition](../../../core/libs/prx/libSceMouse/Export.cpp) returns `MOUSE_ERROR_INVALID_ARG` for unreadable or unwritable position memory through guarded copies. This is a host-safety fallback; console behavior for non-null invalid pointers is unmeasured. Initialization and null/zero-scale checks precede the memory access; a failed input copy does not write.

- [sceMouseGetHandle, sceMouseExtensionSetConfig and sceMouseExtensionScalePosition](../../../core/libs/prx/libSceMouse/src/mouse_impl.cpp) (libSceMouse) - follow the same [13.42 disassembly](https://github.com/boykopovar/AnyPS5/issues/15088#issuecomment-6580877653), not a console; none reaches the driver.
  - `GetHandle(userId, type, index)` returns the handle `sceMouseOpen` gave that user and type, or 0x80df0008. The console skips slots whose +0xc8 field is 1 when `index` is non-zero; that field's meaning is unknown, and no slot here has it.
  - `ExtensionSetConfig(handle, config)` refuses a null or a non-zero byte in 5..0x1f, then stores the u32 at 0 and the byte at 4; nothing here reads them yet. A guarded guest copy rejects unreadable non-null config memory with `MOUSE_ERROR_INVALID_ARG`, a host-safety choice not measured on the console.
  - `ExtensionScalePosition(uint16* position, uint16 scale)` rounds `*position * (scale - 1) / 65535` up. The console divides with a multiply by 0x80008001 and a shift by 47, which is the floor, and adds 1 when the remainder isn't 0, through a compare of `-(product * 65537)` with 0x10002 ([@BunnyFl's emulation](https://github.com/boykopovar/AnyPS5/pull/15106#pullrequestreview-5739861373)).

- [Publish](../../../core/libs/prx/libSceMouse/src/mouse_impl.cpp) (libSceMouse) - consecutive motion-only reports with the same buttons are summed into the newest unread entry, so a title that reads a few entries per frame gets current motion instead of a full queue of old reports. Reports with no motion and no button, wheel, tilt or connection change are dropped. Per-report granularity and the console's own report rate are not reproduced

- [sceMouseResetAbsolutePosition, sceMouseSetAbsoluteVirtualScreenSize, sceMouseSetAbsoluteHighPrecisionMode, sceMouseReadAbsolutePosition](../../../core/libs/prx/libSceMouse/src/mouse_impl.cpp) (libSceMouse) - follow firmware 13.42 [run natively](https://github.com/boykopovar/AnyPS5/issues/11477#issuecomment-6502712241) with the driver stubbed: checks and order, screen sizes and rescale, the mode byte, the curve with its fraction, the 40-byte record. Host choices, after [XatiX's title-tested version](https://github.com/boykopovar/AnyPS5/issues/11477#issuecomment-6503782633): each host event is one sample with unscaled counts, in its own queue, so `sceMouseRead`'s motion merging does not feed the curve. A read takes all pending samples; past `num`, same-button neighbours share a record, each still moving the pointer, and the last `num` records are kept. Speed is taken as 4, the hand swap and flagged bit never apply, and a disconnected mouse stands in for a zero driver status
- [sceMouseDebugGetDeviceId](../../../core/libs/prx/libSceMouse/src/mouse_impl.cpp) - validation order and the empty/live-slot split follow the [retail 11.00 dump decode](https://github.com/boykopovar/AnyPS5/issues/12063#issuecomment-6483898452): not-initialized first, then null output, -1 written up front, a match on a port handle with an empty slot returns success leaving -1, a live slot writes the device id, and no match returns INVALID_HANDLE. A closed handle returns INVALID_HANDLE like the other mouse functions; whether the console treats the port handle as valid after `sceMouseClose` is not covered by the decode. The reported device id is a model constant for the single emulated device; the console's device-id assignment is not decoded.

- [sceMouseReadAbsolutePosition](../../../core/libs/prx/libSceMouse/src/mouse_impl.cpp) (libSceMouse) - the console driver's treatment of unread samples across disconnection is unknown. The host drops pending absolute samples when the mouse disconnects so a later reconnect cannot replay motion from the previous connection; the absolute pointer position itself is retained.
