# libSceContentSearch technical debt

### Silent stubs

- [Empty results](../../../core/libs/prx/libSceContentSearch/Export.cpp) - titles query the service without failing when zero items are returned. The search operations emulate an empty content database rather than throwing unimplemented stubs.
- [sceContentSearchTerm](../../../core/libs/prx/libSceContentSearch/Export.cpp) (libSceContentSearch) - does not release backend resources; unverified on real hardware.
- [Error precedence](../../../core/libs/prx/libSceContentSearch/Export.cpp) (libSceContentSearch) - the precedence of `ErrorNotInitialized` (0x80810001) over argument errors in `sceContentSearchInit` and `sceContentSearchTerm` is unverified on real hardware.
- [sceContentSearchSearchContent](../../../core/libs/prx/libSceContentSearch/Export.cpp) (libSceContentSearch) - accepts all well-formed queries and reports zero results; filter and sort parameters are validated but not evaluated.

### Functional

- [Content queries](../../../core/libs/prx/libSceContentSearch/Export.cpp) use an empty host library and always report update id 0; the console's initial update id is unverified. No content rows are produced. Every title is assumed to have search permission. Nested filter/sort validation is incomplete: empty nested column sets, null filter values and unknown enum values throw. Guest heap allocation and the platform-dependent minimum heap size are unimplemented. Initialization and outer pointer/count/limit validation follow the supplied module. In `sceContentSearchGetTotalContentSize`, `sceContentSearchGetNumOfContent` and `sceContentSearchGetContentLastUpdateId`, returning `ErrorInvalidArgument` for non-null unmapped pointers is an unmeasured host-safety fallback; in `GetTotalContentSize` and `GetNumOfContent`, the first output is stored before the second pointer is copied out, so if only the second pointer is unwritable, the first value is stored when `ErrorInvalidArgument` is returned.
- [sceContentSearchGetNumOfApplication, sceContentSearchGetApplicationLastUpdateId and sceContentSearchGetMyApplicationIndex](../../../core/libs/prx/libSceContentSearch/Export.cpp) (libSceContentSearch) - signatures from the 11.00 module wrappers at `0x18e70`, `0x18f70` and `0x191a0` in `libSceContentSearch.sprx` (SHA-256 `af44252b7b9a0c2d83d01197a4d38119375fb14b82c7e2a822187a49432b42e4`): `GetNumOfApplication` takes the column-set and order-by pairs plus the count and update-id outputs; `GetApplicationLastUpdateId` writes a 64-bit update id. The host reports zero applications and update id 0 because the host library has no application records; the console values are unverified. `GetMyApplicationIndex` writes a 32-bit index, defaults it to 0 before delegating, and returns the delegate's result, which is not established when the title is absent from the library, so the host writes 0 and then throws through `NotImplemented_nid_no_patch`. All three check initialization and null outputs first, and `GetNumOfApplication` validates the column-set and order-by contents as the content queries do. `sceContentSearchSearchApplication` still throws because its eleven-argument contract is not mapped.
- [Metadata access](../../../core/libs/prx/libSceContentSearch/Export.cpp) cannot open metadata by path or content id because missing-content errors remain unresolved: past their argument checks, both opening calls go through `NotImplemented_nid_no_patch`. No metadata handles are issued. The field-info and value queries reject invalid outer pointers, then go through `NotImplemented_nid_no_patch`, as no metadata id is ever opened and the console's error for one depends on the requested field; closing an unopened handle returns the confirmed invalid-argument error.
