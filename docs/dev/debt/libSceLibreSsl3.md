# libSceLibreSsl3 technical debt

- [libtls CA memory and verification settings](../../../core/libs/prx/libSceLibreSsl3/src/LibTls.cpp) - Five additional exports copy owned CA and certificate bytes, assign a protocol bitmask, and set client-certificate and hostname-verification flags. They follow [OpenBSD libtls `tls_config.c`](https://github.com/openbsd/src/blob/master/lib/libtls/tls_config.c). `tls_config_set_cert_mem` copies the bytes but does not derive the public key hash or parse the certificate as [tls_keypair.c](https://github.com/openbsd/src/blob/master/lib/libtls/tls_keypair.c) does, so malformed certificates are accepted and the error string stays null. TLS transport, certificate parsing and cipher-list validation remain unimplemented; `tls_config_set_ciphers` still throws; `tls_config_parse_protocols` is implemented in `TlsProtocols.cpp`. Native PS5 ABI and option interoperability are unverified.
- [OBJ_cmp](../../../core/libs/prx/libSceLibreSsl3/src/ObjCmp.cpp) (libSceLibreSsl3) - PS5 behavior and the library's LibreSSL version are not verified. The 40-byte LP64 `ASN1_OBJECT` layout and the comparison (length difference first, then the first differing byte as a difference of unsigned values) follow the public [LibreSSL source](https://github.com/libressl/openbsd/blob/bc9483725c5815efb64b6d9acc52fc5fba139212/src/lib/libcrypto/objects/obj_lib.c); the magnitude of a byte mismatch is the byte difference rather than whatever the console's `memcmp` returns. Null objects, null data with a nonzero length and negative lengths throw. LibreSSL subtracts unequal lengths before reading data, so unequal negative lengths do not necessarily fault; only equal negative lengths reach its byte comparison.
- [EVP_MD_block_size](../../../core/libs/prx/libSceLibreSsl3/AdditionalExports.cpp) (libSceLibreSsl3) - no console measurement. The result follows LibreSSL 2.5.4 [evp_lib.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/evp/evp_lib.c).
- [`X509_PUBKEY_get0_param`](../../../core/libs/prx/libSceLibreSsl3/src/X509PubkeyParam.cpp) follows LibreSSL 4.0.0 `crypto/asn1/x_pubkey.c` at [`ce488b78e0bd994780569df718596b9776ff681a`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/asn1/x_pubkey.c) and its `x509_local.h`, `x509.h` and `asn1.h` layouts. The function returns borrowed pointers and writes the encoded key length only when the key output is requested. The PS5 layout and malformed-object behavior are not verified on hardware; layout assertions match the pinned x86-64 source declarations.
- [`X509_set_version`](../../../core/libs/prx/libSceLibreSsl3/src/X509.cpp) follows LibreSSL 4.0.0 `crypto/x509/x509_set.c` at [`ce488b78e0bd994780569df718596b9776ff681a`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/x509/x509_set.c) and the `X509_CINF` layout in its `x509_local.h`. Versions outside 0 to 2 return 0 without mutation; a missing version integer is allocated from the guest heap, the encoding is marked modified, and the value is set through `ASN1_INTEGER_set`. A null certificate returns 0 and null certificate info, undefined upstream, throws. The 104-byte `X509_CINF` layout and the `enc.modified` offset 96 are not measured on the console.
### Functional

The PS5 layout and console behaviour are unverified. Closes when: compared with the console.

- [AES_wrap_key](../../../core/libs/prx/libSceLibreSsl3/src/AesWrap.cpp) - follows [RFC 3394](https://www.rfc-editor.org/rfc/rfc3394) with the default IV `A6A6A6A6A6A6A6A6`, six rounds and the 64-bit counter XORed into the A block; it encrypts through libSceLibreSsl's `AES_encrypt`. Inputs below 16 bytes or not a multiple of 8 return -1 as LibreSSL does (OpenSSL 1.1 returns 0); null key, input or output throws where LibreSSL dereferences it. - [SSL_get_version](../../../core/libs/prx/libSceLibreSsl3/src/Ssl.cpp) - maps the SSL version field to the LibreSSL strings `TLSv1`, `TLSv1.1`, `TLSv1.2`, `TLSv1.3`, `DTLSv1`, `DTLSv1.2` or `unknown`; a null SSL throws. - [libtls context and configuration lifecycle](../../../core/libs/prx/libSceLibreSsl3/src/LibTls.cpp) - Ten exports implement only preconnection lifecycle and configuration. TLS handshake, read/write, certificate validation and encrypted transport still throw; callers cannot establish TLS sessions. No PS5 native ABI or error strings have been measured. Signatures and config ownership follow the [LibreSSL libtls API](https://man.openbsd.org/tls_init.3) and [source](https://github.com/libressl/openbsd/tree/master/src/lib/libtls): independent config allocation, refcounts held by client/server contexts, copied key memory zeroized on replacement/free, error pointers and fresh-context close/configure behavior. A server without a certificate fails. Future transport must consume the retained config and implement certificate/SSL context state.


- [OpenSSL_version](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) - other firmware revisions are unverified. Selectors 0 through 5 follow the public firmware 13.40 measurements in [discussion #8981](https://github.com/boykopovar/AnyPS5/discussions/8981#discussioncomment-19111214); unknown selectors follow LibreSSL 4.0.0 and return `not available`. No independent console test was run.

- [ERR_load_crypto_strings and ERR_peek_last_error](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) have no console execution verification. [Firmware 13.42 modules run on a PC](https://github.com/boykopovar/AnyPS5/pull/9535#issuecomment-6407060914) retained numeric-only output after loaders and matched queue order/overflow; whether the two firmware modules share a queue was not tested. This implementation reads libSceLibreSsl's calling-thread queue. `ERR_print_errors_cb` remains throwing because guest thread identifiers and diagnostic metadata are unverified.

### Functional

- [RSA_set0_key, RSA_set0_factors, RSA_set0_crt_params and BN_clear_free](../../../core/libs/prx/libSceLibreSsl3/src/RsaSetters.cpp) have no console verification or key-constructor/destructor interoperability measurement. They use the existing 152-byte RSA layout and the 24-byte BIGNUM layout of [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto), following `rsa/rsa_lib.c` and `bn/bn_lib.c`: a successful setter owns supplied components, retains omitted components and clears replaced components through the guest allocator; static limb arrays are borrowed. Missing required components return zero before mutation. Null RSA objects and negative owned limb capacities throw instead of dereferencing invalid memory or erasing an unbounded range. Malformed pointers and aliased component ownership are unverified. Closes when: compared with the console and complete key lifetimes.

- [`EC_POINT_clear_free`](../../../core/libs/prx/libSceLibreSsl3/AdditionalExports.cpp) releases the opaque legacy `EcPoint` wrapper through `EC_POINT_free`; mbedTLS zeroizes and frees each coordinate limb. This matches LibreSSL's clear-free delegation, but the host wrapper itself follows its existing C++ destructor/allocation path rather than LibreSSL's native struct `freezero` allocation path. PS5-specific behavior is unverified.

- [Forwarded BN_new and BN_free](../../../core/libs/prx/libSceLibreSsl3/ParentExports.cpp) still throw in the parent library. Future implementations must allocate owned BIGNUM limbs and structs from the same guest heap used by the RSA setters and set `BN_FLG_MALLOCED` on heap-owned structs. Constructor/setter/destructor interoperability remains unverified.
- [SSL_SESSION_get_master_key](../../../core/libs/prx/libSceLibreSsl3/src/SessionMetadata.cpp) (libSceLibreSsl3) - the NID is in the PS5 3.20 inventory; console prototype and version equivalence are unverified. The LP64 behaviour follows the bundled LibreSSL `ssl_sess.c`: a null `out` returns the stored length, otherwise the number of copied bytes is returned and the key is truncated to `max_out`. A null session returns 0 and a stored length above the 48-byte field clamps to 48 as host-safety limits; console behaviour for those inputs is unmeasured.

- [OCSP_CERTID_free](../../../core/libs/prx/libSceLibreSsl3/src/OcspCertId.cpp) - console ABI and allocator equivalence are unmeasured. The 32-byte LP64 layout and reverse SEQUENCE field destruction follow LibreSSL 4.0.0 [`ocsp_asn.c`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/ocsp/ocsp_asn.c), `ocsp_local.h`, `asn1/tasn_fre.c` and `asn1/x_algor.c` at the same revision. Existing ASN.1 destructors release the fields through the application heap; static OIDs remain borrowed. Closes when: compared with the console.
- [OCSP_resp_find_status](../../../core/libs/prx/libSceLibreSsl3/src/OcspFindStatus.cpp) follows [LibreSSL 4.0.0 ocsp_cl.c and ocsp_lib.c](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/ocsp): first matching ID, OID/name/key/serial comparison, ignored algorithm parameters, borrowed status/time outputs and untouched outputs on a miss, including null basic responses. The existing parent OCSP records and `OCSP_single_get0_status` are reused through NID imports. Signed serial comparison is private, ported from `asn1/a_int.c`, using the implemented `ASN1_OCTET_STRING_cmp` for its `ASN1_STRING_cmp` operation; no compare export is added. Null response data, single responses, IDs, algorithms and serials throw where upstream dereferences them. Console layout/ABI equivalence and constructor interoperability are unmeasured. The pending-export count is a recount of Export.cpp stubs. Closes when: compared with the console.
