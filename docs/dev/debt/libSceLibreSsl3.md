# libSceLibreSsl3 technical debt

### Unknown function info

- [libSceLibreSsl3 pending exports](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) - 72 named callable exports, excluding `CRYPTO_memcmp`, `MD5`, `SHA1`, `d2i_ASN1_INTEGER`, `EVP_PKEY_up_ref`, `EC_KEY_up_ref`, `SSL_CTX_up_ref`, `SSL_up_ref`, `SSL_SESSION_up_ref`, `SSL_CTX_set_min_proto_version`, `SSL_CTX_set_max_proto_version`, `SSL_get_client_random`, `X509_up_ref`, `X509_get_version` and `BIO_up_ref`, remain unimplemented from the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceLibreSsl3.c), cross-checked against the same module in PS5 firmware 13.60. Their signatures and behaviour are unverified; the declarations use the no-parameter unknown-signature convention and throw through `NotImplemented_nid_no_patch`.

### Functional

- [ASN.1 integer decoding](../../../core/libs/prx/libSceLibreSsl3/src/IntegerDecoder.cpp) throws on rejected encodings/allocation failures instead of matching native NULL/error handling. Redundant-sign/empty-content rejection retains old output that the module frees and clears. The decoder does not populate the legacy queue; remaining LibreSSL3 ERR exports throw. [13.42 native-PC evidence](https://github.com/boykopovar/AnyPS5/pull/10948#issuecomment-6412137728), using a recording allocator, confirms tested replacement/free order, allocation cleanup and negative-length NULL returns. Nonnegative null input faults natively and throws here. Console/application-heap ABI and untested error-precedence/overflow combinations remain unverified. Contracts follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/asn1). Closes when: error/replacement semantics and console/allocator interoperability are verified.
- [CRYPTO_memcmp](../../../core/libs/prx/libSceLibreSsl3/Export.cpp) follows the public [LibreSSL signature and equality contract](https://man.openbsd.org/CRYPTO_memcmp.3), without PS5 verification. The exact nonzero result for unequal buffers is unspecified by that contract. Content-independent execution of its volatile byte reads still depends on the compiler; inspect optimized code when changing toolchains. Closes when: measured on a PS5 and the supported toolchains' generated code is checked.
- [MD5 and SHA1](../../../core/libs/prx/libSceLibreSsl3/src/Digest.cpp) (libSceLibreSsl3) - follow LibreSSL's [md5.c, sha1.c](https://github.com/libressl/openbsd/tree/bc9483725c5815efb64b6d9acc52fc5fba139212/src/lib/libcrypto) and hash through libSceLibreSsl's `MD5_*` and `SHA1_*`. A null digest buffer, which LibreSSL 4.0.0 does not check, throws. Nothing is checked on the console
- [EVP_PKEY_up_ref and EC_KEY_up_ref](../../../core/libs/prx/libSceLibreSsl3/src/Key.cpp) - console layouts and retain/release interoperability are unverified. The 32-byte EVP and 64-byte EC layouts, with counters at offsets 4 and 48, follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto) `evp/evp_local.h`, `evp/p_lib.c`, `ec/ec_local.h` and `ec/ec_key.c`. Atomic retains replace its internal mutex; future releases must synchronize with the same counters. With no key constructors/destructors in this module, tests use caller-owned objects without validating allocator or destruction compatibility. Null keys and signed-counter overflow, undefined upstream, throw without mutation. Closes when: console layouts and lifetime interoperability are measured.
- [SSL_CTX_up_ref](../../../core/libs/prx/libSceLibreSsl3/src/Key.cpp) - console layout and retain/release interoperability are unverified. The SSL_CTX layout, with references counter at offset 40, follows [LibreSSL 4.0.0](https://github.com/libressl/openbsd/blob/bc9483725c5815efb64b6d9acc52fc5fba139212/src/lib/libssl/ssl_lib.c#L2244-L2248). Atomic retain replaces internal locking; future releases must synchronize with the same counter. With no context constructor or destructor in this module, tests use caller-owned objects without validating allocator or destruction compatibility. Null context and signed-counter overflow, undefined upstream, throw without mutation. Closes when: console layout and lifetime interoperability are measured.
- [SSL and SSL_SESSION retains, SSL_CTX version bounds and SSL_get_client_random](../../../core/libs/prx/libSceLibreSsl3/src/Ssl.cpp) - the SSL_METHOD, SSL_CTX, SSL, SSL3_STATE and SSL_SESSION offsets follow [LibreSSL 4.0.0 ssl_local.h](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libssl/ssl_local.h) and are not measured on the console. No SSL constructor is implemented: on Linux and macOS, libSceLibreSsl3 importers reach the LibreSSL 2.5.4 constructor stubs of libSceLibreSsl by dependency lookup. 2.5.4 puts the SSL and SSL_SESSION counters at 168 and 160 and SSL s3 at 48, and the method and SSL_CTX version bounds in internal structs, so every call here would misread a 2.5.4 object. Signed-counter overflow at INT32_MAX and null objects, methods and SSL3 state, undefined upstream, throw without mutation. Closes when: the offsets are measured on the firmware module and SSL constructors use these layouts.
- [X509_up_ref and X509_get_version](../../../core/libs/prx/libSceLibreSsl3/src/X509.cpp) - X509_get_version queues its ASN.1 errors in the libSceLibreSsl queue without file or line, while the firmware module keeps its own queue. libSceLibreSsl3 importers can read it only on Linux and macOS, where their ERR_get_error resolves to libSceLibreSsl by dependency lookup; Windows imports search only the named module and libc. The X509 and X509_CINF offsets follow [LibreSSL 4.0.0 x509_local.h](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/x509/x509_local.h), match 2.5.4 and are not measured on the console. Signed-counter overflow at INT32_MAX and null certificates, certificate info and integer data with a positive length, undefined upstream, throw without mutation. Closes when: the offsets and the error queue are measured on the firmware module and importers read the queue on every host.
- [BIO_up_ref](../../../core/libs/prx/libSceLibreSsl3/src/Key.cpp) - the console layout is unverified. The counter at offset 80 of the 112-byte `BIO`, and the result of 1 when the new count is above 1, follow [LibreSSL 4.0.0](https://github.com/libressl/openbsd/tree/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/bio) `bio_local.h` and [`bio_lib.c` L198-L202](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/bio/bio_lib.c#L198-L202). An atomic retain replaces `CRYPTO_add` and its lock. This module creates no BIO, so tests use caller-owned ones. A null BIO and signed-counter overflow at INT32_MAX, undefined upstream, throw without mutation. Closes when: the layout is measured on the firmware module.
