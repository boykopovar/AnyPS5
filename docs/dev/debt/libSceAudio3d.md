# libSceAudio3d technical debt

### Silent stubs

- [libSceAudio3d](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - bed PCM is mixed and played: `sceAudio3dBedWrite` and `sceAudio3dBedWrite2` store the bed, `sceAudio3dPortAdvance` mixes it into a stereo frame with a linear-balance pan and a 5.1/7.1 downmix ([Mixer.hpp](../../../core/libs/prx/libSceAudio3d/Mixer.hpp)) and queues the frame, and `sceAudio3dPortPush` opens a type-126 AudioOut port on first use and submits the queued frames to it. The explicit `sceAudio3dAudioOutOpen`, `sceAudio3dAudioOutOutput` and `sceAudio3dAudioOutOutputs` exports queue their blocks, and `sceAudio3dPortPush` and `sceAudio3dPortFlush` drain them. Object attributes are validated but produce no audio and no panning: the ids of the `PCM`, `GAIN` and `POSITION` attributes and the layout of the `POSITION` value are unknown, as the aerolib NID list gives the names only, the Orbital IDA type database gives the signatures only and shadPS4's values are PS4, so an object has no samples, gain or position to mix. `sceAudio3dPortSetAttribute` accepts the late reverb level and the downmix spread attributes and ignores them. The attribute enum values and the panning model are unverified, `sceAudio3dPortGetAttributesSupported` reports no capabilities, `sceAudio3dPortGetParameters` reports `size_this = 0x28`, and `sceAudio3dPortGetState`, `sceAudio3dPortGetStatus`, `sceAudio3dPortGetBufferLevel`, `sceAudio3dPortCreate`, `sceAudio3dPortDestroy`, `sceAudio3dPortFreeState`, `sceAudio3dPortQueryDebug`, `sceAudio3dPortOpenEx`, `sceAudio3dSetGpuRenderer`, `sceAudio3dReportRegisterHandler`, `sceAudio3dReportUnregisterHandler`, `sceAudio3dCreateSpeakerArray`, `sceAudio3dDeleteSpeakerArray`, `sceAudio3dGetSpeakerArrayMemorySize`, `sceAudio3dGetSpeakerArrayMixCoefficients` and `sceAudio3dGetSpeakerArrayMixCoefficients2` are `NotImplemented` stubs

### Unknown function info

- [sceAudio3dPortOpen](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - buffer modes 0 and 1 (also selected by the 0x10 and 0x18 parameter sizes) and 3 beds depend on an SDK version check in the module ([prosper](https://github.com/mattias800/prosper)) and throw. A repeated `sceAudio3dInitialize` (`NOT_READY` in shadPS4, 0 in prosper) and `sceAudio3dPortAdvance` on a full queue (`NOT_READY` in shadPS4, unhandled in KytyPS5) throw too
- [sceAudio3dObjectReserve](../../../core/libs/prx/libSceAudio3d/Export.cpp) (libSceAudio3d) - object ids, the `max_objects` limit and the checks of `sceAudio3dObjectReserve` and `sceAudio3dObjectUnreserve` follow [shadPS4](https://github.com/shadps4-emu/shadPS4) (PS4), the only reference with a body: ids count up from 1 per port, skipping 0, 0xFFFFFFFF and ids in use, and a failed reserve writes 0xFFFFFFFF
