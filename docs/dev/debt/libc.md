### Unknown function info

- [GuestArenaArmOwned](../../../core/libs/prx/libc/include/WindowsMappings.hpp) (libc) is a host-only byte-change proof, not console ABI. Tokens cover whole 64 KiB blocks; writes outside the requested subrange can invalidate them. Callers must synchronize stores around the snapshot they cache.
- [GuestArenaArmOwned](../../../core/libs/prx/libc/include/WindowsMappings.hpp) (libc) accepts only fully committed writable write-watched blocks queryable as one Windows allocation. Private commits require flag 1. Shared, pinned, host-open, unwatched and incomplete blocks refuse; other platforms refuse.
- [GuestArenaArmOwned](../../../core/libs/prx/libc/include/WindowsMappings.hpp) (libc) bounds token and pending maps to 65,536 blocks each. Full pending capacity refuses new blocks before resetting writes; token pressure invalidates lowest-address proofs. Impact on titles is unmeasured.
- [GuestArenaOwnedUnchanged](../../../core/libs/prx/libc/include/WindowsMappings.hpp) (libc) requires mapping changes, pins and host accesses to pass through the arena APIs. It does not prove unchanged protection or track GPU writes; future driver consumers must check GPU write stamps separately.
- [GuestArenaOwnedUnchanged](../../../core/libs/prx/libc/include/WindowsMappings.hpp) (libc) conservatively invalidates tokens on rearming, protection notifications and clearing collections. The mutex serializes tracker operations, not concurrent CPU stores; no snapshot transaction or epoch reuse is supplied.

- [frexpf](../../../core/libs/prx/libc/src/Math.cpp) (libc) - follows the bundled PPSA03766 implementation: exponent-bit decomposition, conditional single-precision subnormal scaling, zero exponent for zero/NaN/infinity, and unchanged signaling NaNs. PPSA07923 agrees on results/exponents but unconditionally scales finite inputs, additionally raising overflow/inexact on large values; that SDK variant is not reproduced. Masked-exception observations cover rounding, DAZ/FTZ and sticky flags; unmasked traps and other SDK versions are unverified.
- [std::__sce_v2 _Poly and _XLgamma](../../../core/libs/prx/libc/src/MathExact.cpp) (libc) follow the `libc.prx` bundled with PPSA03671 v01.001.005 (J03848509). `_Poly` uses that module's fused multiply-add loop; when an operand is a NaN it returns the quieted NaN of `x`, then of the running value, then of the coefficient, the order that loop's `vfmadd213sd` showed on an AMD Zen 2 host, not the host `fma`'s order. The three `_XLgamma` overloads use the six-term Lanczos series that module uses, with its constants and operation order, but call this libc's `log`, `logf` and `logl`. Those are host functions, not the module's: they return other last bits for some arguments and do not raise the module's x87 flags on negative arguments, so `_XLgamma` inherits those differences. Console execution and other firmware or SDK versions are unverified.

- On macOS the [write watch](../../../core/libs/prx/libc/src/GuestWriteWatch.cpp) write-protects watched pages and records the first write to each from a SIGBUS/SIGSEGV handler, because macOS has no counterpart to `userfaultfd` write-protect or `MEM_WRITE_WATCH`. The protection is real, so:
  - a system call that writes into a protected page fails with `EFAULT` instead of faulting. `GuestArena::HostWrite` lifts the protection for the calls it brackets (file reads and socket receives), as [Host writes into guest memory](../CONVENTIONS.md#host-writes-into-guest-memory) requires; a host call that writes guest memory without it (`clock_gettime` and the like into a watched page) fails;
  - code that changes the protection of watched pages has to do it through `GuestWriteWatchProtect`, which changes the host protection and the recorded one under the watch's lock, as `mprotect` in libkernel does. Code that maps over them registers the range again (`GuestWriteWatchRegister`), which reads the new host protection; `GuestWriteWatchProtectionChanged`, for code that changes a protection itself, has no caller yet. Code that asks the kernel for a page's protection has to ask `GuestWriteWatchProtection` first, since a watched page is read-only between a collection and the next write, as `sceKernelVirtualQuery` does for memory outside the guest allocation registry;
  - the handler is installed when libc loads and passes other faults to the handler installed before it. A handler installed later has to do the same.
  - a read trap (`GuestWriteWatchTrapReads`) takes all access to its pages until the resolver set with `GuestWriteWatchSetReadTrapResolver` has run for it. libSceAgcDriver sets them on storage images at labels ([Label read traps](libSceAgcDriver.md)). A fault on a trapped page, read or write, waits while the resolver runs on the watch's own thread; a host write and `GuestWriteWatchProtect` run it first on the calling thread. A system call that reads a trapped page fails with `EFAULT`. A resolver that stores into its range with the CPU makes each page accessible to every thread at its first store there, and one that starts a host write over it makes the whole range accessible, so another thread can read a partly stored range; stores through a host import of the memory alone do not. Registering or unregistering memory drops its traps without running the resolver. A thread that holds something the resolver needs and then touches a trapped range, or starts a host write or protect over one being resolved, waits for the resolver forever; and a resolver that touches the pages of a trap it was not called for gets them without that trap ever being resolved.
  - a write fault in a watched file mapping whose backing has been truncated can still be retried indefinitely. The watch records page permissions, not the backing's lifetime.
  - a write fault on a page whose two predecessors were written since the last collection unprotects the rest of its 64 KiB block (at most `APS5_WRITE_WATCH_FAULT_AHEAD` pages, 32 by default) where the pages keep the same protection, and records them all as written, so a collection after a sequential write can report pages nobody wrote. They stay inside a 64 KiB block one of whose pages was written, the unit libSceAgcDriver's write-back decides on.
